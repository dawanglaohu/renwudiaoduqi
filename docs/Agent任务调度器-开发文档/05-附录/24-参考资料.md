### 官方文档（联网核实）

完整记录在 `_run/research-agents-web.md`。

- **Codex** —— https://learn.chatgpt.com/docs/ （文档站已由 `developers.openai.com/codex` 迁移至此）
  - `codex://` deep link **只填充输入框、不自动发送**（官方明文）
  - `codex app-server` 标注 "primarily for development and debugging and **may change without notice**"；
    WebSocket 传输 "**unsupported** for production workloads"
  - `codex mcp-server` **已废弃**，官方指向 app server
  - 会话路径 `$CODEX_HOME/sessions/YYYY/MM/DD/rollout-〈ts〉-〈thread_id〉.jsonl`；
    **官方建议用 `thread/list` + `thread/read` 而非解析文件**
- **Claude Code** —— https://code.claude.com/docs/ （由 `docs.claude.com/en/docs/claude-code` 迁移）
  - Desktop 对照表原文：`--print` / `--output-format` → **"Not available. Desktop is interactive only."**；
    "Scripting and automation | Desktop: **Not available**"
  - Desktop 现为一个 app 三个 tab：Chat / Cowork / Code
  - `claude agents --json` 字段：`state`（`working|blocked|done|failed|stopped`）、`waitingFor`、`sessionId`、`pid`
  - 会话路径 `~/.claude/projects/〈project〉/〈session-id〉.jsonl`
  - **Desktop 与 CLI 共享 `~/.claude/settings.json` 的 hooks 配置**——
    这是唯一能从 GUI 会话向外回报状态的官方机制
- **pi** —— https://github.com/earendil-works/pi
  - `docs/rpc.md` 原文：**"Node `readline` is not protocol-compliant"**——
    它会在 `U+2028` / `U+2029` 处断行，而那在 JSON 字符串里合法（本项目 E-203 的来源）
  - README 原文：**"No MCP."**（设计使然）
  - RPC 事件含 `agent_settled`——一个干净的完成信号
- **Grok Build** —— https://github.com/xai-org/grok-build ｜ https://docs.x.ai/build/
  - headless **不读管道 stdin**（与 pi 相反）
  - 会话存 SQLite，**schema 未公开**；回读走 `grok sessions` / `grok export`
  - **命名冲突**：社区 https://github.com/superagent-ai/grok-cli 同样占用 `grok` 与 `~/.grok`
- **DeepSeek Harness** —— https://github.com/deepseek-ai/deepseek-harness ｜ https://deepseek.com/harness
  - CLI 名 `dsh`；按 profile 启动：`headless` / `sdk` / `web`。**`acp` profile 经 2026-09-01 实测确认不存在**——`@deepseek-ai/dsh-acp` 在 `0.1.0-rc.6`/`0.1.1-rc.2`/`0.1.2-alpha.3` 各版本均无 `dsh.bundle` 字段（是库不是 profile 层，对照 `dsh-headless` 有 `bundle.patch`），`latest` 指向的 `0.0.1-rc.1` 依赖 npm 上不存在的 `@deepseek-ai/dsh-type-meta`（404）；实际启动 `--profile acp` 为零输出直接退出
  - README 原文：**"in developer preview and iterating rapidly.
    THERE WILL BE COMPATIBILITY-BREAKING CHANGES."**，`SESSION_FORMAT_VERSION = 0`
  - 官方 Python SDK：`pip install deepseek-harness-sdk`
- **ACP（Agent Client Protocol）** —— https://agentclientprotocol.com ｜
  https://github.com/agentclientprotocol/agent-client-protocol
  - 由 Zed Industries 与 JetBrains 背书，明确对标 LSP
  - **方向性**：MCP 是「agent → 工具」，**ACP 是「外部驱动 → agent」**——正是本产品需要的那个
  - 机器可读注册表（每小时更新）：
    `https://cdn.agentclientprotocol.com/registry/v1/latest/registry.json`
  - v1 为当前版本；**v2 草案**才加 `session/list`、`session/delete`、恢复回放
  - 现成统一适配层 `acpx` —— https://github.com/openclaw/acpx （MIT，pre-1.0）

## 关于本文档的两处降级

按流程规定，在此明确说明：

1. **`diagram-generator` 技能在本机不存在**（已核对 `~/.claude/skills/`、插件目录与 `D:\skill\`）。
   06 节的数据流图与 09 节的 ER 图**按其规格手绘**：
   参与方使用文档里已存在的模块 ID、只画数据流动不重复依赖关系、只给 mermaid 源码不给图片。
   12 节与 09 节的时序图与状态机图同理。
2. **阅读器内置的极简 mermaid 解析器只渲染 `sequenceDiagram` 与 `stateDiagram-v2`。**
   因此 12 节的四张时序图与 09 节的状态机图**会渲染成可点击 SVG**（模块 ID 与边界编号可点开），
   而数据流图与 ER 图**以源码形式显示**。在 Obsidian 里全部正常渲染。
