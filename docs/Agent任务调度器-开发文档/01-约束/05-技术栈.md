## 分层取值

| 层 | 取值 | 一句话理由 |
|---|---|---|
| daemon 语言 | **Node.js 22 LTS + TypeScript**（strict） | 原话点名的 agent 阵容里 claude / pi / grok 三者走 npm 生态，Node 已是既定环境依赖；与 Web UI 同语言，任务/事件/运行流的类型定义只写一套（决策 23） |
| daemon HTTP 层 | **Fastify** | 需要 SSE 长连接 + 静态托管 Web UI 产物；插件化中间件顺序显式，便于把鉴权钉在固定位置 |
| 持久化（结构化） | **SQLite，better-sqlite3，WAL 模式** | 任务/运行/快照/索引要按条件筛选分页，且指纹比对需要查询能力（决策 26） |
| 持久化（日志正文） | **文件系统，每次运行一个 NDJSON 文件**，库里记字节偏移索引 | GB 级正文塞进数据库既不好轮转也不好分段读；偏移索引直接支撑分段加载（决策 26，E-149） |
| 客户端协议 | **HTTP(REST) + SSE**，SSE 客户端**自写**（fetch + ReadableStream） | 事件补推去重正是 SSE `Last-Event-ID` 的原生语义；但原生 `EventSource` **不能带 Authorization 头**，与「鉴权默认开启」冲突，所以必须自写（决策 27） |
| 前端框架 | **React 18 + TypeScript + Vite** | 代码由模型产出，训练数据最厚（决策 24） |
| 样式 | **Tailwind CSS** | 与 shadcn/ui 配套 |
| 组件库 | **shadcn/ui（radix 之上）** | 是复制进仓库的源码而非黑盒依赖，改写成本最低 |
| 虚拟滚动 | **TanStack Virtual**（唯一指定） | 十万行日志是硬需求；指定唯一实现，避免多个任务各引一个 |
| 客户端状态 | **zustand** | 单人自用规模，不需要更重的方案 |
| 桌面壳 | **Tauri v2** | 壳只做窗口 + 系统通知 + 令牌存储，Tauri v2 的 single-instance / autostart / notification 官方插件正好一一对上（决策 25） |
| 手机壳 | **Capacitor**，第一版 **Android** | 同为纯 WebView 容器定位，与「两端共用一套 Web UI」吻合（决策 25） |
| 测试 | **Vitest**（单元与集成） | Vite 的配套选择，不引入第二套 runner |
| 包管理 | **pnpm 9**，单仓多包（daemon / web / shell-desktop / shell-mobile / shared） | 本机已装；shared 包承载两端共用的类型 |
| 目标平台 | **Windows 10/11 优先** | 用户的 agent 全在 Windows 上，也只有它能被真实验证（决策 21） |

> Vitest 与 pnpm 两项未单独裁决，是已定选型（Vite、单仓多包）的惯例配套，
> 由主代理按可逆优先推定；要换成本极低。

## 一并钉死的实现约束

这些不是建议，是约束——不写死，六个任务派出去会长出六种写法：

- **子进程一律 `shell: false` + 参数数组**，任何情况下不拼接 shell 字符串（E-42）。
- **agent 可执行文件路径由注册表解析真实路径**，不得假定 `.exe` 后缀
  （npm 全局装的是 `.cmd` shim，直接 spawn 会 ENOENT）（E-130）。
- **spawn 时强制 UTF-8 环境，按行剥 `\r`**，否则中文提示词与输出乱码（E-131）。
- **行读取器设单行上限**，超限截断并标记（E-141）。
- **内存只保留最近 N 条事件的环形缓冲**，历史落盘按需回读（E-142）。
- **事件按帧（50–100ms）批量提交渲染**，禁止一条事件一次 `setState`（E-144）。

## 否决的备选

记在这里，是为了三个月后没人再把已经settled的问题重新翻出来。

| 备选 | 为什么否决 |
|---|---|
| **Go / Rust / Python 写 daemon** | 「单文件二进制免运行时依赖」的优势在本项目**不存在**——开发机与运行机是同一台 Windows，且 Node 因 agent 生态必然已装。换语言只换来前后端类型各写一套 |
| **手机端做 PWA** | **技术上不成立**：局域网 http 下手机浏览器对 LAN IP 拿不到 secure context，service worker 注册不了，PWA 的安装/离线/推送整条链路不可用——不只是「iOS 上受限」。且原话写的是「手机 app 端」不是网页（决策 3） |
| **手机端用 React Native** | 与「两端共用一套 Web UI」直接冲突，等于手机端 UI 重写一遍（决策 25） |
| **桌面端用 Electron** | 不是错误选项，只是次选：100MB+ 的体积对一个常驻工具偏重。~~保留为 R-01 的预案~~ **预案已撤销（2026-09-01）**——Tauri v2 空壳构建本机已跑通，R-01 关闭。壳零逻辑使得切换成本只有几十行，这条退路技术上依然成立，但不再有触发它的理由 |
| **WebSocket 替代 SSE** | 本产品的通信形状是「服务端单向推流 + 普通写请求」，WebSocket 的全双工用不上，反而要自己实现断线事件补齐——而那正是 SSE `Last-Event-ID` 免费给的（决策 27） |
| **纯 HTTP 轮询** | 与「盯着运行流」这个主场景直接冲突，实时性差且耗电（决策 27） |
| **纯 JSON 文件做持久化** | 任务与运行记录到几千条后查询与并发写都会出问题，且指纹比对需要查询能力（决策 26） |
| **嵌入式 KV（LevelDB 等）** | 缺 SQL 查询能力，列表筛选与指纹比对要自己写索引，等于重造 SQLite 的一部分（决策 26） |
| **Svelte / Vue / 原生 Web Components** | 都能做，但代码由模型产出，React 的训练数据厚度与组件生态在本项目是决定性的（决策 24） |
| **自建中继服务器 + APNs/FCM 推送** | 要传输源码与对话内容，自建中继把数据责任揽到产品身上；原话通篇没提账号云端外网（决策 2，见非目标第二条） |
| **UI 自动化 / 模拟点击驱动桌面版 agent** | **不需要**。本机实测四个 agent 全都有正规程序化入口（codex 的 app-server daemon 与 `exec`、claude 的 `--print` + stream-json、pi 的 `--mode rpc`、grok 的 leader socket 与 ACP 流）。截屏点按钮那类脆弱方案直接排除 |
