## 结论先行：桌面版能不能被外部发派？

**原始需求第 4 点问的就是这个。答案分两半，两半都要说清楚。**
（核对时间：2026-08-31。本结论**只在此处维护**，其他小节交叉引用而不复述。）

**一、两个桌面 GUI 都不能被外部直接发派任务。**

- **codex 桌面版**——它其实就是 ChatGPT 桌面 app 里的一个模式，不是独立产品。
  有 `codex://` deep link，但官方明文写着它**只把内容填进输入框、不会自动发送**。
  〔证据强度：**官方明文**〕
- **claude 桌面端**——官方对照表逐字写着 `--print` / `--output-format` →
  "Not available. Desktop is interactive only."，以及
  "Scripting and automation | Desktop: **Not available**"。
  〔证据强度：**官方明文**〕

**二、但这不影响本产品，因为每家都有官方的 headless 引擎，而且会话与 GUI 互通。**

本产品统一走各家的 **CLI / daemon 通道**——下表里那四个可执行文件就是通道本体。
更要紧的是：**headless 跑出来的会话可以在对应的 GUI 里打开继续**
（codex 用 `codex://threads/〈id〉` 或 TUI 内 `/app`；claude 用 TUI 内 `/desktop`）。
所以实际形态是「**后台派活跑完，想深入时切到 GUI 接手**」，桌面版并没有白装。
〔证据强度：**官方文档**；本机未逐条实测〕

**三、一条相关的推断，不要当事实用。**

`codex agents` 的 help 文本称它浏览「共享本地 app-server daemon」上的所有会话，
且 `~/.codex/config.toml` 里确有 `[desktop]` 段——这**暗示**桌面 app 与 CLI 共用同一个
daemon 与同一份配置。〔证据强度：**仅 help 文本佐证，本机未实测，属推断**〕
**本产品不得有任何任务的验收条件依赖这一条**（E-251）；
真被证伪时只需删掉这一句，不触发返工。

完整引文与出处见 24 节；下面两张表是本机 `--help` 与配置文件的一手实测。

## 被调度的 agent（本机实测已装 5 个）

| agent | 可执行文件 | 非交互入口 | 结构化输出 | 会话存储 |
|---|---|---|---|---|
| codex | `D:\Program Files\nodejs\node_global\codex` | `codex exec` | `--json`（JSONL 事件流） | `~/.codex/sessions/{年}/…` |
| claude | `D:\Program Files\nodejs\node_global\claude` | `-p / --print` | `--output-format stream-json` | `~/.claude/projects/〈路径编码〉/〈uuid〉.jsonl` |
| pi | `D:\Program Files\nodejs\node_global\pi` | `-p / --print` | `--mode json/rpc` | `--session-dir` 指定 |
| grok | `C:\Users\admin\.grok\bin\grok` | `-p / --single`、`grok agent` | `--output-format streaming-json`（**ACP 原生事件**） | `grok sessions` / `grok export` |
| DeepSeek Harness | `D:\Program Files\DeepSeek Harness`（v43.4.0，Electron；CLI 未全局安装，入口在 `resources/host/node_modules/@deepseek-ai/dsh/lib/bin.js`） | `dsh --profile headless "任务"`（**2026-09-01 已实测**） | **无流式**：只在跑完后输出末条 assistant **纯文本** + 退出码 0/1。`--profile acp` **经实测不存在**，不是备选（E-253） | dsh 侧无列举接口；`〈dsh_home〉/sessions` 存在（`C:\Users\admin\.dsh`）但 headless 是否写入未验证，回读一律靠本产品自己的运行记录 |

**claude / pi / grok 三家支持由调用方指定 session-id**；
**codex 不支持**——它只提供 `codex exec resume 〈id〉` / `fork`，认的是它自己生成的 thread id，
所以 codex 适配器必须**另存一份「任务 id ↔ thread id」映射**才能回读（这是 M4-T8 的隐含产出）。
四家都支持恢复 / 分叉，这是调度器能回读会话的共同前提。

## agent 的模型配置文件（实测四家四种格式）

| agent | 配置文件 | 格式与关键字段 |
|---|---|---|
| codex | `~/.codex/config.toml` | TOML；`model`、`model_provider`、`model_reasoning_effort`、`[model_providers.*]` |
| claude | `~/.claude/settings.json` | JSON；`model`，另有 `env.ANTHROPIC_MODEL`、`ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL` |
| grok | `~/.grok/config.toml` | TOML；`[models]` 目录段 + `[model]` 当前段 |
| pi | `~/.pi/agent/models.json`、`models-store.json` | JSON；有专门的模型目录文件 |

补充来源（配置文件之外）：`grok models`、`pi --models`。

## 账号、密钥、第三方服务

- **本产品自身不需要任何账号或密钥**，不调用任何云服务，不自建服务器。
- 各 agent 的登录态由 agent 自己维护（`~/.codex/auth.json`、`~/.grok/auth.json`、
  `~/.pi/agent/auth.json` 等）。**调度器绝不读取、不搬运、不代管这些凭据。**
- **运行环境刻意不注入 git 凭据、不启用 credential helper**（E-138）。

## 数据来源

唯一输入是 `unattended-run` 技能产出的 `docs-data.js`，格式为：

```
window.DOCS = <一个 JSON 字面量>;
```

去掉头尾即可 `JSON.parse`，不需要 JS 引擎（E-16）。其中：

- `data.tasks[]` — `{id, title, module, deps[], input, output, accept, est, edges[]}`
- `data.modules[]` — `{id, role, deps[]}`
- `data.edges[]` — `{id, scene, trigger, expect, module}`
- `pres.handoff` — `{docsPath, repo, mainBranch, branchPrefix, stack, frontendModules, design, architecture, taskPaths, taskSkills, conventions}`
- `groups[]` — 24 节的完整 markdown 正文

**注意 payload 里没有 `schemaVersion`**，只有每次重建都会变的 `generated` 时间戳，
所以变更判定必须按 `data.tasks` 内容算指纹（E-17）。

## 要对接的既有系统

**只有一个方向：读。** 读 `docs-data.js`、读各 agent 的配置文件与会话文件、读 git 工作区。
**不写回开发文档目录的任何文件**，包括不碰阅读器的 localStorage（决策 14）。

## 人力与工期

用户**一个字都没提**人力与工期。已确认的事实：单人单机自用，使用者就是文档作者本人。
因此本文档的人天估算按**一个人**推算，不设交付日期。

## 部署环境

不部署。daemon 跑在用户自己那台 Windows 上，开机自启，监听可配置端口；
手机通过局域网连接，出门要用则由用户自己接隧道。**没有任何服务器环节。**
