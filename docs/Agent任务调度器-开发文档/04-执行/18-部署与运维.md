# 部署与运维

**这个产品不部署。** 没有服务器、没有容器、没有 CI/CD 流水线——
daemon 跑在用户自己那台装着 agent 的 Windows 上（决策 2、21）。
所以本节讲的是「装到本机、开机自启、出问题怎么恢复」。

## 环境矩阵

| 环境 | 是什么 | 数据目录 |
|---|---|---|
| **开发** | 同一台机器，`pnpm dev` 起 daemon + Vite dev server（Vite proxy 转发 `/api`，不注册 CORS） | `%APPDATA%\agent-scheduler-dev\` |
| **本机正式** | 打包后的 daemon + 静态产物 + 两个壳 | `%APPDATA%\agent-scheduler\` |
| ~~测试 / 预发 / 生产~~ | **不存在** | — |

开发与正式**必须用不同数据目录**，否则一次调试会污染真实运行记录。

## 配置清单

分三份，读取时机与热更能力各不相同（08 节 config）：

### 一、`daemon.json` + 环境变量 —— 启动读一次，不支持热更

| 项 | 必填 | 默认 | 缺失时的行为 |
|---|---|---|---|
| `AGSCHED_PORT` | 否 | `7817` | 用默认；**格式非法则打印变量名与期望格式后退出**，不静默回落 |
| `AGSCHED_BIND` | 否 | `0.0.0.0` | 用默认（手机要连；鉴权默认开启兜底） |
| `AGSCHED_DATA_DIR` | 否 | `%APPDATA%\agent-scheduler` | 用默认；目录不存在则创建 |
| `AGSCHED_LOG_LEVEL` | 否 | `info` | 用默认 |
| `AGSCHED_DEV` | 否 | 关 | **只控制错误响应带不带 stack；明令不得影响鉴权、不得放宽任何校验** |

改了这五项**必须重启**——端口与数据目录热更没有安全语义（E-03、E-150）。

### 二、`agents.json` —— 支持热加载

每个 agent 一条，字段：是否启用、可执行绝对路径、启动参数模板（白名单模板变量）、
工作目录、环境变量、并发上限、默认模型、两字符短码、`adapterKind`、
`envDenylist`、三档超时、版本指纹探测命令与期望模式。

- 热加载实现固定为 `fs.watch` + **300ms 防抖 + 内容指纹去重**
  （编辑器保存会触发多次写事件，不去重会重载多次）
- **校验失败保留上一版**并发警告事件，**绝不因此退出 daemon**（E-94）
- 未知字段忽略并 warn，缺字段回落内置默认（E-92 靠 defaults 与用户覆盖**分开存两份**来算差）
- **`adapterKind` 热切换必须校验该 agent 无在途运行**，否则拒绝并保留旧值（E-189）
- **在途运行只读派发时的快照，不读当前值**（E-93）

### 三、派发快照 —— 写一次，永不迁移

每次派发把注册表条目**逐字段深拷贝**进 `runs.launch_spec_json`。
它记录的是「派发那一刻注册表长什么样」，**改了就失去快照的意义**。

## 安装

1. 装 Node 22 LTS（`node --version` 低于要求，daemon 启动自检即退出，E-139）
2. 装 Windows WebView2 运行时（Tauri 桌面壳需要；缺失时启动检测并引导安装，E-148）
3. 安装包同时装 daemon 与桌面壳（决策 1）
4. **首次运行注册开机自启**——机制由 M1 提供，**壳负责触发**（决策 40）：
   - 注册**必须幂等且接受可执行文件路径**；壳每次启动校验注册项与当前可执行文件一致，
     不一致则重写（E-209）
   - **注册失败必须非致命**：UAC 拒绝时 daemon 仍由壳当场拉起、功能完整，
     仅重启后需手动开壳；设置页提供「重试注册自启」（E-210）
   - 用户手动关掉自启项 → 下次启动**只检测并询问，不静默重注册**（E-208）
   - **完全不装壳、直接命令行起 daemon，全部功能照常**（E-212）
5. **首次配对**：零已配对设备时，daemon 把一次性配对码打印到控制台并写入
   数据目录下的 `pairing-code.txt`（`0600`，用后即删）——
   **不为此新增免鉴权端点**（E-226，见 10 节）

手机端：Capacitor 打的 Android 包；构建环境未就绪时**降级为浏览器直接打开局域网 URL**，
只损失原生通知与安全令牌存储（R-02、E-200）。

## 发布与回滚

没有灰度、没有多版本并存（10 节）：

- **daemon 与两个壳同批分发**，`GET /version` 返回 `apiVersion`，
  **壳启动时校验**，不兼容时提示升级而不是抛底层错误（E-14）
- 数据库迁移**只增不改**：`migrations/NNNN_*.sql` 按序号新增，
  已应用文件禁止修改（要改回来就再加一个迁移），**不写 down 脚本**
- 因此**回滚 = 装回旧版安装包**，但**不能回滚已执行的迁移**。
  所以新列必须可空或带默认值（09 节），旧版 daemon 读新库时忽略未知列即可
- 升级后内置默认变了而用户恰好覆盖了同一字段 → 保留用户覆盖，
  提示「内置默认已更新（旧值 → 新值）」并给一键采纳（E-92）

## 备份

**要备份的只有数据目录**：`app.db` + `agents.json` + `daemon.json`
（`runs/` 下的日志正文按需，体积大且可再生性差但非关键）。

- WAL 模式下**不能只拷 `app.db`**——必须连 `app.db-wal` 与 `app.db-shm` 一起，
  或先让 daemon 停下
- **厂商会话文件不属于本产品的备份范围**——它们是 agent 自己的产物，只读引用（E-96）
- 数据目录在 `%APPDATA%` 下，**天然不在仓库内**；仓库里禁止出现 `.env` 类文件

## 故障恢复手册

| 症状 | 先看 | 处置 |
|---|---|---|
| daemon 起不来，提示版本 | `node --version` | 装 Node 22 LTS（E-139） |
| daemon 起不来，提示端口占用 | 是否已有实例在跑 | 单实例锁生效，**第二个实例拒绝启动是正确行为**（E-03） |
| 启动崩在原生模块 | 是否刚升过 Node | `pnpm rebuild`（better-sqlite3 的 ABI 不匹配，E-152） |
| 重启后一堆「运行中」 | `reconcile-runs` 的输出 | 进程不存在 → 标「异常终止」；存在但接不回 → 标「失联」并给杀掉入口。**绝不推定成功**（E-123、E-02） |
| 某 agent 突然全部失败 | 该 agent 的探测结果与 `unmapped_event_count` | 多半是厂商改版：先看版本指纹是否仍匹配（E-198），再看未知事件计数是否上涨（E-202）；必要时把 `adapterKind` 切成 `generic-acp`（E-186） |
| 手机连不上 | 配对失败报到哪个环节 | 「扫到码但连不上 host:port」→ 用手填地址兜底（E-06）；IP 变了 → 令牌仍有效，重新发现或重扫码（E-09） |
| 会话打不开 | 日志文件是否还在 | 被手工删了 → 元数据仍在，日志区提示「日志文件已丢失」（E-151）；被保留策略清了 → 明确提示「已清理」（E-221） |
| 磁盘写满 | `disk-watch` 告警 | **立即停止新派发**；按任务归档（E-103、E-104）。**M1 绝不自行删除正文**，删什么由 M6 定（E-205） |
| 索引比文件多 | `log-index-repair` 的 `error` 日志 | **这是数据损坏**（正常态只允许「文件比索引多」）。停机排查，不要继续写入 |

## 运维上的硬约束

- **daemon 优雅退出时不杀 agent 子进程**——E-01 / E-51 要求任务继续跑。
  但必须承认：**除 codex app-server / grok leader socket 这类外部常驻通道外，
  子进程管道无法跨 daemon 重启重挂**，重启后只能对账不能重挂（08 节 proc）
- **单实例锁 + SQLite `busy_timeout`，启动失败即退出，绝不双写**（E-150）
- **不注册 CORS 插件**（生产同源，开发用 Vite proxy）
- **不做任何遥测、崩溃上报、自动更新检查**
