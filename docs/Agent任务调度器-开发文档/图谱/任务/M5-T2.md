## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 上游任务改动尚未落地进当前 HEAD 就要派下游时**拒绝派发**并说明「下游 base 缺上游产出」（[[E-70]]）
2) 同时提供「以上游任务分支为 base 建 worktree」的显式选项，**绝不默默从旧 HEAD 起**（[[E-70]]）
3) 每任务独立 session 与独立工作区，每 agent 有并发上限（[[E-31]]）

## 必须处理的边界

- [[E-31]]　同一 agent 并发多任务
    - 触发：一个 agent 被同时派多个任务
    - 期望：每任务独立 session 与独立工作区（grok 用自带 --worktree，其余用 git worktree 兜底），并设每 agent 并发上限
- [[E-70]]　下游 base 缺上游产出
    - 触发：上游任务改动尚未被用户落地进当前 HEAD 就要派下游
    - 期望：拒绝派发并说明「下游 base 缺上游产出」，同时提供「以上游任务分支为 base 建 worktree」的显式选项；绝不默默从旧 HEAD 起

## 实施沉淀

<!-- notes:begin -->
- **上游产出缺失判定与祖先截断**：在 git 分支合入流程中，用户可能采用 squash merge、rebase 或普通的 merge commit。如果只用 `git merge-base --is-ancestor`，squash 合并生成的新提交与原分支无拓扑祖先关系，会直接被误判为「未进 HEAD」。因此在祖先判定返回 1 时回退执行 `git diff --quiet HEAD <upstreamBranch>`，只有两者皆失败且存在差异时才确认为未合入（E-273）。
- **拒绝静默起新分支（E-70 契约）**：当上游依赖未合并时，如果调度器静默采用 HEAD 作为下游任务的 base，下游 agent 将看不到上游代码，直接导致重复开发或代码冲突。必须抛出 `E_UPSTREAM_BASE_MISSING` 阻断，并在错误 details 中携带 `availableUpstreamBases`，提供显式的 `upstreamBranch` 选项。下游如果显式以该分支为 base，调度器通过 `git worktree add -b <newBranch> <worktreePath> <upstreamBranch>` 构建叠加分支，确保上游产出无缝传递。
- **工作区隔离与 Grok 原生 worktree 分支策略（E-31）**：不同 agent 工具链的工作区隔离机制存在差异。Grok 原生自带 `--worktree` 与 `--worktree-ref` 命令行参数支持，若由 daemon 外层再次调用 `git worktree add` 容易引发 worktree 路径与锁冲突；因此对 Grok 仅计算隔离路径并注入 `--worktree` 参数，由其自身维护隔离；对其余 agent（codex、claude、pi 等）则统一在 daemon 侧通过 `git worktree add` 创建工作区并以 `resolveBranchName` 防重命名。
- **并发上限与会话独立性**：每个任务无论指派给哪个 agent，必须获得独立的 `sessionId` 与独立的工作区目录。调度器在进入 workspace 准备前同步校验 `currentActiveRuns >= maxConcurrency`，达标立即截断并返回 429 `E_AGENT_BUSY`（带 retryable: true），避免未就绪的 worktree 磁盘空间和 git 引用被无谓占用。sessionId 只从注入的 `deps.ids.newId()` 取，缺注入直接抛 `E_INTERNAL` 而不回落到 `Date.now()`：时间戳兜底会在同一毫秒的两次派发里撞号，也让单元测试无法复现。
<!-- notes:end -->
