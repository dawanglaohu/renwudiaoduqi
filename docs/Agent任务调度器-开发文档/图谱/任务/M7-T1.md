# M7-T1　机械检查两层与执行目录

- 所属模块：[[M7]]　**审查流水线**——对已结束的运行做「合不合格」的判定：先跑本地机械检查，通过后以只读档派一个 agent 跑文档给出的审查提示词，产出 pass / rework / doc-issue 并回灌 rework 意见；从审查输出提取返工文本、按能力位选回灌／恢复／新开返工运行，以及解析收口运行的八段报告，也归它；第 N+1 轮审查续接同一审查会话、查 bug 阶段的运行与五段报告解析同样归它。凡「判定一次运行的结果」的都归它；审查、查 bug 阶段的运行用哪个 agent、模型与思考强度，一律读派发快照里的任务指派（审查可被 pipeline 设置的「审查覆盖」替换），不自己取 agent 默认
- 前置依赖：[[M5-T3]]、[[M6-T1]]
- 完成后解锁：[[M7-T2]]

## 输入 / 产出

- **输入**：M5-T3 的 diff；文档声明的 build/test 命令
- **产出**：`service/review.ts` 的机械层

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 零配置层（diff 非空／退出码／会话无致命错误／验收关键词命中）恒执行
项目命令层留空则跳过并在 UI 明示「机械检查覆盖有限」（[[E-60]]）
2) 退出码为 0 但 diff 为空时机械层直接判失败，**不派审查 agent**，标「无改动」转人（[[E-61]]、[[E-23]]）
3) 执行目录恒为该任务的 worktree，**绝不在用户主工作区跑**（[[E-67]]）
4) build/test 命令 10 分钟硬超时后杀掉，标「机械检查超时」转人，**不重试**（[[E-66]]）

## 必须处理的边界

- [[E-23]]　退出码为 0 但活没干完
    - 触发：agent 自行放弃或上下文超限后正常退出
    - 期望：退出码不等于验收通过；状态机必须把「已退出」与「已落地」分开，后者只能由自动审查或人确认
- [[E-60]]　机械检查覆盖有限
    - 触发：项目未在文档里声明 build/test 命令
    - 期望：机械检查分两层：零配置层（diff 非空、退出码、会话无致命错误、验收标准关键词命中）恒执行；项目命令层留空则跳过并在 UI 明示「机械检查覆盖有限」
- [[E-61]]　退出码 0 但没有改动
    - 触发：agent 正常退出但 diff 为空
    - 期望：机械层直接判失败（呼应 E-23），不派审查 agent，标「无改动」转人
- [[E-66]]　build/test 命令挂死
    - 触发：测试进程不退出
    - 期望：默认 10 分钟超时后杀掉，标「机械检查超时」转人，不重试
- [[E-67]]　机械检查跑错目录
    - 触发：检查命令的执行位置
    - 期望：恒为该任务的 worktree，绝不在用户主工作区跑，避免污染

## 实施沉淀

<!-- notes:begin -->
- **两层检查的短路与降级语义（E-60、E-61、E-23、R4）**：零配置层作为硬闸门必须全数通过，项目命令层才可能被执行。若 agent 退出码缺席或为 null（例如被信号杀死的非正常退出），严禁回落为 0 导致误放行，必须判零配置层失败（R4）；若 agent 退出码为 0 但 diff 经计算为空，直接短路判负并标 `无改动` 转人，严禁派发审查 agent 造成无效 API 开销；项目命令层留空是正常开发状态而非异常，跳过执行并外露 `机械检查覆盖有限` 标记，避免阻塞全自动流水线。
- **工作区路径防污染硬约束（E-67）**：机械检查可能包含测试与构建命令，绝对禁止在用户主工作区执行。`assertWorktreeDirectory` 在执行任何 git diff 或子进程命令前校验路径，在 Windows 下做规范化后大小写不敏感比对，一旦目标工作区与主仓库根目录重合立即以 `E_WORKSPACE_UNAVAILABLE` 阻断。
- **超时必杀与不可重试语义（E-66、R1、R2）**：机械检查命令默认设置 10 分钟硬超时（`DEFAULT_CHECK_TIMEOUT_MS`），子进程挂死时由 `proc/spawn.ts` 的 `killTree` 彻底清理进程树，退出原因置为 `mechanical_check_timeout`，`retryable` 恒置为 false，直接进入 `awaiting_human` 等待人工介入，禁止自动重试导致持续占用机器资源。Windows 上解析到 `.cmd/.bat` 脚本时必须传递 `resolution.executable.sourcePath` 给 `spawnManaged` 以正确触发 ComSpec 包装，避免裸 `cmd.exe` 挂死（R1）；可执行文件在候选目录不存在时立即外露 `E_AGENT_EXEC_NOT_FOUND`，禁止透传进 `spawnManaged` 产生 127 误判（R2）。
- **环境变量与分层事务合规（08 节架构约束、R3）**：service 层禁止直接读取 `process.platform` 与 `process.env`；宿主输入经构造参数 `deps.hostInputs` 注入，未注入时由 `resolveEffectiveHostInputs` 在平台边界调 `platform/host.ts` 的 `takePlatformHostInputs()` 收取（该回落待接进容器后收紧为必传）。状态机评估遵守「机械检查在事务外执行，数据库迁移收进单个事务（每次显式传递 `endedAt`）」原则，对接仓储 `RunsAbortRepo`，防止 `runs.ended_at` 被赋空或多次开启事务。
