## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 批次树纯 props，折叠的批不渲染子行（不是 `display:none`）
标题计数「已落地 x/n · 在跑 y · 等你 z」、收口徽标、能否收口、默认展开全部读 daemon 字段，组件内不算任何计数，展开集只来自 props（[[E-284]]、[[E-272]] 的呈现侧）
2) 展开集存 `batch-expansion.ts` 模块级 Set，左栏与任务列表页共用
首次按 `defaultExpanded` seed，`batch.advanced` 经 `subscribeMilestone` 到达且 `to ∈ {running, wrapping, awaiting_landing, needs_attention}` 时并入，任何事件永不删元素，手动折叠后同批事件仍展开
不进 store、不进任何持久化键，`check-forbidden` 白名单不变（[[E-284]]）
3) `pulse-dot` 一个组件被 spine 与批次树两处 import
`@keyframes` 只在 `base.css` 且恰一处、`animation:` 不出 `styles/`，两条 grep 禁令进 `pnpm -w check`
`RUN_PULSE` 以 `satisfies` 覆盖 13 个状态，live 恰为 starting/running/reviewing/reworking，awaiting_* 静态暖点，终态与 queued 无点
`prefers-reduced-motion` 下环冻结在中间不透明度（[[E-282]]）
4) 任务行「进 HEAD」标记三态同色、固定 `7ch` 列，`false` 的 title 显示判定方法

5) 行高 30px，phone/phone-xs 44px 且开合槽 44×44
`role="tree"` 键盘可达
手机档批次树是任务列表 pane 的顶层结构并取代 M9-T12 的折叠列表（[[E-13]]），narrow 档沿用左栏抽屉（决策 86）

## 必须处理的边界

- [[E-13]]　手机竖屏看批次与并行窗口
    - 触发：小屏访问宽表格视图
    - 期望：降级为可折叠列表，不得让桌面宽表格横向滚动
- [[E-272]]　全部已验收但分支未进 HEAD
    - 触发：本批任务全部 landed，至少一条 landed 运行的分支尚未进入当前 HEAD
    - 期望：批次转 `awaiting_landing`，标题显示「等你落地 N 个」暖色（N 来自 daemon 字段 notInHeadCount）；不派收口、不解锁下一批；进 HEAD 判定只在 `scheduler-tick` 内按节流做（每运行 ≥30s 一次、每 tick ≤20 条），不在任何读接口现跑 git，不做比 tick 更密的轮询
- [[E-282]]　呼吸灯与运行轨同屏
    - 触发：批次树执行行与流甲板当前步同时可见
    - 期望：两处 import 同一个 `pulse-dot` 组件、共用 `@keyframes agsched-pulse` 与 `--pulse`，算同一种动画；只对 starting/running/reviewing/reworking 呼吸，awaiting_* 静态暖点，终态与 queued 无点；`prefers-reduced-motion` 下环冻结在中间不透明度
- [[E-284]]　自动展开只增不减
    - 触发：`batch.advanced` 到达时该批已被用户手动折叠，或本会话已展开多批
    - 期望：事件到达且 `to ∈ {running, wrapping, awaiting_landing, needs_attention}` 时并入展开集，永不从集合删元素（除切换文档整体清空与用户手动 toggle）；不折叠用户手动展开的批；展开集只存内存，刷新后回到 daemon 的 `defaultExpanded`
- [[E-298]]　任务行的「进 HEAD」标记
    - 触发：任务已验收、未验收或从未派发
    - 期望：三态：true「进 HEAD」、false「未进 HEAD」（title 显示 method）、null「—」；同色不用色相；前端只读 `TaskDto.inHead`，不由分支名或运行状态推断
- [[E-299]]　落地闸门开关切到自动
    - 触发：用户把第三个开关从「等我确认」切到「自动」
    - 期望：不弹 dialog、不二次确认，开关下常驻一行提示「审查 pass 后直接标记已验收，仍不执行任何 git 操作」；PATCH 全量三值，状态以 `settings.gates_changed` 回流为准；三个开关同一形态，第三个不再置灰

## 实施沉淀

<!-- notes:begin -->
1. 模块级 Set 与局部重渲染隔离：
   批次树展开集跨越运行甲板左栏与任务列表独立页面两处使用，若置入全局 zustand store 或 React Context，高频事件或批次频繁折叠展开会触发整屏组件树的不必要重绘。选定 `batch-expansion.ts` 模块级 Set 并搭配 `useSyncExternalStore`，使重渲染仅限制在消费展开集的 `useBatchTree` 与 `useTaskList` 容器内部。
2. 自动展开只增不减的生命周期语义：
   调度器推进任务时，批次进入 `running`、`wrapping`、`awaiting_landing` 或 `needs_attention` 代表有活跃运行或等待人工决策，必须立即并入展开集以保证用户视线不遗漏待办，即使用户之前曾手动折叠过该批也需重新展开；而当批次进入 `done` 终态时，坚决不从集合中删除已有元素，避免打断用户当前正在浏览的任务上下文。
3. 呼吸环动效的单点收敛与无障碍降级：
   全站连续动效严格收敛为 1.6s 呼吸环一种，禁止任何组件在自身内联 style 或单独 class 中直接写 `animation:`。`@keyframes agsched-pulse` 唯一定义在 `base.css` 并由 `check-forbidden.ts` 静态分析强行机检。在开启 `prefers-reduced-motion` 的系统环境中，呼吸外环在 CSS 中停止旋转缩放动画，静态冻结在中等不透明度，既保留了节点位置可视性，又消除了晕动症风险。
4. 落地闸门交互与非乐观翻转：
   用户将落地闸门从「等我确认」切至「自动」时，根据 E-299 严禁弹窗阻断流程，仅在开关下方常驻提示行以明确其只改变审查通过后的判定而不代跑 git 命令。更新请求向服务端提交全量三值，前端展示层完全受控，必须等待服务端 `settings.gates_changed` milestone 事件回流才刷新开关选中项，彻底避免网络抖动或鉴权失败导致的界面乐观翻转假象。
5. 返工 R1-R5 调整与快照不可变性：
   - 消费契约模型（R1, R5）：重构 `BatchTree` 纯粹消费 shared/daemon 的 `BatchDto` 与 `TaskDto` 字段，杜绝在前端猜测字段（如默认判定方法或将缺失统计兜底为 1），字段缺失一律显式呈现「—」。
   - `useSyncExternalStore` 引用稳定性（R3）：原实现直接返回内部可变 Set 导致 `Object.is` 误判为无变动而跳过消费者组件重渲染；修复为内部变动时生成新的 `ReadonlySet` 快照引用，并在单测中覆盖 toggle 与 `batch.advanced` 均触发重渲染。
   - 闸门开关非乐观翻转（R4）：补齐 `GET /api/v1/settings/gates` 服务端端点；容器在发送 PATCH 后绝不在响应体或 finally 中提前退出 pending 态或篡改当前状态，严格阻塞至 `settings.gates_changed` 事件到达后单向流转。
   - 统一批次树装配（R2）：左栏、手机端 tasks pane 以及 `#/tasks` 路由全面接入 `BatchTree`，废弃并取代原有的 `MobileBatchList`。
