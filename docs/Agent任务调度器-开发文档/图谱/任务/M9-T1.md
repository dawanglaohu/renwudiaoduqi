- 完成后解锁：[[M9-T2]]、[[M9-T3]]、[[M9-T4]]、[[M10-T1]]

- **输入**：11 节的 tokens 与组件规范
- **产出**：`packages/web/` 骨架、`styles/tokens.css`、`theme-provider`、两个检查脚本

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) `styles/tokens.css` 的 `:root` 与 `[data-theme]` 两个块是**全仓唯一允许出现颜色字面量**的地方，由 `check-forbidden.ts` 机检（[[E-170]]）
2) 深浅两套 token 成对存在，`check-contrast.ts` 遍历前景/背景配对算 WCAG 比值并在不达标时失败（[[E-169]]）
3) 主题走 `html` 元素上的 `data-theme` 属性，跟随系统主题与字号，**不锁根字号、不用 `text-size-adjust:none`、不用 zoom**（[[E-15]]）
4) 「无色 = 不用管」在浅色下有显式取值，运行轨仍可见且不被误读为禁用（[[E-171]]）
5) 视觉方向**只以 token 层表达**——颜色、字号、圆角、形状枚举全部收敛为 CSS 变量与一张枚举表，使方向被否决时代价 ≤ 改一个 token 文件（[[E-159]]、[[E-161]]）
6) 深色新增任一状态或 chip 时，**同一 PR 内必须补齐浅色 token**，禁止「先深色后补」（[[E-173]]）
7) 文档或阅读器中出现的任何配色截图必须标注「示意，未经目视确认」（[[E-162]]）
8) 第一个前端任务完成后必须出一屏真页给用户目视确认
用户不看或直接认可即视为该风险关闭（[[E-160]]）

## 必须处理的边界

- [[E-15]]　深色模式与系统字号放大
    - 触发：系统主题或字号变更
    - 期望：一套 Web UI 跟随系统主题与字号，壳不做覆盖
- [[E-159]]　方向可能被推翻
    - 触发：视觉方向未经用户目视确认即写进文档
    - 期望：方向**只以 token 层表达**：颜色、字号、圆角、运行轨形状表全部收敛为 CSS 变量与一张形状枚举表，使日后被否决的代价 ≤ 改一个 token 文件，而不是重排组件结构。**注：方向已于 2026-09-01 获确认（R-03 关闭），但这条约束不随之放松**——它防的是「日后想改」，不只是「当初没确认」，仍由 M9-T1 验收
- [[E-160]]　用户不看真页或直接认可
    - 触发：第一个前端任务的真页摆出来后用户没反应
    - 期望：该风险项自动转为「已接受」并关闭，不阻塞后续任务，不再二次追问。**2026-09-01 已按此路径关闭**：真页（运行甲板）摆出后用户明确认可，R-03 关闭，**不再就视觉方向二次追问**
- [[E-161]]　用户看图后否决方向
    - 触发：目视确认时被打回
    - 期望：只允许替换 token 值与运行轨形状枚举；若否决触及 E-110（状态不能只靠色相）或 E-145（窄屏不得横向滚动），这些是硬约束不随方向变，必须在新方向里重新满足
- [[E-162]]　文档自证为伪证据
    - 触发：阅读器或文档里出现配色截图/示意图
    - 期望：必须标注「示意，未经目视确认」，避免文档自身成为「已确认」的伪证据
- [[E-169]]　浅色对比度不达标
    - 触发：某组 token 配对未过阈值
    - 期望：改浅色 token 值，不改组件——下限设在 token 层，修复面才收敛
- [[E-170]]　组件里写死颜色
    - 触发：未引用 token 的硬编码色值
    - 期望：浅色模式下必然显形，按禁令违规处理并加入 lint；浅色在此充当硬编码探测器
- [[E-171]]　「无色 = 不用管」在浅底
    - 触发：语义系统里的无色态切到浅色
    - 期望：必须显式给出浅色取值，保证运行轨仍可见且不被误读为「禁用」；不允许该状态在浅色下消失
- [[E-173]]　浅色欠账重新滋生
    - 触发：深色新增一个状态或一个 chip
    - 期望：同一 PR 内必须补浅色 token，禁止「先深色后补」

## 实施沉淀

<!-- notes:begin -->
1. 主题解析与 DOM 同步契约（E-15）：状态中允许存储 `system | dark | light` 三态，但 DOM 上 `html[data-theme]` 严格只写入经过媒体查询解析后的 `dark` 或 `light`。若将 `system` 直传 DOM，CSS 选择器 `[data-theme="dark"]` 与 `[data-theme="light"]` 均失配并回退至 `:root` 深色，导致系统浅色模式下静默失效。同时 `color-scheme` 必须与解析后的具体主题同步，避免原生滚动条脱节。
2. 浅色独立调色板与对称性约束（E-169、E-173）：浅色模式是经独立对比度核算的配色而非数学反色。`--needs`（`#B0740C`）用于填充背景，若作文字仅 3.9:1，需拆出 `--needs-ink`（`#8A5A05`，5.8:1）承接文字；`--on-auto` 在深色下为近黑（`#04140F`），浅色下则为纯白（`#FFFFFF`）。`check-contrast.ts` 按「值解析成颜色的 token」求两侧键集合的并集再双向断言对等，所以深色里新加一个状态色或 chip 色而没补浅色，当场失败——这正是「先深色后补」在 CI 上的出口。
3. 浅底语义无色态的显式取值（E-171）：运行轨 `--spine-done` 与 `--spine-pending` 在浅底显式声明为 `rgba(101,111,110,.40)` 与 `rgba(101,111,110,.26)`，实测对比度分别为 1.72:1 与 1.41:1，保证状态在浅底清晰可见且不被误读为 disabled 灰掉。
4. 视觉方向收敛至 token 层（E-159、E-161）：`tailwind.config.ts` 不写任何颜色字面量与字体栈，只把栅格、圆角、颜色、字族、字号、阴影与时长 alias 到 `var(--*)`，因此后续视觉迭代只改 `tokens.css` 一个文件，不动组件结构。`check-forbidden.ts` 把守这条线：tokens.css 之外出现任何 hex/rgb/hsl 即失败，`html`/`:root` 锁根字号、`text-size-adjust: none`、`zoom` 也一并拦下（E-15）。
<!-- notes:end -->
