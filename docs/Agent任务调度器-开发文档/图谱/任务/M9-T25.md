## 必须处理的边界

- [[E-06]]　同网段但连不上
    - 触发：手机与 PC 不同网段，或 WiFi 开了 AP 隔离
    - 期望：配对失败报到具体环节（「扫到码但连不上 host:port」），并提供手填地址兜底
- [[E-222]]　命中未登记的 hash
    - 触发：`#/xxx` 或 `#/run/` 缺参数
    - 期望：渲染「未知路径」页并给「回到运行甲板」，保留顶栏；**绝不白屏、绝不抛异常**
- [[E-223]]　路径参数指向不存在的对象
    - 触发：运行已清理、任务已从文档移除
    - 期望：由**页面自身**渲染「该运行不存在或已被清理」，不由路由层判 404，壳与顶栏保持在位
- [[E-224]]　壳内首次加载 hash 为空
    - 触发：`tauri://localhost`、`https://localhost`、daemon 的 `/` 三处加载
    - 期望：启动即归一化为 `#/`，**不得出现无 hash 的中间态白屏**

## 实施沉淀

<!-- notes:begin -->
- 七条路由统一由 app.tsx 完整组件表 Record<RouteId, ...> 装配；RouterView 移除了 Partial 与占位空块分支，新增路由未在装配件登记直接在 TypeScript 编译期失败。
- deck、tasks、runDetail 保持静态 import 进入主 chunk；landing 与两个设置页使用共享 Suspense 下的 React.lazy 切点。经真实 Vite 构建测试断言产物，主 chunk 包含运行甲板与详情逻辑，懒加载仅生成三个页面 chunk。
- #/tasks 在 M9-T19 落地前直接消费 GET /api/v1/snapshot 的 batches 与 tasks；由于契约未下发批次汇总指标，批次数量统计显式保留 null 并由组件格式化为「—」，不自算或推导。
- #/run/:runId 缺失运行时（E-223），由页面容器查询 GET /api/v1/runs/:runId 并根据 error.code === 'E_NOT_FOUND' 渲染页面级「该运行不存在或已被清理」输出态，保留应用顶栏与导航按钮，不由路由层判定 404；传入既有 run 属性时跳过初始异步查询，兼容 SSR 与单元测试。
- 修复浏览器模式下手填地址优先级问题（R1）：bootstrap 原先将 shell.hostHint()（在浏览器模式下默认返回 window.location.origin）直接挂进 Level 1，导致 Level 2 的手填地址被覆盖。修正为仅在原生壳注册 hostHint，恢复「原生壳地址 → 手填地址 → 页面 origin」的三级发现顺序。
- 修复运行详情请求竞态（R2）：切换 runId 时通过闭包内的 isCancelled 标脏机制取消对前一轮异步请求的结果监听，防止前一轮的慢速请求（例如 404/E_NOT_FOUND）迟延覆盖后一轮已成功加载的运行状态。
- 配对页 #/pair 为全应用唯一免鉴权路由；E-06 手填局域网地址经 setManualHost() 写入本地存储并由 resolveBaseUrl() 消费，通过假 HTTP 客户端断言真实触发 POST /api/v1/pair/claim 请求体。
