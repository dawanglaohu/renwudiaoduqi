# M3-T2　任务、批次与依赖导入

- 所属模块：[[M3]]　**文档接入**——把 `docs-data.js` 变成本产品唯一的任务真相源（任务、依赖、批次、并行窗口、验收标准、边界编号、实施与审查两段提示词），并负责内容指纹、派发时快照与文档重出后的三个标记。凡「这条数据来自文档」的都归它
- 前置依赖：[[M3-T1]]
- 完成后解锁：[[M3-T3]]、[[M3-T4]]、[[M8-T1]]

## 输入 / 产出

- **输入**：M3-T1 的解析结果
- **产出**：`repo/tasks.ts`、`repo/batches.ts`、导入校验

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 任务、依赖、批次、并行窗口、验收标准、边界编号、`taskPaths`、两段提示词全部正确落库
2) `deps` 指向不存在的 id 或成环时导入即校验，禁止进入自动批次派发但仍允许手动单点派发，**不因一条脏边卡死整个交接台**（[[E-20]]）
3) 多份文档按文档路径 + 指纹隔离，任务 id 不跨项目冲突，列表按文档分组不混排（[[E-21]]、[[E-87]]）
4) 依赖成环时与上游同规则**就地截断为层 0**（落进第 1 批），并在导入报告与 UI 列出环上任务 id，该批派发前**强制人工确认**（[[E-241]]）
5) `deps` 指向不存在的任务 id 时只计入存在的前驱，**被忽略的幽灵 id 必须在导入报告里列出**（[[E-242]]）
6) 批次号**不作持久标识**，每次导入按当前分层重算
历史派发记录只认任务 id 与快照（[[E-243]]）
7) 全部任务无依赖时只有「第 1 批」，界面照常按批次呈现，**不退化成无批次列表**（[[E-244]]）

## 必须处理的边界

- [[E-20]]　依赖脏数据
    - 触发：deps 指向不存在的 id，或依赖成环
    - 期望：导入时校验，禁止进入自动批次派发；仍允许手动单点派发，不得因一条脏边卡死整个交接台
- [[E-21]]　多份文档同时接入
    - 触发：用户接入多个项目的文档
    - 期望：按 pres.handoff 的 repo/branchPrefix 加文档指纹分工作区，任务 id 不跨项目冲突
- [[E-241]]　任务依赖成环
    - 触发：导入时 `deps` 构成环
    - 期望：与上游 `layerOf` 同规则**就地截断为层 0**（成环任务落进第 1 批），同时在导入报告与 UI 打显式告警列出环上的任务 id，该批派发前**强制人工确认**，不静默
- [[E-242]]　deps 引用了幽灵任务
    - 触发：`deps` 指向 tasks 中不存在的 id
    - 期望：与 `layerOf` 一致只计入存在的前驱，但**被忽略的幽灵 id 必须在导入报告里列出**
- [[E-243]]　文档重出导致批次号位移
    - 触发：依赖变化，分层结果整体改变
    - 期望：批次号**不作任何持久标识**，`tasks.batch_id` 每次导入按当前分层重算；历史派发记录只认任务 id 与派发快照，**不认批次号**
- [[E-244]]　全部任务无依赖
    - 触发：分层结果只有一层
    - 期望：只有「第 1 批」，界面照常按批次呈现，**不因只有一批而退化成无批次列表**
- [[E-87]]　同时接管多份文档
    - 触发：用户接入多个项目
    - 期望：按文档路径 + 指纹隔离，任务列表按文档分组，跨文档不混排、不共用批次编号
