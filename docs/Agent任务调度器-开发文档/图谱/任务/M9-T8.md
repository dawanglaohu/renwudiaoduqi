# M9-T8　虚拟列表与日志窗口

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯、按窗口数呈现的任务流水线泳道与「会话已归档」历史行、顶栏两个流水线开关，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值、「能否收口」、泳道分配、阶段推进与会话归档都是 daemon 给的字段）；指派面板的分组模型下拉、登录态徽标与刷新按钮、参照条的「来源」段同样只呈现 daemon 下发的字段，不算取值链
- 前置依赖：[[M9-T7]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：M9-T7 的条目
- **产出**：`components/virtual-rows.tsx`、`features/run-detail/log-window.ts`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 十万行日志只挂载可视窗口，**任何时候不把全量放进 DOM 或 store**（[[E-143]]）
2) 内存只保留 6 段（每段 ≤2000 行），滚出窗口即丢弃并可重拉（[[E-98]] 的客户端侧）
3) 用户滚到中部时新事件到达**不自动跳底**，显示「N 条新事件」
仅贴底才跟随（[[E-100]]）
4) ANSI 转义与重复刷新行折叠，控制字符不破坏布局（[[E-101]]）
5) 单行超长按宽度截断并可展开，**绝不把整行塞进 DOM**（[[E-102]]）
6) 虚拟滚动只经这一个包装使用，**禁止第二处直接 import**

## 必须处理的边界

- [[E-100]]　运行中日志持续追加
    - 触发：任务仍在跑
    - 期望：尾部自动跟随；用户一旦向上翻页即停止跟随，并出现「回到底部（有 N 行新增）」
- [[E-101]]　日志含终端控制序列
    - 触发：ANSI 转义、光标回退、进度条刷屏
    - 期望：落盘保留原文，渲染时折叠重复刷新行，不让控制字符破坏布局
- [[E-102]]　单行超长
    - 触发：整段 base64 或压缩 JSON
    - 期望：按宽度截断并可展开，绝不把整行塞进 DOM
- [[E-143]]　超长日志的渲染
    - 触发：单任务日志超过 10 万行
    - 期望：虚拟列表只挂载可视窗口，向上滚动时按段向 daemon 请求历史片段；任何时候都不把全量日志放进 DOM 或 store
- [[E-98]]　单会话体积超阈值
    - 触发：超过 20 MB 或 50 万字
    - 期望：默认只加载尾部片段，顶部给「向上加载更多」，并提供「用系统默认程序打开原始文件」

## 实施沉淀

<!-- notes:begin -->
1. 虚拟滚动单点收敛（AC 6, E-143）：将 `@tanstack/react-virtual` 严格限制在 `components/virtual-rows.tsx` 单个组件内使用，向外暴露 `VirtualRowsHandle` 命令式句柄与 `onScroll` 度量。其余任何业务容器与展示组件禁止直接依赖虚拟滚动实现细节。
2. 分段内存滑动窗口（AC 2, E-98, E-143）：daemon 单段读取最大限制为 2000 行（`SEGMENT_MAX_LINES`）。客户端通过 `LogWindowManager` 将内存驻留严格控制在至多 6 段（`MAX_RETAINED_SEGMENTS = 6`，上限 12,000 行）。向上翻页加载历史段时驱逐尾部段；向下回滚时重拉先前被驱逐的较新段；实时流追加超过 2000 行自动切片并驱逐头部段。十万行日志绝不把全量塞进 store 或 DOM。
3. 视口跟随与未读计数（AC 3, E-100）：监听虚拟列表滚动状态，当距离容器底部小于 24px 时判为贴底，此时新日志到达自动跟随且未读计数为 0；用户一旦向上翻页滚动离开底部，自动跟随立即挂起，新到达行只累加 `unreadNewCount`，并在右下角浮动呈现「回到底部（有 N 行新增）」，点击后滚动至底部并清零未读。
4. ANSI 解析与终端控制字符过滤（AC 4, E-101）：采用纯字符扫描器替代正则字面量，避免触发 Biome 对正则内控制字符的校验阻断；非打印控制字符（ASCII 0-8, 11-12, 14-31, 127）全部剥除；`\r` 回车字符按光标重置行首规则计算最终覆写结果；SGR 颜色代码统一映射至 `tokens.css` 中已定义的 `--down`、`--auto`、`--needs`、`--ink-1/3`，零颜色字面量。高频刷新进度行通过正则特征识别并折叠。
5. 超长单行性能保护（AC 5, E-102）：单行文本超过 300 字符时默认截断，并在行尾挂载展开按钮；用户展开时封顶挂载前 2000 字符，提示剩余字符已省略以保护 DOM 性能，杜绝因数十万字符 base64 或单行 JSON 导致浏览器排版树冻结。
