# M9-T8　虚拟列表与日志窗口

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯、按窗口数呈现的任务流水线泳道与「会话已归档」历史行、顶栏两个流水线开关，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值、「能否收口」、泳道分配、阶段推进与会话归档都是 daemon 给的字段）；指派面板的分组模型下拉、登录态徽标与刷新按钮、参照条的「来源」段同样只呈现 daemon 下发的字段，不算取值链

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 十万行日志只挂载可视窗口，**任何时候不把全量放进 DOM 或 store**（[[E-143]]）
2) 内存只保留 6 段（每段 ≤2000 行），滚出窗口即丢弃并可重拉（[[E-98]] 的客户端侧）
3) 用户滚到中部时新事件到达**不自动跳底**，显示「N 条新事件」
仅贴底才跟随（[[E-100]]）
4) ANSI 转义与重复刷新行折叠，控制字符不破坏布局（[[E-101]]）
5) 单行超长按宽度截断并可展开，**绝不把整行塞进 DOM**（[[E-102]]）
6) 虚拟滚动只经这一个包装使用，**禁止第二处直接 import**
7) 日志端点 client 侧接线：`GET /api/v1/runs/:runId/log` 的出参须透出 [[E-98]] 三项 `isExceedsThreshold` / `originalFilePath` / `openCommand`（daemon 服务已算出，路由与 shared DTO 一并补齐
出参为新增字段，不改已有四字段语义），`fromSeq` 须接受 `prevCursor`/`nextCursor` **原样回传**的游标字符串（`fileSeq:byteOffset`，与 daemon 服务既有的 `parseCursor` 一致，仅放宽查询 schema，不改游标格式）
前端只读契约字段——**禁止自造与后端对应的 DTO，禁止从日志正文文本嗅探业务标志或边界编号**

## 必须处理的边界

- [[E-100]]　运行中日志持续追加
    - 触发：任务仍在跑
    - 期望：尾部自动跟随；用户一旦向上翻页即停止跟随，并出现「回到底部（有 N 行新增）」
- [[E-101]]　日志含终端控制序列
    - 触发：ANSI 转义、光标回退、进度条刷屏
    - 期望：落盘保留原文，渲染时折叠重复刷新行，不让控制字符破坏布局
- [[E-102]]　单行超长
    - 触发：整段 base64 或压缩 JSON
    - 期望：按宽度截断并可展开，绝不把整行塞进 DOM
- [[E-143]]　超长日志的渲染
    - 触发：单任务日志超过 10 万行
    - 期望：虚拟列表只挂载可视窗口，向上滚动时按段向 daemon 请求历史片段；任何时候都不把全量日志放进 DOM 或 store
- [[E-98]]　单会话体积超阈值
    - 触发：超过 20 MB 或 50 万字
    - 期望：默认只加载尾部片段，顶部给「向上加载更多」，并提供「用系统默认程序打开原始文件」

## 实施沉淀

<!-- notes:begin -->
1. 虚拟滚动单点收敛（AC 6, E-143）：将 `@tanstack/react-virtual` 严格限制在 `components/virtual-rows.tsx` 单个组件内使用，向外暴露 `VirtualRowsHandle` 命令式句柄与 `onScroll` 度量。其余任何业务容器与展示组件禁止直接依赖虚拟滚动实现细节。
2. 分段内存滑动窗口与引用稳定性（AC 2, E-98, E-143, R2, R6）：daemon 单段读取限制为 2000 行（`SEGMENT_MAX_LINES`）。客户端通过 `LogWindowManager` 将内存驻留严格控制在至多 6 段（`LOG_SEGMENT_MAX_IN_MEMORY = 6`，上限 12,000 行）。管理器内部持有 `version` 与 `cachedState` 快照，仅在状态变更时重建，使 `getState()` 在连续调用时返回稳定引用，彻底消除 `useSyncExternalStore` 导致的无限更新告警。
3. 视口跟随与未读计数（AC 3, E-100, R1）：在 `RunDetailContainer` 中监听 `state.totalLines` 与 `state.isAtBottom`；当贴底且尾部增长时自动触发 `virtualRef.current?.scrollToBottom()` 尾部跟随；用户滚到中部时（`isAtBottom === false`）绝不自动跳底，新到达行只累加 `unreadNewCount`，并在右下角浮动呈现「回到底部（有 N 行新增）」，点击后滚动至底部并清零未读。审查方补修：增长信号必须取单调的 `totalLines`——进度刷新行被折叠时 `retainedLinesCount` 不增长、满 6 段驱逐头部时还会下降，用计数判断会在这两种情况下漏掉跟随。
4. ANSI 解析与终端控制字符过滤（AC 4, E-101, R3）：采用纯字符扫描器替代正则字面量，规避 Biome 规则限制；非打印控制字符全部剥除；`\r` 回车字符按光标重置行首规则计算最终覆写结果；SGR 颜色代码统一映射至 `tokens.css` 变量；识别相邻进度刷新行（`isProgressLine`）就地折叠并维护 `refreshCount` 与 `collapsedLines`，在前端界面提供折叠展开交互。
5. 超长单行性能保护（AC 5, E-102）：单行文本超过 300 字符时默认截断；用户展开时封顶挂载前 2000 字符，提示剩余字符已省略以保护 DOM 性能，杜绝整段 base64 或压缩 JSON 导致浏览器排版树冻结。
6. 端点契约与游标贯通（R5）：放宽 daemon 路由的 `fromSeq` 查询参数 schema，允许接收形如 `"0:9"` 的游标字符串；路由出参透出 `isExceedsThreshold`、`originalFilePath` 与 `openCommand` 并补充 shared `GetRunLogResponse` 类型声明；前端调用统一改走 `ROUTES` 与 `httpClient.callRoute` 原样传回游标，并在容器内接通 `LogLoadNewerBar` 确保滚出窗口后可双向重新拉取。
7. 实时推流水位消费（R4）：`useLogWindow` 在订阅 SSE 事件总线时记录已消费的事件 `id` 与 `seq` 水位，按序消费每个 flush 周期内所有新增的 `agent_message_chunk`、`agent_thought_chunk` 与 `run.stderr_line`，杜绝只取末尾事件导致的正文漏丢。审查方补修：水位起点由 `seedStreamWatermark()` 取订阅瞬间的缓冲末尾——缓冲是应用级单连接共享的、最多 600 条，不设起点会把挂载前已在缓冲里的历史事件当新行重放，与 REST 尾部片段整段重复。
8. REST 与 SSE 的语义不能混为一谈：REST 片段带可回拉的字节游标，SSE message/thought 是 token delta。首屏必须显式 backward；delta 在同一未闭合逻辑行内合并；若实时段驱逐了所有 REST 游标，向上加载要重新请求尾部锚点，不能保留一个点击无效的按钮。
