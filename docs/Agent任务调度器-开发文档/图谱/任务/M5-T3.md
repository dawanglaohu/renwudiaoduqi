# M5-T3　diff 读取与改动文件数

- 所属模块：[[M5]]　**工作区与 Git**——为每个任务准备、隔离与回收独立 worktree，从中读出改动（改动文件数、diff stat、diff 正文）并生成只读落地清单。凡要碰 git 或任务工作目录的都归它
- 前置依赖：[[M5-T1]]
- 完成后解锁：[[M5-T4]]、[[M6-T3]]、[[M7-T1]]

## 输入 / 产出

- **输入**：M5-T1 的 worktree
- **产出**：`getDiffStat()` / `getDiffText()`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 改动文件数用 git 工作区 diff 得出，**不解析各家 tool 事件**，四个 agent 共用一套逻辑
2) diff 基线取 worktree 自身 HEAD，**不与主工作区混算**（[[E-72]]）
3) agent 在 worktree 里自行 `git commit` 或 `git push` 时不拦截，但 push 到远端的事件要在任务详情高亮标注（[[E-75]]）

## 必须处理的边界

- [[E-72]]　主工作区有未提交改动
    - 触发：用户自己手上有活没提交
    - 期望：建 worktree 不受影响也不去 stash 用户的东西；diff 基线取 worktree 自身 HEAD，不与主工作区混算
- [[E-75]]　agent 自己动了远端
    - 触发：agent 在 worktree 里自行 `git commit` 或 `git push`
    - 期望：不拦截其行为（拦不住），但 push 到远端的事件要在任务详情里高亮标注，让人知道发生了什么

## 实施沉淀

<!-- notes:begin -->
- 为什么不解析各家 tool 事件（AC 1）：Codex、Claude、Grok、Pi 各自的工具调用协议各异（write_to_file、apply_diff 等），且子进程可能通过 bash/cmd 间接修改文件或自行撤销改动。直接在工作区通过 `git diff --numstat` 与 `git status --porcelain` 读取改动，以真实文件系统为唯一真相源，四家共用一套逻辑零分支。
- 为什么 diff 基线取 worktree 自身 HEAD（AC 2、E-72）：主工作区（用户检出）往往有用户未提交的改动。工作区所有 git 命令的 cwd 严格锁定在任务独立 worktree 目录内，diff 默认基线为该 worktree 自身当前的 `HEAD`，不仅天然隔离主工作区脏改动，也不需要 stash 用户的任何改动。
- 为什么补齐未跟踪文件（untracked files）diff：标准 `git diff HEAD` 仅包含已跟踪文件的改动，若 agent 全新创建文件且未执行 `git add`，原生 diff 输出为空，会导致下游 M7-T1 误判为「无改动」。实现中通过 `status --porcelain -z -uall` 枚举所有未跟踪文件，将其行数累加入 insertions，并在 `getDiffText()` 中规格化为 `diff --git a/... b/...` 补丁，保证新建文件也能被完整核算与审查。
- 为什么不拦截 commit/push 而是只检测（AC 3、E-75）：具有工作区写权限或无限制权限的 agent 可能自行运行 `git commit` 或 `git push`，拦截子进程的子命令代价过高且容易引发 agent 异常崩溃。检测实现必须先解析本次运行起点 SHA 作为稳定基线（不使用移动后的 HEAD），只在 HEAD 前进且远端同名引用或包含新 HEAD 的远端分支 tip 不等于基线时才判为远端推送，彻底规避新建 worktree 时起点 commit 被 `origin/main` 包含导致的误报。
<!-- notes:end -->
