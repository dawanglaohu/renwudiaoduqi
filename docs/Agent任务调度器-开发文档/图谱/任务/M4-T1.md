# M4-T1　agent 注册表两层结构与热加载

- 所属模块：[[M4]]　**Agent 适配**——把形态各异的 agent 抽象成同一个可派发对象：注册表（含每个 agent 通用的版本指纹探测字段与具名的「适配器种类」枚举）、可执行探测、模型清单读取与降级、启动参数与三档权限映射、以各家原生通道为主干把输出归一化成 ACP `session/update` 词汇的事件、可回话与**是否提供流式事件**等能力位，并自实现一个通用 ACP 适配器作为兜底与第 6 家及以后的入口。凡「某一家 agent 跟别家怎么不一样」的都归它
- 前置依赖：[[M1-T1]]
- 完成后解锁：[[M4-T2]]、[[M4-T3]]、[[M4-T5]]、[[M4-T7]]、[[M8-T1]]

## 输入 / 产出

- **输入**：04 节的四家配置文件实测结果
- **产出**：`config/registry.ts`、`config/defaults.ts`、`agents.json` schema

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 数据层可配（路径／参数模板／并发上限／默认模型／短码／`adapterKind`／超时），代码层解析器按具名枚举选，用户不能自写解析规则
2) 热加载用 `fs.watch` + 300ms 防抖 + 内容指纹去重，编辑器一次保存不触发多次重载（[[E-93]]）
3) 校验失败保留上一版并发警告事件，**绝不因此退出 daemon**
未知字段忽略并 warn，缺字段回落内置默认（[[E-94]]）
4) 内置默认与用户覆盖**分开存两份**，升级后能算出差异并给一键采纳（[[E-92]]）
5) 并发上限为 0 或负数等同禁用该 agent，不是无限并发（[[E-91]]）

## 必须处理的边界

- [[E-91]]　并发上限被设为 0 或负数
    - 触发：用户误填
    - 期望：等同「禁用该 agent」，而不是无限并发
- [[E-92]]　升级后内置默认变了
    - 触发：用户恰好覆盖了同一字段
    - 期望：保留用户覆盖，在该字段旁提示「内置默认已更新（旧值 → 新值）」并给一键采纳
- [[E-93]]　配置文件被外部手改
    - 触发：用户直接编辑了注册表文件
    - 期望：daemon 监听变更热加载，只影响之后新起的任务；在途运行沿用启动时的参数快照
- [[E-94]]　配置含未知字段或缺字段
    - 触发：版本不匹配
    - 期望：未知字段忽略并记一条警告，缺字段回落内置默认；绝不因配置问题拒绝启动 daemon

## 实施沉淀

<!-- notes:begin -->
- `defaults` 是上次确认的内置默认基线，不是启动时自动刷新的缓存。自动改成当前默认会抹掉升级差异，使界面无法给出可信的“旧值 → 新值”；只有采纳对应字段时才推进该字段基线并移除同字段覆盖。
- 监听目标是配置文件所在目录。常见编辑器会用临时文件替换 `agents.json`，直接监听旧 inode 会丢失后续变更；目录事件仍须经过 300ms 防抖和原始 UTF-8 内容指纹去重。
- 注册表只在整份配置校验成功后替换不可变快照。失败路径不改 generation 或当前引用；已取得旧快照的派发流程不会被后续热加载改写。
- `maxConcurrency` 的零值和负值不归一化成其他并发数，原值保留用于诊断，派发语义统一读取派生的 `isEnabled=false`。任何把非正数解释成“无限”的简化都会破坏 E-91。
- `agents.json` 只选择具名 `adapterKind`，不接收事件解析函数、字段映射或厂商事件规则。新增解析能力必须进入对应适配器代码，不能借未知字段绕过代码审查。
<!-- notes:end -->
