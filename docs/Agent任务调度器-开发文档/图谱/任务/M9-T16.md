# M9-T16　空态四步引导、批次汇总与落地清单页

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯、按窗口数呈现的任务流水线泳道与「会话已归档」历史行、顶栏两个流水线开关，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值、「能否收口」、泳道分配、阶段推进与会话归档都是 daemon 给的字段）；指派面板的分组模型下拉、登录态徽标与刷新按钮、参照条的「来源」段同样只呈现 daemon 下发的字段，不算取值链
- 前置依赖：[[M9-T9]]、[[M5-T4]]
- 完成后解锁：[[M9-T18]]、[[M9-T19]]

## 输入 / 产出

- **输入**：M5-T4 的落地清单数据
- **产出**：`empty-onboarding.tsx`、`batch-summary-bar.tsx`、`landing-page`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 空态是「选文档 → 选批次 → **逐任务指派** → 派发」四步引导，当前步高亮、已完成步显示所选值可点回改，**不是插画**（[[E-108]]）
2) 批次汇总条是四个数字 + 一条比例条，**不得升格成饼图或环形图**挤占运行流主位（[[E-111]]）
3) 落地清单页展示 worktree 路径、分支名、diff 摘要、可一键复制的 `gh stack` 命令文本与 `build_docs.py --landed` 命令，每条各带复制按钮（[[E-74]] 的呈现侧）
4) 文档变更横幅显示「本文档已更新，N 个任务的依据已变」并可进入受影响任务的过滤列表（[[E-19]] 的呈现侧）
5) 「在整个会话中查找」是显式入口，避免用户误以为 Ctrl+F 已搜全文（[[E-218]]）
6) 长时间盯屏下深色为默认、日志等宽（[[E-110]] 的呈现侧）

## 必须处理的边界

- [[E-108]]　零运行空态
    - 触发：首次使用或全部空闲
    - 期望：空态直接是「选文档 → 选批次 → 选模型 → 派发」的四步引导，而不是一张插画
- [[E-110]]　长时间盯屏与色觉差异
    - 触发：用户连续监看数小时，或投屏/色弱
    - 期望：深色为默认，日志用等宽字体；状态区分不能只靠色相，必须同时有形状或文字
- [[E-111]]　一次派发涉及一整批
    - 触发：批次里有十几个任务
    - 期望：批次要有自己的汇总条（进行中 / 待审批 / 已落地 / 失败各几个），但汇总条不能挤占运行流的主位
- [[E-19]]　验收标准被事后改动
    - 触发：同一 id 的 input/output/accept 文本被改过
    - 期望：派发时把这三段快照进任务记录；列表标「文档已更新，与派发时不一致」
- [[E-218]]　浏览器 Ctrl+F 搜不全
    - 触发：用户在几十 MB 会话里按 Ctrl+F
    - 期望：浏览器只搜到当前已加载分段；会话视图**必须另给一个显式的「在整个会话中查找」入口**，否则用户会误以为已搜全文
- [[E-74]]　用户要落地
    - 触发：任务已验收，准备合并
    - 期望：提供只读落地清单（worktree 绝对路径、分支名、diff 摘要、可一键复制的 `gh stack` 命令文本），复制而不执行

## 实施沉淀

<!-- notes:begin -->
1. 空态控制台化（E-108）：拒绝使用占位插画或卡通空态图。工作台语域下空态直接呈现「选文档 → 选批次 → 逐任务指派 → 派发」的四步向导；已完成步骤展示具体选中值并支持点击回跳修改。第三步坚持逐任务独立指派而不是「整批统一选模型」，以支持同批次不同任务分派至不同 Agent 及不同思考强度档位（决策 52 / E-31）。
2. 批次汇总防挤占（E-111）：汇总条固定为「4 个 Commit Mono 大数 + 1 条线性比例条」，高度锁定约 44px。禁止升格为饼图或环形图以防挤压运行流核心监看区。状态数值与色块均配专属内联 SVG 形状（进行中 ▮、待审批 ◆、已落地 ✓、失败 ✕），在黑白打印或色弱模式下依然具备辨识度（E-110）。
3. 落地清单只读隔离（E-74）：界面仅提供 worktree 路径、分支名、diff 摘要与复制命令，严禁前端自动触发 git commit/push/merge 或后台执行脚本，操作权限严格保留在人工终端。
4. 全会话检索入口隔离（E-218）：针对虚拟滚动和分段加载导致浏览器 Ctrl+F 无法检索全量日志的问题，在界面中提供显式的全会话查找入口并注明限制，防止用户对全量日志产生漏搜误判。
<!-- notes:end -->
