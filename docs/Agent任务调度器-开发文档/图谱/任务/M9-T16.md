## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 空态是「选文档 → 选批次 → **逐任务指派** → 派发」四步引导，当前步高亮、已完成步显示所选值可点回改，**不是插画**（[[E-108]]）
2) 批次汇总条是四个数字 + 一条比例条，**不得升格成饼图或环形图**挤占运行流主位（[[E-111]]）
3) 落地清单页展示 worktree 路径、分支名、diff 摘要、可一键复制的 `gh stack` 命令文本与 `build_docs.py --landed` 命令，每条各带复制按钮（[[E-74]] 的呈现侧）
4) 文档变更横幅显示「本文档已更新，N 个任务的依据已变」并可进入受影响任务的过滤列表（[[E-19]] 的呈现侧）
5) 「在整个会话中查找」是显式入口，避免用户误以为 Ctrl+F 已搜全文（[[E-218]]）
6) 长时间盯屏下深色为默认、日志等宽（[[E-110]] 的呈现侧）
7) **呈现侧数据来源与落点（本次审查定点补记，不改已有 1–6 条）**：第一步文档清单、第二步批次清单、第三步任务与 agent／模型清单、第四步并发与瓶颈来源、批次汇总条的四个数字一律读 daemon 下发字段，**缺失显示「—」，不得用 `Math.min`／`Math.max` 自算并发或瓶颈来源，也不得内置演示用的文档／批次／任务／agent／模型清单与计数冒充真实数据**（[[E-52]]、[[E-47]]、[[E-111]]、[[E-254]]）
第三步「逐任务指派」面板与第四步并发瓶颈说明的**正文归 M9-T18**（`assign-panel.tsx`），本任务只交四步外壳、步骤槽位、已完成步回显与「派发」动作，第二步须按已选文档过滤批次（`OnboardingBatchOption.docId`）。落地清单只在 `features/landing/` 取数、`pages/landing-page.tsx` 只装配（07 节：pages 禁止 import `src/api`／`src/store`，禁止组件内 `useEffect` 取数），worktree 路径／分支名／diff／命令全部来自 `GET /api/v1/tasks/:taskId/landing`，**拉取失败按错误体系就地 inline notice 或首屏 connect-failed（带 requestId），不得在 catch 里造缺省清单冒充真实清单**
[[E-218]] 的显式入口落在**会话视图**（`features/run-detail/`，边界原文「会话视图必须另给一个显式的『在整个会话中查找』入口」），结果只来自 `GET /api/v1/runs/:runId/search`（`{hits,truncated,scannedUntilSeq,canceled}`，M6-T9），**不得用随机数冒充命中数或无条件宣称已检索全量**。`app/app.tsx` 是路由装配件（`main.tsx` 只挂载）：本任务先接 `#/landing/:taskId` 与零运行空态（`features/run-deck/run-deck-view.tsx` 渲染 `EmptyOnboarding`），其余路径维持 `RouterView` 占位，后续任务增量接。

## 必须处理的边界

- [[E-108]]　零运行空态
    - 触发：首次使用或全部空闲
    - 期望：空态直接是「选文档 → 选批次 → 选模型 → 派发」的四步引导，而不是一张插画
- [[E-110]]　长时间盯屏与色觉差异
    - 触发：用户连续监看数小时，或投屏/色弱
    - 期望：深色为默认，日志用等宽字体；状态区分不能只靠色相，必须同时有形状或文字
- [[E-111]]　一次派发涉及一整批
    - 触发：批次里有十几个任务
    - 期望：批次要有自己的汇总条（进行中 / 待审批 / 已落地 / 失败各几个），但汇总条不能挤占运行流的主位
- [[E-19]]　验收标准被事后改动
    - 触发：同一 id 的 input/output/accept 文本被改过
    - 期望：派发时把这三段快照进任务记录；列表标「文档已更新，与派发时不一致」
- [[E-218]]　浏览器 Ctrl+F 搜不全
    - 触发：用户在几十 MB 会话里按 Ctrl+F
    - 期望：浏览器只搜到当前已加载分段；会话视图**必须另给一个显式的「在整个会话中查找」入口**，否则用户会误以为已搜全文
- [[E-254]]　agent 不支持思考强度
    - 触发：dsh 无对应参数；某些模型或某些 agent 版本也没有
    - 期望：该 agent 的思考强度置 NULL、**派发时不传任何相关参数**，UI 一律显示「—」并在 title 说明原因。**绝不补一个默认档冒充**——补了等于谎称控制生效（与 E-26「数据缺失显示—，不拿 0 冒充」同理）。不因不支持而禁用该 agent（与 E-35 对称）
- [[E-47]]　单 agent 并发满但窗口有空位
    - 触发：某 agent 达到并发上限，整体窗口未满
    - 期望：空位让给其他 agent 的任务，不空转等待
- [[E-52]]　并发瓶颈来源不明
    - 触发：实际并发数低于用户预期
    - 期望：实际并发取 min(窗口数, 每 agent 上限, 用户设定)，UI 显示这三者中哪一个成了瓶颈；用户可向下调，向上超过窗口数需显式解锁并提示后果
- [[E-74]]　用户要落地
    - 触发：任务已验收，准备合并
    - 期望：提供只读落地清单（worktree 绝对路径、分支名、diff 摘要、可一键复制的 `gh stack` 命令文本），复制而不执行

## 实施沉淀

<!-- notes:begin -->
1. 空态控制台化（E-108）：拒绝使用占位插画或卡通空态图。工作台语域下空态直接呈现「选文档 → 选批次 → 逐任务指派 → 派发」的四步向导；已完成步骤展示具体选中值并支持点击回跳修改。第三步坚持逐任务独立指派而不是「整批统一选模型」，以支持同批次不同任务分派至不同 Agent 及不同思考强度档位（决策 52 / E-31）。
2. 批次汇总防挤占（E-111）：汇总条紧凑呈现「4 个 Commit Mono 大数 + 1 条线性比例条」，不设固定高度挤占运行流主位。禁止升格为饼图或环形图以防挤压实时监看区。四个数字与总数严格读取 daemon 字段，缺失显示「—」而不以前端求和或零值冒充（E-26）；状态数值与色块均配专属内联 SVG 形状（进行中 ▮、待审批 ◆、已落地 ✓、失败 ✕），在黑白打印或色弱模式下依然具备辨识度（E-110）。
3. 落地清单只读隔离（E-74）：界面仅提供 worktree 路径、分支名、diff 摘要与复制命令，严禁前端自动触发 git commit/push/merge 或后台执行脚本，操作权限严格保留在人工终端。
4. 全会话检索入口隔离（E-218）：针对虚拟滚动和分段加载导致浏览器 Ctrl+F 无法检索全量日志的问题，显式查找入口统一落会话视图（features/run-detail/run-detail-container.tsx），通过 components/session-search-entrance.tsx 纯展示组件承接；检索严格走 GET /api/v1/runs/:runId/search 接口并呈现真实命中（hits.length / scannedUntilSeq / truncated），禁止在落地清单页混放、禁止使用随机数假造命中数、不无条件宣称已检索全量。
<!-- notes:end -->
