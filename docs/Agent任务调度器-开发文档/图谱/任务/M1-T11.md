# M1-T11　端到端冒烟：真起 daemon、真浏览器、派发主流程

- 所属模块：[[M1]]　**运行底座**——让 daemon 在这台机器上稳定跑起来并把字节落到磁盘上：进程单实例与端口、启动自检、开机自启注册、数据目录、结构化存储的连接与迁移、日志正文的追加写与字节偏移索引、以及全部平台差异（进程树终止、路径规范化与长路径、配置目录、子进程编码）的唯一收口。凡与操作系统、磁盘、进程存活打交道而不带任何业务概念的都归它
- 前置依赖：[[M1-T10]]、[[M2-T2]]、[[M2-T5]]、[[M10-T4]]、[[M10-T5]]、[[M9-T24]]、[[M9-T25]]、[[M9-T26]]、[[M9-T27]]、[[M8-T10]]、[[M7-T9]]
- 完成后解锁：无，它不卡别人

- **输入**：M1-T10 的 `bootstrap.mjs` 入口与 `createHttpServer()`；M2-T2 的配对自举 `pairing-code.txt`；M2-T5 的 SSE 服务端；M10-T4 的单次构建与 `80-static.ts` 托管；M10-T5 的 `desktop-ci.yml`；M9-T24 的样式产物；M9-T25 的七条路由；M9-T26 的 `bootstrap.ts`；M9-T27 的生产配对入口冒烟与 Playwright 依赖；M8-T10 的真实 spawn；M7-T9 的容器接线

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) `pnpm -w e2e` 先 `pnpm --filter @agent-scheduler/web build`，在临时 `AGSCHED_DATA_DIR` 与随机 `AGSCHED_PORT` 下用 `node packages/daemon/bootstrap.mjs` 起真实 daemon，读 `pairing-code.txt` 走 `POST /api/v1/pair/claim` 拿令牌，daemon 退出码与 stdout 全程收集（[[E-226]]、[[E-139]]）
2) Playwright chromium（`playwright` 包作库在 Vitest 里跑，不引入第二套 runner）打开 `http://127.0.0.1:〈port〉/#/pair`，手填地址与配对码完成配对后落到 `#/`
断言 `getComputedStyle(document.body).fontFamily` 含 `Public Sans`、`#root` 首个子元素 `background-color` 不是 `rgba(0, 0, 0, 0)`、`document.styleSheets` 里存在含 `.flex` 规则的样式表（[[E-159]]、[[E-175]]）
3) 导入 `e2e/fixtures/docs-data.js` 后页面出现该文档的两个任务
用 fixture 注册表里的假 agent 派发第一个任务，断言运行轨出现该运行、`data-connection-status` 变为 `online`、至少一条 `agent_message_chunk` 文本经 SSE 到达 DOM（[[E-108]]、[[E-10]]、[[E-31]]）
4) 不 mock：生产代码里不出现 `window.__setToken` 之类测试钩子、e2e 不替换 `spawnManaged`（arch 测试 grep 断言）
假 agent 走与真 agent 相同的 spawn 路径（[[E-135]]）
5) 失败定位：每步失败时把截图、daemon stdout 与 stderr、最后一次 DOM 快照写入 `e2e/artifacts/` 并由 CI 上传为 artifact
`e2e-smoke` job 至少在 Ubuntu runner 跑，失败阻断发布
`pnpm -w check` 的 include 不含 `e2e/`（[[E-265]]）

## 必须处理的边界

- [[E-10]]　手机断网期间任务跑完
    - 触发：提醒产生时手机不在线
    - 期望：提醒事件在 daemon 侧按 event id 入队，手机重连后补推并去重，不得丢弃
- [[E-108]]　零运行空态
    - 触发：首次使用或全部空闲
    - 期望：空态直接是「选文档 → 选批次 → 选模型 → 派发」的四步引导，而不是一张插画
- [[E-135]]　审查 agent 的权限
    - 触发：审查阶段派出去的 agent
    - 期望：固定给只读档（read-only / plan），审查 agent 不得改代码，否则「审查通过」失去意义
- [[E-139]]　Node 版本过低
    - 触发：daemon 启动时 `node --version` 低于声明的最低大版本
    - 期望：自检失败并打印所需版本后退出，不静默降级或半残运行。**版本检查必须由旧版 Node 可解析的纯 JS 垫片（`.mjs`，不含 TypeScript 语法、不依赖 Node 22 专属选项）在加载 TypeScript 与任何 Node 22 专属参数之前执行**；垫片只做版本判定，失败时打印 `requires Node.js >= 22` 并以非 0 退出，通过后才加载 `main.ts` 入口（Node 22 也不允许直接跑 `.ts`，因此垫片是正式启动入口）
- [[E-159]]　方向可能被推翻
    - 触发：视觉方向未经用户目视确认即写进文档
    - 期望：方向**只以 token 层表达**：颜色、字号、圆角、运行轨形状表全部收敛为 CSS 变量与一张形状枚举表，使日后被否决的代价 ≤ 改一个 token 文件，而不是重排组件结构。**注：方向已于 2026-09-01 获确认（R-03 关闭），但这条约束不随之放松**——它防的是「日后想改」，不只是「当初没确认」，仍由 M9-T1 验收
- [[E-175]]　无外网环境
    - 触发：手机壳冷启动、局域网 daemon 可达但无公网
    - 期望：字体与 Web UI 同源同命运，随 daemon 静态产物一起托管，**不单独引入 CDN**
- [[E-226]]　**全新装机的自举困境**
    - 触发：零已配对设备、两个壳都未就绪，而 `POST /pair/code` 需 device 令牌
    - 期望：daemon 必须能把一次性配对码**输出到本机控制台或数据目录文件**；POSIX 文件模式固定 `0600`，Windows DACL 只允许当前用户，用后即删。**不得为此新增第四个免鉴权端点**
- [[E-265]]　三平台矩阵任一失败
    - 触发：Windows、macOS、Ubuntu 任一 runner 的 workspace check、平台集成测试或桌面壳构建失败
    - 期望：整体发布检查失败；不得把失败平台降级成可忽略项后继续标记三平台版本
- [[E-31]]　同一 agent 并发多任务
    - 触发：一个 agent 被同时派多个任务
    - 期望：每任务独立 session 与独立工作区（grok 用自带 --worktree，其余用 git worktree 兜底），并设每 agent 并发上限

## 实施沉淀

<!-- notes:begin -->
- **怎么实现的**：
  1. 编写完整的端到端自动化测试 `e2e/smoke.test.ts`，基于 Vitest + Playwright Chromium 作为库直接调度，避免引入第二套测试 runner；
  2. 实现了 7 个独立清晰的 `it()` 步骤，覆盖构建检查、自举配对、真实浏览器配对与视觉 token 断言、文档导入、真实工作区与真实子进程派发、实时 SSE 推流到 DOM 与断流负控、无 mock 架构检查及产物归档配置；
  3. 编写 `fake-agent.mjs` 与 Windows 批处理 `fake-agent.cmd`，响应 `--version` 以通过启动自检探测，读取 `e2e/fixtures/agents.json` 作为测试注册表基底，并在派发后按 Codex 规范输出 NDJSON 流；
  4. 配置 `desktop-ci.yml` 引入 `e2e-smoke` 作为发布门禁 job；在 `package.json` 添加 `e2e` 脚本并在 `biome.json` 中忽略 `e2e/**` 确保 `pnpm -w check` 纯净；
  5. 每次测试创建独立临时 Git 仓库，在其中建立哨兵工作树并派发任务；信号文件位于当前 daemon 数据目录，结束时只删除本次创建的临时目录。
- **为什么这么选**：
  1. 采用 Playwright 作为库直接在 Vitest 进程内执行，遵循 AC 2“不引入第二套 runner”的规范，统一测试工具链；
  2. 假 agent 保持与真 agent 完全一致的 `spawnManaged` 执行通道和独立工作区创建流程，通过真实 stdout 行管道流转至 `mapCodexEvents`、SSE 广播到前端渲染，绝不使用测试后门；
  3. 失败时捕获脱敏 DOM 快照、全页截图、daemon stdout/stderr 到 `e2e/artifacts/`，CI 通过 `upload-artifact` 收集，覆盖 beforeAll setup 阶段，快速定位。
- **踩了什么坑**：
  1. `docs-data.js` 导入时 daemon 严格校验纯 JSON 格式（剥除 `window.DOCS = ` 前缀后直接 `JSON.parse`），属性名必须加双引号，否则会抛 `E_DOC_SOURCE_UNREADABLE`；
  2. `daemon` 启动时会通过 `--version` 探测 agent 可用性（正则匹配 `\bcodex\b`），未响应 `--version` 会被标为不可用导致派发 409；因此 `fake-agent.mjs` 必须支持 `--version` 输出 `codex 0.1.0`；
  3. 前端 `BatchTree` 默认折叠，折叠状态下子行不会创建到 DOM 中，需要先展开批次节点后再断言任务 DOM；
  4. 前端日志窗口在详情页首屏会先走 REST 加载历史片段，必须确保浏览器流与事件总线订阅在 fake agent 产生新 chunk 之前建立，才能诚实验证 SSE live stream 到达 DOM；
  5. 文档导入可能与运行甲板上一轮空快照并发，测试需等新文档及两个任务出现在服务端快照，再重载浏览器验证批次树；
  6. SSE 长连接正常在线时浏览器不会达到 `networkidle`；导航只等 DOM 装载，之后分别等待批次、运行日志请求和实时事件。
