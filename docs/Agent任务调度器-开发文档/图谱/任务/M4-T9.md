# M4-T9　claude 原生适配器

- 所属模块：[[M4]]　**Agent 适配**——把形态各异的 agent 抽象成同一个可派发对象：注册表（含每个 agent 通用的版本指纹探测字段与具名的「适配器种类」枚举）、可执行探测、模型清单读取与降级、启动参数与三档权限映射、以各家原生通道为主干把输出归一化成 ACP `session/update` 词汇的事件、可回话与**是否提供流式事件**等能力位，并自实现一个通用 ACP 适配器作为兜底与第 6 家及以后的入口。凡「某一家 agent 跟别家怎么不一样」的都归它；登录态探测（三值、只跑 agent 自己的状态命令、结果缓存）与模型清单的四级来源合并（实时／配置／内置别名／历史）也归它——它们都是「这一家怎么问」的事
- 前置依赖：[[M4-T3]]、[[M1-T8]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：`claude --bg` + `agents --json` 的实测字段
- **产出**：`adapters/claude/` 四件套

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) `--bg` 与 `-p` **不同时使用**
后台会话经 `claude agents --json` 回读 `state`／`waitingFor`／`sessionId`
2) 子进程环境清掉 `ANTHROPIC_MODEL` 与 `ANTHROPIC_DEFAULT_*_MODEL`，并从首帧读回自报的实际模型，与所选不一致时标记（[[E-37]]）
3) 未知厂商事件按 [[E-202]] 丢弃并对 `runs.unmapped_event_count` 计数，绝不崩溃也绝不臆造 kind
4) 能力位声明可回话为真（`--input-format stream-json`）

    - 期望：适配器只依赖已验证的最小子集（`prompt` / `steer` / `abort` / `get_state` + `agent_settled` 事件）；未知事件类型一律忽略并计数，不因新增事件崩溃

## 实施沉淀

<!-- notes:begin -->
- **参数互斥防御**：Claude CLI 的 `--bg` 用于无交互守护运行，与交互式或管道模式的 `-p`／`--print` 存在底层机制冲突。适配器在参数组装阶段对 `isBackground` 状态进行互斥剔除，并在组装完成后执行双重检查，若两者同时存在立即抛出类型化 `E_VALIDATION`，阻止无效启动。
- **环境隔离与首帧对账**：Anthropic 官方 CLI 优先读取环境中的 `ANTHROPIC_MODEL` 与 `ANTHROPIC_DEFAULT_*_MODEL`，当其存在时会静默覆盖 `--model` 命令行参数（E-37）。因此子进程派发规格中必须同时使用静态黑名单与动态正则匹配将其剔除；同时流式映射器在解析到 `system/init` 等首帧时提取自报模型并与预选模型比对，不一致时在事件中显式标记 `modelMismatch` 供调度台高亮。
- **未映射事件与纯文本分流**：根据 08 节与 E-202 约束，非 JSON 的裸字符串属于常规标准输出（如版本头、告警文本），直接流经 raw 日志而不触发未映射事件计数；能正确反序列化为 JSON 但 `type` 无法识别的厂商事件则属于未知 RPC 扩展，一律丢弃且仅自增 `unmapped_event_count`，绝不虚构事件 kind。
<!-- notes:end -->
