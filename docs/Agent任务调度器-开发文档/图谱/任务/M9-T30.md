# M9-T30　文档级开始、暂停、继续与批次进度

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯、按窗口数呈现的任务流水线泳道与「会话已归档」历史行、顶栏两个流水线开关，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值、「能否收口」、泳道分配、阶段推进与会话归档都是 daemon 给的字段）；指派面板的分组模型下拉、登录态徽标与刷新按钮、参照条的「来源」段同样只呈现 daemon 下发的字段，不算取值链

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 导入后显示文档级开始按钮与默认 Agent/模型/思考强度设置
导入、切换文档、浏览批次均不调用 start
点击一次开始调用文档控制接口，不再要求逐批开始（[[E-360]]、[[E-365]]）
2) 开始/暂停/继续以及第 N/M 批、本批进度、窗口占用、完成状态均来自 daemon
按 shared 类型与 capability 显示动作
完成计数取 daemon 根据 membershipFingerprint 完成证据核对的结果
收口进度使用服务端 generationId 的当前集合计数，显示2轮有效自动收口/6次物理尝试额度，不拿全局历史编号算余量
已完成批次新增任务后显示未完成直到新收口有效
前端不计算调度顺序或伪造运行状态（[[E-362]]、[[E-363]]、[[E-369]]）
3) gates、分支进 HEAD、收口、失败和契约阻断显示具体原因及已有处理入口
未完成不得显示全部完成
已注册 Agent 临时不可用仍可接受合法开始/继续，显示 running 等待状态与 agent_unavailable、提供已有 Agent 刷新入口
不可静默替换或将合法等待当作未建计划的错误（[[E-364]]、[[E-365]]）
4) 默认思考强度按 EffortValue 序列化，保留合法vendor选项
控制请求携带本客户端观察的 expectedVersion，传输重试保持该值
版本冲突刷新并提示，不自动用新版本重发
请求处理中禁用重复点击
失败保留真实状态并显示错误，双端操作按服务端结果收敛
异步旧文档回包和保存回滚不得覆盖当前文档（[[E-361]]、[[E-367]]）
5) SSE 变化和重连快照刷新 execution
重启后显式显示已暂停/需要继续，刷新确认文档后才接受继续
断线期间不启用控制（[[E-368]]、[[E-369]]）
6) 默认指派只决定未派任务，局部任务草稿仍能覆盖
旧单批动作独立标注，不能冒充文档级开始
7) 1920×1080、1440×900 与390×844 检查布局、键盘和移动操作，保留主题/窗口设置/批次树/审批功能，UI 与 race 回归和 pnpm -w check 通过
与 M1-T12 共同给出真实浏览器证据（[[E-370]]）

## 必须处理的边界

- [[E-360]]　导入或切换文档意外启动
    - 触发：新导入、刷新、重绑定或页面切换
    - 期望：新导入保持 idle；这些操作不新增执行授权或直接建运行；已有 running 计划在来源不变时继续，来源变化则按 E-369 暂停；仅文档级开始授予执行权
- [[E-361]]　同文档控制并发与响应丢失
    - 触发：双端开始/暂停/继续、重复点击、响应丢失重试或 tick 并发
    - 期望：控制请求携带实际观察的 expectedVersion，状态更新前做版本比较；相同目标状态仅只读返回，过期请求不能撤销更新的暂停；版本冲突返回当前状态，客户端不自动换新版本重试；最多一份活动计划，不重复派任务或占窗口
- [[E-362]]　批次顺序与窗口、Agent 名额、路径冲突
    - 触发：同批任务超过窗口；多文档共用 Agent 或有效路径
    - 期望：只向当前批派实施任务；槽位空闲自动补位，Agent 名额与路径冲突仍全局生效；改变窗口不杀已有运行
- [[E-363]]　收口前越批或收口后缺少接力
    - 触发：当前批任务验收但未进 HEAD、未收口或收口 open；收口 clean/fixed
    - 期望：未 done 不启动下一批；当前批全部满足原收口契约达到 done 后，下一 tick 自动激活最早未完成批次，不要求用户逐批再点派发
- [[E-364]]　人工闸门或失败任务卡住自动推进
    - 触发：派发前、审查后、落地前闸门等待；收口手动或 needs_attention；任务失败
    - 期望：保留现有闸门与失败不自动重派；同批无依赖兄弟继续；下一批等待 done；DTO 与页面给出原因和处理入口
- [[E-365]]　后续批次无逐任务指派或默认 Agent 不可用
    - 触发：只配置一次文档默认指派；后续任务存在局部覆盖；指定 Agent 离线
    - 期望：任务草稿优先，其次文档默认，再读 Agent 配置；默认与草稿共用 effort: EffortValue，合法 vendor 原值经既有取值域校验并冻结，不丢成三档；无局部覆盖的后续批次直接沿用；未知 Agent ID/非法参数拒绝且不建计划；已注册 Agent 临时不可用时保存 running 等待计划与 agent_unavailable，不静默换家，观测恢复后自动补位，其他有效覆盖仍可派发
- [[E-367]]　暂停与异步派发检查竞态
    - 触发：用户暂停先提交，start/resume/tick 的异步预检后完成；暂停期间收口结束
    - 期望：提交前重读执行状态和 version；暂停后不新增自动运行或将 queued 转 starting；暂停前已接受的 starting/running 继续，结果照常保存；继续恢复待派阶段而不重跑原实施，下一批仍等待继续
- [[E-368]]　daemon 重启与终态任务重复运行
    - 触发：执行计划 running 时重启；任务已 failed、interrupted、orphaned 或 aborted
    - 期望：重启前意图与执行位置持久保留，job 启动前 running 转 paused，显示 daemon_restarted；继续只补未派任务，终态任务需显式重派
- [[E-369]]　执行中文档变更、不可读或契约待复核
    - 触发：任务 ID/contractHash 变化、源失效，或仅 readiness/reasons 更新
    - 期望：契约指纹变化或不可读暂停新自动派发，在途快照不变；已完成批次新增任务、移批、删任务或成员契约变化时，membershipFingerprint 与 completionFingerprint 不一致即作废旧完成证据；显式开始/继续经受控白名单 done→idle 重开受影响批次；确认成员变化才建立新 generationId，每代保留2轮有效自动收口/6次物理尝试上限，同源控制不清额度；新成员重新验收收口，保留已验收任务与历史；仅就绪元数据变化不暂停整份文档，就绪兄弟继续
- [[E-370]]　文档级执行只在测试替身里成立
    - 触发：实现控制接口与批次接力后验收
    - 期望：真实页面导入无运行，点击一次开始后经生产 bootstrap、工作树、收口和 SSE 连续运行；验证窗口、跨批、暂停/继续、重启、双端幂等、已完成批次新增任务不被跳过与实际 Agent 入口，缺证据不得宣称交付
