# M1-T4　日志正文追加写、字节偏移索引与切片

- 所属模块：[[M1]]　**运行底座**——让 daemon 在这台机器上稳定跑起来并把字节落到磁盘上：进程单实例与端口、启动自检、开机自启注册、数据目录、结构化存储的连接与迁移、日志正文的追加写与字节偏移索引、以及全部平台差异（进程树终止、路径规范化与长路径、配置目录、子进程编码）的唯一收口。凡与操作系统、磁盘、进程存活打交道而不带任何业务概念的都归它
- 前置依赖：[[M1-T2]]
- 完成后解锁：[[M1-T5]]、[[M6-T2]]、[[M6-T8]]

## 输入 / 产出

- **输入**：M1-T2 的库连接
- **产出**：`src/logstore/`：`AppendQueue` / 文件读写与恢复扫描 / 200MB 切片；`repo/events-index-repo.ts`、`repo/log-segments-repo.ts` 保存索引；`service/logstore.ts` 编排先文件后索引；`jobs/log-index-repair.ts` 的启动入口调用该 service，扫描与写库不放在 job 内

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 恒先 append 文件成功再写索引行，代码中不存在反序路径
2) 单次运行超 200MB 时按大小切片并在 `log_segments` 记边界（[[E-149]]）
3) 崩溃重启后从最后一条索引的 `byte_offset+byte_len` 扫到 EOF 补齐
「索引比文件多」记 `error` 而非静默修正（[[E-24]]）
4) 日志文件被手工删除时返回 `E_LOG_FILE_MISSING` 类型化结果而非抛异常（[[E-151]]）

## 必须处理的边界

- [[E-149]]　单次运行日志过大
    - 触发：超过 200MB
    - 期望：按大小切片并在索引表记录段边界，UI 按段拉取，不生成无法打开的巨型单文件
- [[E-151]]　日志文件被手工删除
    - 触发：用户清理了某次运行的日志
    - 期望：列表与元数据仍正常显示，日志区提示「日志文件已丢失」，页面不整体报错
- [[E-24]]　单任务日志膨胀
    - 触发：会话输出达到几十 MB
    - 期望：落盘归档并轮转，UI 只加载尾部与分页，内存不留全量

## 实施沉淀

<!-- notes:begin -->
- **分层（R5）**：logstore 只做文件与扫描（不 import repo）；repo 只做预编译 SQL（不 import logstore）；`service/logstore.ts` 组织两者并用 unitOfWork 写索引；job 只调 service。旧 `factory.ts` / `logstore.ts` 已删除，装配由容器层后续接线。
- **写序（R1）**：`appendEvent` 先把帧化字节（正文+LF 单次 append）写入文件，返回后再在 unitOfWork 里写段边界与索引行；索引写入失败被捕获为 `indexError` 返回值，不向调用方抛、不丢文件字节，repair 会补回。重建 writer 走 `resumeRunWriterState`（纯文件扫描），恢复到已有最大段号与文件长度，不会从 0 覆盖。
- **修复（R2）**：`repairRun` 以 lastIndexedFileSeq/lastIndexedEnd 为起点有界扫描；对已登记段用磁盘实长校验「索引比文件多」→ error 条目（E-24），缺失文件→E_LOG_FILE_MISSING 条目（E-151）；对未登记的磁盘尾段从 0 扫到 EOF。envelope 保留原 id/seq，非里程碑（如 `agent_message_chunk`）与残缺尾行不入库，第二次执行零插入（幂等）。
- **分页（R3）**：`readSegmentPage` 在游标到达段尾时推进到下一段 `byteStart`，不再出现 `0:3 → 0:3` 卡死；service 侧合并已登记段与磁盘活动尾段为段列表。段内分页按 chunk 限制切分，游标严格单调递增。
- **错误（R4）**：stat→read 之间删除文件的异步 ENOENT 从流 'error' 事件捕获并包装成 E_LOG_FILE_MISSING；EACCES/ENOSPC 等包装成 E_INTERNAL+cause；SQLITE_BUSY 经 unitOfWork 的 toDatabaseError 映射 E_DB_BUSY。均有专门测试。
- **信封（R6）**：正文行包含全部事件（全量原文，永不截断）；索引表只收里程碑，id/seq 取自 envelope 本身，`isMilestoneEventKind` 同时接入正常写与恢复扫描两条路径。
- **测试**：`logstore-integration.test.ts` 用真实临时文件 + 真实 SQLite（:memory: + 0001 迁移，关 FK 避免种入全图）验证文件→service→repo 顺序；单测覆盖游标推进、UTF-8 多字节跨块/跨页、重建 writer、ENOENT 竞态、EACCES、SQLITE_BUSY。本机 WSL 需用 g++-10 从源码重编 better-sqlite3（prebuild 需 GLIBC_2.33）。
