# M9-T17　流头部参照条与会话序号

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯、按窗口数呈现的任务流水线泳道与「会话已归档」历史行、顶栏两个流水线开关，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值、「能否收口」、泳道分配、阶段推进与会话归档都是 daemon 给的字段）；指派面板的分组模型下拉、登录态徽标与刷新按钮、参照条的「来源」段同样只呈现 daemon 下发的字段，不算取值链
- 前置依赖：[[M9-T9]]、[[M4-T6]]、[[M4-T7]]、[[M4-T14]]、[[M8-T9]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：M4-T6 的取值链；M4-T7 的两张映射表；M4-T14 的 `RunDto.effort`（`EffortValue`）；M8-T9 的 `RunDto.assignmentSource` / `followedTaskId`
- **产出**：`stream-head-meta.tsx`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 每条流头部之下**常驻**一条「模型 · 思考强度 · 权限档 · 来源」参照条（网格 `auto auto auto minmax(0,1fr)`，第四段可截断、前三段不截断），回答四问中的「它凭什么这么干」，**不可折叠**——要点开才看得到等于没答
第四段读 `RunDto.assignmentSource` / `followedTaskId`，文案「来源：任务指派／审查覆盖／收口设置（跟随 〈taskKey〉）」，`agent_default` 显示「来源：任务指派（agent 默认）」（括注可见），四值之外或缺失显示「来源：—」并把原始值放 title，`compact`／`narrow` 档用短文案
`RunDto.effort` 为 `{vendor}` 时第二段显示原串并 title「厂商原值，未映射到三档」
前端不读快照、不读设置推来源（[[E-347]]、[[E-357]]）
2) 思考强度不支持的 agent 显示「—」并在 title 说明原因，**不补默认档冒充**（[[E-254]]）
3) 自报值与所选不一致时**两者都显示**并转 `--needs`，模型与思考强度同规则（[[E-37]]、[[E-256]]）
4) 权限档为最高档时该段转 `--down` 且**持续显示**，不是一次性提示（[[E-136]] 的呈现侧）
5) 同一 agent 的多个并发会话在 monogram 右下角带**中性会话序号**角标，**序号不占色相**——它是身份的一部分不是状态（[[E-31]] 的呈现侧、决策 33）

## 必须处理的边界

- [[E-136]]　某 agent 被调到最高档
    - 触发：用户手动提权
    - 期望：该 agent 卡片与每次派发确认页持续显示醒目标记（非一次性 toast）；档位不随切换到「自动模式」而隐式变化
- [[E-254]]　agent 不支持思考强度
    - 触发：dsh 无对应参数；某些模型或某些 agent 版本也没有
    - 期望：该 agent 的思考强度置 NULL、**派发时不传任何相关参数**，UI 一律显示「—」并在 title 说明原因。**绝不补一个默认档冒充**——补了等于谎称控制生效（与 E-26「数据缺失显示—，不拿 0 冒充」同理）。不因不支持而禁用该 agent（与 E-35 对称）
- [[E-256]]　自报思考强度与所选不一致
    - 触发：agent 实际用的档位与派发时所选不同
    - 期望：与 `reported_model` 对称：**流头部持续高亮标出两者**（`高 → 实际 中`），不静默采信任何一边；该运行的收据里一并记录实际值
- [[E-31]]　同一 agent 并发多任务
    - 触发：一个 agent 被同时派多个任务
    - 期望：每任务独立 session 与独立工作区（grok 用自带 --worktree，其余用 git worktree 兜底），并设每 agent 并发上限
- [[E-347]]　同一任务各阶段的模型、思考强度或来源不一致
    - 触发：实施用任务指派、审查用 `reviewOverride`、查 bug 逐字实施；或某阶段 agent 自报值与所选不同
    - 期望：流头部参照条**逐阶段**显示「模型 · 思考强度 · 来源」，来源三值文案「任务指派」「审查覆盖」「收口设置（跟随 〈taskKey〉）」，`agent_default` 显示「来源：任务指派（agent 默认）」（决策 124）；自报不一致按 E-37／E-256 逐阶段高亮，不做跨阶段比对、不把阶段间的合法差异当不一致；前端不算取值链，只显示 `RunDto.assignmentSource` 与 `effort`
- [[E-357]]　参照条「来源」段的取值与缺失
    - 触发：参照条渲染每条运行的第三段；`assignmentSource` 为 `agent_default`、四值之外或缺失；被跟随任务未记录或已从文档删除；「N 分钟前探测」的时间推进
    - 期望：`RunDto.assignmentSource`（`runs.assignment_source`，NULL 读作 `task`）与 `followedTaskId`（service 从快照 `assignment_json` 联结取，不新增 `runs` 列）是唯一来源，前端不读快照不算取值链；`task` → 「来源：任务指派」、`review_override` → 「来源：审查覆盖」、`wrapup_settings` → 「来源：收口设置（跟随 〈taskKey〉）」，`followedTaskId` 为 null 时「（跟随任务未记录）」；`agent_default` → 「来源：任务指派（agent 默认）」括注可见、title 说明按 agent 当前生效默认运行，模型／强度为空时仍显示「—」；四值之外或缺失 → 「来源：—」并把原始值放 title，不报错不映射；后端只在模型与强度**都**回落时返回 `agent_default`，只回落一项返回 `task`，前端不自行对比推断半回落；被跟随任务 ID 不在当前文档 → 显示 ID 文本不做链接；`compact`／`narrow` 档用短文案「任务／审查／收口」并把长文案放 title，括注不省略允许换行；第四段可截断、前三段不截断；「N 分钟前探测」由 `hooks/use-minute-tick.ts` 的模块级 60 秒 tick 驱动（只碰本地时钟、无订阅者不起、不 import api），时钟回拨显示「刚刚」，超 24 小时灰显（决策 124、127、129）
- [[E-37]]　环境变量与命令行参数冲突
    - 触发：claude 的 `env.ANTHROPIC_MODEL` 等覆盖与 `--model` 同时存在
    - 期望：派发时在子进程环境里清掉这类变量，并从 NDJSON 首帧读回 agent 自报的实际模型，UI 显示「实际使用：X」，与所选不一致时高亮
