# M9-T17　流头部参照条与会话序号

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**
- 前置依赖：[[M9-T9]]、[[M4-T6]]、[[M4-T7]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：M4-T6 的取值链；M4-T7 的两张映射表
- **产出**：`stream-head-meta.tsx`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 每条流头部之下**常驻**一条「模型 · 思考强度 · 权限档」参照条，回答四问中的「它凭什么这么干」，**不可折叠**——要点开才看得到等于没答
2) 思考强度不支持的 agent 显示「—」并在 title 说明原因，**不补默认档冒充**（[[E-254]]）
3) 自报值与所选不一致时**两者都显示**并转 `--needs`，模型与思考强度同规则（[[E-37]]、[[E-256]]）
4) 权限档为最高档时该段转 `--down` 且**持续显示**，不是一次性提示（[[E-136]] 的呈现侧）
5) 同一 agent 的多个并发会话在 monogram 右下角带**中性会话序号**角标，**序号不占色相**——它是身份的一部分不是状态（[[E-31]] 的呈现侧、决策 33）

## 必须处理的边界

- [[E-136]]　某 agent 被调到最高档
    - 触发：用户手动提权
    - 期望：该 agent 卡片与每次派发确认页持续显示醒目标记（非一次性 toast）；档位不随切换到「自动模式」而隐式变化
- [[E-254]]　agent 不支持思考强度
    - 触发：dsh 无对应参数；某些模型或某些 agent 版本也没有
    - 期望：该 agent 的思考强度置 NULL、**派发时不传任何相关参数**，UI 一律显示「—」并在 title 说明原因。**绝不补一个默认档冒充**——补了等于谎称控制生效（与 E-26「数据缺失显示—，不拿 0 冒充」同理）。不因不支持而禁用该 agent（与 E-35 对称）
- [[E-256]]　自报思考强度与所选不一致
    - 触发：agent 实际用的档位与派发时所选不同
    - 期望：与 `reported_model` 对称：**流头部持续高亮标出两者**（`高 → 实际 中`），不静默采信任何一边；该运行的收据里一并记录实际值
- [[E-31]]　同一 agent 并发多任务
    - 触发：一个 agent 被同时派多个任务
    - 期望：每任务独立 session 与独立工作区（grok 用自带 --worktree，其余用 git worktree 兜底），并设每 agent 并发上限
- [[E-37]]　环境变量与命令行参数冲突
    - 触发：claude 的 `env.ANTHROPIC_MODEL` 等覆盖与 `--model` 同时存在
    - 期望：派发时在子进程环境里清掉这类变量，并从 NDJSON 首帧读回 agent 自报的实际模型，UI 显示「实际使用：X」，与所选不一致时高亮
