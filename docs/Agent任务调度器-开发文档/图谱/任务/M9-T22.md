# M9-T22　顶栏流水线开关与流水线设置页

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯、按窗口数呈现的任务流水线泳道与「会话已归档」历史行、顶栏两个流水线开关，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值、「能否收口」、泳道分配、阶段推进与会话归档都是 daemon 给的字段）；指派面板的分组模型下拉、登录态徽标与刷新按钮、参照条的「来源」段同样只呈现 daemon 下发的字段，不算取值链

- 完成后解锁：[[M9-T23]]

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 两个开关同一形态（二段、高 `--h-btn-sm`）放三个闸门右侧、1px 竖线隔开
`gate-toggles.tsx` 与 `pipeline-toggles.tsx` 都只 import `ui/segmented-toggle`、互不 import、不复制 markup，`check-forbidden` 机检
2) 受控无内部 state：值来自 `GET /settings/pipeline`，`value=null` 显示「—」并 disabled（[[E-26]]）
`onChange` 给出两值，容器用缓存里的 `reviewOverride` / `wrapupAssignment` 补齐后 `PATCH /settings/pipeline` **四键全量**（[[E-356]]），`pending` 期间 disabled、DOM 不翻转，状态等 `settings.pipeline_changed` 回流（[[E-157]]、[[E-318]]）
3) 「查 bug」切开与「收口」切手动各常驻一行说明，不弹 dialog（[[E-306]]、[[E-312]]）
4) `#/settings/pipeline` 是第八条路由、`lazy` 且与其他 settings 页同一 Suspense，页面只摆同一个容器（`layout='settings'`）并显示「当前值来自 daemon」
手机档顶栏不渲染这五个开关，只在设置页可切
5) `E_PIPELINE_STAGE_DISABLED` 按 `details.stage` 就地 inline notice，不 toast
6) `pipeline-toggles.test.tsx`、`routes.test.ts`、`check-forbidden.test.ts` 新增用例通过

## 必须处理的边界

- [[E-157]]　写操作与事件流打架
    - 触发：客户端发起「中止运行中的任务」
    - 期望：走 POST 接口，最终状态一律以回流事件为准，UI 不拿 POST 响应体直接改状态
- [[E-26]]　token 用量字段缺失
    - 触发：各家字段名/单位不一致或压根没有
    - 期望：缺失时显示「—」，不得拿 0 冒充
- [[E-306]]　查 bug 开关中途切换
    - 触发：`pipeline.bughunt` 在有任务在途时从 0 切 1 或从 1 切 0
    - 期望：只影响**尚未到达**查 bug 阶段的任务：审查 pass 那一刻读当前值决定是否派查 bug 运行；已在跑的查 bug 运行不杀、结果照常处理；阶段链只在任务实际进入该阶段时才出现「查 bug」节点，不画灰色「已跳过」节点；开关值存 `settings(key='pipeline')`，写成功发 `settings.pipeline_changed`
- [[E-312]]　收口模式为手动
    - 触发：`pipeline.wrapupMode='manual'` 且本批全部 landed 并进 HEAD
    - 期望：tick 第 2 步不调 `triggerWrapup`；批次留在 `running`（分支未全进 HEAD 时是 `awaiting_landing`），`canWrapup=true` 且标题追加「可收口」暖色；只有 `POST /batches/:id/wrapup` 能进 `wrapping`；下一批仍等本批 `done`（E-281）；切回自动后下一次 tick 立即按 E-283 自动派
- [[E-318]]　流水线设置存储缺行或损坏
    - 触发：`settings` 表无 key=pipeline 行，或 `value_json` 非法／含未知值
    - 期望：缺行返回内置默认 `{bughunt: 0, wrapupMode: 'auto'}` 不插行；非法回落默认并 warn，不退出、不覆盖坏值直到下一次 PATCH；PATCH 两字段整体写入，缺字段或值非法返回 `E_VALIDATION`；写成功发 `settings.pipeline_changed` 让另一端刷新
- [[E-356]]　pipeline 设置四键的写入与校验
    - 触发：`PATCH /settings/pipeline` 缺键、`reviewOverride.agentId` 不在注册表、dsh 配了 `effortTier`、旧库 `pipeline` 行只有两键
    - 期望：四键 `{bughunt, wrapupMode, reviewOverride, wrapupAssignment}` 整体写入，缺任一 `E_VALIDATION`（AJV `additionalProperties:false`、`required` 四项）；`reviewOverride`／`wrapupAssignment.agentId` 必须存在于注册表当前快照，否则 `E_VALIDATION`（`details.field` 用点路径），校验只查注册表快照不起探测子进程；`effortTier` 只收三档不收 vendor，该 agent `effortVendorMap` 为 null 时非 null → `E_VALIDATION`（reason `effort_unsupported`）；`modelName` 不做清单校验（等同 manual 来源，E-36）；缺行返回默认 `{bughunt:0, wrapupMode:'auto', reviewOverride:null, wrapupAssignment:{mode:'follow'}}` 不插行，旧行只有两键读侧补默认不改库，任一键形状非法整体回落默认并 warn（E-292 同法）；不需迁移（JSON 列）；写成功发 `settings.pipeline_changed{pipeline}`（完整四键）并 nudge tick；两项设置不进 `gates` 行、不进 `documents`，算出的结果进快照 `assignment_json`、设置本体不进；运行时再核一次 agent 存在与可用，不可用走各阶段既有转人路径

## 实施沉淀

<!-- notes:begin -->
1. **二段开关原语抽离与单向依赖**：
   - 为避免在 `gate-toggles` 和 `pipeline-toggles` 中重复维护二段按钮样式与状态绑定，在 `ui/segmented-toggle.tsx` 中实现了符合 07 节与 11 节 UI 规范的纯 UI 原语 `SegmentedToggle`。高度严格固定为 `--h-btn-sm`（26px），内部禁止出现任何业务词，当 `value=null` 时渲染占位符 `—` 并 disabled（E-26）。
   - `gate-toggles.tsx` 和 `pipeline-toggles.tsx` 均只从 `ui/segmented-toggle.tsx` 引入该组件，互不 import，由 `check-forbidden.ts` 的 Check 15 `TOGGLES_MUTUAL_IMPORT` 进行机械扫描保护（AC 1）。
2. **纯受控、四键全量 PATCH 与事件时序竞态防护（R2）**：
   - 流水线开关完全受控，无组件内部状态（E-157、E-318）。在点击切换时，`use-pipeline-settings` 读取内存缓存中的 `reviewOverride` 与 `wrapupAssignment`，与变更后的 `bughunt` / `wrapupMode` 合并为全量四键后发送 `PATCH /api/v1/settings/pipeline`（E-356）。
   - **防御迟到的 GET**：通过 `sourceVersionRef` 记录事件版本快照，当组件发起的 GET 请求延迟返回时，若期间已接收到较新的 `settings.pipeline_changed` 事件，则直接丢弃过时的 GET 响应，绝不覆盖新事件数据。
   - **防御多设备事件竞态提前解除 pending**：每次本地 PATCH 记录四键目标与当前设备 ID。其他设备事件仍更新服务端真实值，但只有匹配本次目标的本设备回流和 HTTP 成功均到达后才解除 pending；缺少设备 ID 的旧会话按完整四键目标匹配回流。一次只允许一个在途写入。
3. **顶栏布局与防溢出架构（R1）**：
   - 顶栏控制行固定 52px（`--h-topbar: 52px`）。两条常驻说明在顶栏下方的独立流式区域展示，随状态出现并推开后续页面；设置页仍在卡片内展示同样的说明，不弹 dialog。
   - 1280px 宽度时五个开关保持顶栏横排和竖向分隔线；600px 宽度时开关排在顶栏下方并以横线分组，页面不出现横向溢出；390px 移动档隐藏顶栏开关，仅在设置页切换。
