# M9-T21　任务流水线泳道与历史行

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯、按窗口数呈现的任务流水线泳道与「会话已归档」历史行、顶栏两个流水线开关，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值、「能否收口」、泳道分配、阶段推进与会话归档都是 daemon 给的字段）；指派面板的分组模型下拉、登录态徽标与刷新按钮、参照条的「来源」段同样只呈现 daemon 下发的字段，不算取值链

- 完成后解锁：[[M9-T22]]

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 泳道数与顺序只来自 `lanes[]`（按 `laneNo` 升序、不补洞），前端不算槽位、不算下一个任务、不推断阶段
`components/` / `features/` / `pages/` 出现阶段字面量比较即 `check-forbidden` 失败（[[E-317]]）
2) 阶段链每阶段一行 30px（触摸 44px），已过阶段折一行带总耗时、当前阶段展开步骤、未来阶段虚线且耗时列留空
紧凑档当前阶段只保留最后一行步骤，五档都不折、不换表示，260px 放不下按 [[E-166]] 加宽列宽（[[E-315]]）
3) 返工回环由 `LOOP_PIECES` 按行片段画在 20px 轨列内，`reworkCount=0` 不画
「第 N 轮」= `reworkCount+1` 只在 ≥1 时显示
查 bug 后再审的回环指向审查行且轮次沿用同一计数（[[E-307]] 的呈现侧）
`spine.tsx` 与 `stage-chain.tsx` 不测量 DOM
4) 「查 bug」行只在存在 `kind='bughunt'` 运行时出现、不画「已跳过」节点（[[E-306]] 的呈现侧）
「落地」行恒最后
5) 阶段行 Enter 或点击 → `onOpenRun(runId)` 打开该阶段最近一次运行详情
`readOnly` 或 `runId=null` 的行无 tabIndex（[[E-313]]）
6) 历史行只有一条、绑定 `archivedTaskIds[0]`（收口泳道用 `archivedWrapupRunId`），折叠六段固定顺序，展开渲染只读阶段链、零 `pulse-dot`、props 无任何动作 callback
泳道第一个任务不渲染历史行与分隔线（[[E-314]]、[[E-325]]）
7) 空闲泳道渲染 `idleText`（含 `nextBlockedBy`），不画假链，停止键置灰保持原位
`overLimit` 泳道头部 chip「超出窗口数」
停靠中（`awaiting_human`）的任务不在甲板上（[[E-309]]、[[E-319]]、[[E-326]]） 7b) 阶段顺序只来自 shared 的 `PIPELINE_STAGES`，`rework`／`queued` 落在实施行，未知 `stage` 显示「—」不抛错（[[E-332]]）
`lanes` 经 `api/lanes.ts` 从 `GET /snapshot` 取、丢弃其余键，快照缺 `lanes` 显示「泳道数据不可用」（[[E-333]]）
8) 停止键与审批槽位只在 `stream-column.tsx` 里、所有 `kind` / `densityTier` 分支之外渲染
`pipeline-lane.test.tsx` 与 `stream-column.test.tsx` 各一张 `5 档 × {running, idle, overLimit, wrapup}` 矩阵断言停止键存在（[[E-236]]、[[E-106]]）
9) 手机档一次一条泳道 + `lane-run-strip` ◀ ▶（各 ≥44×44，`laneCount<=1` 或到边界 disabled 不隐藏），当前泳道号存 `selection-store` 内存、不进 URL（[[E-324]]） 10) `lib/stage-rows.test.ts` 与 `lib/spine-shape.test.ts` 追加用例全部通过

## 必须处理的边界

- [[E-106]]　桌面端多流并置
    - 触发：同时 5 个以上运行流
    - 期望：多流并置（分栏或网格），每流各自带常驻停止控件；不做「一次只能看一个」的模态
- [[E-166]]　紧凑档宽度不够
    - 触发：260px 放不下「头部 + 运行轨 + 停止键 + 最后一行」
    - 期望：加宽紧凑档列宽，不许砍掉停止控件或把状态降级成纯色点（那会违反 E-110）
- [[E-236]]　某一档漏掉停止键
    - 触发：档位分支影响了控件存在性
    - 期望：停止控件与审批槽位**必须渲染在所有档位分支之外**；分支只允许影响布局与截断。**配一条按档位枚举逐档断言停止控件存在的单测，把 E-106 变成机检**
- [[E-306]]　查 bug 开关中途切换
    - 触发：`pipeline.bughunt` 在有任务在途时从 0 切 1 或从 1 切 0
    - 期望：只影响**尚未到达**查 bug 阶段的任务：审查 pass 那一刻读当前值决定是否派查 bug 运行；已在跑的查 bug 运行不杀、结果照常处理；阶段链只在任务实际进入该阶段时才出现「查 bug」节点，不画灰色「已跳过」节点；开关值存 `settings(key='pipeline')`，写成功发 `settings.pipeline_changed`
- [[E-307]]　查 bug 修了东西
    - 触发：查 bug 报告 FIXED 段非空且自审查 pass 以来工作区 diff 非空
    - 期望：`rework_count<2`：先 `+1`，再通知**该任务的同一审查会话**再审一轮（续接规则同 E-304），提示词头部「第 N 轮，只核查 bug 阶段的修改：〈FIXED 条目原文〉」；`rework_count` 已达 2：不派再审、不 +1，任务转 `awaiting_human`，闸门 comment 写 `bughunt_fixed_over_limit`，审批卡列 FIXED 条目与 diff 摘要；FIXED 非空且 NOT_FIXED 含 S1/S2：直接转人、不先再审；运行轨上画成查 bug 节点回到审查节点的回环，轮次沿用同一 `rework_count`；不派第二个审查会话、不跳过再审直接落地
- [[E-309]]　窗口数调小
    - 触发：用户把并行窗口数从 N 调到 M＜N，而在跑的流水线数 ＞M
    - 期望：不杀任何在跑流水线，只停止补位；`lanes` 仍按实际占用返回并标 `overLimit`，空出的泳道不再补，直到占用 ≤M；调整立即生效、不需重启批次；被移除的空泳道其历史行随之消失、不迁移
- [[E-313]]　点击阶段节点
    - 触发：用户点泳道阶段链上的任一阶段节点（含历史行展开后的节点）
    - 期望：打开该阶段对应运行的详情 `#/run/〈runId〉`，不是任务详情；一个阶段有多次运行（E-112 恢复产生的新运行）时打开最近一次，更早的在运行详情里展开（E-27）；返工回环节点打开对应轮次的审查运行；`runId` 来自 daemon 的 `lanes[]` 与该任务的运行列表，前端不推算
- [[E-314]]　历史行只读
    - 触发：用户展开泳道里「会话已归档」的上一任务历史行
    - 期望：只展示阶段链、各阶段耗时与轮次（同一阶段链组件，无脉冲）；回话输入框、停止、重跑动作全部不渲染（不是置灰）；点阶段节点仍可打开该运行详情（E-313）；归档会话的原始文件按 E-96／E-97 只读引用，正文被清理后行仍显示、详情页给「正文已不可用」占位
- [[E-315]]　紧凑档的阶段链
    - 触发：流数 ≥4 进入紧凑档，泳道宽 260px
    - 期望：**不折、不换表示**：同一条竖直运行轨与同一批阶段节点，每阶段一行 30px（网格沿用运行流条目 `20px minmax(0,1fr) auto 16px`），标签「实施」「审查 · 第 N 轮」「查 bug」「落地」13px、右列阶段耗时等宽 12px；已过阶段折成一行带总耗时，当前阶段行下只保留它的最后一行步骤，未来阶段虚线轨段且耗时列留空；返工回环画在 20px 轨列内、轮次以文字写在审查节点行，`rework_count=0` 不画回环；不做悬停展开态、不退化为图标、不去掉耗时或文字；260px 放不下按 E-166 加宽列宽；按 E-165 展开某条时该泳道各阶段内步骤全部展开、其余仍 260px 只显示阶段行
- [[E-317]]　泳道分配的算法归属
    - 触发：前端拿到快照与事件要画泳道
    - 期望：`lanes[]` 由 daemon 的纯函数算出，随 `GET /snapshot` 与 `lane.assigned`／`lane.released` 事件下发；前端只按 `laneNo` 排列，不算槽位、不算下一个任务、不推断阶段；字段缺失显示「—」
- [[E-319]]　空闲泳道
    - 触发：泳道无任务
    - 期望：显示「空闲 · 队列下一个是 〈ID〉（等 〈前置〉 落地）」，〈ID〉与前置来自 daemon 的 `nextTaskId` 与其未落地前置；无任何未派任务时显示「空闲 · 本批已全部派出」；不画假的阶段链；手机档运行条写「泳道 k/N · 空闲」，拇指栏停止键置灰但保持原位
- [[E-324]]　手机端的泳道
    - 触发：手机档（phone／phone-xs）打开运行甲板且窗口数 N＞1
    - 期望：不并排、不横向滚动（E-145）：沿用单栏切换，一次只看一条泳道；顶部 44px 运行条「泳道 k/N · 〈taskKey〉 · 状态字形+文字」两端各一个 ≥44×44 的 ◀ ▶ 切换按钮，N=1 时禁用不隐藏；非当前泳道转「等你」计入全局未处理徽标，点徽标打开既有运行列表抽屉、每行一条泳道；当前泳道补位时跟随新任务、不跳去别的泳道；窗口数调小后 N 显示现存泳道数，泳道消失后落到 min(k, N′)；当前泳道号存 `selection-store` 内存，不进 URL、不持久化；收口运行占的泳道同样单流显示，不出「收口」按钮
- [[E-325]]　历史行的数量与替换
    - 触发：泳道先后跑过多个任务
    - 期望：只保留最近一条：新任务补位时替换为刚结束的任务，被挤出的任务去批次树／任务列表／运行详情看（E-27）；泳道第一个任务不渲染历史行、不放占位、不出分隔线；历史行绑定在本泳道跑过的那组已归档运行（按 run id）而不绑任务，同一任务重派到别的泳道时本泳道历史行仍显示归档流水线自己的终态、不出现两处呼吸；折叠一行的内容固定为 `taskKey · 标题截断 · 终态徽标（字形+文字）· 第 N 轮（N≥2 才显示）· 总耗时 · 「会话已归档」chip`；收口运行占过的泳道历史行显示「批次收口 · 第 N 轮 · 第 M 批」+ 收口裁定徽标；daemon 重启／页面刷新后历史行来自快照，不由前端内存推算
- [[E-326]]　任务停在人工闸门期间的泳道与会话
    - 触发：运行以任何原因进入 `awaiting_human`（pass 等确认、E-55 超限、审查未完成、doc-issue、查 bug 转人等），或 daemon 重启后成为 `orphaned`
    - 期望：同一事务里 `tasks.lane_no` 置 NULL、发 `lane.released{reason:'awaiting_human'}`，下一 tick 补位；该任务全部运行**不写 `session_archived_at`、不 killTree**，进程自然退出只留 `vendor_session_ref` 供恢复；路径锁仍按 E-46 到 landed 才释放；`awaiting_reply` 不释放泳道、继续占额度；人放行→landed 或人判失败→failed 才按 E-302 归档，此时不再发 `lane.released`；等待不过期、不自动放行（E-58），daemon 重启不改其状态；停靠中的任务不在甲板上，入口只有批次树「等你」行、全局未处理徽标与任务／运行详情里的审批卡
- [[E-332]]　阶段顺序与未知阶段
    - 触发：前端要画未来阶段的虚线行；或 daemon 下发的 `stage` 不在已知集合内
    - 期望：阶段链顺序来自 shared 的 `PIPELINE_STAGES = ['implement','review','bughunt','landing']`（`lib/` 只 `import type`，值由容器作 `stageOrder` 传入）；`stage='rework'`／`queued` 落在实施行（标签「返工实施 · 第 N 轮」／「排队」），不是独立行；未来行 = 顺序表里当前阶段之后的项去掉 `bughunt`（只在该任务出现 `kind='bughunt'` 运行后插入，开关开着也不预画）；`landing` 恒最后一行；`stage` 不在 `LANE_STAGES` 内 → 当前行标签显示「—」、未来行不画、不抛错；daemon 侧 arch 测试断言 `deriveLanes()` 可能产出的阶段集合与 shared `LANE_STAGES` 逐项相等，加阶段必须同 PR 改两处
- [[E-333]]　泳道数据的取数与缓存
    - 触发：前端拉 `lanes[]` 或收到泳道事件
    - 期望：`api/lanes.ts` 调既有 `GET /snapshot?docId` 只取 `.lanes`，`latestEventId` 与其余键一律丢弃、不写 `connection-store.lastEventId`；快照缺 `lanes` 键或不是数组 → 运行甲板显示「泳道数据不可用」并按 E-26 不自算槽位，不回退到按运行分流的旧布局；同一 tick 内连续到达 `lane.released` 与 `lane.assigned` → `resource-cache` 对同一 key 的在途请求合并只发一次，失效发生在请求已发出之后则响应到达后必须再拉一次；`lane.assigned` 同时失效 `lanes` 与 `runs` 时两个 fetcher 各自请求，不从快照里取 `runs`

## 实施沉淀

<!-- notes:begin -->
1. 阶段字面量比较解耦（E-317, E-332）：
   为满足展示层禁止出现阶段字面量比较的架构约束，所有阶段判定、规范化（如 rework/queued 归属 implement）、标签派生及未知阶段兜底全量收敛在 `lib/stage-rows.ts` 纯函数内。`components/` 与 `features/` 仅消费 `deriveStageRows` 生成的行模型或 `getLaneKind` 分类，杜绝在 React 组件内散落 `'implement'` / `'review'` 字符串判断。
2. 零 DOM 测量的回环渲染（E-307, AC 3）：
   返工回环不使用跨行绝对定位或 DOM 尺寸计算，而是由 `lib/spine-shape.ts` 的 `LOOP_PIECES` 常量按行拆分为 `top`（hook+below）、`middle`（above+below）、`bottom`（hook+above）三个离散片段，在运行轨左侧固定坐标（x=4.5）拼接连贯回路。查 bug 阶段触发返工时，回环直接从查 bug 行 hook 连回审查行，并复用同一 `reworkCount`。
3. 泳道请求合并与失效防抖（E-333）：
   `api/lanes.ts` 在同一 tick 内到达连续泳道事件时，合并共享同一个 Promise；若在请求在途期间收到失效标记，则在当前响应到达后自动发起第二次拉取，保证最终一致性。解析快照时严格只读取 `.lanes` 键，未提供或非数组时显式抛错呈现「泳道数据不可用」，绝不在前端自算槽位。
4. StreamColumn 架构扫描断言（E-236, E-106）：
   既有单测要求 `data-action="stop-stream"` 之后禁止出现任何 `kind ===` 或 `tier ===` 源码字面量，因此 `StreamColumn` 内部将空闲占位与默认阶段占位收敛为对 `Boolean(idleText)` 的纯插槽判断，保证停止键、参照条、主内容区与审批槽位在源码结构上彻底脱离分支条件。
5. 真实甲板入口与归档运行（R1、R2）：
   `RunDeckContainer` 从快照和独立运行接口取数据，使用 `fetchLanes` 消费 daemon 的泳道字段；`RunDeckView` 将这些字段连同收口报告插槽交给 `LanesContainer`。历史行按归档任务、运行的泳道号和归档收口运行 ID 选择运行；收口裁定与轮次取批次收口记录，不用运行的审查裁定或尝试次数代替。
6. 手机与空闲泳道（R3）：
   甲板手机导航使用 daemon 返回的实际泳道列表，当前 `laneNo` 存在 `selection-store` 内存中；泳道消失时收敛到仍存在的位置。空闲泳道有历史行时仍显示 `nextTaskId` 与 `nextBlockedBy` 形成的提示。
7. 真实模型轮次的派发接线（R1）：
   在隔离仓库用正式 HTTP 服务和实际 Codex 进程验收时，修复实施与审查两条路径对可执行文件的遗漏。实施派发时把注册表路径冻结到运行快照，启动时只读快照；Codex 使用携带冻结提示词的 `exec --json`，关闭标准输入，避免 CLI 等待额外输入而停在「思考中」。审查新会话从当轮指派读取配置。回归覆盖快照路径、审查启动规格和进程标准输入。
