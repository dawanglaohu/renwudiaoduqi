2) 集成测试（真容器 + 假子进程）：假实施进程退出码 0 后 `evaluateMechanicalCheck` 被调一次、`kind=review` 运行行被 INSERT、`task.review_verdict` 发出

3) `reconcile-runs` 启动期把库里预置的 `running` 且 pid 不存在的行标 `interrupted`，pid 存在的标「失联」，不推定成功（[[E-123]]）

4) `disk-watch` 超阈值置「停止新派发」后 `POST /runs` 返回错误信封且已有运行继续

5) route 与 job 复用同一批 service 方法：arch 测试断言 `jobs/` 下无 `repo/` import，`http/routes/gates.ts` 与 tick 拿到的是同一个 `gateService` 实例（08 节隔离规则）

## 必须处理的边界

- [[E-104]]　存储盘写满
    - 触发：追加写失败
    - 期望：立即停止新派发并明确报错；恢复后要能继续追加，已有记录不得损坏
- [[E-120]]　长思考被误判停滞
    - 触发：超过阈值但 NDJSON 仍在输出
    - 期望：只标「疑似停滞」的弱提示，不改运行状态；只有完全无流事件超阈值才升级为醒目告警
- [[E-123]]　daemon 重启后的孤儿记录
    - 触发：重启后仍有状态为「运行中」的记录
    - 期望：启动时按 PID 对账，进程不存在则标「异常终止（daemon 重启）」，绝不推定成功
- [[E-53]]　落地闸门可设自动
    - 触发：三个闸门各自可设「自动」或「等我确认」
    - 期望：落地闸门默认「等我确认」，可切到「自动」：自动只表示审查 pass 后直接进 `landed`（已验收），产品仍不执行任何 git 操作（决策 12）；UI 三个开关同一形态、第三个不再置灰，切到自动时行内常驻一句说明而不弹确认框
- [[E-57]]　两端同时点确认
    - 触发：手机与桌面同时对同一闸门确认
    - 期望：幂等，第二次提示「已由另一端确认」，不产生两次派发

## 实施沉淀

<!-- notes:begin -->
1. 真实审查材料绑定与缺失转人工（R1）：彻底废除 `createFallbackReviewContext` 假快照、固定 `'codex'` 指派和 `'+change\n'` 假 diff。审查前按实施 `run.snapshot_id` 读取真实派发快照、真实指派与工作区 `diffStat`/`diffText`；任意材料缺失立即类型化转入 `awaiting_human` 并沉淀 `snapshot_missing`/`diff_missing`/`assignment_missing` 闸门，绝不带假数据派发。
2. 审查输出写入落盘保障（R2）：`attachProcess` 建立 `pendingWrites` 跟踪所有原始行与事件的异步追加 promise。进程退出时显式等待输出写入全部落盘后，再执行退出事件入库、关闭 logstore writer，最后调用 `finalizeReview` 回读 logstore 与评定裁决，规避异步流与文件落盘时序差导致的评定截断或未完成错误。
3. 审查派发异常全链路可恢复性（R3）：`dispatchReviewRun` 插入审查运行后立即通过 `onRunInserted` 返回该行 ID。若进程启动失败，service 层只处理本次已插入的审查运行，在 `unitOfWork.run` 事务内将其落到 `failed`、实施运行转入 `awaiting_human`、释放 task lane 并幂等生成 waiting 闸门；事务完成后创建并广播事件。错误详情写入双方运行的 `queued_reason` 与闸门 `comment`。`evaluateMechanicalCheck` 对终态与 `awaiting_human` 提前返回，重复触发不产生残留运行或重复闸门。
4. 自动与人工落地状态收口完备与幂等（R4）：`gateService` 接入 `sessionArchiveService`。无论人工在落地闸门 `decideGate('pass')` 还是配置 `landing: 'auto'` 时经 `resolveAfterReviewAndApply` 自动放行，均在事务内完成 `archiveTaskInTx` 批次标记与 `tasks.lane_no` 槽位释放，事务后触发 `terminateArchived` 进程终结与 `task.sessions_archived`、`task.landed`、`lane.released` 终态事件广播。自动路径仅在任务已记录落地时短路；运行行已是 landed、任务仍未记录时继续补齐落地闸门和任务状态，重复决断不再派发。
5. 组合根依赖解耦与后台任务全集边界：`reviewService`、`gateService` 与 `runService` 间通过 holder 闭包引用规避循环构造；容器 jobs 严格收拢为规范规定的五个任务。`reconcile-runs` 启动按 PID 对账，进程消失标 `interrupted`、存在标 `orphaned`，绝不推定成功；`stall-detector` 超时只发弱告警不杀进程；`disk-watch` 触发停止派发标志后直接在 HTTP 层返回 507 错误信封。
