# M7-T9　审查、闸门与五个 job 接进容器

- 所属模块：[[M7]]　**审查流水线**——对已结束的运行做「合不合格」的判定：先跑本地机械检查，通过后以只读档派一个 agent 跑文档给出的审查提示词，产出 pass / rework / doc-issue 并回灌 rework 意见；从审查输出提取返工文本、按能力位选回灌／恢复／新开返工运行，以及解析收口运行的八段报告，也归它；第 N+1 轮审查续接同一审查会话、查 bug 阶段的运行与五段报告解析同样归它。凡「判定一次运行的结果」的都归它；审查、查 bug 阶段的运行用哪个 agent、模型与思考强度，一律读派发快照里的任务指派（审查可被 pipeline 设置的「审查覆盖」替换），不自己取 agent 默认
- 前置依赖：[[M1-T4]]、[[M1-T5]]、[[M1-T6]]、[[M6-T2]]、[[M6-T4]]、[[M7-T2]]、[[M7-T3]]、[[M7-T4]]、[[M7-T6]]、[[M8-T4]]、[[M8-T6]]
- 完成后解锁：[[M1-T11]]

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) `createContainer()` 返回的 `services.review` 与 `services.gates` 非空，`jobs.map` 出的名字恰为 `reconcile-runs`、`log-index-repair`、`stall-detector`、`scheduler-tick`、`disk-watch` 五个且顺序固定（arch 测试逐字断言，08 节「只有五个」）
`main.ts` 在 `listen()` 后启动并打印五行 `job started`（[[E-123]]）
2) 集成测试（真容器 + 假子进程）：假实施进程退出码 0 后 `evaluateMechanicalCheck` 被调一次、`kind=review` 运行行被 INSERT、`task.review_verdict` 发出
假审查进程吐 `VERDICT: pass` 后出现 `waiting` 闸门行，`GET /api/v1/gates?pending` 返回它，`POST /api/v1/gates/:gateId/decide` 传 `pass` 后实施运行迁 `landed` 并发 `task.landed` 带 `by:human`（[[E-53]]、[[E-57]]）
3) `reconcile-runs` 启动期把库里预置的 `running` 且 pid 不存在的行标 `interrupted`，pid 存在的标「失联」，不推定成功（[[E-123]]）
`stall-detector` 对 `last_event_at` 超阈值的行只发 `run.stalled_suspected`、状态不变、进程不杀（[[E-120]]）
4) `disk-watch` 超阈值置「停止新派发」后 `POST /runs` 返回错误信封且已有运行继续
`log-index-repair` 启动期跑一次即 `stop()`（[[E-104]]）
5) route 与 job 复用同一批 service 方法：arch 测试断言 `jobs/` 下无 `repo/` import，`http/routes/gates.ts` 与 tick 拿到的是同一个 `gateService` 实例（08 节隔离规则）

## 必须处理的边界

- [[E-104]]　存储盘写满
    - 触发：追加写失败
    - 期望：立即停止新派发并明确报错；恢复后要能继续追加，已有记录不得损坏
- [[E-120]]　长思考被误判停滞
    - 触发：超过阈值但 NDJSON 仍在输出
    - 期望：只标「疑似停滞」的弱提示，不改运行状态；只有完全无流事件超阈值才升级为醒目告警
- [[E-123]]　daemon 重启后的孤儿记录
    - 触发：重启后仍有状态为「运行中」的记录
    - 期望：启动时按 PID 对账，进程不存在则标「异常终止（daemon 重启）」，绝不推定成功
- [[E-53]]　落地闸门可设自动
    - 触发：三个闸门各自可设「自动」或「等我确认」
    - 期望：落地闸门默认「等我确认」，可切到「自动」：自动只表示审查 pass 后直接进 `landed`（已验收），产品仍不执行任何 git 操作（决策 12）；UI 三个开关同一形态、第三个不再置灰，切到自动时行内常驻一句说明而不弹确认框
- [[E-57]]　两端同时点确认
    - 触发：手机与桌面同时对同一闸门确认
    - 期望：幂等，第二次提示「已由另一端确认」，不产生两次派发
