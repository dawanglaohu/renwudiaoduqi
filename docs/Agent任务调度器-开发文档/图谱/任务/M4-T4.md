# M4-T4　可用性探测与不可用态

- 所属模块：[[M4]]　**Agent 适配**——把形态各异的 agent 抽象成同一个可派发对象：注册表（含每个 agent 通用的版本指纹探测字段与具名的「适配器种类」枚举）、可执行探测、模型清单读取与降级、启动参数与三档权限映射、以各家原生通道为主干把输出归一化成 ACP `session/update` 词汇的事件、可回话与**是否提供流式事件**等能力位，并自实现一个通用 ACP 适配器作为兜底与第 6 家及以后的入口。凡「某一家 agent 跟别家怎么不一样」的都归它
- 前置依赖：[[M4-T3]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：M4-T3
- **产出**：启动期探测、`agent.availability_changed` 事件、`http/routes/agents.ts`（列表 / PATCH / probe / models 四个端点）

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) agent 未安装或不在 PATH 时启动期即标「未检测到」并在 UI 置灰、写明缺什么，**不等到派发那一刻才失败**（[[E-29]]、[[E-40]]）
2) 可执行路径不存在或不可执行时标「不可用（路径无效）」并从派发目标移除，不阻塞其他 agent，点击可跳到该项配置（[[E-88]]）
3) `pi` 指向了别的可执行文件时由同一套指纹探测发现不匹配并提示手填，绝不按错误参数静默派发（[[E-201]]）

## 必须处理的边界

- [[E-201]]　pi 指向了别的可执行
    - 触发：PATH 上的 `pi` 换了
    - 期望：由同一套指纹探测发现不匹配，标不可用并提示手填路径，绝不按错误参数静默派发
- [[E-29]]　agent 没装或版本过老
    - 触发：不在 PATH，或版本没有 --output-format
    - 期望：启动时探测并在 UI 置灰该 agent 且写明缺什么，不得等到派发那一刻才失败
- [[E-40]]　agent 未安装或不在 PATH
    - 触发：探测不到可执行文件
    - 期望：该 agent 标「未检测到」，不列清单且不可被选为派发目标；已指向它的任务在派发前就报错，而不是跑到一半失败
- [[E-88]]　可执行路径无效
    - 触发：配置里的路径不存在或不可执行
    - 期望：该 agent 标「不可用（路径无效）」，从派发目标下拉中移除，不阻塞其他 agent；点击可直接跳到该项配置
