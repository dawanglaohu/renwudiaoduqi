# M4-T4　可用性探测与不可用态

- 所属模块：[[M4]]　**Agent 适配**——把形态各异的 agent 抽象成同一个可派发对象：注册表（含每个 agent 通用的版本指纹探测字段与具名的「适配器种类」枚举）、可执行探测、模型清单读取与降级、启动参数与三档权限映射、以各家原生通道为主干把输出归一化成 ACP `session/update` 词汇的事件、可回话与**是否提供流式事件**等能力位，并自实现一个通用 ACP 适配器作为兜底与第 6 家及以后的入口。凡「某一家 agent 跟别家怎么不一样」的都归它
- 前置依赖：[[M4-T3]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：M4-T3
- **产出**：启动期探测、`agent.availability_changed` 事件、`http/routes/agents.ts`（列表 / PATCH / probe / models 四个端点）

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) agent 未安装或不在平台可见候选目录时启动期即标「未检测到」并在 UI 置灰、写明缺什么，**不等到派发那一刻才失败**（[[E-29]]、[[E-40]]）
2) 可执行路径不存在、POSIX 无执行位、链接目标无效时显示对应类型化原因并从派发目标移除，不阻塞其他 agent，点击可跳到该项配置（[[E-88]]、[[E-262]]、[[E-263]]）
3) `pi` 指向了别的可执行文件时由同一套指纹探测发现不匹配并提示手填，绝不按错误参数静默派发（[[E-201]]）

## 必须处理的边界

- [[E-201]]　pi 指向了别的可执行
    - 触发：PATH 上的 `pi` 换了
    - 期望：由同一套指纹探测发现不匹配，标不可用并提示手填路径，绝不按错误参数静默派发
- [[E-262]]　POSIX 可执行文件没有执行权限
    - 触发：macOS/Linux 目标存在但 `X_OK` 校验失败
    - 期望：启动前返回 `E_AGENT_EXEC_NOT_EXECUTABLE` 并包含路径；不得自动 `chmod`，不得转交 shell 猜测执行方式
- [[E-263]]　符号链接目标无效
    - 触发：macOS/Linux 可执行路径经符号链接后不存在、成环或不是普通文件
    - 期望：返回 `E_AGENT_EXEC_INVALID_TARGET`，报告原始路径与解析目标；不缓存失败结果，不回退到同名 PATH 候选
- [[E-29]]　agent 没装或版本过老
    - 触发：不在 PATH，或版本没有 --output-format
    - 期望：启动时探测并在 UI 置灰该 agent 且写明缺什么，不得等到派发那一刻才失败
- [[E-40]]　agent 未安装或不在 PATH
    - 触发：探测不到可执行文件
    - 期望：该 agent 标「未检测到」，不列清单且不可被选为派发目标；已指向它的任务在派发前就报错，而不是跑到一半失败
- [[E-88]]　可执行路径无效
    - 触发：配置里的路径不存在或不可执行
    - 期望：该 agent 标「不可用（路径无效）」，从派发目标下拉中移除，不阻塞其他 agent；点击可直接跳到该项配置

## 实施沉淀

<!-- notes:begin -->
1. 启动期探测与可用性状态隔离：每个 agent 在服务启动（`probeAll`）时并行探测其可用性，通过 `Promise.allSettled` 与独立 try/catch 隔离各 agent 异常，单个 agent 路径无效、缺失或无执行权限绝不阻塞其他 agent 的正常探测（E-88）。
2. 类型化不可用原因与缺失项透传：探测失败时严格依据底层返回的错误码（如 `E_AGENT_EXEC_NOT_FOUND`、`E_AGENT_EXEC_NOT_EXECUTABLE`、`E_AGENT_EXEC_INVALID_TARGET`、`E_AGENT_VERSION_UNRECOGNIZED`）设置状态，并在 DTO 中提供 `missingRequirements` 与 `unavailableReason`，UI 据此将不可用 agent 置灰并写明原因（E-29、E-40、E-262、E-263）。
3. 派发前硬闸门而非中途失败：通过 `assertCanDispatch` 在任务派发阶段执行前置校验，针对未就绪、可执行文件缺失或指纹不匹配（如 `pi` 被替换为别的程序）直接抛出类型化 `AppError`，严禁按错误参数静默派发（E-40、E-201）。
4. 符号链接与无效目标不缓存：符号链接损坏或无效目标返回 `E_AGENT_EXEC_INVALID_TARGET` 且不缓存失败结果，不回退到同名 PATH 候选，保障后续修复后即时恢复（E-263）。
5. 状态变更事件流式广播：仅在 agent 可用性发生实质变更（首次初始化或状态翻转）时通过 `EventBus` 发布 `agent.availability_changed` 事件，避免高频无意义广播。
6. 可用性结论的失效依据是配置代次而不是时间：每个探测状态记住当时的注册表 generation，`listAgents`、`getAgent`、`assertCanDispatch` 发现代次落后就强制重探，热加载也主动触发一次全量重探；配置被改成坏路径后不会拿着旧结论放行派发（E-88、E-93）。
7. `agents.json` 的读写收归 `config/registry.ts`：服务只提交字段覆盖，注册表合并后先校验再落盘；磁盘上不可解析或字段非法时拒绝写入并保留原文，reload 被判退时以 `E_VALIDATION` 上报，不把旧值当成功返回（E-88、E-93）。
8. 符号链接按 `lstat` + `readlink` 判定链接本身，`realpath` 失败即链接目标无效，原始路径与解析目标一并进 DTO 供 UI 展示（E-263）。
