# M4-T5　四家模型清单读取与降级

- 所属模块：[[M4]]　**Agent 适配**——把形态各异的 agent 抽象成同一个可派发对象：注册表（含每个 agent 通用的版本指纹探测字段与具名的「适配器种类」枚举）、可执行探测、模型清单读取与降级、启动参数与三档权限映射、以各家原生通道为主干把输出归一化成 ACP `session/update` 词汇的事件、可回话与**是否提供流式事件**等能力位，并自实现一个通用 ACP 适配器作为兜底与第 6 家及以后的入口。凡「某一家 agent 跟别家怎么不一样」的都归它
- 前置依赖：[[M4-T1]]
- 完成后解锁：[[M4-T6]]、[[M9-T14]]

## 输入 / 产出

- **输入**：04 节实测的四种配置格式
- **产出**：`readModels()` 四个具名解析器

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) codex TOML／claude JSON／grok TOML／pi models.json 四种格式各自读出清单
2) 列模型命令超 5 秒或退出码非 0 时降级为「配置文件当前值 + 历史用过 + 手填」并标「清单可能不全」，**绝不阻塞派发**（[[E-38]]）
3) 输出格式变化解析不了时同样降级，且原始 stdout 保留在可展开日志里不静默吞掉（[[E-39]]、[[E-90]]）
4) 配置文件缺失或语法损坏时视为「无配置值」不崩溃，提示解析失败并给出文件绝对路径（[[E-43]]）
5) 每次打开设置页按文件 mtime 重读，不长期缓存（[[E-44]]）

## 必须处理的边界

- [[E-38]]　列模型命令超时或失败
    - 触发：`grok models` / `pi --models` 超过 5 秒或退出码非 0
    - 期望：清单降级为「配置文件当前值 + 该 agent 历史用过的模型 + 手填」，UI 标注「清单可能不全」，绝不阻塞派发
- [[E-39]]　列模型输出格式变化
    - 触发：厂商改了输出格式，解析不了
    - 期望：同 E-38 降级，且把原始 stdout 保留在可展开日志里，不静默吞掉
- [[E-43]]　配置文件缺失或损坏
    - 触发：TOML/JSON 语法错误，或文件不存在
    - 期望：视为「无配置值」，不崩溃；UI 提示解析失败并给出文件绝对路径
- [[E-44]]　用户在别处切换了模型
    - 触发：外部修改了 agent 配置文件后回到设置页
    - 期望：每次打开设置页按文件 mtime 重读，不长期缓存
- [[E-90]]　模型解析器失效
    - 触发：某家改了 models.json 结构
    - 期望：模型选择器降级为手动输入，同时保留上次成功解析的缓存清单，绝不因此禁止派发

## 实施沉淀

<!-- notes:begin -->
- **宿主快照与异步文件系统接入 (R3)**：适配器层彻底剥离直接 `node:os` 和同步 `fs` API，全部改为由外部/容器注入 `hostInputs` 宿主快照（获取真实 homedir 及平台类型）以及可替换的 `ModelReaderFileSystem`（默认采用 `node:fs/promises` 异步操作）。通过 `source-contracts.test.ts` 源码架构断言锁死该约束。
- **严格语法解析与错误暴露 (R1)**：TOML 解析器显式拒绝 `model = ???` 等无引号非法裸值（抛出 `SyntaxError`），确保非法值绝不被误当作模型名；同时 Pi 在解析 `settings.json`、`models.json`、`models-store.json` 时坚决不空吞解析异常，任一损坏均将错误及其绝对路径暴露于 `configError`/`configErrors`（E-43）。
- **进程启动收敛与不可放大超时 (R2)**：列模型命令不再执行裸命令字符串，必须经由 `platform.resolveExecutable` 校验为平台绝对启动对象后传参执行；生产超时硬上限严格锁死在 `5000ms`（`Math.min(timeout, 5000)`，任何入参不得放大）；利用 `AbortController` 绑定底层操作生命周期实现超时收敛与终止，废弃不可取消的 `Promise.race`，且任何失败分支均产出类型化结果而不使用 `throw new Error`。
- **Pi 合法空目录语义 (R4)**：Pi 默认未配置外部供应商时输出的 `{ "providers": {} }` 以及 `{ "models": [] }` 均为合法空目录状态，修正后将其判定为有效目录（返回空数组）而非解析器损坏（E-90），继续完整合并 `settings.json` 默认模型、`models-store.json`（如 antigravity）及历史缓存。
- **动态 mtime 校验 (E-44)**：适配器每次调用均异步查询最新文件的 `mtimeMs`，杜绝无期限内存缓存导致外部文件被修改后出现陈旧数据。
<!-- notes:end -->
