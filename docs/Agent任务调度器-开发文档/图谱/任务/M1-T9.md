# M1-T9　三平台进程树与原生自启适配器

- 所属模块：[[M1]]　**运行底座**——让 daemon 在这台机器上稳定跑起来并把字节落到磁盘上：进程单实例与端口、启动自检、开机自启注册、数据目录、结构化存储的连接与迁移、日志正文的追加写与字节偏移索引、以及全部平台差异（进程树终止、路径规范化与长路径、配置目录、子进程编码）的唯一收口。凡与操作系统、磁盘、进程存活打交道而不带任何业务概念的都归它
- 前置依赖：[[M1-T3]]
- 完成后解锁：[[M1-T6]]、[[M1-T7]]、[[M6-T5]]

## 输入 / 产出

- **输入**：M1-T3 的 platform 契约、宿主路径输入与 `DaemonLaunchSpec`
- **产出**：`src/platform/windows.ts`、`darwin.ts`、`linux.ts` 与平台集成测试

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) Windows `killTree` 先 `taskkill /PID 〈pid〉 /T`，3 秒后仍存活再加 `/F`
macOS/Linux 对独立进程组先 `SIGTERM`，3 秒后仍存活再 `SIGKILL`，每次尝试都写事件（[[E-119]]）
2) 三平台实现同一 `autostart.register(spec)/status(spec)/unregister()` 契约，分别使用 Task Scheduler、LaunchAgent、`systemd --user`
完整保留 `file/args/cwd`，业务代码不直接判断平台（[[E-132]]、[[E-209]]）
3) 自启集成测试使用唯一隔离名称并在 `finally` 清理
残留即测试失败且输出人工删除命令（[[E-269]]）
4) 三平台之外返回 `E_PLATFORM_UNSUPPORTED`，不得静默套用相近实现

## 必须处理的边界

- [[E-119]]　三平台进程树残留
    - 触发：agent 派生了 node/git/npm 子进程
    - 期望：中止必须杀整棵进程树：Windows 先 `taskkill /T` 后按需 `/F`；macOS/Linux 对独立进程组先发 `SIGTERM`、3 秒后按需 `SIGKILL`。只杀父进程会留下占文件锁的孤儿进程
- [[E-132]]　平台分支散落各处
    - 触发：业务代码直接判断 `process.platform`，或某一宿主静默走另一宿主逻辑
    - 期望：一律收口到单一 `platform` 契约及 Windows/macOS/Linux 三个适配器（进程树终止、自启、配置目录、路径与可执行文件解析）；三平台之外返回 `E_PLATFORM_UNSUPPORTED`
- [[E-209]]　升级后自启项指向旧路径
    - 触发：安装位置、macOS `.app` 位置或 Node 脚本参数变化，原生自启项仍引用旧启动方式
    - 期望：壳每次启动根据实际安装位置解析完整 `DaemonLaunchSpec`；`register` 幂等接收该冻结对象，逐字段校验原生注册项与当前绝对 `file`、`args[]`、绝对 `cwd`，不一致则重写；桌面按钮和自启共用同一对象且恒不经 shell，安装包不得预写固定绝对路径；重写失败降级为「需手动启动」并给出该平台可复制命令
- [[E-269]]　自启集成测试留下真实注册项
    - 触发：测试中断或清理失败
    - 期望：使用带唯一测试标识的隔离自启项并在 `finally` 清理；清理失败必须使测试失败并输出残留项与人工删除命令
