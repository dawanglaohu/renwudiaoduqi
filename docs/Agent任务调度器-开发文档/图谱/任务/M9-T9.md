# M9-T9　多流甲板与密度档

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯、按窗口数呈现的任务流水线泳道与「会话已归档」历史行、顶栏两个流水线开关，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值、「能否收口」、泳道分配、阶段推进与会话归档都是 daemon 给的字段）；指派面板的分组模型下拉、登录态徽标与刷新按钮、参照条的「来源」段同样只呈现 daemon 下发的字段，不算取值链
- 前置依赖：[[M9-T7]]
- 完成后解锁：[[M9-T11]]、[[M9-T12]]、[[M9-T16]]、[[M9-T17]]、[[M9-T21]]

- **输入**：M9-T7；11 节断点表
- **产出**：`stream-column.tsx`、`useDensityTier()`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 档位是**单点计算**的枚举（`full/compact/narrow/phone/phone-xs`）并以 prop 下传，不散落多处（[[E-235]]）
2) 流数 ≥4 默认紧凑档，用 auto-fill **换行网格**（每格 min 260px）**而非横向滚动**（[[E-164]]）
3) 紧凑档展开某条时该条占满宽度、其余保持 260px **留在同屏绝不折叠消失**（[[E-165]]）
4) 260px 放不下时加宽列宽，**不许砍掉停止控件或把状态降级成纯色点**（[[E-166]]）
5) 停止控件与审批槽位渲染在**所有档位分支之外**
配按档位枚举逐档断言停止控件存在的单测（[[E-236]]、[[E-106]]）
6) narrow 档停止键仍常驻可见，**禁止 hover 显示或收进 `⋯`**（[[E-237]]）
7) 拖动窗口切换档位时不重挂虚拟列表、不弹回顶部、不中断跟随（[[E-238]]）
8) 档位只依据视口宽度 + 指针类型，**绝不按 UA 猜设备**（[[E-239]]）
9) 流数 ≤3 且窗口 ≥1440px 时默认完整档、不出现横向滚动，档位选择记忆到本地（[[E-163]]） 10) 完整档横向滚动时若视野外某条流转成「要你」，视口左右边缘出现常驻计数标记（[[E-167]]） 11) 桌面窗口 <1100px 退化为单列列表，**不套用手机端规则**，也不允许在 900px 硬塞三栏（[[E-168]]） 12) `stream-column.tsx` 是泳道外壳：五段网格 `[head][refBar][body][afterBody][foot]`，停止键与审批槽位在所有 `kind` / 档位分支之外渲染
流数恒等于 `lanes[]` 长度（并行窗口数），一条流就是一个任务槽位，阶段链由 M9-T21 填进 `body`（[[E-311]]、[[E-317]] 的呈现侧）

## 必须处理的边界

- [[E-106]]　桌面端多流并置
    - 触发：同时 5 个以上运行流
    - 期望：多流并置（分栏或网格），每流各自带常驻停止控件；不做「一次只能看一个」的模态
- [[E-163]]　少量运行流
    - 触发：流数 ≤ 3 且窗口 ≥ 1440px
    - 期望：默认完整档、不出现横向滚动；紧凑档开关仍在，档位状态记忆到本地
- [[E-164]]　多运行流排布
    - 触发：流数 ≥ 4
    - 期望：默认紧凑档；紧凑档用 auto-fill **换行网格**（每格 min 260px）而非横向滚动，八条流在 1440px 下折成两行全部可见
- [[E-165]]　紧凑档展开某条流
    - 触发：用户点开一条细看
    - 期望：该条占满宽度、其余保持 260px 留在同屏，**绝不把其余流折叠消失**——E-106 要求每条流常驻停止控件，看不见的流等于停不掉
- [[E-166]]　紧凑档宽度不够
    - 触发：260px 放不下「头部 + 运行轨 + 停止键 + 最后一行」
    - 期望：加宽紧凑档列宽，不许砍掉停止控件或把状态降级成纯色点（那会违反 E-110）
- [[E-167]]　视野外的流转成「要你」
    - 触发：完整档横向滚动时，屏幕外某条流进入待审批态
    - 期望：视口左右边缘出现常驻计数标记（如「← 2 条待处理」），否则横向滚动恰好藏住用户唯一明确要求被提醒的那件事
- [[E-168]]　桌面窗口被拖窄
    - 触发：宽度 < 1100px
    - 期望：退化为单列列表；不套用手机端规则，也不允许在 900px 硬塞三栏
- [[E-235]]　档位分支散落各处
    - 触发：多个组件各自判断断点
    - 期望：档位必须是 `useDensityTier()` **单点计算**出的枚举（`full / compact / narrow / phone / phone-xs`）并以 prop 下传
- [[E-236]]　某一档漏掉停止键
    - 触发：档位分支影响了控件存在性
    - 期望：停止控件与审批槽位**必须渲染在所有档位分支之外**；分支只允许影响布局与截断。**配一条按档位枚举逐档断言停止控件存在的单测，把 E-106 变成机检**
- [[E-237]]　窄窗下想省空间
    - 触发：narrow 档（桌面窄窗，有鼠标）
    - 期望：停止键**仍须常驻可见**，禁止改成 hover 显示或收进 `⋯`（11 节禁令 10）
- [[E-238]]　拖动窗口打断状态
    - 触发：从 1200px 拖到 1000px 再拖回，期间某条流展开
    - 期望：档位切换**不得重挂虚拟列表把滚动位置弹回顶部**，也不得中断 SSE 跟随状态
- [[E-239]]　按 UA 猜设备
    - 触发：触屏笔电 / 平板横竖屏切换
    - 期望：档位判定**只依据视口宽度 + 指针类型，绝不按 UA 猜设备**；触屏下仍走 narrow，只把命中区放大到 44px
- [[E-311]]　一个任务的多个阶段同时在跑
    - 触发：同一任务的实施运行已退出、审查运行在跑，或查 bug 运行在跑
    - 期望：全部阶段共用**同一个槽位**：槽位按任务计数，不按运行计数；审查与查 bug 运行不额外占窗口，但各占该 agent 并发上限 1 名额（M8-T1 的计数不变）；`lanes[].currentRunId` 指向当前阶段的运行
- [[E-317]]　泳道分配的算法归属
    - 触发：前端拿到快照与事件要画泳道
    - 期望：`lanes[]` 由 daemon 的纯函数算出，随 `GET /snapshot` 与 `lane.assigned`／`lane.released` 事件下发；前端只按 `laneNo` 排列，不算槽位、不算下一个任务、不推断阶段；字段缺失显示「—」

## 实施沉淀

<!-- notes:begin -->
1. 档位单点收敛与断点正交分离（E-235、E-239）：
   档位决策由 `computeDensityTier` 纯函数单点计算出 `full/compact/narrow/phone/phone-xs` 五个枚举值，禁止组件各自通过 media query 或条件分支发散判定。判定输入严格正交为视口宽度（`<1100`、`>=1440`）与指针粗细（`(pointer: coarse)`），绝不读取 `navigator.userAgent` 猜测设备；触屏笔记本或平板横竖屏切换时（宽度 < 1100px）直接归入 `narrow`，只放大点击区至 44px（E-239），避免被错误降级为手机端规则。

2. 停止键与审批槽位无条件常驻（E-106、E-236、E-237）：
   `StreamColumn` 外壳采用严格五段网格结构 `[head][refBar][body][afterBody][foot]`。在架构层面保证停止键位于 `[head]`、审批槽位位于 `[afterBody]`，两者完全置于任何档位分支（tier）与运行类型（kind）的条件渲染之外；禁止在 narrow 档使用 hover 显示或收进 `⋯` 菜单。测试以 5 档 × 停止键与审批槽位矩阵机检兜底，任何分支影响控件存在性均阻断构建。

3. 紧凑档换行网格与同屏保全（E-164、E-165、E-166）：
   流数 ≥ 4 时默认紧凑档，采用 `auto-fill` 换行网格（每格 `min 260px`）而非横向滚动，确保 8 条流在 1440px 视口下自动折成两行完全可见。某流展开细看时，仅赋予展开流 `col-span-full` 占满当前行全宽，其余流依旧以 `min 260px` 保留在同一屏中，严禁折叠隐藏（E-106 约束看不见的流等于无法停止）。

4. 跨断点窗口拖拽的 React 树稳定性（E-238）：
   容器层不使用依据档位分流不同子树的条件渲染结构（如 `{tier === 'narrow' ? <NarrowView /> : <GridView />}` 会彻底销毁并重建流子树），而是保持统一的 DOM 拓扑和稳定的 `key={lane.laneNo}`。视口变化时仅切换容器布局类名并通过 prop 下传档位，虚拟列表滚动偏移量与 SSE 事件流连接完全不受拖拽干扰。

5. 视野外待审批提示与禁令合规（E-167、E-145）：
   完整档多流横向滚动时，通过实时检测屏幕可视范围外的待审批（`waiting`/`awaiting_input`）泳道，在视口左/右边缘常驻悬浮「← N 条待处理」/「N 条待处理 →」交互胶囊，点击直达对应流。此外，甲板各容器全面遵循 `check-forbidden` 对 `overflow-x` 字面的静态分析禁令，统一采用 `overflow-auto` 与换行网格。
