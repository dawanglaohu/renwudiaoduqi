# M4-T8　codex 原生适配器

- 所属模块：[[M4]]　**Agent 适配**——把形态各异的 agent 抽象成同一个可派发对象：注册表（含每个 agent 通用的版本指纹探测字段与具名的「适配器种类」枚举）、可执行探测、模型清单读取与降级、启动参数与三档权限映射、以各家原生通道为主干把输出归一化成 ACP `session/update` 词汇的事件、可回话与**是否提供流式事件**等能力位，并自实现一个通用 ACP 适配器作为兜底与第 6 家及以后的入口。凡「某一家 agent 跟别家怎么不一样」的都归它
- 前置依赖：[[M4-T3]]、[[M1-T8]]
- 完成后解锁：[[M4-T12]]、[[M6-T6]]

## 输入 / 产出

- **输入**：`codex exec --json` 与 app-server 的实测事件形状
- **产出**：`adapters/codex/`：`buildLaunchSpec` / `readModels` / `map-events` / `capabilities`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 主用 app-server，保留 `codex exec --json` 为退路
两者产出同一套归一化事件
2) 厂商事件字符串只出现在本目录，`service`/`jobs`/`http` 中出现即架构测试失败
3) 原生通道破坏性变更时把 `adapterKind` 切成 `generic-acp` **只改一行数据不改代码**，能力位随之收窄并由 UI 灰掉按钮（[[E-186]]）
4) 能力位声明可回话为真（`codex queue --thread --message`）

## 必须处理的边界

- [[E-186]]　原生通道破坏性变更
    - 触发：codex app-server 官方明说 may change without notice
    - 期望：在数据层注册表把该 agent 的适配器种类由 `native` 切为 `generic-acp`，**不改代码不重打包**；能力位随之收窄并由 UI 灰掉对应按钮；在途任务按 E-02 语义标「失联」而非「失败」

## 实施沉淀

<!-- notes:begin -->
- **双通道的 item 词汇并不一致（AC 1）**：`app-server` 的 `ThreadItem` 用驼峰（`commandExecution`、`fileChange`、`agentMessage`，字段 `aggregatedOutput`/`exitCode`/`durationMs`），`exec --json` 用下划线（`command_execution`、`file_change`、`agent_message`、`reasoning`，字段 `aggregated_output`/`exit_code`），且 exec 把思考文本放在 `item.completed` 的 `reasoning` item 里而不是增量事件。`map-events.ts` 按两套拼写归一、payload 里一律用驼峰名，同一命令在两条通道产出同一套 `tool_call`/`tool_call_update`/`agent_message_chunk`/`agent_thought_chunk`。新增 item 类型时两套拼写都要加，只加一套会让另一条通道少事件（未知类型至少会计入 `unmappedCount`，不会静默消失）。
- **权限与思考强度走 `-c` 键名（E-137）**：`app-server` 没有 `--sandbox`，只能靠 `-c` 覆盖配置，且能生效的键是 `sandbox_mode`——`sandbox` 会被 codex 静默忽略（实测 `codex -c sandbox=bogus-mode …` 不报错，`-c sandbox_mode=bogus-mode …` 报 `unknown variant … in sandbox_mode`），写错等于权限档位在主动通道上不生效。三档值仍取自 `domain/permission-tier.ts`，exec 通道保留 `--sandbox <value>`。
- **回合结束不等于成功（R3）**：app-server 的 `turn/completed` 带 `turn.status`（`completed`/`failed`/`interrupted`/`inProgress`）与只在 failed 时填充的 `turn.error`，退出码必须据此判定，不能一律当 0；「绝不推定成功」同样约束事件映射层。
- **配置驱动的 E-186 防线**：针对官方标明可能无通知突变的 app-server 通道，本模块在数据层注册表保留 `adapterKind`（`native` 与 `generic-acp`）切换开关。发生破坏性变更时，改动单行注册表数据即可将适配种类切至通用 ACP，`getCodexCapabilities` 随之将 `canReply` 置假，UI 自动灰掉回话相关按钮，且不涉及任何源码变更或程序重新打包。
- **架构事件防污染（AC 2）**：将 Codex 专有事件字符集中在 `CODEX_VENDOR_EVENT_STRINGS` 中，配合单元测试扫描 `service/`、`jobs/` 与 `http/`，确保只有 `adapters/codex/` 能感知厂商特有字段。测试同时断言该清单覆盖 `map-events.ts` 里除通用名（`plan`/`agent_message_chunk`/`agent_thought_chunk`/`error`）以外的所有 `case` 字面量：新增分支忘记登记会直接红。
