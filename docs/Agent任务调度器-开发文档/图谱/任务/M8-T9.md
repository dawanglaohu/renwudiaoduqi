# M8-T9　任务指派贯穿流水线与阶段覆盖取值链

- 所属模块：[[M8]]　**派发调度**——决定什么时候把哪个任务、用哪个 agent 与哪个模型、以什么权限派出去，并按批次、并行窗口、每 agent 并发与路径冲突限流，在三个闸门处停或放行、失败或重派时重新入队；判定本批分支是否都进了 HEAD、触发收口运行、按收口报告派修复运行与管理收口轮次也归它；泳道（窗口槽位）分配、任务终态后的补位、查 bug 与收口模式两个开关的持久化同样归它——泳道分配是它算出的派生数据。凡涉及顺序、名额、放行、重派的都归它；任务指派写进派发快照、阶段取值链（任务指派 → 阶段覆盖 → agent 默认）与收口指派设置也归它——它是唯一决定「这一阶段用谁跑」的地方，M7 只消费结果

## 必须处理的边界

- [[E-295]]　收口运行中途失败或被中止
    - 触发：收口运行 failed/aborted/interrupted 时工作区已有半成品改动
    - 期望：不回滚工作区、不派修复运行；批次 `needs_attention` 并开收口闸门；落地清单照常列出该分支并标「未完成的收口改动」，由人决定丢弃或合入
- [[E-304]]　审查会话不能续接或已撑爆
    - 触发：第 N+1 轮审查时审查 agent 的 `canReply` 与 `canResume` 都为假，或续接投递返回上下文超限／未送达
    - 期望：新开审查运行（`review_round=N+1`、`continued_from_run_id` 指向上一轮审查运行），提示词头部带轮次与上一轮 REWORK 条目原文、只核这些条目；分支按能力位决定而不是试了再降级；不静默丢失轮次
- [[E-323]]　查 bug 运行本身失败
    - 触发：`kind='bughunt'` 的运行 failed／aborted／interrupted 或启动超时
    - 期望：不计入 rework_count；被审任务转 `awaiting_human`，闸门 comment 写 `bughunt_failed`；人批准 → 进落地闸门，打回 → 既有 rework 通路；不静默跳过该阶段、不当作干净
- [[E-331]]　查 bug 的手动触发与失败重跑
    - 触发：开关为关时人想对某任务查一次；或查 bug 运行失败后人想再查
    - 期望：产品不提供手动查 bug 端点、界面不渲染置灰入口，人复制交接台该任务的查 bug 提示词自己派或按 E-59 打回／放行；`E_PIPELINE_STAGE_DISABLED` 不再有「手动派查 bug」分支；查 bug 运行失败（E-323）后允许对该 `kind='bughunt'` 行调既有 `POST /runs/:id/rerun`（复用派发载荷、同一工作树），仅当任务仍停在 `bughunt_failed` 的 `awaiting_human`，派出即作废 E-323 开的闸门、不读开关当前值；返工后再审 pass 逐次读开关，可能再派一次查 bug，不设「每任务一次」上限
- [[E-341]]　阶段覆盖字段为空、或在非审查阶段出现
    - 触发：`reviewOverride` 只填 `agentId`；或 `rework`／`bughunt`／`wrapup-fix` 阶段派发时设置里有 `reviewOverride`
    - 期望：`resolveAssignment()` 是唯一取值链：`review` 阶段 `modelName`／`effortTier` 为空回落任务指派（同家沿用，跨家见 E-342）；**`rework`、`bughunt`、`wrapup-fix` 三个阶段逐字读任务指派快照，零回落**，传入的 `stageOverride`／`manualOverride` 被忽略（单测断言输出 `===` 输入）；在途运行禁止读注册表当前 `defaultModel`／`defaultEffortTier`（E-93），只有 `implement` 首派与跨家覆盖时由 service 现读 agent 默认；`source` 四值 `task`／`review_override`／`wrapup_settings`／`agent_default` 写进 `runs.assignment_source` 并随 `RunDto` 下发
- [[E-342]]　覆盖 agent 与实施 agent 不同家
    - 触发：`reviewOverride.agentId` 或固定收口指派与任务指派的 agent 不同家（如 codex 任务由 claude 审查）
    - 期望：模型不跨家带：覆盖未给 `modelName` 时为 null（跟随覆盖 agent 配置，E-35）并记 warning `model_dropped_cross_family`；思考强度用 `remapEffortAcrossAgents()`：三档 `{tier}` 原样保留、`{vendor}` 在源家映射表反查回三档、反查不到或目标家 `effortVendorMap` 为 null → null 并记 warning `effort_unmappable`，参照条显示「—」且 title 说明「〈值〉 无法映射到 〈agent〉」；权限档不在指派里，审查仍固定只读档（E-135）
- [[E-343]]　指派快照与配置当前值后来不一致
    - 触发：任务派出后用户手改了 `config.toml`／`settings.json` 的模型或思考强度，或改了注册表默认
    - 期望：**不回写快照、不改在途运行**：`assignment_json` 只写不改（E-93 同法），该任务后续阶段仍读派发时那一份；设置页「当前配置」随文件 mtime 刷新显示新值；参照条不高亮不一致（它只对自报值高亮，E-37／E-256）；只有换 agent 重派或用户显式清除覆盖才产生新快照（E-33、E-34）
- [[E-344]]　收口指派缺省与取不到
    - 触发：tick 自动触发收口；`wrapupAssignment` 为 `{mode:'follow'}`（默认）或 `fixed`
    - 期望：`follow`：取本批 `ended_at` 最晚的 `landed` 实施运行的任务指派（并列取 run id 字典序最大），第 2 轮沿用上一轮收口快照；本批没有任何成功实施运行快照（全部人工裁定 landed）→ `follow_source_missing`，不派、批次 `needs_attention`（原因 `agent_unavailable` 同一出口），卡片提示改固定指派或手动 body 覆盖。`fixed`：只填 agentId 时 model／effort 回落 follow 取到的值（同家沿用、跨家按 E-342 重映射）；agentId 已从注册表删除 → 设置页标红「agent 不存在」，触发时同上转 `needs_attention`。手动 `POST /batches/:id/wrapup` 的 body 覆盖优先级最高、只作用该轮；收口快照 `assignment_json.source='wrapup_settings'`、`followedTaskId` 在 follow 模式为被跟随任务；收口修复运行沿用被修任务的指派快照，不读本项
- [[E-347]]　同一任务各阶段的模型、思考强度或来源不一致
    - 触发：实施用任务指派、审查用 `reviewOverride`、查 bug 逐字实施；或某阶段 agent 自报值与所选不同
    - 期望：流头部参照条**逐阶段**显示「模型 · 思考强度 · 来源」，来源三值文案「任务指派」「审查覆盖」「收口设置（跟随 〈taskKey〉）」，`agent_default` 显示「来源：任务指派（agent 默认）」（决策 124）；自报不一致按 E-37／E-256 逐阶段高亮，不做跨阶段比对、不把阶段间的合法差异当不一致；前端不算取值链，只显示 `RunDto.assignmentSource` 与 `effort`
- [[E-348]]　运行零产出退出
    - 触发：任何 kind 的运行在首条内容事件（`agent_message_chunk`／`agent_thought_chunk`／`tool_call` 任一）之前进程退出（不论退出码，含 0）、启动超时或错误类事件；dsh 无流式时最终输出解析不出任何内容也算
    - 期望：判定只看事件 kind、不匹配 stderr／stdout 文本（与 E-330 同一结构规则）。实施运行（含 `origin=rework`／`wrapup-fix`）：`exited → reviewing → awaiting_human` 两跳（reason `exited_before_output`），**不跑机械检查、不派审查、不计 `rework_count`**，`tasks.lane_no` 置 NULL 并发 `lane.released{reason:'awaiting_human'}`（E-326）；审查运行走 E-62、查 bug 运行走 E-323、收口运行走 E-295。事务后重跑一次该 agent 的登录态探测（dsh 不探）。审批卡（`GateDto.context`）附退出码、退出信号、stderr 末 20 行（来自该 run 最后一条 `run.exited` 事件的 `stderrTail`，已脱敏，旧事件缺字段显示「无记录（旧运行）」）、刚探测的登录态，与固定提示句「agent 未产出任何内容就退出，常见原因：未登录、模型名不可用、参数被拒」，不写「未登录」定论；动作「重跑」（复用 `POST /runs/:id/rerun`）、「换 agent 重派」、「标失败」（`awaiting_human → failed`），手机端只有重跑与标失败；每次都转人不自动重试；同一 agent 多条泳道同时零产出各自转人、不暂停该 agent；启动超时与 spawn 失败仍走既有 `starting → failed`、手动停止不进本判定；内容事件之后才失败走既有路径并正常计数
- [[E-352]]　跨家审查覆盖的快照与不可用
    - 触发：`reviewOverride.agentId` 与实施快照 `launch_spec_json` 的 agent 不同家；或派审查时覆盖 agent 已不在注册表／不可用
    - 期望：派审查时同一事务 INSERT 子快照（`parent_snapshot_id` 指向实施快照，文本列、`contract_hash`、`task_paths_json`、`bug_prompt`、`assignment_json` 逐字复制，`launch_spec_json` 换成覆盖 agent 当时的注册表副本），审查行 `snapshot_id` 指向子快照；同家覆盖或无覆盖不建子快照、直接挂实施快照；「最近快照」类查询（收口跟随、指派面板「上次派发」、契约比对）一律 `parent_snapshot_id IS NULL`，子快照不参与「契约是否变化」判断；覆盖 agent 不可用 → 不建、不派、不换家，实施行 `awaiting_human` 并在闸门 comment 写 `review_agent_unavailable`；审查运行 rerun 与第 N+1 轮续接复用同一子快照；`reviewOverride` 中途改了只影响新开的审查会话，续接同会话时 `resolveAssignment` 结果与第 N 轮不等则走 `new_session`（E-304）；子快照在快照详情里标「审查覆盖快照 · 父快照 〈id〉」，不在任务快照列表主行出现
- [[E-354]]　探测与清单命令的输出落日志
    - 触发：登录探测或 `live` 清单的 stdout／stderr 要进 logger、`rawStdout`、`warnings`、事件 payload（含 `run.exited.stderrTail`）
    - 期望：先过 `redactSecrets()`：`sk-…`、`xai-…`、`ghp_…`、`Bearer …`、JWT 三段形状替换为 `[REDACTED]`，替换处 UI 显示「[已脱敏]」不静默删行；解析器读原文（脱敏后 JSON 会坏）；单测断言五类样本各命中且不误伤 `gpt-5.6-sol`／`opus[1m]`；CI 扫 fixtures 目录断言零命中真实令牌；日志只在 `debug` 打原文且必须已脱敏（16 节埋点 18）
- [[E-356]]　pipeline 设置四键的写入与校验
    - 触发：`PATCH /settings/pipeline` 缺键、`reviewOverride.agentId` 不在注册表、dsh 配了 `effortTier`、旧库 `pipeline` 行只有两键
    - 期望：四键 `{bughunt, wrapupMode, reviewOverride, wrapupAssignment}` 整体写入，缺任一 `E_VALIDATION`（AJV `additionalProperties:false`、`required` 四项）；`reviewOverride`／`wrapupAssignment.agentId` 必须存在于注册表当前快照，否则 `E_VALIDATION`（`details.field` 用点路径），校验只查注册表快照不起探测子进程；`effortTier` 只收三档不收 vendor，该 agent `effortVendorMap` 为 null 时非 null → `E_VALIDATION`（reason `effort_unsupported`）；`modelName` 不做清单校验（等同 manual 来源，E-36）；缺行返回默认 `{bughunt:0, wrapupMode:'auto', reviewOverride:null, wrapupAssignment:{mode:'follow'}}` 不插行，旧行只有两键读侧补默认不改库，任一键形状非法整体回落默认并 warn（E-292 同法）；不需迁移（JSON 列）；写成功发 `settings.pipeline_changed{pipeline}`（完整四键）并 nudge tick；两项设置不进 `gates` 行、不进 `documents`，算出的结果进快照 `assignment_json`、设置本体不进；运行时再核一次 agent 存在与可用，不可用走各阶段既有转人路径
- [[E-357]]　参照条「来源」段的取值与缺失
    - 触发：参照条渲染每条运行的第三段；`assignmentSource` 为 `agent_default`、四值之外或缺失；被跟随任务未记录或已从文档删除；「N 分钟前探测」的时间推进
    - 期望：`RunDto.assignmentSource`（`runs.assignment_source`，NULL 读作 `task`）与 `followedTaskId`（service 从快照 `assignment_json` 联结取，不新增 `runs` 列）是唯一来源，前端不读快照不算取值链；`task` → 「来源：任务指派」、`review_override` → 「来源：审查覆盖」、`wrapup_settings` → 「来源：收口设置（跟随 〈taskKey〉）」，`followedTaskId` 为 null 时「（跟随任务未记录）」；`agent_default` → 「来源：任务指派（agent 默认）」括注可见、title 说明按 agent 当前生效默认运行，模型／强度为空时仍显示「—」；四值之外或缺失 → 「来源：—」并把原始值放 title，不报错不映射；后端只在模型与强度**都**回落时返回 `agent_default`，只回落一项返回 `task`，前端不自行对比推断半回落；被跟随任务 ID 不在当前文档 → 显示 ID 文本不做链接；`compact`／`narrow` 档用短文案「任务／审查／收口」并把长文案放 title，括注不省略允许换行；第四段可截断、前三段不截断；「N 分钟前探测」由 `hooks/use-minute-tick.ts` 的模块级 60 秒 tick 驱动（只碰本地时钟、无订阅者不起、不 import api），时钟回拨显示「刚刚」，超 24 小时灰显（决策 124、127、129）
