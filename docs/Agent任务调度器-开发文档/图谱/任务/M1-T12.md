# M1-T12　文档顺序自动执行的真实端到端验收

- 所属模块：[[M1]]　**运行底座**——让 daemon 在这台机器上稳定跑起来并把字节落到磁盘上：进程单实例与端口、启动自检、开机自启注册、数据目录、结构化存储的连接与迁移、日志正文的追加写与字节偏移索引、以及全部平台差异（进程树终止、路径规范化与长路径、配置目录、子进程编码）的唯一收口。凡与操作系统、磁盘、进程存活打交道而不带任何业务概念的都归它
- 前置依赖：[[M9-T30]]、[[M1-T11]]、[[M10-T5]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：`docs/Agent任务调度器-开发文档/05-附录/22-决策记录.md` 的「文档级顺序自动执行」扩展合同；M9-T30 的开始/暂停/继续页面；M1-T11 的真 daemon、浏览器、配对和 SSE 冒烟；M10-T5 的三平台门禁
- **产出**：`e2e/document-execution.test.ts`、`e2e/fixtures/document-execution-docs-data.js`、`e2e/fixtures/document-execution-agent.mjs`、`e2e/fixtures/document-execution-agents.json`、`vitest.e2e.config.ts`、`.github/workflows/desktop-ci.yml`；可复现证据、失败产物与实际 Agent smoke 记录

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 从真实 bootstrap 起隔离 daemon，真实页面配对导入至少三批文档，等两个 tick 确认零运行，再只点一次开始（[[E-360]]、[[E-370]]）
2) 首批任务超过窗口，断言并行上限、排队和释放后补位
默认指派沿用到后续批，任务覆盖有效，多文档不串执行位置且共享 Agent 名额/路径限流
初始已注册 Agent 临时不可用时真实开始保存 running 与 agent_unavailable、对应任务零运行，正常恢复/刷新后无需第二次开始即派发
等待中暂停则恢复后仍不派，其他有效任务覆盖可继续
未知 ID/非法参数拒绝且无计划（[[E-362]]、[[E-365]]）
3) 在隔离仓库正常合并任务与收口分支模拟人工操作
真实收口 clean/fixed 后无需点击第二批即经 SSE 出现第二批运行
未落地、open、手动收口或 needs_attention 时后批零运行（[[E-363]]、[[E-364]]）
4) 真实按钮暂停和继续，暂停期间当前已接受运行完成也不启动后批
真实复现继续响应丢失→另一端暂停→旧expectedVersion重试，暂停与零新运行必须保持
默认EffortValue的合法vendor选项通过真实保存及快照核对不丢失
双端重复开始及请求重试不增加实施尝试、快照或窗口（[[E-361]]、[[E-367]]）
5) 真重启 daemon 读取持久位置并显示暂停，继续后只补未派任务
失败、中断、孤儿和停止任务不自动重派（[[E-368]]）
6) 正常修改/刷新文档与移走源文件验证暂停、提示、快照冻结、确认后继续
文档完成后在已完成批次新增任务再开始，按 membershipFingerprint 和 completionFingerprint 验证新任务必须运行、旧已验收任务不重复，新成员重新收口前不跳批或显示 completed
覆盖任务移批/删除/契约变化、缺旧完成证据及晚到旧收口
wrapping 时新增任务后正常刷新并继续，受影响活动批次受控回 idle、source_runs_pending 等旧来源运行结束，旧代回调不恢复 done，新任务随后运行并重新收口
真实 API 的 tasks_json/BatchWrapupDto.tasks 仍为排序任务 ID string[]、哈希只留在冻结输入与指纹
通过正常入口使旧代第6次才完成，再新增任务验证新 generationId 首次收口可用、同代2轮有效自动收口/6次物理尝试上限保留，重复控制不重置，旧代回调与闸门不推进新代
仅 readiness 变化不暂停就绪兄弟（[[E-369]]）
7) 不拦截 fetch、不直写数据库、不注入 sessionStorage 或生产测试钩子
可控 Agent 作为普通注册条目走生产 spawn
至少一家实际本机 Agent 经开始入口跑通实施与审查，记录型号/模型与步骤（[[E-370]]）
8) pnpm -w check 和 pnpm -w e2e 通过，Windows/macOS/Ubuntu 执行计划与调度回归纳入现有 CI
失败上传截图、daemon stdout/stderr 和 DOM，任一缺证据不得关闭本扩展

## 必须处理的边界

- [[E-360]]　导入或切换文档意外启动
    - 触发：新导入、刷新、重绑定或页面切换
    - 期望：新导入保持 idle；这些操作不新增执行授权或直接建运行；已有 running 计划在来源不变时继续，来源变化则按 E-369 暂停；仅文档级开始授予执行权
- [[E-361]]　同文档控制并发与响应丢失
    - 触发：双端开始/暂停/继续、重复点击、响应丢失重试或 tick 并发
    - 期望：控制请求携带实际观察的 expectedVersion，状态更新前做版本比较；相同目标状态仅只读返回，过期请求不能撤销更新的暂停；版本冲突返回当前状态，客户端不自动换新版本重试；最多一份活动计划，不重复派任务或占窗口
- [[E-362]]　批次顺序与窗口、Agent 名额、路径冲突
    - 触发：同批任务超过窗口；多文档共用 Agent 或有效路径
    - 期望：只向当前批派实施任务；槽位空闲自动补位，Agent 名额与路径冲突仍全局生效；改变窗口不杀已有运行
- [[E-363]]　收口前越批或收口后缺少接力
    - 触发：当前批任务验收但未进 HEAD、未收口或收口 open；收口 clean/fixed
    - 期望：未 done 不启动下一批；当前批全部满足原收口契约达到 done 后，下一 tick 自动激活最早未完成批次，不要求用户逐批再点派发
- [[E-364]]　人工闸门或失败任务卡住自动推进
    - 触发：派发前、审查后、落地前闸门等待；收口手动或 needs_attention；任务失败
    - 期望：保留现有闸门与失败不自动重派；同批无依赖兄弟继续；下一批等待 done；DTO 与页面给出原因和处理入口
- [[E-365]]　后续批次无逐任务指派或默认 Agent 不可用
    - 触发：只配置一次文档默认指派；后续任务存在局部覆盖；指定 Agent 离线
    - 期望：任务草稿优先，其次文档默认，再读 Agent 配置；默认与草稿共用 effort: EffortValue，合法 vendor 原值经既有取值域校验并冻结，不丢成三档；无局部覆盖的后续批次直接沿用；未知 Agent ID/非法参数拒绝且不建计划；已注册 Agent 临时不可用时保存 running 等待计划与 agent_unavailable，不静默换家，观测恢复后自动补位，其他有效覆盖仍可派发
- [[E-367]]　暂停与异步派发检查竞态
    - 触发：用户暂停先提交，start/resume/tick 的异步预检后完成；暂停期间收口结束
    - 期望：提交前重读执行状态和 version；暂停后不新增自动运行或将 queued 转 starting；暂停前已接受的 starting/running 继续，结果照常保存；继续恢复待派阶段而不重跑原实施，下一批仍等待继续
- [[E-368]]　daemon 重启与终态任务重复运行
    - 触发：执行计划 running 时重启；任务已 failed、interrupted、orphaned 或 aborted
    - 期望：重启前意图与执行位置持久保留，job 启动前 running 转 paused，显示 daemon_restarted；继续只补未派任务，终态任务需显式重派
- [[E-369]]　执行中文档变更、不可读或契约待复核
    - 触发：任务 ID/contractHash 变化、源失效，或仅 readiness/reasons 更新
    - 期望：契约指纹变化或不可读暂停新自动派发，在途快照不变；已完成批次新增任务、移批、删任务或成员契约变化时，membershipFingerprint 与 completionFingerprint 不一致即作废旧完成证据；显式开始/继续经 membership_invalidated 受控白名单把受影响 done 或真实成员变化的活动状态重置 idle；旧来源 starting/running 在途时以 source_runs_pending 等待，旧代 queued 收口按既有 queued→failed 对账，旧代回调只入历史；确认成员变化才建立新 generationId，每代保留2轮有效自动收口/6次物理尝试上限，同源控制不清额度；新成员重新验收收口，保留已验收任务与历史；仅就绪元数据变化不暂停整份文档，就绪兄弟继续
- [[E-370]]　文档级执行只在测试替身里成立
    - 触发：实现控制接口与批次接力后验收
    - 期望：真实页面导入无运行，点击一次开始后经生产 bootstrap、工作树、收口和 SSE 连续运行；验证窗口、跨批、暂停/继续、重启、双端幂等、已完成批次新增任务不被跳过与实际 Agent 入口，缺证据不得宣称交付
