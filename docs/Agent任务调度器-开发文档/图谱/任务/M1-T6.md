# M1-T6　开机自启注册机制与优雅退出对账

- 所属模块：[[M1]]　**运行底座**——让 daemon 在这台机器上稳定跑起来并把字节落到磁盘上：进程单实例与端口、启动自检、开机自启注册、数据目录、结构化存储的连接与迁移、日志正文的追加写与字节偏移索引、以及全部平台差异（进程树终止、路径规范化与长路径、配置目录、子进程编码）的唯一收口。凡与操作系统、磁盘、进程存活打交道而不带任何业务概念的都归它
- 前置依赖：[[M1-T1]]、[[M1-T9]]
- 完成后解锁：[[M10-T2]]

## 输入 / 产出

- **输入**：M1-T9 的 platform 自启契约与 `DaemonLaunchSpec`
- **产出**：`boot/autostart.ts`、`shutdown()`、`reconcile-runs` job

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) `register(spec)` 以绝对 `file`、`args[]`、绝对 `cwd` 写入原生自启项且幂等，重复调用不产生第二项
逐字段变化才重写，绝不把三字段拼成 shell 命令（[[E-209]]）
注册失败为非致命，daemon 仍可被当场拉起（[[E-210]]）
2) Windows Task Scheduler、macOS LaunchAgent、Linux `systemd --user` 均通过同一契约
Linux 没有用户实例时返回 unsupported、给手动启动命令且不写系统级服务（[[E-261]]）
3) 不装壳、直接命令行起 daemon 时全部功能照常，自启从未注册（[[E-212]]）
4) 优雅退出先停 jobs 再关 HTTP，且**不杀 agent 子进程**（[[E-01]]）
5) 重启后按 `runs.pid` 对账：进程不存在标「异常终止」、存在但接不回标「失联」，**绝不推定成功**（[[E-02]]、[[E-123]]）

## 必须处理的边界

- [[E-01]]　桌面 UI 关闭但任务在跑
    - 触发：用户关闭或桌面壳崩溃，agent 会话仍在运行
    - 期望：daemon 继续收流并在完成时发通知；桌面重开后从 daemon 全量拉状态，不重放本地缓存
- [[E-02]]　daemon 重启后会话失联
    - 触发：daemon 被杀或机器重启，agent 会话还活着
    - 期望：按持久化的 task↔session 映射重新 attach；attach 不上的标「失联」而非「失败」，由用户决定是否重派
- [[E-123]]　daemon 重启后的孤儿记录
    - 触发：重启后仍有状态为「运行中」的记录
    - 期望：启动时按 PID 对账，进程不存在则标「异常终止（daemon 重启）」，绝不推定成功
- [[E-209]]　升级后自启项指向旧路径
    - 触发：安装位置、macOS `.app` 位置或 Node 脚本参数变化，原生自启项仍引用旧启动方式
    - 期望：壳每次启动根据实际安装位置解析完整 `DaemonLaunchSpec`；`register` 幂等接收该冻结对象，逐字段校验原生注册项与当前绝对 `file`、`args[]`、绝对 `cwd`，不一致则重写；桌面按钮和自启共用同一对象且恒不经 shell，安装包不得预写固定绝对路径；重写失败降级为「需手动启动」并给出该平台可复制命令
- [[E-210]]　注册被系统拒绝
    - 触发：Task Scheduler、`launchctl` 或 `systemctl --user` 因权限或策略拒绝
    - 期望：注册失败**必须非致命**：daemon 仍由壳当场拉起、功能完整，仅重启后需手动开壳；设置页提供「重试注册自启」按钮并显示原生错误
- [[E-212]]　完全不装壳直接起 daemon
    - 触发：用命令行启动
    - 期望：自启从未注册，**全部功能照常**；M1 只提供机制不自动执行
- [[E-261]]　Linux 没有 systemd 用户实例
    - 触发：精简发行版、容器或禁用 `systemd --user`
    - 期望：自启 `status` 返回 unsupported，`register` 给出手动启动命令且不尝试写系统级服务；daemon 其他功能照常

## 实施沉淀

<!-- notes:begin -->
- **自启注册必须保持非致命降级（E-210、E-261）**：操作系统权限策略（Windows Task Scheduler / macOS launchctl）或精简环境（无 systemd --user 的容器）经常拒绝常驻注册。若将其作为启动致命错误抛出，会使 daemon 无法在受限环境当场拉起。必须统一吞吐为带 manualStartCommand 的结构化失败，让调用方降级为手动复制命令运行。
- **逐字段对象比对替代 shell 字符串匹配（E-209）**：绝对 file、args[] 与 cwd 严禁拼接为 shell 命令比对或注册。不同平台对空格、反斜杠及 Unicode 的转义差异会导致字面串假不一致，引发重复覆写。统一由 parseDaemonLaunchSpec 解析校验并逐字段比对，仅当参数、路径真实变化时重写。
- **退出生命周期严格保全子进程（E-01）**：优雅退出的顺序为先停 background jobs、再关 HTTP server、最后断开 SQLite 连接并释放单实例锁。期间严禁调用 killTree 或向 agent 进程树发送终止信号，桌面关闭或 daemon 重启期间正在执行的子进程必须独立存活，留待重启后通过对账重新认领或落定。
- **启动对账的双态归宿与防推定（E-02、E-123）**：进程表不存在或 PID 非法的在途任务只能转为终态 interrupted（异常终止）；进程依然存活但在当前底座无法重挂的运行只能转为 orphaned（失联），交由人工决定杀掉或归档。严禁根据退出码或进程存活直接推定任务已落地或已完成。
<!-- notes:end -->
