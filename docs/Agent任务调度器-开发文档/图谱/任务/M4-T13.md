# M4-T13　登录态探测与刷新

- 所属模块：[[M4]]　**Agent 适配**——把形态各异的 agent 抽象成同一个可派发对象：注册表（含每个 agent 通用的版本指纹探测字段与具名的「适配器种类」枚举）、可执行探测、模型清单读取与降级、启动参数与三档权限映射、以各家原生通道为主干把输出归一化成 ACP `session/update` 词汇的事件、可回话与**是否提供流式事件**等能力位，并自实现一个通用 ACP 适配器作为兜底与第 6 家及以后的入口。凡「某一家 agent 跟别家怎么不一样」的都归它；登录态探测（三值、只跑 agent 自己的状态命令、结果缓存）与模型清单的四级来源合并（实时／配置／内置别名／历史）也归它——它们都是「这一家怎么问」的事

- 完成后解锁：[[M4-T14]]、[[M9-T23]]

`args` 含 `print-api-key` / `print-bearer-token` / `--credentials` 即 `invalid-config` 拒绝该条
`{provider}` 变量标记只允许在 `pi_auth_check` 的 `args` 里

2) 探测子进程只走 `executeProbeProcess()`（`spawnManaged`、5 秒上限、超时 `kill()`），可执行路径由调用方传 M4-T3 已解析的 `resolvedPath`，为空直接 `unknown/exec_missing` 不起进程
四个解析器按 04 节实测形状判定，超时／不匹配／退出码非 0 一律 `unknown` 并给 10 节字段级契约列出的八值 reason 之一（`timeout` / `exec_missing` / `spawn_failed` / `unparsable` / `exit_nonzero` / `not_supported` / `no_provider` / `not_probed`，pi `status:'invalid'` 归 `unparsable`），`warningCode` 只在 `timeout` / `unparsable` / `spawn_failed` / `exit_nonzero` 时置 `E_AGENT_LOGIN_PROBE_FAILED`，该码不作为 HTTP 错误抛出（[[E-335]]、[[E-346]]）
3) pi 按 provider 逐个并行探测：**provider 集合与 `defaultProvider` 由调用方作参数注入**（`probeLogin({providers, defaultProvider})`，本任务不读 `pi --list-models` 也不读 `settings.json`，接线由 M4-T14 完成），集合为空 → `no_provider` 不起进程，上限 10 个、超出的标 `not_probed`，agent 级状态取 `defaultProvider` 那一项、缺省取第一个 `logged_in`（[[E-349]]）
pi 的登录 fixture 放 `test/fixtures/login/`
`parser='none'`（dsh）不起进程、不写缓存、DTO 的 `login` 为 null
4) `logged_out` 与 `unknown` **都不改 `canDispatch`**，`assertCanDispatch()` 不读 `loginCache`（单测断言）

`service/agents.ts` 无 `setInterval`（arch 断言）
**每次 `refreshLogin()` 结束**（成功、超时、unparsable、exec_missing）都发 `agent.availability_changed{reason:'login_changed', login}`，`changed` 谓词不把 `login` 算进去，订阅方遇该 reason 不得重探（决策 130，[[E-335]]）

`LoginState` 只含枚举、时间、`loginCommand` 与 `providers`（[[E-353]]、[[E-354]]）
7) `loginCommandHint` 只投影到 `LoginState.loginCommand`，`AgentEntryDto` 顶层不含 `loginCommandHint`
hint 为 null 时 `loginCommand` 为 null，pi 出厂即 null
hint 含控制字符或超 200 字加载时置 null 并 warn
非 dsh 的 agent 在首次探测完成前 `login` 为 `{state:'unknown', reason:'not_probed', checkedAt:null, loginCommand}` 而不是 null（决策 133，[[E-355]]）

## 必须处理的边界

- [[E-335]]　登录态探测超时、命令不存在或输出无法解析
    - 触发：探测子进程 5 秒（注册表可覆盖）内未退出；`resolvedPath` 为空；stdout 不匹配任何解析规则
    - 期望：置 `unknown` 并给 reason（`timeout`／`exec_missing`／`spawn_failed`／`unparsable`／`exit_nonzero`），`warningCode` 为 `E_AGENT_LOGIN_PROBE_FAILED` 只作提示；**不禁用派发、不改 `canDispatch`**；徽标显示「无法判定」与「N 分钟前探测」；grok 断网走超时判 `unknown` 而不是 `logged_out`；`parser='none'` 的 agent（dsh）不起进程、不写缓存、DTO 的 `login` 为 null 且 UI 不渲染徽标
- [[E-336]]　agent 判定为 `logged_out` 时派发
    - 触发：用户仍把任务指派给它并派发
    - 期望：**照常派发**（决策 108）；徽标与指派行显示「未登录：在终端运行 〈登录命令〉 后点刷新」；派发失败按 E-36 原样展示 agent 报错，零产出退出按 E-348 转人；代码中不存在按登录态拒绝 `POST /runs` 的路径（单测断言 `assertCanDispatch()` 不读登录缓存）
- [[E-337]]　claude `loggedIn:false` 但 API key 或网关可用
    - 触发：`claude auth status` 返回 `loggedIn:false`（本机实况），而 `ANTHROPIC_API_KEY` 或网关让 Claude Code 正常工作
    - 期望：徽标照显示「未登录」+ 登录命令，派发不禁用；**不做「运行成功即改判 `logged_in`」的推断**（登录态只由 CLI 判定，缓存只由 `refreshLogin()` 写）；`apiProvider` 字段原样进 `LoginState.vendor` 供 title 显示，不参与判定
- [[E-346]]　厂商改了列模型或登录状态命令的输出格式
    - 触发：`grok models` 文本、`pi --list-models` 表头、codex `model/list` 字段、`codex login status` 文本、`claude auth status` JSON 键、`pi auth check` 的 `status` 取值任一变化
    - 期望：清单侧沿用 E-39：解析不了即 `live` 缺失、`rawStdout`（脱敏后）保留在可展开日志里不静默吞掉；登录侧输出不匹配一律 `unknown`（reason `unparsable`）而不是 `logged_out`，不禁用派发；探测命令、匹配模式与 `loginCommandHint` 在注册表数据层，改数据不改代码；codex／grok 的未登录形态本机未实测，对应 fixture 标 `synthetic`
- [[E-349]]　pi 的登录态按 provider
    - 触发：探测 pi；`pi auth check` 必须带 `--provider` 或 `--model`
    - 期望：provider 集合与 `defaultProvider` 由 M4-T14 注入 `probeLogin()`：集合 = 本次 `live` 清单（`pi --list-models` 第一列）的 DISTINCT，`live` 失败时只传 `settings.json` 的 `defaultProvider`（`read-models.ts` 的 `currentConfigProvider`），两者都空 → `unknown`（reason `no_provider`）不起进程；上限 10 个 provider，超出的标 `not_probed`；逐个并行各 5 秒；`ready → logged_in`、`not_ready → logged_out`、`invalid` 或解析失败 → `unknown`；agent 级状态取 `defaultProvider` 那一项，缺省取第一个 `logged_in` 的 provider，没有则 `unknown`；`LoginState.providers` 逐 provider 下发，指派面板的 pi 下拉按 provider 子分组、各带徽标；`{provider}` 变量标记只允许出现在 `parser='pi_auth_check'` 的探测参数里，其余 parser 含它注册表校验拒绝
- [[E-353]]　登录态探测不读凭据
    - 触发：注册表 `loginProbe.args` 被填成输出凭据的命令；代码里有人读凭据文件
    - 期望：注册表校验：`loginProbe.args` 含 `print-api-key`／`print-bearer-token`／`--credentials` 任一子串 → `invalid-config` 拒绝该条并 warn；`test/arch/registry-forbidden-args.test.ts` 扫 `defaults.ts` 兜底；arch 测试扫全仓禁止出现 `auth.json`／`credentials.json`／`.credentials` 路径串（`config/registry.ts` 读 `agents.json` 除外）；`LoginState` 只含枚举、时间、`loginCommand` 与 `providers` 子表，禁止带 stdout／stderr 原文；全仓除 `adapters/login-probe.ts` 与 `adapters/grok/login-patterns.ts` 外禁止出现 `logged in`／`loggedIn`／`not_ready`／`auth check` 字面量
- [[E-354]]　探测与清单命令的输出落日志
    - 触发：登录探测或 `live` 清单的 stdout／stderr 要进 logger、`rawStdout`、`warnings`、事件 payload（含 `run.exited.stderrTail`）
    - 期望：先过 `redactSecrets()`：`sk-…`、`xai-…`、`ghp_…`、`Bearer …`、JWT 三段形状替换为 `[REDACTED]`，替换处 UI 显示「[已脱敏]」不静默删行；解析器读原文（脱敏后 JSON 会坏）；单测断言五类样本各命中且不误伤 `gpt-5.6-sol`／`opus[1m]`；CI 扫 fixtures 目录断言零命中真实令牌；日志只在 `debug` 打原文且必须已脱敏（16 节埋点 18）
- [[E-355]]　登录命令提示为空、探测时间过旧
    - 触发：注册表 `loginCommandHint` 为 null（pi 出厂即 null）；`checkedAt` 距今超过 24 小时；dsh
    - 期望：hint 为 null 且状态 `logged_out`／`unknown` → 徽标照显示，旁边显示通用回落句「按 〈agent〉 自身文档登录后点『刷新』」，「复制命令」按钮不渲染；hint 非空只用于显示与复制，**产品永远不执行登录命令**；hint 含控制字符或超 200 字在注册表加载时置 null 并 warn；徽标 title 显示「N 分钟前探测」，超 24 小时时间灰显、不自动重探；pi 按 provider 的每个徽标走同一回落句；dsh `login` 为 null 不渲染徽标也不渲染回落句；用户在 agent 交互会话里 `/login` 完回来产品不自动感知，靠点「刷新」重探

## 实施沉淀

<!-- notes:begin -->
1. 登录态与派发能力正交解耦：`assertCanDispatch()` 仅依据版本指纹与并发配置放行，绝不以登录态拦截派发；即使处于 `logged_out` 或 `unknown`，任务均照常派发至底层进程（E-336、E-337）。
2. 凭据隔离与参数安全约束：注册表在加载阶段拦截含有 `print-api-key`、`print-bearer-token` 或 `--credentials` 的探测参数，`{provider}` 变量占位符仅开放给 `pi_auth_check`；`redactSecrets()` 是全仓唯一的令牌脱敏入口（`sk-` / `xai-` / `ghp_` / `Bearer` / JWT 三段），登录探测的 stdout／stderr 只由解析器读原文，不落 logger、`rawStdout` 与事件 payload，`LoginState` 也不带原文字段（E-353、E-354）。
3. 缓存生命周期与事件触发：登录态缓存独立于二进制文件 mtime，全仓禁止定时轮询（无 `setInterval`）。缓存仅响应四个明确失效点，在途并发探测经 `inflightLogin` 合并；每次 `refreshLogin()` 完成均发布 `agent.availability_changed{reason:'login_changed', login}`，且可用性变更判定排除登录字段以防重入探测死循环（E-335）。
<!-- notes:end -->
