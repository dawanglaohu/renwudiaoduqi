## 必须处理的边界

- [[E-106]]　桌面端多流并置
    - 触发：同时 5 个以上运行流
    - 期望：多流并置（分栏或网格），每流各自带常驻停止控件；不做「一次只能看一个」的模态
- [[E-108]]　零运行空态
    - 触发：首次使用或全部空闲
    - 期望：空态直接是「选文档 → 选批次 → 选模型 → 派发」的四步引导，而不是一张插画
- [[E-145]]　极窄屏布局
    - 触发：手机竖屏宽度 < 400px
    - 期望：同一套代码降级为单栏切换（任务列表 / 运行流 / 详情），不得出现横向滚动或并排三栏
- [[E-163]]　少量运行流
    - 触发：流数 ≤ 3 且窗口 ≥ 1440px
    - 期望：默认完整档、不出现横向滚动；紧凑档开关仍在，档位状态记忆到本地
- [[E-164]]　多运行流排布
    - 触发：流数 ≥ 4
    - 期望：默认紧凑档；紧凑档用 auto-fill **换行网格**（每格 min 260px）而非横向滚动，八条流在 1440px 下折成两行全部可见
- [[E-165]]　紧凑档展开某条流
    - 触发：用户点开一条细看
    - 期望：该条占满宽度、其余保持 260px 留在同屏，**绝不把其余流折叠消失**——E-106 要求每条流常驻停止控件，看不见的流等于停不掉
- [[E-167]]　视野外的流转成「要你」
    - 触发：完整档横向滚动时，屏幕外某条流进入待审批态
    - 期望：视口左右边缘出现常驻计数标记（如「← 2 条待处理」），否则横向滚动恰好藏住用户唯一明确要求被提醒的那件事
- [[E-168]]　桌面窗口被拖窄
    - 触发：宽度 < 1100px
    - 期望：退化为单列列表；不套用手机端规则，也不允许在 900px 硬塞三栏
- [[E-236]]　某一档漏掉停止键
    - 触发：档位分支影响了控件存在性
    - 期望：停止控件与审批槽位**必须渲染在所有档位分支之外**；分支只允许影响布局与截断。**配一条按档位枚举逐档断言停止控件存在的单测，把 E-106 变成机检**
- [[E-319]]　空闲泳道
    - 触发：泳道无任务
    - 期望：显示「空闲 · 队列下一个是 〈ID〉（等 〈前置〉 落地）」，〈ID〉与前置来自 daemon 的 `nextTaskId` 与其未落地前置；无任何未派任务时显示「空闲 · 本批已全部派出」；不画假的阶段链；手机档运行条写「泳道 k/N · 空闲」，拇指栏停止键置灰但保持原位
- [[E-324]]　手机端的泳道
    - 触发：手机档（phone／phone-xs）打开运行甲板且窗口数 N＞1
    - 期望：不并排、不横向滚动（E-145）：沿用单栏切换，一次只看一条泳道；顶部 44px 运行条「泳道 k/N · 〈taskKey〉 · 状态字形+文字」两端各一个 ≥44×44 的 ◀ ▶ 切换按钮，N=1 时禁用不隐藏；非当前泳道转「等你」计入全局未处理徽标，点徽标打开既有运行列表抽屉、每行一条泳道；当前泳道补位时跟随新任务、不跳去别的泳道；窗口数调小后 N 显示现存泳道数，泳道消失后落到 min(k, N′)；当前泳道号存 `selection-store` 内存，不进 URL、不持久化；收口运行占的泳道同样单流显示，不出「收口」按钮
