# M2-T3　鉴权中间件与免鉴权白名单

- 所属模块：[[M2]]　**接入与设备信任**——定义两端如何连上 daemon 并不丢事件地保持同步：一次性配对码与可单独吊销的设备令牌、鉴权与操作归属、REST 骨架与 API 版本、SSE 服务端的事件信封／重放窗口／保活，以及自写的 SSE 客户端。凡「谁能连上、连上之后按什么协议收发」的都归它
- 前置依赖：[[M2-T2]]
- 完成后解锁：[[M2-T5]]

## 输入 / 产出

- **输入**：M2-T2 的令牌体系
- **产出**：`http/plugins/30-auth.ts`、白名单常量数组

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 鉴权 hook 注册在 `/api/v1` 子 scope 内部而非根实例，静态资源不被拦、后注册路由不漏
2) 免鉴权白名单只有 `/health`、`/pair/claim`、`/version` 三条且写死在常量数组里
3) **代码中不存在任何基于 remoteAddress／网段／`isPrivateIp` 的绕过分支**（[[E-08]]）
4) 401/403 复用同一响应信封并给出 `E_UNAUTHORIZED` / `E_DEVICE_REVOKED` 明确 code
5) `AGSCHED_DEV=1` 不改变任何鉴权行为，仅影响错误响应带不带 stack
6) 每条写操作记录 `actorDeviceId`（谁派的、谁中止的、谁回的话），系统发起记 `null`
将来加人不必迁移历史数据（[[E-128]]）

## 必须处理的边界

- [[E-08]]　daemon 被隧道暴露到公网
    - 触发：用户自行接入 Tailscale/frp
    - 期望：鉴权与加密默认开启；代码中不得存在「局域网内免鉴权」分支
- [[E-128]]　操作归属不明
    - 触发：多设备下不知道是谁派的
    - 期望：记录里保留 `actorDeviceId`（谁派的、谁中止的、谁回的话），将来加人不必迁移历史数据

## 实施沉淀

<!-- notes:begin -->
1. **Fastify 封装边界与作用域穿透**：`authPlugin` 注册于 `{ prefix: '/api/v1' }` 内部，通过 `Symbol.for('skip-override')` 将 `actorDeviceId` 装饰器与 `onRequest` 钩子提升至该子 scope 根部，既避免向全实例根作用域污染（保证静态资源无鉴权访问），又确保在 `50-routes.ts` 及其后续注册的所有 API 路由均无遗漏地受钩子保护。
2. **404 路由与鉴权生命周期解耦**：在 Fastify 中，未匹配路由由 `setNotFoundHandler` 挂载的通配路由承载，若在 `onRequest` 中对非白名单 URL 盲目抛出 `E_UNAUTHORIZED`，会导致非法路径误报 401 状态。通过在钩子开头判定 `request.is404` 提前退出，保证未注册路由直接流转至 404 `E_NOT_FOUND` 错误信封，不把「路由不存在」误报成「令牌无效」。
3. **状态码收敛与信封统一**：`30-auth.ts` 零硬编码 HTTP 状态码数字，鉴权失败与设备吊销均抛出标准 `AppError`（`E_UNAUTHORIZED` 与 `E_DEVICE_REVOKED`）。由末级 `90-error-handler.ts` 映射至 401 状态码，并统一组装 `{error:{code,message,requestId,details?}}` 信封，开发环境 `AGSCHED_DEV=1` 仅透传堆栈信息，绝不放宽鉴权校验。
4. **操作归属单点注入（E-128）**：鉴权成功后立即将 `auth.deviceId` 回填至 `request.actorDeviceId`，白名单端点显式置为 `null`。业务层与领域事件信封统一从请求上下文读取操作归属，实现调用链追溯并为多设备协作提供不可篡改的设备审计信息。
5. **零内网放行（E-08）**：白名单写死且仅限 `/health`、`/pair/claim`、`/version` 三条，代码中彻底杜绝 `remoteAddress`、私有 IP（`10.x`, `192.168.x`, `127.0.0.1`）等内网绕过逻辑，防止 daemon 经 Tailscale/frp 穿透公网时发生未授权访问。
<!-- notes:end -->
