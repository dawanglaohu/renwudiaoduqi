# M4-T12　dsh headless 适配器与通用 ACP 扩展槽

- 所属模块：[[M4]]　**Agent 适配**——把形态各异的 agent 抽象成同一个可派发对象：注册表（含每个 agent 通用的版本指纹探测字段与具名的「适配器种类」枚举）、可执行探测、模型清单读取与降级、启动参数与三档权限映射、以各家原生通道为主干把输出归一化成 ACP `session/update` 词汇的事件、可回话与**是否提供流式事件**等能力位，并自实现一个通用 ACP 适配器作为兜底与第 6 家及以后的入口。凡「某一家 agent 跟别家怎么不一样」的都归它；登录态探测（三值、只跑 agent 自己的状态命令、结果缓存）与模型清单的四级来源合并（实时／配置／内置别名／历史）也归它——它们都是「这一家怎么问」的事
- 前置依赖：[[M4-T8]]
- 完成后解锁：[[M8-T10]]

## 输入 / 产出

- **输入**：dsh 实测契约（`--profile headless`）；ACP v1 规格
- **产出**：`adapters/dsh/`：`buildLaunchSpec` / `readModels` / `map-events` / `capabilities`；`adapters/generic-acp/`（为第 6 家保留）

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) dsh 走 `--profile headless "任务"` 接入为**第一版第五家**：末条 assistant 文本进 stdout、`turn/end` 完成则退出码 0 否则
1、成功时 stderr 为空、不监听端口
CLI 未全局安装，入口默认指向应用内 `bin.js` 且可手填绝对路径（[[E-193]]）
2) **能力位 `hasStreamingEvents` 置假**，运行轨只显示三段、逐步耗时退化为整段耗时，**禁止伪造中间事件**
UI 按能力位灰掉「逐步展开」而非留空列表（[[E-253]]）
3) 启用前必须过探测 + 冒烟任务，契约任一项不符即判未通过并显示原因（[[E-191]]）
4) 启动失败或非 0 退出即标不可用并移出选择器、在途运行标「失联」，**绝不影响其余四家与整批推进**（[[E-192]]、[[E-28]]）
5) 版本超出注册表已知区间时允许启用但常驻提示「版本未验证」（[[E-194]]）
6) 会话回读能力位标「仅本次运行」——dsh 侧无列举接口，历史一律由本产品自己的运行记录提供（[[E-188]]）
7) 通用 ACP 适配器仍产出，作为**第 6 家及以后**的兜底入口：只填启动命令即可接入
既不在注册表也无 ACP 入口的明确标「暂不支持」，不提供半可用状态（[[E-187]]）
8) 同一 agent 的原生与 ACP 适配器任一时刻只允许一种生效，切换必须在无在途运行时进行（[[E-189]]）

## 必须处理的边界

- [[E-187]]　接入第 5/6 个 agent
    - 触发：用户要加注册表之外的 agent
    - 期望：走通用 ACP 适配器，只填启动命令；若该 agent 既不在 ACP 注册表也无 ACP 入口 → 明确标「暂不支持」，不提供半可用状态
- [[E-188]]　ACP v1 没有会话列举
    - 触发：通用 ACP 适配器下要看历史会话
    - 期望：「历史会话列表」一律由本产品自己捕获的运行记录提供，绝不依赖 agent 侧列举；通用 ACP 适配器的会话回读能力位标为「仅本次运行」
- [[E-189]]　一个 agent 两种适配器都可用
    - 触发：原生与 ACP 适配器并存
    - 期望：任一时刻只允许一种生效；切换必须在该 agent 无在途运行时进行
- [[E-191]]　dsh 冒烟任务未通过
    - 触发：第五家 agent 派活前的自检失败
    - 期望：该 agent 保持不可用并显示失败原因（实测契约：`dsh --profile headless "任务"` 应 stdout 出末条文本、退出码 0、stderr 空；任一不符即判未通过），不进入批次派发
- [[E-192]]　dsh 启动失败或非 0 退出
    - 触发：破坏性变更导致启动参数、profile 组合或退出语义变化
    - 期望：该 agent 标不可用并移出派发选择器，在途运行标「失联」，**绝不影响其余四家与整批推进**。headless 无握手阶段，判据只有「进程能否起来」与「退出码」
- [[E-193]]　注册表有 dsh 项但本机未装
    - 触发：用户没装 DeepSeek Harness，或装了但 CLI 入口路径变了
    - 期望：该项显示「未安装」，不出现在派发选择器中，也不产生任何探测开销；给出手填绝对路径入口（CLI 未全局安装，默认入口在应用内 `resources/host/node_modules/@deepseek-ai/dsh/lib/bin.js`）
- [[E-194]]　dsh 版本超出已知区间
    - 触发：实际版本高于注册表记录的可用区间
    - 期望：允许启用，但顶部横幅常驻提示「版本未验证」，不静默假定兼容
- [[E-253]]　dsh 全程无流式事件
    - 触发：dsh 只有 `--profile headless`，跑完才给最后一条 assistant 文本，中途没有任何可归一化的 `session/update` 事件
    - 期望：能力位新增 `hasStreamingEvents`，dsh 置假。**禁止伪造中间事件充数**：运行轨对该 agent 只显示「已派发 → 运行中 → 完成/失败」三段，逐步耗时退化为整段耗时，日志栏在运行期显示「该 agent 不提供过程输出，完成后一次性写入」。UI 按能力位灰掉「逐步展开」而不是留个永远空的列表（与 E-117 同一手法）
- [[E-28]]　DeepSeek Harness 的破坏性变更
    - 触发：官方声明会有破坏性变更且 `SESSION_FORMAT_VERSION = 0`。**2026-09-01 实测**：`--profile headless` 是唯一可用通道；`--profile acp` **不存在**——`@deepseek-ai/dsh-acp` 各版本均无 `dsh.bundle` 字段（是库不是 profile 层），`latest` 指向的 `0.0.1-rc.1` 依赖 404 装不上
    - 期望：走 `--profile headless` 原生适配（第一版内置的第五家），**版本钉死**；启用前必须先跑探测 + 冒烟任务，通过才允许进批次派发；启动失败或非 0 退出即标该 agent 不可用并移出选择器，绝不影响其余四家与整批推进

## 实施沉淀

<!-- notes:begin -->
- dsh headless 模式在完成时由 stdout 一次性输出终端 assistant 文本，执行期没有任何中间可归一化事件；严禁在此处伪造任何虚拟步骤（如假的 tool_call 或 thought_chunk），而是通过 hasStreamingEvents: false 显式由前端运行轨退化为整段耗时。
- 纯文本 stdout 终稿通过 runService 的 acceptsPlainText 通路直接传入 mapper，避免将非 JSON 行误判为 unmapped_event_count 或中断流，多行正文完整保留原文与换行。
- ACP v1 报文映射以 params.update.sessionUpdate 为主干（type/kind 仅作为平铺报文回落），五种 payload 键名严格对齐 shared/api/events 规范与 grok 适配器契约，不替厂商虚构工具执行状态。
- dsh 入口默认指向应用内 resources/host/node_modules/@deepseek-ai/dsh/lib/bin.js，启动规范检测 .js 扩展名时直接切换通过 process.execPath (Node) 托管执行，同时支持用户手填绝对二进制路径。
- 在同一 agent 上原生与通用 ACP 适配器任一时刻仅允许生效一种；通过在 updateAgent 阶段判定 hasInFlightRuns 确保在途运行未终态前严禁热切换 adapterKind。
- 注册表与探针显式记录 dsh 的已知可用版本区间；超出区间但指纹模式匹配时允许启用但常驻提示 Unverified agent version，未安装或完全无法识别的可执行则坚决标为不可用。区间经 mergeAgentConfig 合并进解析结果，探测与 DTO 都读同一份；versionRange 是可选字段且不在 AGENT_CONFIG_FIELD_PATHS 里——把它算进「完整基线」会让缺少该字段的历史 agents.json 永远判为不完整、每次都重写基线并报出假的「内置默认已更新」，所以它只参与覆盖合并、不参与三行差异与一键采纳。
- E-189 的守卫在 service 层，靠注入的 hasInFlightRuns 判在途运行；容器当前没有 runs 仓储可注入（boot/container.ts 只建了 runsAbort），接线随 repo/runs.ts 进容器完成，届时检查还要同时挂到 agents.json 热加载路径上，否则只有 updateAgent 一条路会拦。
<!-- notes:end -->
