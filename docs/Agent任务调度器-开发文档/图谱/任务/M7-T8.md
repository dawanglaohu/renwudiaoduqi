# M7-T8　查 bug 阶段运行与结果解析

- 所属模块：[[M7]]　**审查流水线**——对已结束的运行做「合不合格」的判定：先跑本地机械检查，通过后以只读档派一个 agent 跑文档给出的审查提示词，产出 pass / rework / doc-issue 并回灌 rework 意见；从审查输出提取返工文本、按能力位选回灌／恢复／新开返工运行，以及解析收口运行的八段报告，也归它；第 N+1 轮审查续接同一审查会话、查 bug 阶段的运行与五段报告解析同样归它。凡「判定一次运行的结果」的都归它；审查、查 bug 阶段的运行用哪个 agent、模型与思考强度，一律读派发快照里的任务指派（审查可被 pipeline 设置的「审查覆盖」替换），不自己取 agent 默认
- 前置依赖：[[M7-T3]]、[[M3-T7]]、[[M8-T6]]、[[M7-T7]]
- 完成后解锁：[[M8-T8]]、[[M8-T9]]

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) `finalizeReviewRun()` 判 pass 后读 `settings.pipeline.bughunt`（每次读库、不缓存、不进快照）：为 1 且该实施运行尚无 bughunt 行 → 事务内 INSERT `kind='bughunt'` 行（`queued`、`parent_run_id`=实施运行、`origin='dispatch'`、`permission_tier='workspaceWrite'`、`worktree_path` / `branch_name` 逐字同实施、`prompt_source`），实施行保持 `reviewing`
为 0 → 走既有落地闸门
路由表里没有查 bug 端点，`dispatchBughunt()` 的唯一调用方是判 pass 后的分流
查 bug 运行失败后允许对该行调既有 `POST /runs/:id/rerun`，仅当任务停在 `bughunt_failed` 的 `awaiting_human`（[[E-306]]、[[E-331]]）
2) 提示词四段顺序写死（包装说明 → 引用材料逐字 → 工作区指针 → 结束语），材料取派发快照 `bug_prompt`，NULL 用内置版并 `prompt_source='builtin'`（[[E-316]]）
agent／model／effort **逐字复制被审实施运行行的 `agent_id` / `model_name` / `effort_tier`（任务指派的副本，决策 107），不从 `launch_spec_json.defaultModel` 推导、不读注册表当前默认**，agent 不可用则不派、不换家并转人写 `bughunt_agent_unavailable`（[[E-328]]、[[E-341]]）
M8-T9 落地后改为经 `readTaskAssignment()` 读快照 `assignment_json`，本任务不留第二条取值路径

3) bughunt 行走既有边 `queued → starting → running → exited → reviewing → landed／awaiting_human`，进 `reviewing` 后只做五段解析、不跑机械检查、不派审查 agent、豁免 [[E-61]] 空 diff
tick 的进 HEAD 扫描跳过它（[[E-321]]）
4) `decideBughuntOutcome` 四值：FIXED 非空且工作区 diff 非空 → `rereview`（`rework_count<2` 时 +1 并调 `startReviewRound({round: N+1, reworkItems: FIXED 条目})`

NOT_FIXED 含 S1/S2 → 实施行与 bughunt 行均 `awaiting_human`（reason `bughunt_open_findings`）并释放槽位

5) 不合五段 → 两行均 `awaiting_human`（reason `bughunt_unparsed`），原文保留、不部分解析，人过闸门后实施 `landed`、bughunt `failed`（[[E-320]]）
bughunt 行 failed／aborted／interrupted／启动超时 → 实施行 `awaiting_human`（reason `bughunt_failed`），`rework_count` 不动（[[E-323]]）
6) 事务前解析、事务内迁移、事务后投递（08 节）

## 必须处理的边界

- [[E-306]]　查 bug 开关中途切换
    - 触发：`pipeline.bughunt` 在有任务在途时从 0 切 1 或从 1 切 0
    - 期望：只影响**尚未到达**查 bug 阶段的任务：审查 pass 那一刻读当前值决定是否派查 bug 运行；已在跑的查 bug 运行不杀、结果照常处理；阶段链只在任务实际进入该阶段时才出现「查 bug」节点，不画灰色「已跳过」节点；开关值存 `settings(key='pipeline')`，写成功发 `settings.pipeline_changed`
- [[E-307]]　查 bug 修了东西
    - 触发：查 bug 报告 FIXED 段非空且自审查 pass 以来工作区 diff 非空
    - 期望：`rework_count<2`：先 `+1`，再通知**该任务的同一审查会话**再审一轮（续接规则同 E-304），提示词头部「第 N 轮，只核查 bug 阶段的修改：〈FIXED 条目原文〉」；`rework_count` 已达 2：不派再审、不 +1，任务转 `awaiting_human`，闸门 comment 写 `bughunt_fixed_over_limit`，审批卡列 FIXED 条目与 diff 摘要；FIXED 非空且 NOT_FIXED 含 S1/S2：直接转人、不先再审；运行轨上画成查 bug 节点回到审查节点的回环，轮次沿用同一 `rework_count`；不派第二个审查会话、不跳过再审直接落地
- [[E-308]]　查 bug 有未修的高危项
    - 触发：NOT_FIXED 段含 `S1` 或 `S2` 条目
    - 期望：被审任务转 `awaiting_human`，审批卡列出 NOT_FIXED 原文（FIXED 非空时同时列两段）；不自动派修复、不进落地闸门；只剩 `S3` 或全部为空视为干净
- [[E-316]]　查 bug 提示词文档未提供
    - 触发：派发快照里的 `dispatch[id].bug` 缺失或不是字符串
    - 期望：用内置通用查 bug 提示词并标「文档未提供」（`prompt_source='builtin'`，记 warn）；取派发快照那一刻的文档，不按当前文档；材料逐字引用不改写，外层包装说明覆盖其中的提交／推送／再点审查等步骤
- [[E-320]]　查 bug 输出不合五段
    - 触发：查 bug 运行的最终文本缺 BUGS／FIXED／NOT_FIXED／SUSPECT／NEXT 任一段，或段头顺序找不齐
    - 期望：按「查 bug 未完成」处理：保留原文可读、不做部分解析、不猜；被审任务转 `awaiting_human` 并在查 bug 运行上开一张 `kind='review'` 闸门；不计入 rework_count
- [[E-321]]　查 bug 运行没改代码
    - 触发：`kind='bughunt'` 的运行退出码 0 且自审查 pass 以来工作区 diff 为空
    - 期望：不按 E-61 判失败；BUGS 为空或只剩 S3 且 FIXED 为空 → 干净，直接走落地闸门；FIXED 非空但 diff 为空 → 不再审、不 +1，这些条目按 NOT_FIXED 处理（沿用自报严重度，缺严重度按 S2）走 E-308，UI 标「自报已修但无改动」（与 E-286「按内容不按自报」同一原则）
- [[E-323]]　查 bug 运行本身失败
    - 触发：`kind='bughunt'` 的运行 failed／aborted／interrupted 或启动超时
    - 期望：不计入 rework_count；被审任务转 `awaiting_human`，闸门 comment 写 `bughunt_failed`；人批准 → 进落地闸门，打回 → 既有 rework 通路；不静默跳过该阶段、不当作干净
- [[E-328]]　查 bug 运行的 agent 取值与不可用
    - 触发：派查 bug 运行时
    - 期望：逐字复制该任务最近一次审查判 pass 的 `kind='implement'` 运行（含 `origin=rework`／`wrapup-fix`）**运行行的 `agent_id` / `model_name` / `effort_tier`（M8-T9 后经 `readTaskAssignment()` 读快照 `assignment_json`）**，不读 `launch_spec_json.defaultModel`、不读注册表当前默认（决策 107，E-93、E-341）；model 或 effort 为空同样为空透传、显示「—」；推导出的 agent 不可用（已禁用／探测失败／未安装）→ 不派、不换家，实施行转 `awaiting_human` 并在闸门 comment 写 `bughunt_agent_unavailable`；查 bug 会话恒为该任务新建的会话、`vendor_session_ref` 不得等于该任务实施／审查运行的引用；该 agent 并发已满 → 查 bug 运行 `queued`（`agent_limit_reached`），任务继续占原泳道、实施行仍 `reviewing`；实施 agent 是 dsh 照派，运行轨三段（E-253）
- [[E-329]]　查 bug 运行的 git 禁令与 diff 基线
    - 触发：组装查 bug 提示词与判定 FIXED
    - 期望：包装说明与收口共用同一禁令常量（禁 `git commit/push/checkout/branch/worktree/stash/merge/rebase/reset`、`gh` 任何子命令、文档脚本、改 `docs/`），再加阶段专属覆盖「修完不提交、不推送、不点审查，产品会通知审查会话再审」，FIXED 条目格式覆盖为「B〈n〉 → 改了什么、加了哪个测试」；派查 bug 时记起点树（HEAD SHA 与工作区树对象），FIXED 判定、再审 diff 与「自审查 pass 以来工作区 diff」都以它为基线；agent 违禁 commit 不拦截（E-75）且基线不受影响、不误判无改动；违禁 push 在凭据层失败（E-138）；未提交改动照 E-301 判未进 HEAD，落地清单照 E-74 列出 diff 摘要；查 bug 后人工打回时返工文本头部附「工作区已有查 bug 阶段未提交改动 N 个文件，先看 git status 再改」
- [[E-331]]　查 bug 的手动触发与失败重跑
    - 触发：开关为关时人想对某任务查一次；或查 bug 运行失败后人想再查
    - 期望：产品不提供手动查 bug 端点、界面不渲染置灰入口，人复制交接台该任务的查 bug 提示词自己派或按 E-59 打回／放行；`E_PIPELINE_STAGE_DISABLED` 不再有「手动派查 bug」分支；查 bug 运行失败（E-323）后允许对该 `kind='bughunt'` 行调既有 `POST /runs/:id/rerun`（复用派发载荷、同一工作树），仅当任务仍停在 `bughunt_failed` 的 `awaiting_human`，派出即作废 E-323 开的闸门、不读开关当前值；返工后再审 pass 逐次读开关，可能再派一次查 bug，不设「每任务一次」上限
- [[E-341]]　阶段覆盖字段为空、或在非审查阶段出现
    - 触发：`reviewOverride` 只填 `agentId`；或 `rework`／`bughunt`／`wrapup-fix` 阶段派发时设置里有 `reviewOverride`
    - 期望：`resolveAssignment()` 是唯一取值链：`review` 阶段 `modelName`／`effortTier` 为空回落任务指派（同家沿用，跨家见 E-342）；**`rework`、`bughunt`、`wrapup-fix` 三个阶段逐字读任务指派快照，零回落**，传入的 `stageOverride`／`manualOverride` 被忽略（单测断言输出 `===` 输入）；在途运行禁止读注册表当前 `defaultModel`／`defaultEffortTier`（E-93），只有 `implement` 首派与跨家覆盖时由 service 现读 agent 默认；`source` 四值 `task`／`review_override`／`wrapup_settings`／`agent_default` 写进 `runs.assignment_source` 并随 `RunDto` 下发
- [[E-61]]　退出码 0 但没有改动
    - 触发：agent 正常退出但 diff 为空
    - 期望：机械层直接判失败（呼应 E-23），不派审查 agent，标「无改动」转人
