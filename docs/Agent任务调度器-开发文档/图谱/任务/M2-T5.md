# M2-T5　SSE 服务端：分帧、心跳、重放与断流

- 所属模块：[[M2]]　**接入与设备信任**——定义两端如何连上 daemon 并不丢事件地保持同步：一次性配对码与可单独吊销的设备令牌、鉴权与操作归属、REST 骨架与 API 版本、SSE 服务端的事件信封／重放窗口／保活，以及自写的 SSE 客户端。凡「谁能连上、连上之后按什么协议收发」的都归它
- 前置依赖：[[M2-T3]]、[[M2-T4]]
- 完成后解锁：[[M9-T5]]

## 输入 / 产出

- **输入**：M2-T4 的事件总线
- **产出**：`http/sse.ts`、`GET /events`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 响应头含 `text/event-stream`、`no-cache, no-transform`、`keep-alive`、**`X-Accel-Buffering: no`**，每 15 秒写一行 `:\n\n` 心跳（[[E-154]]）
2) 带 `Last-Event-ID` 重连时从重放缓冲补齐
小于缓冲最小 id 则返回 409 `E_REPLAY_WINDOW_EXPIRED` 并主动关流，**不静默丢事件**（[[E-153]]）
3) 两端同时在线时每条连接各自维护游标与去重，服务端不假设只有一个客户端（[[E-155]]）
4) 令牌过期或被吊销时主动关闭该流并返回带信封的 401（[[E-156]]）
5) 路由内只操作 `reply.raw`，不调用 `reply.send`

## 必须处理的边界

- [[E-153]]　断线超过重放窗口
    - 触发：离线时长超过服务端保留的最近 N 条事件
    - 期望：服务端返回「重放窗口已过期」，客户端改为 REST 拉全量当前状态快照后从最新 event id 续接，不允许静默丢事件
- [[E-154]]　反代缓冲导致流不实时
    - 触发：用户自接的隧道或反向代理缓冲了响应
    - 期望：设 `X-Accel-Buffering: no` + `Cache-Control: no-transform`，并按固定间隔发心跳注释行保活
- [[E-155]]　两端同时在线
    - 触发：桌面与手机各开一条流
    - 期望：每条连接各自维护自己的游标与去重，服务端不做「只有一个客户端」的假设
- [[E-156]]　令牌过期而流仍开着
    - 触发：令牌被撤销或过期
    - 期望：服务端主动关闭该流并返回 401，客户端提示重新配对，不进入无限重连

## 实施沉淀

<!-- notes:begin -->
- **重放与实时订阅的接缝无损保证**：若先从环形缓冲拉取历史再订阅总线，两步之间的并发事件会被遗漏；若直接订阅后再重放，未完成重放前的新事件会产生乱序。因此采用阶段切换机制：握手时先挂接总线监听并将新事件置入连接私有的暂存队列，待环形缓冲的历史重放逐帧刷入流中并推进本地游标后，再回放暂存队列中大于游标的事件并转为实时流，实现确定性的单调严格递增。
- **响应头即时刷新（flushHeaders）**：Node.js http.ServerResponse 在无立即数据块写出时可能缓冲 TCP 头部。SSE 作为长连接流协议，首包必须立即送达代理和客户端以确立无缓冲通道（X-Accel-Buffering: no），显式调用 flushHeaders() 避免反代因为等待首个数据帧而挂起握手。
- **设备吊销的双通道断流（E-156）**：一方面通过 PairingService.registerConnection 监听主动吊销事件，在触发时向流写出 401 错误信封事件并主动关流；另一方面在 15 秒的心跳循环中防御性复核当前设备的持久化状态，防止极端情况下内存监听泄漏或带外吊销无法传达。
<!-- notes:end -->
