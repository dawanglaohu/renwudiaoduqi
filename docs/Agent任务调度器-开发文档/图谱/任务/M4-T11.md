# M4-T11　grok 原生适配器

- 所属模块：[[M4]]　**Agent 适配**——把形态各异的 agent 抽象成同一个可派发对象：注册表（含每个 agent 通用的版本指纹探测字段与具名的「适配器种类」枚举）、可执行探测、模型清单读取与降级、启动参数与三档权限映射、以各家原生通道为主干把输出归一化成 ACP `session/update` 词汇的事件、可回话与**是否提供流式事件**等能力位，并自实现一个通用 ACP 适配器作为兜底与第 6 家及以后的入口。凡「某一家 agent 跟别家怎么不一样」的都归它
- 前置依赖：[[M4-T3]]、[[M1-T8]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：`--output-format streaming-json`（ACP 原生）与 `grok sessions`／`export`
- **产出**：`adapters/grok/` 四件套

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 直接消费其 ACP session updates，作为归一化词汇的参照实现
2) 会话回读只走 `grok sessions list/search` 与 `grok export 〈id〉`，**禁止直连其 SQLite**（schema 未公开）
3) headless **不读管道 stdin**，提示词经 `--prompt-file` 或参数传入
4) 与社区同名 CLI 的区分由 M4-T3 的指纹探测负责，本任务不再判定
5) 该家拿不到 token 用量时字段置 null 由上层显示「—」，**不得填 0**（[[E-26]]）

## 必须处理的边界

- [[E-26]]　token 用量字段缺失
    - 触发：各家字段名/单位不一致或压根没有
    - 期望：缺失时显示「—」，不得拿 0 冒充

## 实施沉淀

<!-- notes:begin -->
1. ACP 参照实现设计：Grok Build 原生输出为标准 ACP `session/update`（`--output-format streaming-json`），适配器将其直接归一化映射至 `agent_message_chunk`、`agent_thought_chunk`、`tool_call`、`tool_call_update`、`plan`、`available_commands_update`，作为全项目各适配器归一化词汇的参照基准。
2. 会话回读边界与 SQLite 隔离：Grok 本地会话存放在 SQLite 中，但官方未公开 schema 且无格式稳定性承诺。适配器会话回读严格通过 `grok sessions list/search` 与 `grok export <id>` 经子进程执行与输出解析获取，禁止以任何形式直接连接或读取其 SQLite 文件。
3. Headless 管道差异：与 pi 依赖管道 stdin 传入提示词相反，Grok headless 模式明确不消费管道 stdin；派发规格必须严格经由 `--prompt-file <path>` 或 `-p <prompt>` 命令行参数透传提示词，避免子进程因等待 stdin 而卡死。
4. Token 用量缺失严禁伪造（E-26）：部分模型或版本不提供 token 消耗数据。当字段不存在或不可解析时必须保持 `null` 由上层显示「—」，严禁将缺失值填为 `0`，避免向用户与收据系统伪造「零消耗」误导。
5. 同名 CLI 判定正交解耦：与 npm 社区同名 `superagent-ai/grok-cli` 的冲突排查完全收敛于 M4-T3 的指纹探测机制，本适配器仅消费已经平台与指纹解析的绝对执行入口，避免重复判定产生状态漂移。
<!-- notes:end -->
