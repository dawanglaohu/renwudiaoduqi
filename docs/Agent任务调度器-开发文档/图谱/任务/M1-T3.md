## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) `appDataDir(hostInputs)` 返回规范化绝对路径：Windows 采用绝对 `APPDATA`，否则回落 `homedir/AppData/Roaming`
macOS 取 `homedir/Library/Application Support`
Linux 采用绝对 `XDG_DATA_HOME`，否则回落 `homedir/.local/share`，最后追加应用目录
覆盖变量缺失、相对值、空格与 Unicode 主目录，结果不得含 `~`、`${...}`、`%...%`，主目录不绝对则报 `E_DATA_DIR_UNRESOLVABLE`（[[E-271]]）
2) Windows 盘符、UNC、长路径、空格与 Unicode 可实际读写
不因传统 260 字符限制或字符本身拒绝（[[E-129]]）
3) macOS/Linux 解析符号链接，要求普通文件与 `X_OK`
无执行位返回 `E_AGENT_EXEC_NOT_EXECUTABLE`，坏链接/成环/非文件返回 `E_AGENT_EXEC_INVALID_TARGET`，不自动 chmod、不回退 PATH（[[E-262]]、[[E-263]]）
4) 另一平台路径格式保留原值但标无效，绝不猜测转换（[[E-264]]）
5) Windows `.cmd`/`.bat` 只经 `ComSpec`，适配器接收完整原始参数数组后统一包装
`quoteForCmd()` 与包装接口须以真实子进程验证最终 argv，覆盖普通参数、空参数、空格、Unicode、引号、分号（U+003B）、`&`、`^`、`%`、`!`，含空格与元字符的脚本路径也可启动
ComSpec 分支按 08 节设置 `windowsVerbatimArguments:true`，NUL/CR/LF 参数启动前报 `E_VALIDATION`，不得改变参数或执行额外命令
6) 最小环境下优先显式绝对路径，缺失时列出固定候选
代码不读取或执行 shell 启动文件（[[E-270]]）
7) `DaemonLaunchSpec` 只含绝对 `file`、`args[]`、绝对 `cwd`，共享 schema 拒绝相对路径与 shell 字符串（[[E-209]]）

## 必须处理的边界

- [[E-129]]　路径含空格、Unicode、元字符或 Windows 长路径
    - 触发：工作区、数据目录或 agent 路径包含这些字符，或是 UNC / 超过传统 260 字符限制
    - 期望：按当前平台规范化并以独立 argv 传递；Windows 在进入文件系统前使用长路径命名空间，不得以传统 260 字符阈值拒绝。若超过接口或当前文件系统上限，必须在启动/写入前报告实际限制
- [[E-209]]　升级后自启项指向旧路径
    - 触发：安装位置、macOS `.app` 位置或 Node 脚本参数变化，原生自启项仍引用旧启动方式
    - 期望：壳每次启动根据实际安装位置解析完整 `DaemonLaunchSpec`；`register` 幂等接收该冻结对象，逐字段校验原生注册项与当前绝对 `file`、`args[]`、绝对 `cwd`，不一致则重写；桌面按钮和自启共用同一对象且恒不经 shell，安装包不得预写固定绝对路径；重写失败降级为「需手动启动」并给出该平台可复制命令
- [[E-262]]　POSIX 可执行文件没有执行权限
    - 触发：macOS/Linux 目标存在但 `X_OK` 校验失败
    - 期望：启动前返回 `E_AGENT_EXEC_NOT_EXECUTABLE` 并包含路径；不得自动 `chmod`，不得转交 shell 猜测执行方式
- [[E-263]]　符号链接目标无效
    - 触发：macOS/Linux 可执行路径经符号链接后不存在、成环或不是普通文件
    - 期望：返回 `E_AGENT_EXEC_INVALID_TARGET`，报告原始路径与解析目标；不缓存失败结果，不回退到同名 PATH 候选
- [[E-264]]　配置保存了另一平台的路径格式
    - 触发：当前系统读到 Windows 盘符/UNC，或 Windows 读到 POSIX 绝对路径
    - 期望：保存值原样保留但标为当前平台无效；不擅自转换盘符、反斜杠、根目录或挂载点，要求用户选择本机路径
- [[E-270]]　图形界面或自启进程找不到 shell 中已安装的 agent
    - 触发：agent 只通过 `.zshrc`、`.bashrc` 等 shell 启动文件加入 `PATH`，而 macOS/Linux GUI 或服务没有继承这些变量
    - 期望：先使用用户配置的绝对路径，再检查平台级固定候选目录；仍找不到时列出已检查位置并要求用户选择文件，不读取、不执行用户 shell 启动文件
- [[E-271]]　平台数据目录输入缺失或不是绝对路径
    - 触发：Windows `APPDATA` 缺失/相对，Linux `XDG_DATA_HOME` 缺失/相对，或主目录含空格与 Unicode
    - 期望：boot 注入冻结的宿主输入；Windows 只采用绝对 `APPDATA`，否则回落绝对 `homedir/AppData/Roaming`；macOS 用绝对 `homedir/Library/Application Support`；Linux 只采用绝对 `XDG_DATA_HOME`，否则回落绝对 `homedir/.local/share`，再追加应用目录。不得把 `~`、`${...}`、`%...%` 当路径交给文件系统；主目录本身不绝对则返回 `E_DATA_DIR_UNRESOLVABLE`。**`~` 禁令只针对词首的波浪号展开符**（`~`、`~user`、`~/x`）——shell 的波浪号展开也只在这种情况下发生；出现在路径中间的 `~` 是字面文本，最典型的是 Windows 8.3 短名（`C:\Users\RUNNER~1\…`、`C:\PROGRA~1\…`），把这类绝对路径判为未展开会让 daemon 在普通 Windows 机器上直接拒绝启动。实现按 `/^~/` 判定，`${...}` 与 `%...%` 两条规则不变

## 实施沉淀

<!-- notes:begin -->
- platform 用判别联合封装原生文件系统失败，code 直接取 10 节的事实源；错误层可据此构造 `AppError`，platform 不得另建错误码注册表，否则 `codes.ts` 投影会出现两个权威来源。
- 配置提供了路径就只校验该值，缺失时才枚举固定候选。坏链接、无执行位和外来平台格式均不得继续尝试同名候选，否则配置错误会被另一份安装静默掩盖。
- Windows 对外保留规范化的盘符或 UNC 路径，只在调用文件系统前加 `\\?\` / `\\?\UNC\`。命名空间前缀进入配置或共享启动契约会造成不必要的持久化差异。
- POSIX 先用 `lstat/readlink` 留下原始链接和可报告目标，再以 `realpath`、普通文件与 `X_OK` 决定可执行性。失败不缓存，避免文件修复后仍被旧结果阻断。
- platform 不读 PATH、`ComSpec` 或 shell 启动文件；调用方可显式注入 `windowsComSpecPath`，否则使用固定系统候选。不得为发现 agent 放宽 `process.env` 的唯一读取边界。
- `DaemonLaunchSpec.args` 允许空格和 shell 元字符，因为它们仍是独立 argv；schema 拒绝的是字符串命令、相对 file/cwd 和额外字段。
- M1-T7 在拿到 `launchKind: 'com-spec'` 时必须调用 `wrapForComSpec(executable.sourcePath, args, executable.file)`，然后原样消费冻结对象；不能继续追加参数或额外拼串、转义。`resolveExecutable` 的 ComSpec 分支只返回已验证的脚本和解释器路径，`argsPrefix` 为空。
- Windows CLI 包装脚本通过 `%*` 转发给原生程序，参数经历外层 ComSpec 和批处理转发两次解析。`quoteForCmd()` 先编码原生 argv 所需的引号与反斜杠，再对包括引号在内的 cmd 元字符转义两次；脚本路径只经过外层 cmd，因此只转义一次。只处理反斜杠引号会让引号后的 `&` 成为命令，未保护的 `%变量名%` 会被展开。包装接口不负责猜测脚本内部新增的 shell、`call` 或自定义参数处理方式。
- `wrapForComSpec()` 在启动前拒绝包含 NUL、CR、LF 的参数，返回 `E_VALIDATION` 和 `details.argumentIndex`；正常参数仍须保留原值、个数和顺序。
- `platform.test.ts` 在 Windows 上实际启动 `.cmd` 与 `.bat`，通过 Node 回显最终 argv，覆盖普通/空/多参数、空格、Unicode、引号、分号、`&`、`^`、`%`、`!`、尾部反斜杠及组合输入。带空格、中文和元字符的脚本目录也参与测试；无害文件哨兵检测额外命令，显式测试变量检测意外展开。非 Windows 环境跳过这组原生批处理用例，不把字符串断言算作 Windows 实机证据。
