# M9-T27　修复生产配对入口并固定真浏览器回归

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯、按窗口数呈现的任务流水线泳道与「会话已归档」历史行、顶栏两个流水线开关，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值、「能否收口」、泳道分配、阶段推进与会话归档都是 daemon 给的字段）；指派面板的分组模型下拉、登录态徽标与刷新按钮、参照条的「来源」段同样只呈现 daemon 下发的字段，不算取值链
- 前置依赖：[[M1-T10]]、[[M2-T2]]、[[M9-T24]]、[[M9-T25]]、[[M9-T26]]、[[M10-T4]]
- 完成后解锁：[[M1-T11]]

## 输入 / 产出

- **输入**：M9-T25 的七路由装配；M9-T26 的启动令牌链；M2-T2 的本机一次性配对码；M10-T4 的 daemon 静态托管；2026-09-21 主干 `e5084d7` 真浏览器复现：`app.tsx` 只注册 landing，`routes.tsx` 把 `#/pair` 降级为 hash 文本（诊断证据，不作测试 fixture）
- **产出**：`e2e/pairing-entry.test.ts` 的独立生产配对冒烟、`vitest.pairing.config.ts`、根 `smoke:pair` 脚本与 Playwright 依赖、Ubuntu CI 配对冒烟 job；如生产装配仍缺 `pair`，定点修复 `app.tsx` / `routes.tsx`；失败截图与 daemon 日志收在 gitignored `e2e/artifacts/`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 从干净 Web 生产构建与全新临时数据目录启动真实 `packages/daemon/bootstrap.mjs`，浏览器从 `/` 进入后必须归一到 `#/pair`，出现可编辑的地址和配对码输入及可操作的确认按钮，不得只显示 hash 字面量或缺少配对容器的空元素
此断言同时在 1280×800 和 390×844 下验证（[[E-224]]）
2) 真实浏览器输入 daemon 实际写出的短期一次性码，经公开 `POST /api/v1/pair/claim` 返回令牌并导航到 `#/`
码用后失效，不能通过注入 sessionStorage、mock fetch、路由拦截或生产测试钩子绕过配对（[[E-06]]、[[E-226]]）
3) 产物中的主 JS、CSS 与本地字体成功加载，`data-style-loaded=true`，computed `--page` 与 body 背景非透明
浏览器中 `/api/v1/health` 返回 200
失败时记录截图、DOM 摘要、daemon stdout/stderr，上传与留存的日志必须对本机控制台允许输出的配对码及令牌脱敏（[[E-175]]）
4) `pnpm -w smoke:pair` 可独立运行，执行完关闭浏览器/daemon 并清理临时数据与码
Ubuntu CI 运行该脚本且失败阻断，`pnpm -w check` 同样通过
不把这一入口冒烟冒充 M1-T11 的文档导入、真实派发与 SSE 到 DOM 主流程（[[E-265]]）

## 必须处理的边界

- [[E-06]]　同网段但连不上
    - 触发：手机与 PC 不同网段，或 WiFi 开了 AP 隔离
    - 期望：配对失败报到具体环节（「扫到码但连不上 host:port」），并提供手填地址兜底
- [[E-175]]　无外网环境
    - 触发：手机壳冷启动、局域网 daemon 可达但无公网
    - 期望：字体与 Web UI 同源同命运，随 daemon 静态产物一起托管，**不单独引入 CDN**
- [[E-224]]　壳内首次加载 hash 为空
    - 触发：`tauri://localhost`、`https://localhost`、daemon 的 `/` 三处加载
    - 期望：启动即归一化为 `#/`，**不得出现无 hash 的中间态白屏**
- [[E-226]]　**全新装机的自举困境**
    - 触发：零已配对设备、两个壳都未就绪，而 `POST /pair/code` 需 device 令牌
    - 期望：daemon 必须能把一次性配对码**输出到本机控制台或数据目录文件**；POSIX 文件模式固定 `0600`，Windows DACL 只允许当前用户，用后即删。**不得为此新增第四个免鉴权端点**
- [[E-265]]　三平台矩阵任一失败
    - 触发：Windows、macOS、Ubuntu 任一 runner 的 workspace check、平台集成测试或桌面壳构建失败
    - 期望：整体发布检查失败；不得把失败平台降级成可忽略项后继续标记三平台版本
