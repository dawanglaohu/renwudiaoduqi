# M9-T11　停止的乐观呈现与离线态

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯、按窗口数呈现的任务流水线泳道与「会话已归档」历史行、顶栏两个流水线开关，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值、「能否收口」、泳道分配、阶段推进与会话归档都是 daemon 给的字段）；指派面板的分组模型下拉、登录态徽标与刷新按钮、参照条的「来源」段同样只呈现 daemon 下发的字段，不算取值链
- 前置依赖：[[M9-T9]]、[[M9-T5]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：M9-T5 的连接状态
- **产出**：`local-intent` Map（event-bus 旁的 mutable Map）、`offline-banner.tsx`、`store/connection-store.ts`（只放 07 节四个字段）、`store/notice-store.ts`（回滚横幅）、`features/run-deck/use-stop-intent.ts`（一帧内置态与失败回滚）、`features/run-deck/use-connection-state.ts`（SSE→connection-store 的唯一接线；07 节只允许 features 层订阅 api/event-bus）

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 按停止键后**一帧内**本地置态并写明「你在第 N/M 步停止」，不等回包
服务端事件到达即清 intent，失败则清 intent + 横幅回滚（[[E-157]]）
2) 断连时顶栏显示「离线，最后同步于 X」并**禁用派发按钮**，恢复后自动补拉（[[E-12]]）
3) daemon 未运行时明确提示「电脑上的调度服务未启动」，**而不是连接超时**（[[E-04]]）
4) 版本不兼容时提示升级而不是抛底层错误（[[E-14]]）

## 必须处理的边界

- [[E-04]]　未开桌面直接从手机派活
    - 触发：daemon 未运行时手机端发起派发
    - 期望：明确提示「电脑上的调度服务未启动」，而不是连接超时
- [[E-12]]　壳内 WebView 与 daemon 断连
    - 触发：网络中断或 daemon 停止
    - 期望：顶部显示「离线，最后同步于 X」并禁用派发按钮，避免用户以为任务已派出；恢复后自动补拉事件
- [[E-14]]　两端版本不一致
    - 触发：只更新了桌面壳或只更新了手机壳
    - 期望：daemon 暴露 API 版本号，壳启动时校验，不兼容时提示升级，而不是抛底层错误
- [[E-157]]　写操作与事件流打架
    - 触发：客户端发起「中止运行中的任务」
    - 期望：走 POST 接口，最终状态一律以回流事件为准，UI 不拿 POST 响应体直接改状态

## 实施沉淀

<!-- notes:begin -->
- 停止的乐观呈现与状态回流解耦（E-157）：按停止键后必须在一帧内反馈，但不能直接改 `run.state`（最终状态以服务端 SSE 过去式事件为准）。管线收敛至 `features/run-deck/use-stop-intent.ts`，停止点击时同步在 0ms 内写入 event-bus 旁的 `localIntents` mutable Map（`{runId, kind: 'stopping', atStep}`），返回「你在第 N/M 步停止」，绝不写进 zustand 镜像（避免一份数据两处缓存导致服务端确认后残留）；调用方注入 POST，接口成功时保持原样静待服务端 `run.state_changed` / `run.exited` / `run.aborted` 事件自动清理 Map；接口失败则清理 Map 并往 notice slice 写入回滚横幅（`notice-store`），且错误不向外抛出造成未捕获异常。
- 连接状态架构与派发防护（E-12, 07:249, 07:298）：`connection-store` 严格遵循 07:249 约束，仅保留 `status`、`lastSyncedAt`、`lastEventId`、`needsPairing` 四个字段与基础 setter / reset，store 目录完全不依赖 `src/api`。`canDispatch` 严格作为 selector（`selectCanDispatch` / `useCanDispatch`）导出，禁止将派生值存入 store。连接状态由 `features/run-deck/use-connection-state.ts` 单向驱动，复用全应用唯一的 SSE 连接；当连接从 offline/reconnecting 恢复至 online 时，由 store 的 `setStatus` 触发一次 `triggerResync()` 全量补拉，无需业务层轮询。
- 服务未启动与连接超时的语义隔离（E-04）：移动端或桌面端无法连接 daemon 时，`OfflineBanner` 在 `isDaemonRunning === false` 或 `daemonErrorReason === 'daemon_down'` 时强制呈现明确文案「电脑上的调度服务未启动」，显式阻止回落为「连接超时」或技术异常字串，避免用户误判为网络延迟。
- 契约版本不兼容的平滑降级（E-14）：校验 `apiVersion` 与客户端共享常量 `CURRENT_API_VERSION`（'v1'）。发生不兼容时直接返回不兼容信息并在顶栏渲染升级提示横幅，不抛出底层未捕获异常或阻断整页渲染，防止客户端直接白屏崩毁。
- 组件视觉规范与分层约束（11 节）：`OfflineBanner` 保持为纯展示层组件（props in / callback out），完全不直连 store 或 api，全量使用 Tailwind 设计 token（`bg-down-soft`, `text-meta`, `rounded-sm` 等）及 4px 栅格；移除重连态的 `animate-pulse`，遵循 11 节「全页唯一连续动画是运行轨呼吸环」的交互原则。
