# M9-T11　停止的乐观呈现与离线态

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯、按窗口数呈现的任务流水线泳道与「会话已归档」历史行、顶栏两个流水线开关，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值、「能否收口」、泳道分配、阶段推进与会话归档都是 daemon 给的字段）；指派面板的分组模型下拉、登录态徽标与刷新按钮、参照条的「来源」段同样只呈现 daemon 下发的字段，不算取值链
- 前置依赖：[[M9-T9]]、[[M9-T5]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：M9-T5 的连接状态
- **产出**：`local-intent` Map、`offline-banner.tsx`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 按停止键后**一帧内**本地置态并写明「你在第 N/M 步停止」，不等回包
服务端事件到达即清 intent，失败则清 intent + 横幅回滚（[[E-157]]）
2) 断连时顶栏显示「离线，最后同步于 X」并**禁用派发按钮**，恢复后自动补拉（[[E-12]]）
3) daemon 未运行时明确提示「电脑上的调度服务未启动」，**而不是连接超时**（[[E-04]]）
4) 版本不兼容时提示升级而不是抛底层错误（[[E-14]]）

## 必须处理的边界

- [[E-04]]　未开桌面直接从手机派活
    - 触发：daemon 未运行时手机端发起派发
    - 期望：明确提示「电脑上的调度服务未启动」，而不是连接超时
- [[E-12]]　壳内 WebView 与 daemon 断连
    - 触发：网络中断或 daemon 停止
    - 期望：顶部显示「离线，最后同步于 X」并禁用派发按钮，避免用户以为任务已派出；恢复后自动补拉事件
- [[E-14]]　两端版本不一致
    - 触发：只更新了桌面壳或只更新了手机壳
    - 期望：daemon 暴露 API 版本号，壳启动时校验，不兼容时提示升级，而不是抛底层错误
- [[E-157]]　写操作与事件流打架
    - 触发：客户端发起「中止运行中的任务」
    - 期望：走 POST 接口，最终状态一律以回流事件为准，UI 不拿 POST 响应体直接改状态

## 实施沉淀

<!-- notes:begin -->
- 停止的乐观呈现与状态回流解耦（E-157）：按停止键后必须在一帧内反馈，但不能直接改 `run.state`（最终状态以服务端 SSE 过去式事件为准）。实现采用 `localIntents` mutable Map 与 zustand `activeStopIntents` 结合，停止点击时同步在 0ms 内写入「你在第 N/M 步停止」；若 POST 接口失败则立即清除 intent 并弹出横幅回滚提示（`rollbackNotice`）；若接口成功则等待服务端 `run.state_changed` / `run.exited` / `run.aborted` 事件清除 intent，避免写操作与事件流乱序打架。
- 断连离线态与派发防护（E-12）：`canDispatch` 统一在 `connection-store` 单点计算，当连接为 `offline`、`reconnecting`、`needsPairing` 或 daemon 未运行时严格置为 false，确保派发按钮立即被禁用。通过 `registerResyncHandler` 注册恢复回调，状态自 offline/reconnecting 恢复至 online 时自动触发全量补拉，无需业务层轮询。
- 服务未启动与连接超时的语义隔离（E-04）：移动端或桌面端无法连接 daemon 时，底层 fetch 错误常被笼统包装成 timeout 或 network error。`getOfflineErrorMessage` 和 `OfflineBanner` 在 `isDaemonRunning === false` 时强制呈现明确文案「电脑上的调度服务未启动」，显式阻止回落为「连接超时」或技术异常字串，避免用户误判为网络延迟。
- 契约版本不兼容的平滑降级（E-14）：校验 `GET /version` 的 `apiVersion` 与客户端共享常量 `CURRENT_API_VERSION`（'v1'）。发生不兼容时直接标记 `isVersionCompatible = false` 并在顶栏渲染升级提示横幅，不抛出底层未捕获异常或阻断整页渲染，防止客户端直接白屏崩毁。
- 组件与状态分层约束：`OfflineBanner` 保持为纯展示层组件（props in / callback out），完全不直连 store 或 api，所有颜色样式收敛至 tokens.css 的 CSS 变量；`connection-store` 提供低频连接状态管理与乐观停止辅助，高频运行日志与流事件继续与 zustand 隔离。
<!-- notes:end -->
