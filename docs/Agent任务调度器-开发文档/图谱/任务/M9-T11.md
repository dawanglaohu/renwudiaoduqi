# M9-T11　停止的乐观呈现与离线态

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值与「能否收口」都是 daemon 给的字段）
- 前置依赖：[[M9-T9]]、[[M9-T5]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：M9-T5 的连接状态
- **产出**：`local-intent` Map、`offline-banner.tsx`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 按停止键后**一帧内**本地置态并写明「你在第 N/M 步停止」，不等回包
服务端事件到达即清 intent，失败则清 intent + 横幅回滚（[[E-157]]）
2) 断连时顶栏显示「离线，最后同步于 X」并**禁用派发按钮**，恢复后自动补拉（[[E-12]]）
3) daemon 未运行时明确提示「电脑上的调度服务未启动」，**而不是连接超时**（[[E-04]]）
4) 版本不兼容时提示升级而不是抛底层错误（[[E-14]]）

## 必须处理的边界

- [[E-04]]　未开桌面直接从手机派活
    - 触发：daemon 未运行时手机端发起派发
    - 期望：明确提示「电脑上的调度服务未启动」，而不是连接超时
- [[E-12]]　壳内 WebView 与 daemon 断连
    - 触发：网络中断或 daemon 停止
    - 期望：顶部显示「离线，最后同步于 X」并禁用派发按钮，避免用户以为任务已派出；恢复后自动补拉事件
- [[E-14]]　两端版本不一致
    - 触发：只更新了桌面壳或只更新了手机壳
    - 期望：daemon 暴露 API 版本号，壳启动时校验，不兼容时提示升级，而不是抛底层错误
- [[E-157]]　写操作与事件流打架
    - 触发：客户端发起「中止运行中的任务」
    - 期望：走 POST 接口，最终状态一律以回流事件为准，UI 不拿 POST 响应体直接改状态
