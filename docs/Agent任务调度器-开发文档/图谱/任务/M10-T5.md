# M10-T5　三平台 CI、桌面产物与支持清单

- 所属模块：[[M10]]　**桌面壳与手机壳**——只做窗口与单实例、系统通知、令牌安全存储三件事的两个原生容器，外加 daemon 未运行时的引导、Windows/macOS/Linux 桌面构建与运行依赖检测。壳按界面声明的可选桥接接口去实现，界面在没有壳时按能力探测降级，因此依赖方向恒为壳→界面
- 前置依赖：[[M10-T4]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：M10-T4 的共享打包管线；17 节测试矩阵
- **产出**：GitHub Actions 三平台 workflow、运行时启动清单解析器与前置检查 launcher、平台/架构支持清单、人工 GUI 验收模板

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) Windows、macOS、Ubuntu runner 均执行 `pnpm -w check`、平台集成测试、daemon 启动 smoke 与 Tauri 构建，任一失败阻断整个版本（[[E-265]]）
2) 每个平台把安装产物展开到含空格与 Unicode 的临时根目录，以该位置模拟 `current_exe/resource_dir` 并生成经共享 schema 校验的绝对 `DaemonLaunchSpec`
smoke 必须用同一个 `file/args/cwd` 真正启动 daemon 并通过健康检查，安装包不得预写构建机绝对路径
daemon、路径/进程适配与桌面壳任一产品层缺失都阻断发布（[[E-209]]、[[E-257]]）
3) Linux 包元数据或 WebView 前命令行 launcher 检测 WebKitGTK/GTK，缺依赖时进程在创建 GUI 前列出发行版对应安装指引
该检查本身纳入 Ubuntu runner（[[E-258]]）
4) CI 不声称自动完成 GUI 交互
每个平台另有人工启动/通知/路径验收记录（[[E-266]]）
5) 支持清单逐项列出 OS、版本基线、CPU 架构和资产名
Windows arm64、Intel/Apple Silicon macOS 与 Linux x64/arm64 缺漏时标“未覆盖”，不提供错架构包（[[E-259]]）
6) macOS 未签名/未公证产物只标构建验证件，正式发布门禁失败（[[E-267]]）
7) Linux 写明 Ubuntu 已验证版本与 WebKitGTK/GTK 依赖，其他发行版只标尽力兼容（[[E-258]]、[[E-268]]）
8) Node/Tauri 提升平台下限时，CI、环境矩阵、发布说明缺一项更新都失败（[[E-260]]）

## 必须处理的边界

- [[E-209]]　升级后自启项指向旧路径
    - 触发：安装位置、macOS `.app` 位置或 Node 脚本参数变化，原生自启项仍引用旧启动方式
    - 期望：壳每次启动根据实际安装位置解析完整 `DaemonLaunchSpec`；`register` 幂等接收该冻结对象，逐字段校验原生注册项与当前绝对 `file`、`args[]`、绝对 `cwd`，不一致则重写；桌面按钮和自启共用同一对象且恒不经 shell，安装包不得预写固定绝对路径；重写失败降级为「需手动启动」并给出该平台可复制命令
- [[E-257]]　平台支持只完成一半
    - 触发：某平台能启动 daemon，但桌面壳无法构建或启动
    - 期望：该平台不得标记为完整支持；三平台发布检查失败，并列出缺失的产品层
- [[E-258]]　Linux 缺少桌面运行依赖
    - 触发：WebKitGTK、GTK 或 Tauri v2 要求的系统库缺失，GUI 甚至无法创建窗口
    - 期望：安装包前置检查或命令行 launcher 在启动 WebView 前列出缺失包与当前发行版可执行的安装指引；不得依赖 GUI 自己报错，该环境不计入已验证平台
- [[E-259]]　CPU 架构没有发布资产
    - 触发：Windows arm64、Apple Silicon、Intel Mac、Linux x64/arm64 中某架构未进入构建矩阵
    - 期望：发布清单明确标「未覆盖」，下载入口不向该架构提供其他架构安装包
- [[E-260]]　上游收紧系统版本下限
    - 触发：Node.js 22 或 Tauri v2 升级后提高最低 OS、libc 或 WebKit 要求
    - 期望：依赖升级必须同步调整 CI 矩阵、环境矩阵与发布说明；未同步则发布检查失败
- [[E-265]]　三平台矩阵任一失败
    - 触发：Windows、macOS、Ubuntu 任一 runner 的 workspace check、平台集成测试或桌面壳构建失败
    - 期望：整体发布检查失败；不得把失败平台降级成可忽略项后继续标记三平台版本
- [[E-266]]　CI 无法执行完整 GUI 测试
    - 触发：托管 runner 缺少交互式桌面或图形会话不稳定
    - 期望：CI 至少验证安装包生成、daemon 启动和平台适配器集成；GUI 操作进入按平台记录的人工验收清单，不得伪报自动化通过
- [[E-267]]　macOS 产物未签名或未公证
    - 触发：CI 没有 Apple 签名/公证凭据
    - 期望：产物只标为构建验证件，不作为可直接分发的正式安装包；正式发布必须由单独签名门禁放行
- [[E-268]]　Linux 只在 Ubuntu 验证
    - 触发：CI 使用 Ubuntu，用户运行其他发行版
    - 期望：发布说明写明 Ubuntu 已验证及依赖基线；其他发行版标为尽力兼容，不表述为同等级支持
