# M8-T5　重派、换 agent 与原样重跑

- 所属模块：[[M8]]　**派发调度**——决定什么时候把哪个任务、用哪个 agent 与哪个模型、以什么权限派出去，并按批次、并行窗口、每 agent 并发与路径冲突限流，在三个闸门处停或放行、失败或重派时重新入队；判定本批分支是否都进了 HEAD、触发收口运行、按收口报告派修复运行与管理收口轮次也归它；泳道（窗口槽位）分配、任务终态后的补位、查 bug 与收口模式两个开关的持久化同样归它——泳道分配是它算出的派生数据。凡涉及顺序、名额、放行、重派的都归它；任务指派写进派发快照、阶段取值链（任务指派 → 阶段覆盖 → agent 默认）与收口指派设置也归它——它是唯一决定「这一阶段用谁跑」的地方，M7 只消费结果
- 前置依赖：[[M8-T3]]
- 完成后解锁：[[M7-T5]]、[[M9-T13]]

## 输入 / 产出

- **输入**：M8-T3 的派发路径
- **产出**：`POST /runs/:id/rerun`、换 agent 重派

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 换 agent 重派时新建运行记录、旧运行转只读留存
默认开干净 worktree，除非显式选「在原改动上继续」（[[E-121]]）
2) 「原样重跑」严格复用原派发载荷（任务／agent／模型／批次／权限档），**不出现任何选择器**，需一次确认（[[E-177]] 的服务端侧）
3) 重跑时原 agent 不在线则立即失败并明示，**禁止静默回退到别的 agent 或模型**（[[E-178]]）
4) 文档快照已变更时禁止重跑并提示去桌面端处理（[[E-180]]）
5) 所属批次已被超越时允许重跑但提示批次错位（[[E-179]]）
6) 模型名在派发时已失效时不做前置白名单校验、直接透传，仅在 agent 结构化报错时精确标注，否则按 [[E-348]] 转人，失败后标「派发失败·模型无效」且该任务不占用窗口名额（[[E-36]]）

## 必须处理的边界

- [[E-121]]　换 agent 重派
    - 触发：用户判断当前 agent 不合适
    - 期望：新建运行记录，旧运行转只读留存；默认开一个干净 worktree，除非用户显式选「在原改动上继续」
- [[E-177]]　手机重跑撞上已在跑
    - 触发：该任务已从桌面端重派或已重新在跑
    - 期望：按钮置灰 + 幂等键拦截，绝不产生第二次运行
- [[E-178]]　重跑时原 agent 不在线
    - 触发：原派发载荷指向的 agent 不可达
    - 期望：快速失败并明示「该 agent 不在线」；**禁止静默回退到别的 agent 或别的模型**——那等于替用户做了一次未授权的编排选择
- [[E-179]]　批次错位重跑
    - 触发：该任务所属批次已被后续批次超越
    - 期望：允许重跑但横幅提示批次错位（如「批次 3 已开始，本条属批次 2」）；单人自用下允许 + 告警优于阻断
- [[E-180]]　拿旧快照盲跑
    - 触发：决策 13 的三个标记显示该任务文档快照已变更
    - 期望：手机端禁用重跑并提示去桌面端处理
- [[E-348]]　运行零产出退出
    - 触发：任何 kind 的运行在首条内容事件（`agent_message_chunk`／`agent_thought_chunk`／`tool_call` 任一）之前进程退出（不论退出码，含 0）、启动超时或错误类事件；dsh 无流式时最终输出解析不出任何内容也算
    - 期望：判定只看事件 kind、不匹配 stderr／stdout 文本（与 E-330 同一结构规则）。实施运行（含 `origin=rework`／`wrapup-fix`）：`exited → reviewing → awaiting_human` 两跳（reason `exited_before_output`），**不跑机械检查、不派审查、不计 `rework_count`**，`tasks.lane_no` 置 NULL 并发 `lane.released{reason:'awaiting_human'}`（E-326）；审查运行走 E-62、查 bug 运行走 E-323、收口运行走 E-295。事务后重跑一次该 agent 的登录态探测（dsh 不探）。审批卡（`GateDto.context`）附退出码、退出信号、stderr 末 20 行（来自该 run 最后一条 `run.exited` 事件的 `stderrTail`，已脱敏，旧事件缺字段显示「无记录（旧运行）」）、刚探测的登录态，与固定提示句「agent 未产出任何内容就退出，常见原因：未登录、模型名不可用、参数被拒」，不写「未登录」定论；动作「重跑」（复用 `POST /runs/:id/rerun`）、「换 agent 重派」、「标失败」（`awaiting_human → failed`），手机端只有重跑与标失败；每次都转人不自动重试；同一 agent 多条泳道同时零产出各自转人、不暂停该 agent；启动超时与 spawn 失败仍走既有 `starting → failed`、手动停止不进本判定；内容事件之后才失败走既有路径并正常计数
- [[E-36]]　模型名在派发时已失效
    - 触发：用户在别处删了该模型，或手填了不存在的名字
    - 期望：不做前置白名单校验（清单本就可能不全），直接透传；仅在 agent 结构化报错时精确标注，否则按 E-348 转人；失败后标「派发失败·模型无效」并原样展示 agent 报错，该任务不占用批次窗口名额

## 实施沉淀

<!-- notes:begin -->
1. 原样重跑（`rerunRun`）必须严格复用 `previousRun.snapshot_id`，禁止重新调用 `takeSnapshotForTask`。派发快照锁定了该任务派发时刻的契约与提示词，重跑属于原派发的后续尝试而非重新编排；重新建快照会刷新时间戳与快照 ID，破坏下游流水线阶段（M7/M8-T9）对原任务指派与快照归属的一致性追踪（决策 129）。
2. 文档快照变更检查（E-180）直接比对决策 13 的三标记（`has_accept_changed`、`has_prompt_changed`、`is_removed_from_doc`），任一为 1 立即抛 `E_SNAPSHOT_STALE` 阻断重跑并提示去桌面端；注意不能在重跑检查前重新生成快照，否则 `takeSnapshotForTask` 内部会把变更标记重置为 0，误伤刚进入的拦截判定。
3. 批次错位（E-179）通过比对同文档其他批次状态，存在序号大于本任务批次且状态非 `idle`（`running`/`paused`/`done`）即判定为被超越。单人自用场景坚持「告警优于阻断」，返回结构化提示文案（如「批次 3 已开始，本条属批次 2」）并在事件流记录，但不中断重跑生成。
4. 换 agent 重派（E-121）默认工作区隔离策略锁死为 `'fresh'` 干净 worktree，仅在请求显式传入 `'reuse'` 时才在原改动上继续，避免不同厂商 agent 因工作区残留文件导致语法或格式冲突。
5. 模型名在派发与重跑时严格不做任何前置白名单校验，直接透传字符串；当子进程退出报错模型无效时，由 `handleModelInvalid` 终态化为 `'failed'` 并写入 `queued_reason='派发失败·模型无效'`，使任务退出 active 集合从而立即释放并发名额（E-36）。
<!-- notes:end -->
