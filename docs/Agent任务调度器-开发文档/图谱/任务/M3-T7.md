# M3-T7　查 bug 提示词取用与快照

- 所属模块：[[M3]]　**文档接入**——把 `docs-data.js` 变成本产品唯一的任务真相源（任务、依赖、批次、并行窗口、验收标准、边界编号、实施与审查两段提示词），并负责内容指纹、派发时快照与文档重出后的三个标记；收口提示词 `dispatchBatches` 的按任务集合匹配也归它。凡「这条数据来自文档」的都归它
- 前置依赖：[[M3-T5]]
- 完成后解锁：[[M7-T8]]

## 输入 / 产出

- **输入**：M3-T5 的快照取用接口；04 节的 `dispatch[id].bug` 输入协议（unattended-run 1.3.1，未落地措辞）
- **产出**：`service/bughunt-context.ts` 的 `getBughuntContext(taskId)`、`domain/bughunt-builtin-prompt.ts`（内置通用查 bug 提示词常量）、`service/docs.ts` 导入 `dispatch[id].bug` 落 `tasks.bug_prompt`、派发快照落 `dispatch_snapshots.bug_prompt`、新增一个迁移（两列 `bug_prompt TEXT NULL`）

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 导入文档时把 `dispatch[id].bug` 逐字存 `tasks.bug_prompt`，缺失或不是字符串存 NULL，**不冻结派发、不报 `E_DOC_SOURCE_UNREADABLE`**
派发时随三段快照一起复制进 `dispatch_snapshots.bug_prompt`（[[E-19]]、[[E-316]]）
2) `getBughuntContext(taskId)` 返回**派发快照那一份** `bugPrompt` 与 `promptSource='docs'`
快照为 NULL 时返回内置通用查 bug 提示词并 `promptSource='builtin'`，不抛错、不回落到当前文档、不让查 bug 阶段停摆（[[E-316]]）
3) 返回的材料逐字不改写、不截断
文档指纹在途中变化时仍取快照那一份，不热改（[[E-50]]）
4) `bug_prompt` 不进任何事件 payload、日志只打长度与前 200 字节（16 节）
迁移为普通 `ALTER TABLE … ADD COLUMN`，旧库直开不回填

## 必须处理的边界

- [[E-19]]　验收标准被事后改动
    - 触发：同一 id 的 input/output/accept 文本被改过
    - 期望：派发时把这三段快照进任务记录；列表标「文档已更新，与派发时不一致」
- [[E-316]]　查 bug 提示词文档未提供
    - 触发：派发快照里的 `dispatch[id].bug` 缺失或不是字符串
    - 期望：用内置通用查 bug 提示词并标「文档未提供」（`prompt_source='builtin'`，记 warn）；取派发快照那一刻的文档，不按当前文档；材料逐字引用不改写，外层包装说明覆盖其中的提交／推送／再点审查等步骤
- [[E-50]]　批次执行途中文档变了
    - 触发：执行期间任务 ID/contractHash 指纹变化，包括任务行未变而范围、条款或提示词变化
    - 期望：已派任务继续用快照跑完，后续派发自动暂停并要人确认新文档，绝不热改在途任务
