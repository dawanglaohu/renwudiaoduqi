# M9-T15　设置页：设备、配对与浏览器模式

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯、按窗口数呈现的任务流水线泳道与「会话已归档」历史行、顶栏两个流水线开关，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值、「能否收口」、泳道分配、阶段推进与会话归档都是 daemon 给的字段）；指派面板的分组模型下拉、登录态徽标与刷新按钮、参照条的「来源」段同样只呈现 daemon 下发的字段，不算取值链
- 前置依赖：[[M9-T4]]、[[M2-T2]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：M2-T2 的配对接口
- **产出**：`settings-devices-page`、`pair-page`、`shell-bridge` 降级

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 配对失败报到具体环节（「扫到码但连不上 host:port」）并提供手填地址兜底（[[E-06]]）
2) 已配对设备可列出并单独吊销，吊销后该设备连接立即断开（[[E-127]]）
3) 保存设备令牌而非 IP
PC 局域网 IP 变化后已授权设备不需重新授权（[[E-09]]）
4) 允许配对多台设备，每台独发一枚可单独吊销的令牌（[[E-125]]）
5) 无壳时令牌落 `sessionStorage`，顶栏常驻提示同时写明「关闭标签后需重新配对」**与「本模式下没有系统通知」**（[[E-229]]）
6) 壳存在时以壳安全存储为唯一真相源，启动清掉会话副本，**绝不双写**（[[E-227]]）
7) 同一浏览器第二个标签需重新配对，设备名默认带「浏览器 · 时间」便于辨认与吊销（[[E-228]]）

## 必须处理的边界

- [[E-06]]　同网段但连不上
    - 触发：手机与 PC 不同网段，或 WiFi 开了 AP 隔离
    - 期望：配对失败报到具体环节（「扫到码但连不上 host:port」），并提供手填地址兜底
- [[E-09]]　PC 局域网 IP 变化
    - 触发：DHCP 续租或切换网络
    - 期望：手机保存设备令牌而非 IP；重连走重新发现或提示重扫码，已授权设备不需重新授权
- [[E-125]]　配对多台设备
    - 触发：手机 + 平板 + 第二台电脑
    - 期望：允许，每设备独发一枚可单独吊销的令牌，仍不引入用户实体
- [[E-127]]　设备丢失或令牌泄露
    - 触发：手机丢了
    - 期望：桌面端能列出已配对设备并一键吊销；吊销后该设备的活动连接立即断开
- [[E-227]]　先浏览器后装壳
    - 触发：壳存在但 sessionStorage 里有旧令牌
    - 期望：以**壳的安全存储为唯一真相源**，启动时清掉会话副本，**绝不双写**
- [[E-228]]　同一浏览器开第二个标签
    - 触发：sessionStorage 按标签隔离
    - 期望：第二个标签需重新配对；设备名默认带「浏览器 · 时间」以便在设备列表里辨认并批量吊销，避免设备列表被脏条目淹没
- [[E-229]]　浏览器模式的能力缺失
    - 触发：无壳运行
    - 期望：顶栏提示除「关闭标签后需重新配对」外，**必须同时写明「本模式下没有系统通知」**，否则用户会以为提醒功能坏了

## 实施沉淀

<!-- notes:begin -->
- 令牌存储边界：令牌绝对不进入 `localStorage`。`localStorage` 跨同源所有标签页持久共享，一旦写入会导致标签页间会话边界失效，破坏无用户模型的单设备鉴权语义；无壳时严格写入 `sessionStorage` 保证标签页隔离，装壳后以原生密钥库为唯一真相源，启动即清空会话副本避免产生双写。
- 浏览器设备名默认值：免壳模式下用户开启新标签页会产生独立的会话配对诉求，若设备名均默认为空白或固定值，桌面端设备列表将充斥大量无法区分的无效条目；按时间戳生成「浏览器 · MM-DD HH:mm」让用户可在管理列表中一眼定位具体标签并精准吊销。
- 令牌与网络 IP 解耦：鉴权凭证完全收敛于 Authorization 头中的 Bearer 令牌，服务端不将客户端 IP 作为授权主体；当局域网 DHCP 续租或客户端漫游导致 PC 局域网 IP 变动时，仅需更新请求目标 BaseURL，已有设备令牌持续有效，无需重新申请配对码。
- 配对异常诊断定位：移动端或跨网段访问最常见故障为路由器开启 AP 隔离或子网掩码不同，此时配对码本身并未失效；捕获连接错误后直接报出「扫到码但连不上 host:port」并自动展开手填输入框，防止用户误判为配对码过期而在服务端频繁无谓重置。
<!-- notes:end -->
