## 实施沉淀

- 契约单一事实源（AC 2, E-234）：运行、批次、任务状态的常量数组与联合类型只定义在 `packages/shared/src/api`；daemon 仅 import/re-export。`TaskState` 为 `RunState | 'never_dispatched'`，三个状态域均由架构测试扫描重复定义。
- 架构守护（AC 2）：`shared-contracts.test.ts` 同时扫描具名状态类型、状态数组、`[...RUN_STATES]` 派生和跨行字面量联合，覆盖单行与多行重复定义。
- 快照派生（AC 5）：`/api/v1/snapshot` 复用一次全量运行查询，按 `manual_state → attempt_no 最大的 runs.state → never_dispatched` 生成任务状态；`listAgents` 在依赖边界即约束为 `readonly AgentEntryDto[]`。真实 Fastify 测试覆盖三层优先级、六个具名数组与设备鉴权。
- 编译期与运行时双重闭环（AC 4, E-234）：前端通过 `satisfies Record<RunState, string>` 确保编译期穷尽 13 个后端运行状态，任何后端状态增减若前端未配置对应映射，`tsc -b --noEmit` 直接阻断；`StatusState` 显式联合 `(typeof RUN_STATE_TO_STATUS)[RunState]`，并通过双向类型排除断言 `_assertStatusStatesExhaustive` 与单测保持与 `STATUS_SHAPES` 的 1:1 映射，杜绝「先上线后补形状」。
- 具名契约与唯一工具（AC 1, AC 3）：`packages/shared/src` 不含 `unknown[]` 或 `state: string`；快照六数组、日志搜索命中、收口问题和计划项分别使用具名 DTO，并由架构测试锁定。`isRecord` 纯类型守卫仅定义在 `packages/shared/src/lib/is-record.ts`。
