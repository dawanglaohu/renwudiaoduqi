# M10-T3　手机壳（Capacitor / Android）

- 所属模块：[[M10]]　**桌面壳与手机壳**——只做窗口与单实例、系统通知、令牌安全存储三件事的两个原生容器，外加 daemon 未运行时的引导、Windows/macOS/Linux 桌面构建与运行依赖检测。壳按界面声明的可选桥接接口去实现，界面在没有壳时按能力探测降级，因此依赖方向恒为壳→界面
- 前置依赖：[[M10-T1]]
- 完成后解锁：[[M10-T4]]

## 输入 / 产出

- **输入**：M10-T1 的契约
- **产出**：`packages/shell-mobile/`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 同一份 web 产物，`webDir` 指向同一次构建，**不为壳单独打第二份产物**
2) 令牌存 Capacitor Preferences，**不落 localStorage**
3) 硬件返回键映射到 `history.back()`，hash 栈退到底时才允许退出 app，**不得一按就退出**（[[E-225]]）
4) app 被系统杀掉后重开用本地 `Last-Event-ID` 补拉未读，**不引入离线推送**（[[E-147]]、[[E-11]]）
5) 「未注册自启」在手机侧不产生任何告警或 UI（[[E-211]]）
6) 无 Android 构建环境时降级为浏览器打开局域网 URL，界面验收标准不变（[[E-200]]）

## 必须处理的边界

- [[E-11]]　手机离线推送不可达
    - 触发：app 不在前台且连接已断
    - 期望：第一版只保证 app 前台/保持连接时的本地通知 + 重开后的未读列表；真正的离线推送需 APNs/FCM（要服务端），明确不做并在 UI 说明
- [[E-147]]　手机 app 被系统杀后重开
    - 触发：Android 后台回收
    - 期望：用本地保存的 Last-Event-ID 补拉未读，不引入离线推送
- [[E-200]]　壳模块受阻而界面已就绪
    - 触发：Android 构建环境不可用导致手机壳延期
    - 期望：「客户端界面」必须能在桌面浏览器直连 daemon 使用，其验收标准**不因壳模块延期而改变**
- [[E-211]]　手机壳没有自启这回事
    - 触发：手机端启动
    - 期望：根本不调用该触发接口，且「未注册自启」在手机侧**不产生任何告警或 UI**；两壳的不对称仅表现为「少调一个接口」
- [[E-225]]　Android 硬件返回键
    - 触发：用户按返回
    - 期望：必须映射到 `history.back()`；hash 栈退到底时才允许退出 app，**不得一按就退出**
