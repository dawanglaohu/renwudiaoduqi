# M10-T3　手机壳（Capacitor / Android）

- 所属模块：[[M10]]　**桌面壳与手机壳**——只做窗口与单实例、系统通知、令牌安全存储三件事的两个原生容器，外加 daemon 未运行时的引导、Windows/macOS/Linux 桌面构建与运行依赖检测。壳按界面声明的可选桥接接口去实现，界面在没有壳时按能力探测降级，因此依赖方向恒为壳→界面
- 前置依赖：[[M10-T1]]
- 完成后解锁：[[M10-T4]]

## 输入 / 产出

- **输入**：M10-T1 的契约
- **产出**：`packages/shell-mobile/`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 同一份 web 产物，`webDir` 指向同一次构建，**不为壳单独打第二份产物**
2) 令牌存 Capacitor Preferences，**不落 localStorage**
3) 硬件返回键映射到 `history.back()`，hash 栈退到底时才允许退出 app，**不得一按就退出**（[[E-225]]）
4) app 被系统杀掉后重开用本地 `Last-Event-ID` 补拉未读，**不引入离线推送**（[[E-147]]、[[E-11]]）
5) 「未注册自启」在手机侧不产生任何告警或 UI（[[E-211]]）
6) 无 Android 构建环境时降级为浏览器打开局域网 URL，界面验收标准不变（[[E-200]]）

## 必须处理的边界

- [[E-11]]　手机离线推送不可达
    - 触发：app 不在前台且连接已断
    - 期望：第一版只保证 app 前台/保持连接时的本地通知 + 重开后的未读列表；真正的离线推送需 APNs/FCM（要服务端），明确不做并在 UI 说明
- [[E-147]]　手机 app 被系统杀后重开
    - 触发：Android 后台回收
    - 期望：用本地保存的 Last-Event-ID 补拉未读，不引入离线推送
- [[E-200]]　壳模块受阻而界面已就绪
    - 触发：Android 构建环境不可用导致手机壳延期
    - 期望：「客户端界面」必须能在桌面浏览器直连 daemon 使用，其验收标准**不因壳模块延期而改变**
- [[E-211]]　手机壳没有自启这回事
    - 触发：手机端启动
    - 期望：根本不调用该触发接口，且「未注册自启」在手机侧**不产生任何告警或 UI**；两壳的不对称仅表现为「少调一个接口」
- [[E-225]]　Android 硬件返回键
    - 触发：用户按返回
    - 期望：必须映射到 `history.back()`；hash 栈退到底时才允许退出 app，**不得一按就退出**

## 实施沉淀

<!-- notes:begin -->
1. **单一构建产物保证**：Capacitor 的 `webDir` 严格配置为 `../web/dist`，直接复用 web 包的输出目录（web 自身的 `base: './'` 与 es2020 目标由后续 web 构建任务落地）。桌面壳、手机壳与 daemon 托管三处消费同一份产物，不为壳单独打第二份。
2. **凭据安全下沉原生层**：设备令牌（`agsched.token`）由 `@capacitor/preferences` 写入 Android SharedPreferences，全过程杜绝写入 `localStorage`。`createPreferencesTokenStore()` 的返回值就是 `ShellBridge.tokenStore`，与网页端降级至 `sessionStorage` 的逻辑严格解耦；把它交给 web 的 `registerNativeShellAdapter()` 是 web 入口侧的接线，不在本任务。
3. **返回键分级消费与防误退**：Android 物理返回键映射至 `history.back()`。在单页 Hash 路由机制下，通过导航深度计数器结合 `location.hash` 归一化判定。若当前存在子视图历史或非根 Hash，优先执行浏览器历史后退；仅当栈深度清零且处于 `#/` 根路径时才调用 `App.exitApp()`，避免用户轻触返回键直接杀死应用。
4. **断线与重启事件补偿（无离线推送服务）**：拒绝引入 APNs/FCM 等第三方云中继服务以避免将本地工程上下文暴露给外网。后台进程被系统回收后，将本地 Preferences 持久化的 `Last-Event-ID` 作为重连请求头恢复 SSE 流；若窗口过期则由前端触发 REST 全量快照更新游标。
5. **双壳不对称性静默抹平**：移动端不具备桌面端系统级自启项能力。手机壳不暴露、不注册、不调用任何自启动接口，同时抑制所有自启缺失警告，确保运行时无任何额外弹窗或日志告警。
6. **明文 daemon 需要两层开关（踩过的坑）**：AndroidManifest 的 `usesCleartextTraffic` 只管 Android OS 层的明文套接字策略，WebView 从 `https://localhost` 请求 `http://〈局域网 IP〉:7817` 还要过混合内容策略一层。只配前者时 fetch 与 SSE 全被 WebView 拦掉，壳看起来装好了却连不上 daemon；两层都开（manifest 明文 + `android.allowMixedContent`）才真正可用。
7. **壳代码的加载与注册入口不在本任务**：web 入口 `main.tsx` 尚未落地，故本任务只交库与原生工程；`initializeMobileShell()` / `createMobileShellAdapter()` 需要由 web 侧在 `platform === 'capacitor'` 时注册给 `registerNativeShellAdapter()`，接线归 M10-T4 的共享打包管线。E-147 的游标读写通道受桥接契约「能力只有三件」约束，尚待裁定（见 PR 审查记录 DOC_ISSUE）。
