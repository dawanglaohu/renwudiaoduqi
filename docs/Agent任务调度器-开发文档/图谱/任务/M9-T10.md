# M9-T10　审批卡与闸门交互

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯、按窗口数呈现的任务流水线泳道与「会话已归档」历史行、顶栏两个流水线开关，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值、「能否收口」、泳道分配、阶段推进与会话归档都是 daemon 给的字段）
- 前置依赖：[[M9-T7]]、[[M8-T4]]
- 完成后解锁：[[M9-T20]]

## 输入 / 产出

- **输入**：M8-T4 的闸门数据
- **产出**：`components/gate-card.tsx`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 审批卡**就地插在该流时间轴里**，禁止 import dialog、禁止 `createPortal`，**不弹全局模态**打断其他还在跑的流（[[E-109]]）
2) 四段固定顺序：要做什么／影响什么／**凭什么（带可点链接回产出该结论的那一步）**／三个动作，「改一下」不是可选项
3) 底部写明「无人应答不会自动批准，任务保持等待」
4) 全局只用一个未处理计数徽标提示
5) 手机上审批派发前闸门时文案必须写「批准派发」，**不得含糊成「同意」**（[[E-182]]）

## 必须处理的边界

- [[E-109]]　半自动命中审批点
    - 触发：某个流需要人批准，其他流还在跑
    - 期望：审批卡就地插在该流的时间轴里，全局只用一个未处理计数徽标提示；不弹全局模态打断其他还在跑的流
- [[E-182]]　审批文案含糊
    - 触发：用户在手机上审批「派发前闸门」
    - 期望：文案必须如实写「批准派发」，不得含糊成「同意」，否则用户不知道自己刚刚启动了一次运行
