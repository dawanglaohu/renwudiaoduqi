# M10-T1　壳桥接契约与能力探测

- 所属模块：[[M10]]　**桌面壳与手机壳**——只做窗口与单实例、系统通知、令牌安全存储三件事的两个原生容器，外加 daemon 未运行时的引导、Windows/macOS/Linux 桌面构建与运行依赖检测。壳按界面声明的可选桥接接口去实现，界面在没有壳时按能力探测降级，因此依赖方向恒为壳→界面
- 前置依赖：[[M9-T1]]
- 完成后解锁：[[M10-T2]]、[[M10-T3]]

## 输入 / 产出

- **输入**：07 节的三件能力
- **产出**：`shared/src/shell/bridge-contract.ts`、`web/src/shell/` 两个文件

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 能力只有三件（`tokenStore`／`notify`／`hostHint`）加两个只读位，契约以类型形式约束，**加第四件需先改文档**
2) 探测同步读两个全局并在模块加载时冻结，**禁止用 userAgent 判定、禁止 try/catch 试探、禁止渲染中重复探测**
3) 全仓除 `src/shell/` 两文件外不出现 `__TAURI` / `Capacitor`，由 `check-forbidden.ts` 机检
4) 无壳时三件能力各有降级实现，桌面浏览器直连**功能不缺**（[[E-200]]）

## 必须处理的边界

- [[E-200]]　壳模块受阻而界面已就绪
    - 触发：Android 构建环境不可用导致手机壳延期
    - 期望：「客户端界面」必须能在桌面浏览器直连 daemon 使用，其验收标准**不因壳模块延期而改变**

## 实施沉淀

<!-- notes:begin -->
- 契约约束硬性收敛：严格按照 07 节约定只保留 tokenStore、notify、hostHint 三件能力及 platform、capabilities 两只读位，未因方便扩展而添加配置注入或进程生命周期等第四件能力，保持壳只作纯容器、不掺杂调度业务。
- 同步探测与冻结时机：探测逻辑通过同步检查 window.__TAURI_INTERNALS__ 与 window.Capacitor?.isNativePlatform?.() 在模块加载时刻立即冻结成不可变常量 SHELL；否决在 React 组件生命周期或 Hook 渲染中动态探测方案，避免因全局变量注入时序产生界面水合不一致或额外 re-render。
- 浏览器降级与安全边界（E-200 / E-227）：无壳直连浏览器模式下，令牌持久化严格限制在 sessionStorage，禁止任何向 localStorage 或 IndexedDB 写入明文令牌的行为；同时在检测到原生壳就绪时主动移除残留的 sessionStorage 副本，杜绝多宿主混用时的双写状态扩散。
- 模拟通知降级体验：浏览器不支持或拒绝通知权限时，降级逻辑通过修改 document.title 前缀 (N) 及派发回退监听器，为后续未读徽标提供统一数据源；严格禁止触发阻塞式 alert() 或在浏览器环境中伪造原生通知能力。
<!-- notes:end -->
