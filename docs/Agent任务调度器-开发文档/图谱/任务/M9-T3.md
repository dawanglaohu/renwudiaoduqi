# M9-T3　自写 hash 路由与守卫

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值与「能否收口」都是 daemon 给的字段）
- 前置依赖：[[M9-T1]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：07 节的七条路径
- **产出**：`app/routes.tsx`、`navigateTo()`、`route-guard.tsx`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 七条平铺路径 + 两个单段参数，hash 模式
三种加载源（daemon `/`、`tauri://localhost`、`https://localhost`）下行为一致
2) 命中未登记 hash 时渲染「未知路径」页并给「回到运行甲板」，保留顶栏，**绝不白屏、绝不抛异常**（[[E-222]]）
3) 路径参数指向不存在的对象时由**页面自身**渲染「该运行不存在或已被清理」，不由路由层判 404（[[E-223]]）
4) 首次加载 hash 为空时启动即归一化为 `#/`，**无中间态白屏**（[[E-224]]）
5) 组件内不出现 `location.hash = ...`，导航一律经 `navigateTo()`

## 必须处理的边界

- [[E-222]]　命中未登记的 hash
    - 触发：`#/xxx` 或 `#/run/` 缺参数
    - 期望：渲染「未知路径」页并给「回到运行甲板」，保留顶栏；**绝不白屏、绝不抛异常**
- [[E-223]]　路径参数指向不存在的对象
    - 触发：运行已清理、任务已从文档移除
    - 期望：由**页面自身**渲染「该运行不存在或已被清理」，不由路由层判 404，壳与顶栏保持在位
- [[E-224]]　壳内首次加载 hash 为空
    - 触发：`tauri://localhost`、`https://localhost`、daemon 的 `/` 三处加载
    - 期望：启动即归一化为 `#/`，**不得出现无 hash 的中间态白屏**
