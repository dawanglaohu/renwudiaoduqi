# M7-T4　rework 回灌与重试上限

- 所属模块：[[M7]]　**审查流水线**——对已结束的运行做「合不合格」的判定：先跑本地机械检查，通过后以只读档派一个 agent 跑文档给出的审查提示词，产出 pass / rework / doc-issue 并回灌 rework 意见；从审查输出提取返工文本、按能力位选回灌／恢复／新开返工运行，以及解析收口运行的八段报告，也归它。凡「判定一次运行的结果」的都归它
- 前置依赖：[[M7-T3]]、[[M6-T6]]
- 完成后解锁：[[M7-T5]]

## 输入 / 产出

- **输入**：M7-T3 的判定；M6-T6 的注入通路
- **产出**：rework 循环

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) rework 意见经回话通路回灌原会话，重试计数 +1
**自动重试上限默认 2 次**，超限转「待人确认」，不无限自动改（[[E-55]]）
2) 回灌后 diff 反而缩小或回退时仍走同一套检查，计数照加，达上限转人（[[E-68]]）
3) 人工打回时必须能附一句话意见，该意见复用同一条 rework 通路（[[E-59]]）
4) 本任务只负责「原会话活着且 `canReply`」的回灌分支
进程已结束或能力位为假时把 `{reviewRunId, targetRunId, reworkText, source}` 交 M7-T5 按能力位选恢复或新开，代码中不存在「先试投递失败再降级」的路径（[[E-279]] 的入口侧）

## 必须处理的边界

- [[E-279]]　无续接能力的 agent 需要返工
    - 触发：被审实施运行的 adapterKind 既不能回灌也不能恢复（dsh headless）
    - 期望：新开实施运行（`origin=rework`、同任务 attempt_no+1、同 worktree 与分支），提示词必须自包含：返工块原文 + 派发快照实施提示词里「收到返工指令时」规则段 + 工作区指针 + 只改列出条目；分支由能力位决定，不由投递结果决定
- [[E-55]]　全自动下审查反复判 rework
    - 触发：审查连续不通过
    - 期望：重试上限默认 2 次，超限转「待人确认」，不无限自动改；回灌、恢复后回灌、新开返工运行三种投递方式计入同一个计数
- [[E-59]]　用户点「打回」
    - 触发：审查后人工判定需返工
    - 期望：必须能附一句话意见，该意见复用 rework 通路回灌原会话
- [[E-68]]　rework 后改动反而回退
    - 触发：回灌意见后 diff 缩小或撤回
    - 期望：仍走同一套检查，重试计数 +1，达上限转人
