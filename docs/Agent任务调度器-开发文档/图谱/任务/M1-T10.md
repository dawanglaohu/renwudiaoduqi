# M1-T10　三平台单实例锁、配置装载与最小常驻 daemon

- 所属模块：[[M1]]　**运行底座**——让 daemon 在这台机器上稳定跑起来并把字节落到磁盘上：进程单实例与端口、启动自检、开机自启注册、数据目录、结构化存储的连接与迁移、日志正文的追加写与字节偏移索引、以及全部平台差异（进程树终止、路径规范化与长路径、配置目录、子进程编码）的唯一收口。凡与操作系统、磁盘、进程存活打交道而不带任何业务概念的都归它
- 前置依赖：[[M1-T1]]、[[M1-T2]]、[[M1-T3]]
- 完成后解锁：[[M2-T1]]

## 输入 / 产出

- **输入**：M1-T1 的垫片与 boot；M1-T3 的 platform 路径契约；M1-T2 已落地的数据库与迁移工厂
- **产出**：`src/platform/` 锁原语（锁路径/权限在 platform 收口）、`src/boot/lock.ts`、`src/config/env.ts`、`src/boot/container.ts`（composition root，M2-T1 在此挂插件）、由 `src/main.ts` 调用的 `createHttpServer()` 工厂（本任务建实例并 listen，提供最小 `GET /api/v1/health` 响应 `{ok:true}`；M2-T1 在同一路由补齐 10 节诊断字段并挂插件，不重复注册）、daemon `test/{unit,integration,arch}/`（按 17 节覆盖真实入口、双用户/不同端口互斥、原生权限、陈旧锁并发回收、探活结果不确定、端口占用与启动顺序）

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 三平台锁路径明确：Windows `%PROGRAMDATA%\agent-scheduler\daemon.lock`、macOS `/Library/Application Support/agent-scheduler/daemon.lock`、Linux `/var/lib/agent-scheduler/daemon.lock`
锁文件存 `{pid, uid, startedAt, port, bind}`
同机多用户共用同一锁
2) 锁文件权限：Windows ACL 仅 Administrators/SYSTEM
macOS root:admin 0600
Linux root:root 0600
用户权限不足时打印所需权限并以非 0 退出，不静默降为每用户锁
3) 第二实例读出持有者 pid 与端口并以 `GET /api/v1/health` 探活
二者都活→打印英文诊断 `Existing instance pid=... port=...`（含义为「已有实例 pid= port=」）后以非 0 退出
两不活→删陈旧锁后重新原子竞争
仅一项存活或任一探测结果不确定时保留锁并拒绝启动，防止持锁者尚未 listen 时被误删
4) listen 被占（EADDRINUSE）时释放锁并以非 0 退出（[[E-03]]）
5) `AGSCHED_PORT=abc` 在 config/env.ts 报错
**config/env.ts 是全仓唯一允许读 `process.env` 的文件**
6) 启动顺序：配置装载 → 锁 → 数据目录 → （库/迁移 M1-T2） → createContainer → createHttpServer → listen → listen 成功后报告 ready（本任务无 jobs 段）

## 必须处理的边界

- [[E-03]]　端口被占用或多实例
    - 触发：daemon 端口被占用，或同机多用户登录
    - 期望：端口可配置 + 单实例锁；锁范围为「整机一个 daemon」（Windows 锁文件位于 `C:\ProgramData\agent-scheduler\daemon.lock`，每用户目录不构成单例边界；`AGSCHED_PORT` 不同的第二个实例同样被拒）。第二个实例启动时读锁文件中的持有者 pid，并探测进程与锁中 bind/port 对应的 `GET /api/v1/health`（绑定通配地址时用本机回环地址连接）：存活（同一锁 / 同一端口仍在听）→打印已有实例 pid 与端口后以非 0 退出，「把请求让给已有实例」即拒绝自身启动并提示客户端直连该 pid 对应端口，不做进程间透传；持有者进程和健康端点都不活→删陈旧锁重新原子竞争；仅一项存活或任一探测不确定时保留锁并拒绝启动，不能把尚未 listen 的持有者当成陈旧锁。端口被非本 daemon 进程占用时 listen 失败、释放锁并以非 0 退出，不在另端口上起服务。锁覆盖 daemon 全生命周期，持有者只有进程退出才释放；绝不允许两个调度器同时推进同一批次
