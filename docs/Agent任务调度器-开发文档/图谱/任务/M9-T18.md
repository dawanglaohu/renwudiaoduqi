# M9-T18　逐任务指派面板与并发瓶颈说明

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯、按窗口数呈现的任务流水线泳道与「会话已归档」历史行、顶栏两个流水线开关，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值、「能否收口」、泳道分配、阶段推进与会话归档都是 daemon 给的字段）；指派面板的分组模型下拉、登录态徽标与刷新按钮、参照条的「来源」段同样只呈现 daemon 下发的字段，不算取值链
- 前置依赖：[[M9-T16]]、[[M4-T6]]、[[M8-T2]]
- 完成后解锁：[[M9-T23]]

## 输入 / 产出

- **输入**：M4-T6 的取值链；M8-T2 的窗口计算
- **产出**：`assign-panel.tsx`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 四步引导第三步是**逐任务指派**而不是「给整批选一个模型」：每行一个任务，各自选 agent／模型／思考强度，已指派行显示所选值可点回改（[[E-108]] 的第三步）
2) **同一个 agent 允许被指派多次，每次是一个独立会话**并显示将要使用的会话序号（[[E-31]]、决策
7、决策 52）
3) 第四步显示并发三者取 min 的结果，并**明确指出是并行窗口、该 agent 上限还是用户设定成了瓶颈**，不只给一个可放行数字（[[E-52]]）
4) 某 agent 已达并发上限时其余任务仍可指派给别家，**不空转等待**（[[E-47]] 的呈现侧）

## 必须处理的边界

- [[E-108]]　零运行空态
    - 触发：首次使用或全部空闲
    - 期望：空态直接是「选文档 → 选批次 → 选模型 → 派发」的四步引导，而不是一张插画
- [[E-31]]　同一 agent 并发多任务
    - 触发：一个 agent 被同时派多个任务
    - 期望：每任务独立 session 与独立工作区（grok 用自带 --worktree，其余用 git worktree 兜底），并设每 agent 并发上限
- [[E-47]]　单 agent 并发满但窗口有空位
    - 触发：某 agent 达到并发上限，整体窗口未满
    - 期望：空位让给其他 agent 的任务，不空转等待
- [[E-52]]　并发瓶颈来源不明
    - 触发：实际并发数低于用户预期
    - 期望：实际并发取 min(窗口数, 每 agent 上限, 用户设定)，UI 显示这三者中哪一个成了瓶颈；用户可向下调，向上超过窗口数需显式解锁并提示后果

## 实施沉淀

<!-- notes:begin -->
1. 逐行独立配置而非整批套用（AC 1、E-108）：否决了「整批一键统一套用模型」的快捷开关或批量指派按钮。四步引导的核心是「逐任务独立治理」，批量套用会破坏对每个任务模型与思考强度的精细权衡，且容易导致不支持思考强度的 Agent 被批量误赋参数。界面坚持每行独立配置，已指派行可随时点击「修改指派」回改。
2. 同 Agent 多次指派的独立会话语义（AC 2、E-31、决策 7、决策 52）：同一个 Agent 被指派给多个任务时，必须作为相互隔离的独立 session 执行。前端在指派阶段即为每个 Agent 动态计算并展示将分配的会话序号（`会话 #1`、`会话 #2`），使用户在派发前便明确认知它们是独立的运行流与工作树，避免误以为同一 Agent 执行会共享上下文或产生写竞争。
3. 单 Agent 满额空位顺延机制（AC 4、E-47）：当某一 Agent 被指派的任务数达到其 `maxConcurrency`（如 2/2）时，界面仅在该 Agent 关联的编辑行和选项中提示满额排队，绝不在全局阻塞其他未指派任务或将其他 Agent 设为不可用。并行窗口的空余槽位必须向其他仍有容量的 Agent（如 Grok、Claude）开放，防止调度器因单一 Agent 满额而空转等待。
4. 并发瓶颈明确归因与越界显式解锁（AC 3、E-52）：有效并发容量取 `min(窗口数, 每 agent 上限, 用户设定)`，但 UI 不能只给出一个单薄的放行数字。展示层必须三因子并列对比并用醒目标签指出具体瓶颈来源（拓扑窗口、Agent 配额还是用户设置）。用户设定允许向下调，但向上超过拓扑窗口数时必须显式勾选解锁框并展示后果提示——因为超过依赖拓扑窗口数并不会带来物理加速，反而会误导用户对并发能力的预期。
5. M4-T6 思考强度与缺省值展示纪律（E-254、E-34、E-41）：不支持思考强度的 Agent（如 Grok）强制置 `null` 并在界面显示 `—`，严禁出于「UI 对齐」或「避免空值」而伪造 `low`/`medium` 默认档，切换 Agent 时立即重置模型覆盖。所有 daemon 下发指标在数据未就绪或为 `null` 时一律显示 `—`，严格杜绝前端私自补 `0` 冒充有效状态。
