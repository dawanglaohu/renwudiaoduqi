# M6-T3　进度信号与通用字段提取

- 所属模块：[[M6]]　**运行监管**——管一次运行从启动到结束的全过程：状态机（「已退出」与「已落地」分开）、收流与落盘编排、按游标分段回读与厂商会话文件的只读引用、进度信号、停滞检测、中止与 daemon 重启后的对账、回话投递。凡「这一次运行现在怎么样、它说过什么」的都归它
- 前置依赖：[[M6-T2]]、[[M5-T3]]
- 完成后解锁：[[M6-T4]]

## 输入 / 产出

- **输入**：M6-T2 的事件流；M5-T3 的 diff
- **产出**：进度字段：最后一条消息／改动文件数／耗时／token

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 四家共用一套逻辑，不做深度语义解析
2) token 用量字段名或单位不一致或缺失时显示「—」，**不得拿 0 冒充**（[[E-26]]）
3) 从首帧读回 agent 自报的实际模型并在与所选不一致时高亮（[[E-37]] 的呈现侧）

## 必须处理的边界

- [[E-26]]　token 用量字段缺失
    - 触发：各家字段名/单位不一致或压根没有
    - 期望：缺失时显示「—」，不得拿 0 冒充
- [[E-37]]　环境变量与命令行参数冲突
    - 触发：claude 的 `env.ANTHROPIC_MODEL` 等覆盖与 `--model` 同时存在
    - 期望：派发时在子进程环境里清掉这类变量，并从 NDJSON 首帧读回 agent 自报的实际模型，UI 显示「实际使用：X」，与所选不一致时高亮
