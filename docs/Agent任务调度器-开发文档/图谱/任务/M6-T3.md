# M6-T3　进度信号与通用字段提取

- 所属模块：[[M6]]　**运行监管**——管一次运行从启动到结束的全过程：状态机（「已退出」与「已落地」分开）、收流与落盘编排、按游标分段回读与厂商会话文件的只读引用、进度信号、停滞检测、中止与 daemon 重启后的对账、回话投递；任务到达终态后结束并归档该任务全部会话（进程还在走 `killTree` 两阶段），归档后会话引用只读、不得复用，也归它。凡「这一次运行现在怎么样、它说过什么」的都归它
- 前置依赖：[[M6-T2]]、[[M5-T3]]
- 完成后解锁：[[M6-T4]]

## 输入 / 产出

- **输入**：M6-T2 的事件流；M5-T3 的 diff
- **产出**：进度字段：最后一条消息／改动文件数／耗时／token

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 五家共用一套逻辑，不做深度语义解析
dsh 无流式时只在完成后补最终字段（[[E-253]]）
2) token 用量字段名或单位不一致或缺失时显示「—」，**不得拿 0 冒充**（[[E-26]]）
3) 从首帧读回 agent 自报的实际模型并在与所选不一致时高亮
无首帧能力的 agent 保持未知，不猜测（[[E-37]] 的呈现侧）

## 必须处理的边界

- [[E-253]]　dsh 全程无流式事件
    - 触发：dsh 只有 `--profile headless`，跑完才给最后一条 assistant 文本，中途没有任何可归一化的 `session/update` 事件
    - 期望：能力位新增 `hasStreamingEvents`，dsh 置假。**禁止伪造中间事件充数**：运行轨对该 agent 只显示「已派发 → 运行中 → 完成/失败」三段，逐步耗时退化为整段耗时，日志栏在运行期显示「该 agent 不提供过程输出，完成后一次性写入」。UI 按能力位灰掉「逐步展开」而不是留个永远空的列表（与 E-117 同一手法）
- [[E-26]]　token 用量字段缺失
    - 触发：各家字段名/单位不一致或压根没有
    - 期望：缺失时显示「—」，不得拿 0 冒充
- [[E-37]]　环境变量与命令行参数冲突
    - 触发：claude 的 `env.ANTHROPIC_MODEL` 等覆盖与 `--model` 同时存在
    - 期望：派发时在子进程环境里清掉这类变量，并从 NDJSON 首帧读回 agent 自报的实际模型，UI 显示「实际使用：X」，与所选不一致时高亮
