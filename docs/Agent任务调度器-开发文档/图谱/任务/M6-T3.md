# M6-T3　进度信号与通用字段提取

- 所属模块：[[M6]]　**运行监管**——管一次运行从启动到结束的全过程：状态机（「已退出」与「已落地」分开）、收流与落盘编排、按游标分段回读与厂商会话文件的只读引用、进度信号、停滞检测、中止与 daemon 重启后的对账、回话投递；任务到达终态后结束并归档该任务全部会话（进程还在走 `killTree` 两阶段），归档后会话引用只读、不得复用，也归它。凡「这一次运行现在怎么样、它说过什么」的都归它
- 前置依赖：[[M6-T2]]、[[M5-T3]]
- 完成后解锁：[[M6-T4]]

## 输入 / 产出

- **输入**：M6-T2 的事件流；M5-T3 的 diff
- **产出**：进度字段：最后一条消息／改动文件数／耗时／token

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 五家共用一套逻辑，不做深度语义解析
dsh 无流式时只在完成后补最终字段（[[E-253]]）
2) token 用量字段名或单位不一致或缺失时显示「—」，**不得拿 0 冒充**（[[E-26]]）
3) 从首帧读回 agent 自报的实际模型并在与所选不一致时高亮
无首帧能力的 agent 保持未知，不猜测（[[E-37]] 的呈现侧）

## 必须处理的边界

- [[E-253]]　dsh 全程无流式事件
    - 触发：dsh 只有 `--profile headless`，跑完才给最后一条 assistant 文本，中途没有任何可归一化的 `session/update` 事件
    - 期望：能力位新增 `hasStreamingEvents`，dsh 置假。**禁止伪造中间事件充数**：运行轨对该 agent 只显示「已派发 → 运行中 → 完成/失败」三段，逐步耗时退化为整段耗时，日志栏在运行期显示「该 agent 不提供过程输出，完成后一次性写入」。UI 按能力位灰掉「逐步展开」而不是留个永远空的列表（与 E-117 同一手法）
- [[E-26]]　token 用量字段缺失
    - 触发：各家字段名/单位不一致或压根没有
    - 期望：缺失时显示「—」，不得拿 0 冒充
- [[E-37]]　环境变量与命令行参数冲突
    - 触发：claude 的 `env.ANTHROPIC_MODEL` 等覆盖与 `--model` 同时存在
    - 期望：派发时在子进程环境里清掉这类变量，并从 NDJSON 首帧读回 agent 自报的实际模型，UI 显示「实际使用：X」，与所选不一致时高亮

## 实施沉淀

<!-- notes:begin -->
- **通用提取与无语义侵入（AC 1）**：Codex、Claude、Pi、Grok 经 M6-T2 归一化后统一产出 ACP（如 `agent_message_chunk`）与标准产品事件。进度提取仅关注阶段里程碑、末条助理消息、Token 统计、耗时与改动文件数，不构建私有 AST 或深度语法解析，避免厂商协议细节变更波及监管层。
- **dsh 无流式退化约束（E-253）**：dsh 运行仅提供 `--profile headless`，中途全无事件流。提取器通过 `hasStreamingEvents` 能力位显式区分，在进行中状态下严禁伪造中间事件充数，`lastMessage` 保持 null，逐步耗时退化为整段耗时并提示延迟写入；仅在退出终态（exited/landed/failed/aborted/interrupted）后从最终输出补齐最终字段。
- **Token 缺失真实语义（AC 2，E-26）**：不同厂商上报字段与粒度各异（部分仅有总数或输入，或存在字符串与非数值）。提取层归一化多级路径（`usage`/`tokenUsage`/`tokens`/`stats`/`vendor`）与字段别名；对缺失、负数或非法单元严格保留 `null`，呈现侧统一映射为全角破折号「—」，绝对不以 `0` 冒充，仅在输入和输出均具备合法整数且总数缺省时做自然求和。
- **首帧自报模型与未知判定（AC 3，E-37）**：首帧模型提取仅识别首帧（`run.started` 或初始化帧）中的模型自报信息。若首帧未自报（如 Codex/Pi/dsh），必须保持 `reportedModel = null`，绝不回退到 `selectedModel` 冒充实际使用，避免掩盖或伪造环境覆盖；仅当自报模型存在且规范化名称与所选模型不一致时才置 `modelMismatch = true` 触发 UI 高亮。
<!-- notes:end -->
