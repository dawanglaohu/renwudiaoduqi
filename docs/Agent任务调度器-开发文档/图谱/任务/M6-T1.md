# M6-T1　运行状态机与非法迁移拦截

- 所属模块：[[M6]]　**运行监管**——管一次运行从启动到结束的全过程：状态机（「已退出」与「已落地」分开）、收流与落盘编排、按游标分段回读与厂商会话文件的只读引用、进度信号、停滞检测、中止与 daemon 重启后的对账、回话投递；任务到达终态后结束并归档该任务全部会话（进程还在走 `killTree` 两阶段），归档后会话引用只读、不得复用，也归它。凡「这一次运行现在怎么样、它说过什么」的都归它
- 前置依赖：[[M1-T2]]
- 完成后解锁：[[M6-T2]]、[[M6-T5]]、[[M6-T6]]、[[M6-T10]]、[[M7-T1]]、[[M8-T3]]

- **输入**：09 节的状态机图与非法迁移表
- **产出**：`domain/run-state-machine.ts`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 状态机迁移表以纯函数实现，`domain/` 顶层零副作用，可被 Vitest 直接 import
2) `exited → landed` 的直接迁移在实现中不存在
落地只能由审查判定或人确认进入（[[E-23]]）
3) `interrupted` 为终态，任何出边都不存在（[[E-123]]）
4) 时钟与 id 从 DI 注入，状态机测试确定性可复现

## 必须处理的边界

- [[E-123]]　daemon 重启后的孤儿记录
    - 触发：重启后仍有状态为「运行中」的记录
    - 期望：启动时按 PID 对账，进程不存在则标「异常终止（daemon 重启）」，绝不推定成功
- [[E-23]]　退出码为 0 但活没干完
    - 触发：agent 自行放弃或上下文超限后正常退出
    - 期望：退出码不等于验收通过；状态机必须把「已退出」与「已落地」分开，后者只能由自动审查或人确认

## 实施沉淀

<!-- notes:begin -->
- 迁移表必须使用穷尽闭合的静态白名单而非排除黑名单：13 个状态的迁移空间有 169 种组合，黑名单必然漏掉非预期跃迁（如 queued → landed 或 failed → running）。白名单零出边的终态（landed/failed/aborted/interrupted）在结构上彻底杜绝后续迁移。
- 退出码与验收落地严格物理解耦（[[E-23]]）：`exited` 的目标有且仅有 `reviewing`，不存在 `exited → landed` 或 `exited → awaiting_human`。进程以退出码 0 结束只代表回合完成，合格落地必须经审查判定通过或由人工审核放行。
- daemon 重启的孤儿对账必须单向标定为终态（[[E-123]]）：`starting` / `running` / `awaiting_reply` 在重启后若进程已死，只能迁移至 `interrupted`；`interrupted` 没有任何出边，杜绝在途对账时被误推定成功或被后续任务覆盖状态。
- 时钟与 ID 生成器通过参数注入而不直接读取系统时钟或随机源：状态迁移伴随派发的 `run.state_changed` 事件时间戳 `ts` 与事件 `id` 由外部环境控制，使并发调度与状态迁移在单测中可完全复现与断言。
- 自动 rework 重试设有硬上限（默认 2 次，[[E-55]]）：在审查判定为 rework 时，超出上限的状态机迁移直接拦截并强制进入 `awaiting_human` 等待人工决策，避免自动化闭环无休止循环修改。
<!-- notes:end -->
