# M6-T1　运行状态机与非法迁移拦截

- 所属模块：[[M6]]　**运行监管**——管一次运行从启动到结束的全过程：状态机（「已退出」与「已落地」分开）、收流与落盘编排、按游标分段回读与厂商会话文件的只读引用、进度信号、停滞检测、中止与 daemon 重启后的对账、回话投递。凡「这一次运行现在怎么样、它说过什么」的都归它
- 前置依赖：[[M1-T2]]
- 完成后解锁：[[M6-T2]]、[[M6-T5]]、[[M6-T6]]、[[M7-T1]]、[[M8-T3]]

## 输入 / 产出

- **输入**：09 节的状态机图与非法迁移表
- **产出**：`domain/run-state-machine.ts`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 状态机迁移表以纯函数实现，`domain/` 顶层零副作用，可被 Vitest 直接 import
2) `exited → landed` 的直接迁移在实现中不存在
落地只能由审查判定或人确认进入（[[E-23]]）
3) `interrupted` 为终态，任何出边都不存在（[[E-123]]）
4) 时钟与 id 从 DI 注入，状态机测试确定性可复现

## 必须处理的边界

- [[E-123]]　daemon 重启后的孤儿记录
    - 触发：重启后仍有状态为「运行中」的记录
    - 期望：启动时按 PID 对账，进程不存在则标「异常终止（daemon 重启）」，绝不推定成功
- [[E-23]]　退出码为 0 但活没干完
    - 触发：agent 自行放弃或上下文超限后正常退出
    - 期望：退出码不等于验收通过；状态机必须把「已退出」与「已落地」分开，后者只能由自动审查或人确认
