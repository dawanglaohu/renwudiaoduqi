# M6-T6　回话投递与能力位约束

- 所属模块：[[M6]]　**运行监管**——管一次运行从启动到结束的全过程：状态机（「已退出」与「已落地」分开）、收流与落盘编排、按游标分段回读与厂商会话文件的只读引用、进度信号、停滞检测、中止与 daemon 重启后的对账、回话投递；任务到达终态后结束并归档该任务全部会话（进程还在走 `killTree` 两阶段），归档后会话引用只读、不得复用，也归它。凡「这一次运行现在怎么样、它说过什么」的都归它
- 前置依赖：[[M6-T1]]、[[M4-T8]]
- 完成后解锁：[[M6-T7]]、[[M6-T10]]、[[M7-T4]]、[[M7-T7]]

## 输入 / 产出

- **输入**：各适配器的注入通道与能力位
- **产出**：`POST /runs/:id/messages`、投递路径

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 「可回话」做成能力位，**UI 按能力位灰掉按钮而不是点了才报错**
不具备时返回 `E_CAPABILITY_UNSUPPORTED`（[[E-117]]）
2) 进程已死或管道已断时消息落地为「未送达」并保留原文可复制，**绝不静默丢弃或假装已发出**（[[E-113]]）
3) 会话已结束但支持 resume 的走「恢复会话后投递」并明示这是一次新运行
不支持恢复的禁用发送并提示改用重派（[[E-112]]）
4) 两端同时回话时按到达先后串行投递，每条记录来源设备与时间戳，**不做去重合并**（[[E-114]]）
5) 空消息拒绝提交
超长在发送前提示并让人确认截断点，**不静默截断**（[[E-116]]）
6) 写 stdin 时检查 `write()` 返回值并在 `drain` 后续写

## 必须处理的边界

- [[E-112]]　会话已结束后才回话
    - 触发：用户在 agent 回合结束后点发送
    - 期望：支持 resume/fork 的 agent 走「恢复会话后投递」并在 UI 明示这是一次新运行（新运行记录、新退出码）；不支持恢复的禁用发送并提示改用重派
- [[E-113]]　消息投递失败
    - 触发：进程已死或管道已断
    - 期望：消息落地为「未送达」并保留原文可复制，绝不静默丢弃或假装已发出
- [[E-114]]　两端同时回话
    - 触发：手机与桌面同时发消息给同一会话
    - 期望：按到达 daemon 的先后串行投递，每条消息记录来源设备与时间戳，不做去重合并
- [[E-116]]　空消息或超长消息
    - 触发：用户提交空内容，或超过 agent 输入上限
    - 期望：空消息拒绝提交；超长在发送前提示并让人确认截断点，不静默截断
- [[E-117]]　agent 不具备注入能力
    - 触发：后续接入的 agent 没有消息注入通道
    - 期望：「可回话」做成能力位，UI 按能力位灰掉按钮，而不是点了才报错
