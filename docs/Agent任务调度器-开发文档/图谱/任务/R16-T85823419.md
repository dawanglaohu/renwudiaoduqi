## 实施沉淀

<!-- notes:begin -->
**为什么选择 startDaemon() 而不是共享 smoke.test.ts 的实例**：AC1 要求隔离数据目录和符合生产锁权限，如果共享则两个 suite 的 daemon 数据相互干扰，配对码文件只能用一次，测试顺序变得脆弱。独立 daemon 让每个 suite 自足。

**断线恢复用 page.context().setOffline(true)**：Playwright 的 setOffline 只影响该 BrowserContext 发出的请求，不影响同进程中的 fetch()（测试进程 → daemon API），所以可以在断线期间用管理员 API 改值，然后恢复网络，验证页面能拿到新值。这是本测试的关键非显然依赖，三个月后维护者不要改成 process-level 断网——会让管理员 API 也断线。

**E-26 null 占位符验证时机**：daemon 首次启动 settings 表没有行，读侧补完整四键默认值（E-318），前端拿到的是有效值，因此不应出现「—」占位符。如果测试报「占位符出现」说明 daemon GET 返回了 null pipeline，去查 E-318 边界的 domain/pipeline-settings.ts 默认值逻辑。

**第二次写入不携旧四键（E-356）**：step 7 通过两次 API PATCH 验证：第一次改 wrapupMode，第二次的 PATCH body 中 wrapupMode 必须是第一次写入后的值，不能是初始值。如果测试失败说明前端缓存（use-pipeline-settings.ts 的 shared source）没有在第一次 SSE 回流后更新本地快照。

**GIF 证据约定**：本测试套件本身是可复跑的机器证据，`step 11` 记录了 GIF 的录制约定。真实 GIF 需要在 CI Ubuntu runner 上用 Playwright 的 page.video() 或 xvfb + ffmpeg 录制，并作为 artifact 上传。本任务范围不包含自动 GIF 录制——这需要 FFmpeg/gifski 依赖，超出有效路径范围，由审查方核实 WSL 补证录制的 GIF 是否满足 AC4。

**两条常驻说明位置差异**：顶栏（layout=topbar）用 React portal 把说明注入 [data-testid="topbar-pipeline-notes"]；设置页（layout=settings）说明 inline 展示。两个位置都需验证，step 5 验证初始状态，step 12 强制设置 bughunt=1/manual 后验证两处说明出现。

**AC2 手机档顶栏隐藏**：app.tsx:57 中顶栏开关用 `hidden min-[600px]:flex`，375px < 600px 所以 CSS display:none。DOM 节点仍存在（虚拟 DOM 不卸载），只是不可见。测试用 getComputedStyle 检查，不用 isVisible()——后者在 display:none 时同样返回 false，但对于「CSS 隐藏但 DOM 存在」的场景，page.evaluate 检查 computedStyle.display 更准确。
