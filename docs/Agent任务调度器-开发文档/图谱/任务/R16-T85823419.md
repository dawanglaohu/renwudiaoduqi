## 实施沉淀

<!-- notes:begin -->
**生产入口**：套件从隔离数据目录启动正式 daemon 与生产 Web，两台独立 Chromium 设备均经配对页面领取身份。浏览器令牌只从生产键 `agsched.token` 读取。Windows 本机机器锁 ACL 与旧 WSL 的 SQLite 预编译库限制本地运行；正式 Ubuntu CI 负责完整真实浏览器验证。

**界面与写入**：Playwright 度量分隔线几何、记录设置页独立 chunk 的网络响应，并在四档窄屏检查溢出。顶栏和设置页点击均发出真实 PATCH；只读请求事件记录四键请求体。DOM 观察器捕获短暂 pending 状态及旧高亮，随后检查 SSE 回流、第二设备同步及离线恢复负控。测试没有拦截或改写 HTTP。

**空值、错误与恢复**：页面脚本运行前安装只读 DOM 观察器，记录正式 GET 完成前的「—」占位帧；daemon 真实拒绝缺键与未知键。浏览器离线期间点击开关，验证就地错误、pending 解除与原值保持，重连后通过界面重试并对照 daemon 值。

**GIF 来源**：套件在配对、桌面顶栏、设置页、SSE 同步及断线恢复后的已断言状态调用 `page.screenshot()`，用 ffmpeg 编码 GIF；旁边的 provenance JSON 记录服务 HEAD、origin 与各帧覆盖范围。CI 在成功或失败时均上传证据。

**套件收尾顺序**：daemon 实例锁是机器级的，根 `pnpm e2e` 在同一 runner 上串行跑三个套件。`afterAll` 把关浏览器、停 daemon 放在 finally 里；否则 GIF 编码失败（如缺 ffmpeg）会跳过停机，后续套件全部拿不到锁。两个 Ubuntu e2e job 都显式安装 ffmpeg。
