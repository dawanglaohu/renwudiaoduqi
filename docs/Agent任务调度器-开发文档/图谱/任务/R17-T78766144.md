## 实施沉淀

<!-- notes:begin -->
1. 原生值必须穿过运行行和指派快照，不能映射成最接近的三档来满足旧类型。Claude 命名档位以实际可执行文件的帮助能力为界；旧 CLI 继续走已有数字预算，冻结的路径与能力需成对保存。
2. `effortOptions: []` 是明确不支持，能力字段缺失是未知。有效模型包含 Agent 生效默认与当前配置，设置写入和新阶段指派都要清空明确不支持的强度；已有快照的返工与原样重跑保持原选择。
3. null 随入口含义不同：审查覆盖显式 null 清空，固定收口空值继承 follow，有 agentId 的手动收口未给字段则为 null。把这些入口复用同一种空值回落会改变既定优先级。
4. 手动收口的能力校验必须覆盖 tier 和 vendor 两形状。只在 vendor 分支拒绝无能力 Agent 会使 DSH 三档请求保存一个并不生效的 high；复验须同时核 HTTP 回应、运行列和 assignment_json，不能放宽 E-254 迁就这种记录。
5. 待复验按 changedFields 处理。仅祖先指纹改变且自身上下文等价的解析原语可独立复验；消费共享手动接口的任务须保留标记直到该能力义务得到真实通过证据，原绿色测试不能替代新增边界回归。
6. 流水线自定义模式的第一次写入省略 `effortVendor`。生效模型的 `effortOptions` 为 `[]` 时，服务端会补上 `effortVendor: null`。设置页用整段 JSON 比较请求和回显，键集不同就停在 `data-pending=true`，后面的模型和强度控件保持禁用。HTTP 200 和 SQLite 行不能算这次 DOM 保存完成。
