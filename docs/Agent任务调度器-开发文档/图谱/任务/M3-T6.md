# M3-T6　收口提示词取用与批次匹配

- 所属模块：[[M3]]　**文档接入**——把 `docs-data.js` 变成本产品唯一的任务真相源（任务、依赖、批次、并行窗口、验收标准、边界编号、实施与审查两段提示词），并负责内容指纹、派发时快照与文档重出后的三个标记；收口提示词 `dispatchBatches` 的按任务集合匹配也归它。凡「这条数据来自文档」的都归它
- 前置依赖：[[M3-T5]]
- 完成后解锁：[[M8-T6]]

## 输入 / 产出

- **输入**：M3-T5 的快照取用接口；04 节的 `dispatchBatches` 输入协议
- **产出**：`service/docs.ts` 的 `getWrapupContext(batchId)`、`domain/wrapup-builtin-prompt.ts`（内置通用收口提示词常量）

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 读派发快照那一刻文档的 `dispatchBatches`，按「`tasks` 集合与本批当前任务集合相等」匹配（顺序无关，多一个少一个都不匹配），命中返回该批 `wrapup` 原文与 `promptSource='docs'`
不按层号匹配（[[E-296]]）
2) 匹配不到或文档未导出该键时返回内置通用收口提示词并 `promptSource='builtin'`，不抛错、不让收口停摆（[[E-296]]）
3) 返回的材料逐字不改写、不截断
文档侧 `batchRecords` 键不读取（决策 73）
4) 文档指纹在收口途中变化时仍取快照那一份，不热改（[[E-50]]）

## 必须处理的边界

- [[E-296]]　收口提示词匹配不到
    - 触发：文档 `dispatchBatches` 里没有 tasks 集合与本批当前任务集合相等的条目，或文档未导出该键
    - 期望：用内置通用收口提示词并标「文档未提供」（`prompt_source=builtin`，记 warn）；匹配只按派发快照那一刻的文档，不按当前文档；材料逐字引用不改写，外层包装说明覆盖其中的提交/推送/PR/合并/记录文件步骤
- [[E-50]]　批次执行途中文档变了
    - 触发：执行期间任务 ID/contractHash 指纹变化，包括任务行未变而范围、条款或提示词变化
    - 期望：已派任务继续用快照跑完，后续派发自动暂停并要人确认新文档，绝不热改在途任务
