# M3-T6　收口提示词取用与批次匹配

- 所属模块：[[M3]]　**文档接入**——把 `docs-data.js` 变成本产品唯一的任务真相源（任务、依赖、批次、并行窗口、验收标准、边界编号、实施与审查两段提示词），并负责内容指纹、派发时快照与文档重出后的三个标记；收口提示词 `dispatchBatches` 的按任务集合匹配也归它。凡「这条数据来自文档」的都归它
- 前置依赖：[[M3-T5]]
- 完成后解锁：[[M8-T6]]

## 输入 / 产出

- **输入**：M3-T5 的快照取用接口；04 节的 `dispatchBatches` 输入协议
- **产出**：`service/docs.ts` 的 `getWrapupContext(batchId)`、`domain/wrapup-builtin-prompt.ts`（内置通用收口提示词常量）

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 读派发快照那一刻文档的 `dispatchBatches`，按「`tasks` 集合与本批当前任务集合相等」匹配（顺序无关，多一个少一个都不匹配），命中返回该批 `wrapup` 原文与 `promptSource='docs'`
不按层号匹配（[[E-296]]）
2) 匹配不到或文档未导出该键时返回内置通用收口提示词并 `promptSource='builtin'`，不抛错、不让收口停摆（[[E-296]]）
3) 返回的材料逐字不改写、不截断
文档侧 `batchRecords` 键不读取（决策 73）
4) 文档指纹在收口途中变化时仍取快照那一份，不热改（[[E-50]]）

## 必须处理的边界

- [[E-296]]　收口提示词匹配不到
    - 触发：文档 `dispatchBatches` 里没有 tasks 集合与本批当前任务集合相等的条目，或文档未导出该键
    - 期望：用内置通用收口提示词并标「文档未提供」（`prompt_source=builtin`，记 warn）；匹配只按派发快照那一刻的文档，不按当前文档；材料逐字引用不改写，外层包装说明覆盖其中的提交/推送/PR/合并/记录文件步骤
- [[E-50]]　批次执行途中文档变了
    - 触发：执行期间任务 ID/contractHash 指纹变化，包括任务行未变而范围、条款或提示词变化
    - 期望：已派任务继续用快照跑完，后续派发自动暂停并要人确认新文档，绝不热改在途任务

## 实施沉淀

<!-- notes:begin -->
1. **任务集合相等比对与层号解耦（AC 1、E-296）**：上游文档 `docs-data.js` 的 `dispatchBatches` 键名虽然是层号字符串（如 `"0"`, `"1"`），但任务依赖调整或局部补丁会导致层号与批次号发生动态位移（E-243）。若按批次号或层号索引会导致收口指令错位。因此匹配必须严格基于当前批次有效任务集合（`task_key` 的 Set 对比）进行双向全等比对（数量与元素严格一致，顺序无关），多一个或少一个任务均判为不匹配并安全回退。
2. **忽略 batchRecords 保持单一解析职责（AC 3、决策 73）**：文档侧导出的 `batchRecords` 属于人工 CLI/工作流的历史记录，调度器坚持收口上下文只由 `dispatchBatches` 或内置提示词提供，解析器严格不读取 `doc.batchRecords` 键，杜绝外部人工记录干扰调度器解析。
3. **闭包状态隔离与快照精确溯源（AC 4、E-50）**：杜绝模块级可变单例，收口锁与历史快照版本映射全部封装在 `createDocsService` 实例闭包内，保证多实例互不污染。当检测到 `docChangedSinceDispatch` 为真时，候选版本只能是用任务派发快照（`dispatch_snapshots`）记录的各任务原始 `contract_hash` 逐任务 100% 精确命中的历史版本；若无法精确命中（如服务重启后仅有新文档），坚决降级至内置通用提示词，严禁回退到当前新文档，杜绝热改在途任务。
4. **内置提示词降级保障（AC 2、E-296）**：文档未提供 `dispatchBatches` 或未能匹配时，记录 warning 并返回 `BUILTIN_WRAPUP_PROMPT`（`promptSource='builtin'`），绝不抛异常阻断收口流程，确保自动化流水线具备完全的韧性。
