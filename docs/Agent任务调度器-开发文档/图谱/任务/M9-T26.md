## 必须处理的边界

- [[E-08]]　daemon 被隧道暴露到公网
    - 触发：用户自行接入 Tailscale/frp
    - 期望：鉴权与加密默认开启；代码中不得存在「局域网内免鉴权」分支
- [[E-10]]　手机断网期间任务跑完
    - 触发：提醒产生时手机不在线
    - 期望：提醒事件在 daemon 侧按 event id 入队，手机重连后补推并去重，不得丢弃
- [[E-12]]　壳内 WebView 与 daemon 断连
    - 触发：网络中断或 daemon 停止
    - 期望：顶部显示「离线，最后同步于 X」并禁用派发按钮，避免用户以为任务已派出；恢复后自动补拉事件
- [[E-156]]　令牌过期而流仍开着
    - 触发：令牌被撤销或过期
    - 期望：服务端主动关闭该流并返回 401，客户端提示重新配对，不进入无限重连
- [[E-158]]　SSE 重连风暴
    - 触发：daemon 重启期间大量重连
    - 期望：客户端指数退避重连并保留 Last-Event-ID，不做无间隔轮询式重连
- [[E-200]]　壳模块受阻而界面已就绪
    - 触发：Android 构建环境不可用导致手机壳延期
    - 期望：「客户端界面」必须能在桌面浏览器直连 daemon 使用，其验收标准**不因壳模块延期而改变**
- [[E-227]]　先浏览器后装壳
    - 触发：壳存在但 sessionStorage 里有旧令牌
    - 期望：以**壳的安全存储为唯一真相源**，启动时清掉会话副本，**绝不双写**

## 实施沉淀

<!-- notes:begin -->
1. `bootstrap.ts` 是连接生命周期的唯一所有者。配对流程与 401 路径只改变 http-client 的模块令牌缓存，token change 监听器再负责开流或停流；这样配对成功不需要第二处 `connect()`，也不会让 React 组件或壳适配器各自维护一条连接。
2. 启动时必须把壳令牌读取结果写回模块缓存，包含 `null`。只在非空时写入会让 HMR、测试复用或同进程再次 bootstrap 继承旧令牌，并在“壳安全存储已为空”的情况下错误开流。
3. 令牌变为 `null` 时必须同时清除原生安全存储。仅清内存与 sessionStorage 会让已吊销令牌在桌面/手机进程重启后重新进入缓存，形成稳定的 401 重启循环；清除失败只记录技术日志，界面仍进入需配对状态。
4. 壳适配器必须在 Web 包内部按冻结的 `SHELL.platform` 自安装。同一份 Vite 产物由 daemon、Tauri 与 Capacitor 三处加载，原生壳包不能靠 import 时序把适配器注入已经打包的 Web 入口；浏览器分支仍走既有 sessionStorage 与 location.origin 降级。
5. `data-connection-status` 写在 `<html>`，顶栏组件从同一 store 只读呈现。前者给 M10-T6/M1-T11 的外部冒烟提供稳定观察点，后者给用户可见反馈；两者不各自订阅 SSE，避免 StrictMode 下重复连接。
6. Rust 的 `generate_handler!` 不只含 Web ShellBridge 的四条命令，还含 `get_launch_spec` 与 `launch_service` 两条壳自有启动命令。命令集合测试必须显式区分两组，不能为追求字面相等删掉启动能力。
7. daemon 容器测试与两端包装管线依赖 gitignored 的 `packages/web/dist`。新工作树先跑 `pnpm --filter @agent-scheduler/web build` 再跑全仓检查，才能验证静态托管与单构建消费；缺 dist 的统一失败不是业务回归。
