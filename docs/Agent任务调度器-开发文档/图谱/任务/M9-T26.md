# M9-T26　SSE 连接与壳适配器在启动序列里接通

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯、按窗口数呈现的任务流水线泳道与「会话已归档」历史行、顶栏两个流水线开关，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值、「能否收口」、泳道分配、阶段推进与会话归档都是 daemon 给的字段）；指派面板的分组模型下拉、登录态徽标与刷新按钮、参照条的「来源」段同样只呈现 daemon 下发的字段，不算取值链
- 前置依赖：[[M9-T4]]、[[M9-T5]]、[[M9-T6]]、[[M9-T11]]、[[M9-T15]]、[[M10-T1]]、[[M10-T2]]、[[M10-T4]]
- 完成后解锁：[[M1-T11]]、[[M10-T6]]

## 输入 / 产出

- **输入**：M9-T5 的 `sseClient`；M9-T6 的 event-bus；M9-T4 的 `resolveBaseUrl()` / `registerShellHostHint()` 与 `registerTokenProvider()`；M9-T11 的 `use-connection-state.ts` 与 `connection-store`；M9-T15 的配对流程；M10-T1 的 `shell-bridge.ts` 与 `registerNativeShellAdapter()`；M10-T2 的 `lib.rs` 命令集合与 `desktop-bridge.ts`；M10-T4 的 `main.tsx`
- **产出**：`src/app/bootstrap.ts`（`bootstrap()`：`SHELL` 探测 → `shellBridge.tokenStore.get()` 并 `registerTokenProvider()` → `registerShellHostHint(shellBridge.hostHint)` 后 `resolveBaseUrl()` → 有令牌 `sseClient.connect()`、无令牌置 `needsPairing`）；`main.tsx` 只 `await bootstrap()` 再 `createRoot`；`src/shell/shell-bridge.ts` 按 `SHELL.platform` 自装适配器（tauri 经 `window.__TAURI_INTERNALS__.invoke` 调 `get_token` / `set_token` / `clear_token` / `get_host_hint`，capacitor 经 `window.Capacitor.Plugins`）并调 `registerNativeShellAdapter()`；顶栏根元素写 `data-connection-status`；`packages/shell-desktop/test/tauri-commands.test.ts`；`packages/web/test/bootstrap.test.ts`；`packages/web/test/wiring-arch.test.ts`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) `sseClient.connect(` 在 `packages/web/src` 下恰出现一处且在 `bootstrap.ts`（`wiring-arch.test.ts` grep）
顺序断言：假壳的 `tokenStore.get` 先于 `resolveBaseUrl` 先于 `connect`
无令牌不 connect 而置 `needsPairing`（[[E-156]]、[[E-08]]）
2) `bootstrap.test.ts` 用 `test/` 假 SSE 服务端：一条 `run.state_changed` 到达后 `connection-store.lastEventId` 等于该事件 id、`data-connection-status` 为 `online`、顶栏「最后同步于」文案更新
断线后变 `reconnecting` 且不轮询（[[E-10]]、[[E-12]]、[[E-158]]）
3) tauri 平台：`SHELL.platform` 为 `tauri`、`capabilities.hasSecureStorage` 为真，`tokenStore.set` 触发恰一次 `invoke` 调 `set_token`，`hostHint()` 返回 `invoke` 调 `get_host_hint` 的字符串，`sessionStorage` 里不存在 `agsched.token`（[[E-227]]）
`tauri-commands.test.ts` 断言 `lib.rs` 的 `generate_handler!` 命令集合与 web 侧调用的命令名集合相等
4) `registerNativeShellAdapter` / `registerTokenProvider` / `registerShellHostHint` 在 `packages/web/src` 生产代码里各至少一处调用
`__TAURI` / `Capacitor` 仍只出现在 `src/shell/` 两文件，`check-forbidden` 不变（[[E-200]]）
5) 壳内真实事件到达 DOM 由 M10-T6 的壳 smoke 读 `data-connection-status` 断言
浏览器模式由 M1-T11 端到端冒烟断言

## 必须处理的边界

- [[E-08]]　daemon 被隧道暴露到公网
    - 触发：用户自行接入 Tailscale/frp
    - 期望：鉴权与加密默认开启；代码中不得存在「局域网内免鉴权」分支
- [[E-10]]　手机断网期间任务跑完
    - 触发：提醒产生时手机不在线
    - 期望：提醒事件在 daemon 侧按 event id 入队，手机重连后补推并去重，不得丢弃
- [[E-12]]　壳内 WebView 与 daemon 断连
    - 触发：网络中断或 daemon 停止
    - 期望：顶部显示「离线，最后同步于 X」并禁用派发按钮，避免用户以为任务已派出；恢复后自动补拉事件
- [[E-156]]　令牌过期而流仍开着
    - 触发：令牌被撤销或过期
    - 期望：服务端主动关闭该流并返回 401，客户端提示重新配对，不进入无限重连
- [[E-158]]　SSE 重连风暴
    - 触发：daemon 重启期间大量重连
    - 期望：客户端指数退避重连并保留 Last-Event-ID，不做无间隔轮询式重连
- [[E-200]]　壳模块受阻而界面已就绪
    - 触发：Android 构建环境不可用导致手机壳延期
    - 期望：「客户端界面」必须能在桌面浏览器直连 daemon 使用，其验收标准**不因壳模块延期而改变**
- [[E-227]]　先浏览器后装壳
    - 触发：壳存在但 sessionStorage 里有旧令牌
    - 期望：以**壳的安全存储为唯一真相源**，启动时清掉会话副本，**绝不双写**
