## 实施沉淀

<!-- notes:begin -->
- 路径段比对（AC 3）：单纯字符串前缀匹配会导致 `model/order` 错误命中 `model/orderitem`，而单纯全等比对则会漏掉目录包含关系（如 `model/order` 目录修改与 `model/order/item.ts` 冲突）。拆解为段数组并在最小长度内逐段匹配，既保证兄弟前缀词完全隔离，又保证目录与内部文件的冲突被如实捕获。
- 路径锁释放判准（AC 1、E-46）：运行状态机中 `running -> exited -> reviewing -> landed`，进程退出（`exited`）仅代表 agent 进程结束，代码尚未完成机械检查、代码审查与落地合入。若在 `exited` 放行后续冲突任务，后续任务基于未合并代码拉分支，必将引发脏读与 git 分支合入冲突；故路径锁持有集合必须覆盖 `exited`、`reviewing` 与 `awaiting_human`，直至 `landed` 或终态失败方可释放。持有状态词表直接投影 `domain/run-state-machine.ts` 的 `RUN_STATES` 并排除四个终态，状态机增删状态时不会留下第二份需要同步的名单。缺失或无法识别的 `state` 一律按持有处理：释放判定是安全侧的开关，读错方向会让两个任务同时改同一批文件，宁可让一个状态未知的任务多排一轮。
- 隔离无特权原则（AC 2）：git worktree 仅提供本地文件系统的运行期物理隔离，最终仍需汇聚合并至同一代码主干。若因「已开辟独立工作树」而放宽路径冲突判定，必然导致两条栈分支同时修改相同文件并在 landing 阶段发生合并冲突。调度器在领域层彻底剔除依据 worktree 放行的分支。
<!-- notes:end -->
