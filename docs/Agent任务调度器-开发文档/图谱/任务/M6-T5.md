# M6-T5　中止、进程树终止与状态落定

- 所属模块：[[M6]]　**运行监管**——管一次运行从启动到结束的全过程：状态机（「已退出」与「已落地」分开）、收流与落盘编排、按游标分段回读与厂商会话文件的只读引用、进度信号、停滞检测、中止与 daemon 重启后的对账、回话投递。凡「这一次运行现在怎么样、它说过什么」的都归它
- 前置依赖：[[M6-T1]]、[[M1-T9]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：M1-T9 的三平台 `killTree`
- **产出**：`abortRun()`、`POST /runs/:id/abort`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 中止一律走平台 `killTree`，业务层禁止直接杀父进程
Windows 与 POSIX 两阶段终止均通过集成测试（[[E-119]]）
2) 中止时 worktree 已有改动则保留 worktree 与 diff，记「已中止（有未验收改动）」，不自动清理不回滚（[[E-118]]）
3) 幂等：已终态时直接返回 accepted
4) 失联的运行提供「杀掉」入口，杀后转 `aborted`（[[E-02]] 的处置侧）

## 必须处理的边界

- [[E-02]]　daemon 重启后会话失联
    - 触发：daemon 被杀或机器重启，agent 会话还活着
    - 期望：按持久化的 task↔session 映射重新 attach；attach 不上的标「失联」而非「失败」，由用户决定是否重派
- [[E-118]]　中止时已有改动
    - 触发：worktree 里 agent 已经改了文件
    - 期望：保留 worktree 与 diff，状态记「已中止（有未验收改动）」，不自动清理、不自动回滚
- [[E-119]]　三平台进程树残留
    - 触发：agent 派生了 node/git/npm 子进程
    - 期望：中止必须杀整棵进程树：Windows 先 `taskkill /T` 后按需 `/F`；macOS/Linux 对独立进程组先发 `SIGTERM`、3 秒后按需 `SIGKILL`。只杀父进程会留下占文件锁的孤儿进程

## 实施沉淀

<!-- notes:begin -->
1. **进程树两阶段终止（E-119）**：业务层严禁使用 `process.kill(pid)` 直杀父进程。直接杀父进程会导致 agent 派生的子进程（如 git、node、npm 等）孤立存活并持有工作区文件锁。终止必须走平台层两阶段策略：Windows 先软性 `taskkill /PID <pid> /T`、等待 3 秒宽限期、探针存活再追加 `/F`；POSIX 则向独立进程组发 `SIGTERM`、等待 3 秒宽限期、探针存活再发 `SIGKILL`。托管进程与重启后对账残留的孤儿 PID（E-02）均复用该契约。
2. **改动保留与不可逆防护（E-118）**：中止发生时若工作区存在未验收改动，状态与原因明确记为「已中止（有未验收改动）」，严禁执行自动清理、`git reset` 或删除 worktree。未完成代码对于开发者排查和接管属于高价值现场，自动化清理会导致不可逆数据丢失。
3. **终态天然幂等（AC 3）**：状态机中 landed/failed/aborted/interrupted 四个终态零出边且不可逆。对终态运行重复调用 abortRun 时直接返回 `{ accepted: true }`，不触发杀进程、不抛异常、不重复写库，保证客户端重试与弱网重发安全。
4. **失联运行处置出口（E-02）**：启动对账将失联运行标为 `orphaned` 后，状态机保留 `orphaned -> aborted` 唯一出边，abort 接口作为处置入口调用平台 killTree 彻底清理并落定终态，释放外部资源。
5. **副作用与事务写序**：better-sqlite3 的 WAL 写入为同步操作，严禁在事务回调中执行 await 或调用耗时副作用。代码严格遵循「先执行异步探针与 killTree，再在事务中同步改库，事务提交返回后再调用 bus.publish 发布事件」的硬顺序。
<!-- notes:end -->
