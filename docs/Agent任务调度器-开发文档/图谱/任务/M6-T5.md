# M6-T5　中止、进程树终止与状态落定

- 所属模块：[[M6]]　**运行监管**——管一次运行从启动到结束的全过程：状态机（「已退出」与「已落地」分开）、收流与落盘编排、按游标分段回读与厂商会话文件的只读引用、进度信号、停滞检测、中止与 daemon 重启后的对账、回话投递。凡「这一次运行现在怎么样、它说过什么」的都归它
- 前置依赖：[[M6-T1]]、[[M1-T3]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：M1-T3 的 `killTree`
- **产出**：`abortRun()`、`POST /runs/:id/abort`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 中止一律走 `killTree`，**禁止用 `child.kill()` 或 `process.kill(pid)`**（[[E-119]]）
2) 中止时 worktree 已有改动则保留 worktree 与 diff，记「已中止（有未验收改动）」，不自动清理不回滚（[[E-118]]）
3) 幂等：已终态时直接返回 accepted
4) 失联的运行提供「杀掉」入口，杀后转 `aborted`（[[E-02]] 的处置侧）

## 必须处理的边界

- [[E-02]]　daemon 重启后会话失联
    - 触发：daemon 被杀或机器重启，agent 会话还活着
    - 期望：按持久化的 task↔session 映射重新 attach；attach 不上的标「失联」而非「失败」，由用户决定是否重派
- [[E-118]]　中止时已有改动
    - 触发：worktree 里 agent 已经改了文件
    - 期望：保留 worktree 与 diff，状态记「已中止（有未验收改动）」，不自动清理、不自动回滚
- [[E-119]]　Windows 进程树残留
    - 触发：agent 派生了 node/git/npm 子进程
    - 期望：中止必须杀整棵进程树（job object 或 `taskkill /T`）；只杀父进程会留下占文件锁的孤儿进程
