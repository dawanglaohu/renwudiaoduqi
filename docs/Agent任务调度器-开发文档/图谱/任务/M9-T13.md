# M9-T13　手机原样重跑入口

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯、按窗口数呈现的任务流水线泳道与「会话已归档」历史行、顶栏两个流水线开关，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值、「能否收口」、泳道分配、阶段推进与会话归档都是 daemon 给的字段）；指派面板的分组模型下拉、登录态徽标与刷新按钮、参照条的「来源」段同样只呈现 daemon 下发的字段，不算取值链
- 前置依赖：[[M9-T12]]、[[M8-T5]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：M8-T5 的重跑接口
- **产出**：流详情页末尾的整宽按钮

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 仅对终态失败/已中止的运行可用，严格复用原派发载荷、**不出现任何选择器**，需一次确认（[[E-177]]）
2) 入口在流详情页日志末尾的整宽按钮，**不进拇指条**
拇指区仍只有停止与审批
3) 「换 agent／换模型重派」保持桌面端独占，手机上只显示一行「请到桌面端」，不做半截表单
4) 手机端不提供「全部重跑」（[[E-181]]）
5) 竖屏 <400px 时该按钮整宽独占一行，与拇指条保持间距防误触

## 必须处理的边界

- [[E-177]]　手机重跑撞上已在跑
    - 触发：该任务已从桌面端重派或已重新在跑
    - 期望：按钮置灰 + 幂等键拦截，绝不产生第二次运行
- [[E-181]]　早上多条失败
    - 触发：一夜之间多个任务挂掉
    - 期望：逐条进入、逐条确认；手机端**不提供「全部重跑」**，批量属编排，留在桌面端

## 实施沉淀

<!-- notes:begin -->
1. 原样重跑在移动端严格锁定为直接复用原派发载荷，禁止在界面上注入任何 Agent/模型/工作区策略下拉选择器（AC 1 & E-177）。若允许在移动端调整参数，既会破坏原快照的一致性链条，又违背「换 agent／换模型重派桌面端独占」的职责边界；手机端仅保留单行中性提示文本引导至桌面端，不拼接半截表单（AC 3）。
2. 二次确认弹窗严格落入 07 节前端架构的 Dialog 四项白名单之一（手机原样重跑确认）。弹窗遵循移动端防误触交互基线：默认焦点锁在「取消」按钮上、触控目标高度锁死 44px（`--h-btn-lg`），并支持 Escape 键与蒙层取消，杜绝口袋误触引发未授权重跑。
3. 日志末尾整宽重跑按钮与常驻底部拇指栏（ThumbBar）的防误触间距（AC 5）：ThumbBar 为 `fixed bottom-0` 常驻区域（高度 `--thumbbar-h: 60px` 加上 safe-area 11px）。若重跑按钮直接贴底，竖屏触控极易误触拇指栏上的「停止」或「审批」；通过在容器底部显式配置 `calc(var(--thumbbar-h,60px) + 16px)` 的防误触间距，确保滚动至最底端时整宽按钮独占一行且与拇指栏物理隔离。
4. 撞上已在跑的拦截（E-177）：前端通过本地在途锁（`isRerunning`）、任务活跃状态嗅探（`hasActiveRun`）以及对服务端 `E_RUN_ALREADY_EXISTS` 错误码的拦截三层防护，一旦触发立即置灰按钮并替换文案为「任务已在运行中」，结合每次派发注入的唯一幂等键 `idempotencyKey`，保证绝不产生第二次运行。
5. 批量重跑属编排调度范畴，手机端坚决不提供「全部重跑」（AC 4 & E-181）。面对晨起多任务挂掉场景，用户必须逐条进入对应流的详情页核对日志并逐条确认，避免因盲目批量重跑导致并发冲击或同一原因引发雪崩式二次失败。
6. 路由装配与 SSR 快照（R1）：`pages/run-detail-page.tsx` 作为页面层纯装配件承载 `#/run/:runId` 路由分发；`useRoute` 的 `getServerSnapshot` 同步当前 `currentCachedMatch`，确保静态标记渲染与集成测试真实贯通全链路。
7. 既有运行拦截与防替安全（R2）：服务端在新建重跑和命中既有 active run 时都返回 HTTP 200 及 run DTO，响应形状无法可靠区分两者。客户端因此不按 `parentRunId` 猜测，也不拿写响应修改当前详情；两种成功响应都只置灰入口并保留原终态日志，等待 SSE/REST 权威状态回流。
8. 端型隔离与错误分层（R3）：原样重跑操作栏严格受控于 `isMobileTier`（仅 `phone` 与 `phone-xs` 呈现），桌面端保持留白并由桌面独占重派；所有错误码严格经 `error-messages.ts` 单一事实源映射中文，英文 `message` 与 `requestId` 收拢在 `<details>` 技术详情中，配齐一键复制。
9. 生产样式接线（R4）：Vite 必须显式加载 Tailwind PostCSS 插件；否则构建产物会原样保留 `@tailwind` 指令，`w-full`、44px 触控高度和拇指条间距等工具类全部失效。验收构建同时检查产物不含原始 `@tailwind` 且包含 `.w-full`。
