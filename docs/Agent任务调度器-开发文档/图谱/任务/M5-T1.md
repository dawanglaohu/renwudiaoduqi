# M5-T1　worktree 准备、分支命名与回收

- 所属模块：[[M5]]　**工作区与 Git**——为每个任务准备、隔离与回收独立 worktree，从中读出改动（改动文件数、diff stat、diff 正文）并生成只读落地清单。凡要碰 git 或任务工作目录的都归它
- 前置依赖：[[M1-T7]]
- 完成后解锁：[[M5-T2]]、[[M5-T3]]、[[M8-T10]]

## 输入 / 产出

- **输入**：M1-T7 的 spawn（git 一律经它）
- **产出**：`workspace/worktree.ts`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 每任务独立 worktree，分支名冲突时自动加序号后缀，**不复用不覆盖已有分支**（[[E-71]]）
2) 目标目录不是 git 仓库时**不静默降级到共享目录并行**，改为强制串行并明确告知原因（[[E-69]]）
3) 主工作区有未提交改动时建 worktree 不受影响也**不去 stash 用户的东西**（[[E-72]]）
4) 磁盘不足或权限问题时标「派发失败·工作区不可用」并释放窗口名额，不让整批卡死（[[E-76]]）

## 必须处理的边界

- [[E-69]]　目标目录不是 git 仓库
    - 触发：无法建 worktree
    - 期望：不静默降级到共享目录并行，改为强制串行（一次只跑一个任务）并明确告知原因
- [[E-71]]　分支名冲突
    - 触发：要建的分支名已存在
    - 期望：自动加序号后缀（任务号-2），不复用、不强制覆盖已有分支
- [[E-72]]　主工作区有未提交改动
    - 触发：用户自己手上有活没提交
    - 期望：建 worktree 不受影响也不去 stash 用户的东西；diff 基线取 worktree 自身 HEAD，不与主工作区混算
- [[E-76]]　worktree 创建失败
    - 触发：磁盘不足或权限问题
    - 期望：该任务标「派发失败·工作区不可用」，释放窗口名额给下一个任务，不让整批卡死

## 实施沉淀

<!-- notes:begin -->
1. Git 子进程出口与防阻塞：所有 git 调用严格收敛于 proc/spawn.ts 的 spawnManaged 单一出口（shell: false、argv 传参），遵循分层架构禁令，不在 workspace 目录直接引入 node:child_process。通过 GitRunner 抽象，真实运行走受控子进程生命周期管理，同时单元测试可无子进程开销精确断言 git 命令参数与状态。
2. 分支与工作区命名冲突处理（E-71）：分支查重时不仅查询 git for-each-ref 的本地分支，还同步解析 git worktree list --porcelain 输出的所有挂载分支。git 规则规定只要分支被任意 worktree 检出，即使不在当前 HEAD 也无法再次 add -b；后缀序号从 -2 起单调递增，对应目录路径同步加后缀，确保文件系统与 git 引用一一匹配且绝不传 -B 覆盖破坏用户既有分支。
3. 非 git 仓库防御（E-69）：检测到目标路径缺少 .git 或非合法 working tree 时，明确拒绝多任务并行 worktree 分配，统一抛出 E_NOT_A_GIT_REPO 并在元数据标注 forcedSerial: true。禁止任何降级到同一目录并发修改的静默分支，避免多 agent 互相踩踏脏文件。
4. 主工作区改动保护（E-72）：严格遵循 git worktree add -b <branch> <path> <baseRef>，不执行任何 git stash、git checkout 或 git reset。主工作区的未暂存文件、暂存区文件保持原封不动；新 worktree 的 baseRef 默认锚定 HEAD，其 diff 基线与主工作区改动物理隔离。
5. 错误分类与窗口名额释放（E-76）：worktree 创建过程中捕获 native 的 ENOSPC/EACCES/EPERM 以及 git 的 'No space left on device' 与 'Permission denied' 报错，统一映射为系统错误码 E_WORKSPACE_UNAVAILABLE，并在 details 中明确标记 releaseSlot: true 与 workspaceUnavailable: true，确保调度器感知后能够立即释放并发槽位，防止阻塞后续排队任务。
6. 可执行文件与 ID 的依赖注入：git 二进制不写死路径，由 platform.resolveExecutable() 按当前宿主解析为绝对路径（启动形态取解析结果的 file，argsPrefix 原样前置），也可由组合根直接注入已解析的 ResolvedExecutable；解析失败向上抛类型化 AppError。git 子进程的 runId 只来自注入的 ids.newId()，不用 Math.random 兜底，保证调度侧 ID 可确定、可复现。
<!-- notes:end -->
