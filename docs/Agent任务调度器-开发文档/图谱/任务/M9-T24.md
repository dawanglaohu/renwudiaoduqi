# M9-T24　前端样式管线接通：postcss 与 tailwind 进 Vite 构建

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯、按窗口数呈现的任务流水线泳道与「会话已归档」历史行、顶栏两个流水线开关，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值、「能否收口」、泳道分配、阶段推进与会话归档都是 daemon 给的字段）；指派面板的分组模型下拉、登录态徽标与刷新按钮、参照条的「来源」段同样只呈现 daemon 下发的字段，不算取值链
- 前置依赖：[[M9-T1]]、[[M10-T4]]
- 完成后解锁：[[M1-T11]]、[[M10-T6]]

## 输入 / 产出

- **输入**：M9-T1 的 `tailwind.config.ts` 与 `styles/tokens.css` / `base.css`；M10-T4 的 `vite.config.ts` 单次构建与 `80-static.ts` 托管
- **产出**：`packages/web/postcss.config.cjs`（`tailwindcss` + `autoprefixer` 两个插件，不含任何 hex 或字体栈）、`packages/web/package.json` devDependencies 加 `postcss` / `autoprefixer`、`vite.config.ts` 的 `css.postcss` 指向它、`app/theme-provider.tsx` 挂载后读 `getComputedStyle(document.documentElement).getPropertyValue('--page')` 非空即写 `document.documentElement.dataset.styleLoaded = 'true'`、`packages/web/test/style-pipeline.test.ts`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) `pnpm --filter @agent-scheduler/web build` 后 `dist/assets/*.css` 不含 `@tailwind` 字面量，且 utility 规则不少于 200 条（测试对产物 grep 形如 `.flex{`、`.gap-2{` 的选择器计数）（[[E-175]]）
2) `style-pipeline.test.ts` 用 PostCSS 直接处理 `src/styles/base.css`，断言输出含 `.bg-page` 规则且值为 `var(--page)`
浏览器里的 computed style 断言由 M1-T11 端到端冒烟承担（[[E-159]]）
3) `theme-provider` 挂载后 `data-style-loaded` 为 `true`，在 jsdom 里 `--page` 为空时不写该属性（不伪造已加载）（[[E-159]]）
4) `check-forbidden.ts` 与 `check-contrast.ts` 仍通过
`postcss.config.cjs` 与 `tailwind.config.ts` 出现 hex 或字体栈即 `check-forbidden` 失败
5) 产物仍 `base: ./`，`vendor-react` / `vendor-ui` 两个分块名不变，三处加载源共用同一份 CSS（[[E-224]]）
