## 实施沉淀

<!-- notes:begin -->
1. 接通前的症状（AC 1）：没有 PostCSS 配置时 Vite 把 `@tailwind base;` 三行原样写进产物（5.3 KB 的 CSS 里带字面量），浏览器忽略它们，全应用的 className 一律失效，但构建照样成功。`style-pipeline.test.ts` 对产物断言 `.flex{display:flex}` 与 `.gap-2{gap:var(--sp-2)}`，删掉配置文件或挪走它就会在这里失败，而不是在某个页面里静默变白。
2. Tailwind 的两处 cwd 陷阱（AC 2）：Tailwind 3 默认按 `process.cwd()` 找 `tailwind.config.*`，content 通配也按 cwd 解析。`vite build` 的 cwd 是 packages/web 所以看不出问题；vitest 的 cwd 是仓库根，同一份 postcss.config.cjs 从那里加载会退回默认主题（没有 `.bg-page`）并扫不到任何源码（零 utility）。因此配置文件以 `path.join(__dirname, 'tailwind.config.ts')` 显式传入，`content.relative: true` 让通配相对配置文件解析。改动这两处之一，先从仓库根跑 `vitest run packages/web/test/style-pipeline.test.ts` 再下结论。
3. `css.postcss` 用字符串路径而不是内联插件数组：Vite 从项目根也能自动发现 postcss.config.cjs，但显式路径让 vite.config.ts 与测试指向同一个文件，插件清单只有一份；内联数组会让测试与构建各持一份，改一处漏一处。
4. `borderColor.DEFAULT`（E-159）：Tailwind preflight 给 `*` 写 `border-color: theme('borderColor.DEFAULT')`，而 `extend.colors` 不改变这个默认值，它仍是框架自带的灰 `#e5e7eb`。应用里 97 处裸 `border` 类会把这个不存在于任何源文件的 hex 画到屏幕上，check-forbidden 扫源码扫不到。把 DEFAULT 指到 `var(--border)` 后，颜色只来自 tokens.css 的规则在编译后的 CSS 层面才成立。同类残留：`ring-N` 不带颜色时 preflight 的 `--tw-ring-color` 默认值是框架蓝，目前所有 ring 用法都显式带颜色，新增时必须带。
5. `data-style-loaded` 只在 `--page` 非空时写（AC 3）：`<link rel="stylesheet">` 在入口脚本之前，浏览器会等渲染阻塞样式表加载完才执行模块脚本，所以 ThemeProvider 的挂载 effect 里已经能读到 token；样式表 404（壳加载错路径、静态托管缺资源）时 `--page` 为空、属性不写，M10-T6 的壳 smoke 据此超时失败而不是误报通过。jsdom 里 `getComputedStyle` 能解析注入 `<style>` 的自定义属性（裸文档读到空串，注入 tokens.css 后读到 `#0f1213`），所以两条分支都是真实执行不是 mock。
6. jsdom 按文件启用（`// @vitest-environment jsdom`），不改根配置的 `environment: 'node'`：其余套件全用 `renderToStaticMarkup`，不需要 DOM；全局切 jsdom 会让每个文件多付环境启动成本，并给「useEffect 不执行」的既有测试假设引入变量。
7. 单一构建产物的验证方式（AC 5、E-224）：测试在子进程用 `--outDir` 指到临时目录跑真实 `vite build`，不复用也不覆盖 packages/web/dist；CI 先 `pnpm --filter @agent-scheduler/web build` 再 `pnpm -w check`，dist 存在时测试顺带断言它也经过了同一管线（避免 daemon 托管一份旧产物而测试用新产物）。
