# M9-T7　运行轨与运行流条目

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值与「能否收口」都是 daemon 给的字段）
- 前置依赖：[[M9-T2]]、[[M9-T6]]
- 完成后解锁：[[M9-T8]]、[[M9-T9]]、[[M9-T10]]

## 输入 / 产出

- **输入**：M9-T2 的形状；M9-T6 的缓冲
- **产出**：`components/spine.tsx`、`stream-row.tsx`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 运行轨**贯穿整栏全高**含未来步骤的虚线段
只画到当前步即判不合格
2) 六种轨段形态（实线／心跳点／虚线／空心方块＋整段转暖／平头截断／半调虚线＋横杠）各自可见且形状先于颜色
3) 条目折叠高度 30px（触摸 44px），网格 `20px minmax(0,1fr) auto 16px`
**每一步都显示耗时**
4) 标签为「工具 + 对象」，成功步默认折叠、失败步默认展开并提供「从这一步重试」
5) 键盘焦点用**内嵌环**，滚动列表不整体抖
6) 轨段形态与状态徽标共用同一张形状枚举，状态区分不只靠色相（[[E-110]]）
「失联」「审查未完成」等态各有专属形状而非复用失败形状（[[E-230]]）

## 必须处理的边界

- [[E-110]]　长时间盯屏与色觉差异
    - 触发：用户连续监看数小时，或投屏/色弱
    - 期望：深色为默认，日志用等宽字体；状态区分不能只靠色相，必须同时有形状或文字
- [[E-230]]　有状态没有专属字形
    - 触发：「失联」「审查未完成」「未识别/降级」这些态不等同于「失败」
    - 期望：形状枚举必须为它们**各补一个专属形状**，绝不复用 `✕`，更不允许只靠颜色区分
