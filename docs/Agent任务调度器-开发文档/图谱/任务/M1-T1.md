# M1-T1　仓库骨架、进程入口与启动自检

- 所属模块：[[M1]]　**运行底座**——让 daemon 在这台机器上稳定跑起来并把字节落到磁盘上：进程单实例与端口、启动自检、开机自启注册、数据目录、结构化存储的连接与迁移、日志正文的追加写与字节偏移索引、以及全部平台差异（进程树终止、路径规范化与长路径、配置目录、子进程编码）的唯一收口。凡与操作系统、磁盘、进程存活打交道而不带任何业务概念的都归它
- 前置依赖：无，可直接开工
- 完成后解锁：[[M1-T2]]、[[M1-T3]]、[[M1-T6]]、[[M4-T1]]

## 输入 / 产出

- **输入**：空仓库；05 节的技术栈取值
- **产出**：pnpm 单仓五包骨架、`biome.json`、`.gitattributes`、`src/main.ts`、`src/boot/` 自检与单实例锁

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) `node --version` 低于 22 时打印所需版本并以非 0 退出，不进入半残运行（[[E-139]]）
2) 第二个实例启动时拒绝并退出，日志写明已有实例 pid（[[E-03]]）
3) `AGSCHED_PORT=abc` 时打印变量名与期望格式后退出，不静默回落 7817
4) 注册 `process.on('unhandledRejection')` 落运行日志，全仓 fire-and-forget 一律显式 `void fn()`（[[E-213]]）
5) `biome.json` 设 `formatter.lineEnding:"lf"` 并配 `.gitattributes`，Windows 上改一行不产生整文件 diff（[[E-214]]）

## 必须处理的边界

- [[E-03]]　端口被占用或多实例
    - 触发：daemon 端口被占用，或同机多用户登录
    - 期望：端口可配置 + 单实例锁，第二个实例拒绝启动并把请求让给已有实例；绝不允许两个调度器同时推进同一批次
- [[E-139]]　Node 版本过低
    - 触发：daemon 启动时 `node --version` 低于声明的最低大版本
    - 期望：自检失败并打印所需版本后退出，不静默降级或半残运行
- [[E-213]]　未 await 的 Promise 静默失败
    - 触发：Biome 无类型感知规则，查不出 `no-floating-promises` 这类问题
    - 期望：兜底走运行期：daemon 注册 `process.on('unhandledRejection')` 落运行日志；**所有 fire-and-forget 必须显式写 `void fn()`**。被这类 bug 咬过两次才单独加 typescript-eslint 的这一条规则，而不是引入整套 ESLint
- [[E-214]]　Windows 上的换行抖动
    - 触发：开发机产生 CRLF
    - 期望：`biome.json` 显式 `formatter.lineEnding: "lf"` 配 `.gitattributes`，避免整文件 diff
