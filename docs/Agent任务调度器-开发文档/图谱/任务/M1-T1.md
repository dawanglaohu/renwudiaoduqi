# M1-T1　仓库骨架、进程入口与 Node 版本垫片

- 所属模块：[[M1]]　**运行底座**——让 daemon 在这台机器上稳定跑起来并把字节落到磁盘上：进程单实例与端口、启动自检、开机自启注册、数据目录、结构化存储的连接与迁移、日志正文的追加写与字节偏移索引、以及全部平台差异（进程树终止、路径规范化与长路径、配置目录、子进程编码）的唯一收口。凡与操作系统、磁盘、进程存活打交道而不带任何业务概念的都归它
- 前置依赖：无，可直接开工
- 完成后解锁：[[M1-T2]]、[[M1-T3]]、[[M1-T6]]、[[M1-T10]]、[[M4-T1]]

## 输入 / 产出

- **输入**：空仓库；05 节的技术栈取值
- **产出**：pnpm 单仓五包骨架（各包含 `package.json` + `tsconfig.json`）、`biome.json`、`.gitattributes`（无 BOM）、`.gitignore`（含 `node_modules/` 与 `**/*.tsbuildinfo`，无 BOM）、根 `tsconfig.json`/`vitest.config.ts`/`pnpm-lock.yaml`、垫片 `packages/daemon/bootstrap.mjs`（CJS 语法、不依赖 Node 22 专属能力）、`src/main.ts`（TS）、`src/boot/`（node-check、guards、容器接线点）、`packages/daemon/test/unit/`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) Node 20 下 `node packages/daemon/bootstrap.mjs` 先打印 `requires Node.js >= 22` 并以非 0 退出
Node 22 下进程持锁常驻（[[E-139]]）
2) `packages/daemon/bootstrap.mjs` 是唯一允许以 `node xxx.mjs` 启动的入口
`main.ts` 只靠垫片加载
3) `process.on('unhandledRejection')` 落运行日志，fire-and-forget 一律显式 `void fn()`
`uncaughtException` 打印后由注入 fatal-exit 回调进 `main.ts` 的 `process.exit(1)`（[[E-213]]）
4) `biome.json` 设 `formatter.lineEnding:"lf"` 并配 `.gitattributes`（[[E-214]]）
5) `assertNever` 外不允许 `throw new Error('...')`，垫片内异常不出现

## 必须处理的边界

- [[E-139]]　Node 版本过低
    - 触发：daemon 启动时 `node --version` 低于声明的最低大版本
    - 期望：自检失败并打印所需版本后退出，不静默降级或半残运行。**版本检查必须由旧版 Node 可解析的纯 JS 垫片（`.mjs`，不含 TypeScript 语法、不依赖 Node 22 专属选项）在加载 TypeScript 与任何 Node 22 专属参数之前执行**；垫片只做版本判定，失败时打印 `requires Node.js >= 22` 并以非 0 退出，通过后才加载 `main.ts` 入口（Node 22 也不允许直接跑 `.ts`，因此垫片是正式启动入口）
- [[E-213]]　未 await 的 Promise 静默失败
    - 触发：Biome 无类型感知规则，查不出 `no-floating-promises` 这类问题
    - 期望：兜底走运行期：daemon 注册 `process.on('unhandledRejection')` 落运行日志；**所有 fire-and-forget 必须显式写 `void fn()`**。被这类 bug 咬过两次才单独加 typescript-eslint 的这一条规则，而不是引入整套 ESLint
- [[E-214]]　Windows 上的换行抖动
    - 触发：开发机产生 CRLF
    - 期望：`biome.json` 显式 `formatter.lineEnding: "lf"` 配 `.gitattributes`，避免整文件 diff

## 实施沉淀

<!-- notes:begin -->
1. **版本门必须是纯 JavaScript 第一入口。** `bootstrap.mjs` 只使用 Node 20 可解析的语法；低版本设置非零退出码后不加载 loader 或 TypeScript。Node 22 分支注册本地 TypeScript loader，再动态导入 `main.ts`。`dev` 与 `start` 均只调用该垫片。
2. **进程输入在启动边界冻结后经 DI 传递。** `config/env.ts` 集中读取 `process.env`，`boot/snapshot.ts` 一次性捕获版本、pid、宿主目录和运行日志写入器，`boot/container.ts` 将这些值接入配置、路径与锁模块。`main.ts` 和 `boot/paths.ts` 不直接读取环境变量。
3. **可预期的启动拒绝使用判别联合返回。** Node 版本、端口格式和锁竞争分别返回类型化失败；原生文件系统异常交给 `main.ts` 的启动拒绝处理器记录并以非零状态退出。启动路径不定义 `EnvFormatError`、`InstanceLockError` 或 `NodeVersionError`，保持错误体系只有批准的 `AppError` 分支可扩展。
4. **全局守卫依赖运行日志写入器与 fatal-exit。** `unhandledRejection` 记录摘要；`uncaughtException` 在 `finally` 中调用由 `main.ts` 注入的 `() => process.exit(1)`，日志写入失败也不会阻止致命退出。TypeScript AST 测试禁止裸 Promise 调用语句，入口使用显式 `void main()`。
5. **成功启动必须同时保持进程与锁存活。** 锁文件写入持有者 pid，常驻实现捕获锁句柄并保留活动计时器。真实 Node 22 子进程测试确认首实例持续运行、第二实例报告首实例 pid 并非零退出；真实 Node 20 子进程确认垫片输出版本要求且不解析 TypeScript。测试运行时按 Windows、macOS、Ubuntu x64 选择随工作区安装的固定版本 Node 二进制。
6. **五包统一由 build mode 校验。** 根配置以 references 指向 daemon、shared、web、shell-desktop、shell-mobile，每包启用 composite；根 `check` 依次运行 `biome ci .`、`tsc -b --noEmit`、`vitest run`。`**/*.tsbuildinfo` 属于本地增量缓存，不进入版本库。
7. E-214：`.gitattributes` 里的 `*.bat`、`*.cmd`、`*.ps1` 保留 CRLF；其余文本与 Biome formatter 使用 LF。
<!-- notes:end -->
