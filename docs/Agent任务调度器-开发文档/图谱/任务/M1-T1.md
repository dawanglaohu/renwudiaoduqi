# M1-T1　仓库骨架、进程入口与最小常驻 daemon 闭环

- 所属模块：[[M1]]　**运行底座**——让 daemon 在这台机器上稳定跑起来并把字节落到磁盘上：进程单实例与端口、启动自检、开机自启注册、数据目录、结构化存储的连接与迁移、日志正文的追加写与字节偏移索引、以及全部平台差异（进程树终止、路径规范化与长路径、配置目录、子进程编码）的唯一收口。凡与操作系统、磁盘、进程存活打交道而不带任何业务概念的都归它
- 前置依赖：无，可直接开工
- 完成后解锁：[[M1-T2]]、[[M1-T3]]、[[M1-T6]]、[[M4-T1]]

## 输入 / 产出

- **输入**：空仓库；05 节的技术栈取值
- **产出**：pnpm 单仓五包骨架（各包含 `package.json` + `tsconfig.json`）、`biome.json`、`.gitattributes`、根 `tsconfig.json`/`vitest.config.ts`/`.gitignore`/`pnpm-lock.yaml`、旧版 Node 可加载的垫片 `bootstrap.mjs`、`src/main.ts`、`src/boot/`（自检、单实例锁、生命周期）、`src/config/env.ts`、最小 `src/http/server.ts`（**只建 Fastify 实例并 listen，不注册插件/路由——插件与路由是 M2-T1 的活**）、composition-root 接线点 `src/boot/container.ts`（M2-T1 在此挂插件）、daemon `test/`（unit+integration+arch 真实可跑，架构骨架测试允许只限定本任务范围内的检查）

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 在 Node 20 与 Node 22 上都能跑 `node bootstrap.mjs`
Node 20 时垫片先打印 `requires Node.js >= 22` 并以非 0 退出，**不进入 TypeScript**（[[E-139]]）
2) 起第一个实例后持锁常驻
第二个实例启动时读出已有实例 pid 与端口并以非 0 退出
杀掉第一个实例后陈旧锁被识别、重启可启动（[[E-03]]，整机一个 daemon，锁放 `C:\ProgramData\agent-scheduler\daemon.lock`）
3) 端口被非本 daemon 进程占用时 listen 失败、释放锁并以非 0 退出（[[E-03]]）
4) `AGSCHED_PORT=abc` 时打印变量名与期望格式后退出，不静默回落 7817
5) `process.on('unhandledRejection')` 落运行日志，fire-and-forget 一律显式 `void fn()`
`uncaughtException` 打印后由注入 fatal-exit 回调进 `main.ts` 的 `process.exit(1)`（[[E-213]]）——**process.exit 仍只在 main.ts**
6) `biome.json` 设 `formatter.lineEnding:"lf"` 并配 `.gitattributes`，Windows 上改一行不产生整文件 diff（[[E-214]]）
7) 启动顺序为 配置/锁 → 数据目录 → （库/迁移由 M1-T2 接线） → buildHttpServer → listen
listen 成功后（本任务无 jobs）报告 ready
锁持有至进程退出

## 必须处理的边界

- [[E-03]]　端口被占用或多实例
    - 触发：daemon 端口被占用，或同机多用户登录
    - 期望：端口可配置 + 单实例锁；锁范围为「整机一个 daemon」（Windows 锁文件位于 `C:\ProgramData\agent-scheduler\daemon.lock`，每用户目录不构成单例边界；`AGSCHED_PORT` 不同的第二个实例同样被拒）。第二个实例启动时读锁文件中的持有者 pid 并探测存活：存活（同一锁 / 同一端口仍在听）→打印已有实例 pid 与端口后以非 0 退出，「把请求让给已有实例」即拒绝自身启动并提示客户端直连该 pid 对应端口，不做进程间透传；持有者已死→删陈旧锁重新竞争。端口被非本 daemon 进程占用时 listen 失败、释放锁并以非 0 退出，不在另端口上起服务。锁覆盖 daemon 全生命周期，持有者只有进程退出才释放；绝不允许两个调度器同时推进同一批次
- [[E-139]]　Node 版本过低
    - 触发：daemon 启动时 `node --version` 低于声明的最低大版本
    - 期望：自检失败并打印所需版本后退出，不静默降级或半残运行。**版本检查必须由旧版 Node 可解析的纯 JS 垫片（`.mjs`，不含 TypeScript 语法、不依赖 Node 22 专属选项）在加载 TypeScript 与任何 Node 22 专属参数之前执行**；垫片只做版本判定，失败时打印 `requires Node.js >= 22` 并以非 0 退出，通过后才加载 `main.ts` 入口（Node 22 也不允许直接跑 `.ts`，因此垫片是正式启动入口）
- [[E-213]]　未 await 的 Promise 静默失败
    - 触发：Biome 无类型感知规则，查不出 `no-floating-promises` 这类问题
    - 期望：兜底走运行期：daemon 注册 `process.on('unhandledRejection')` 落运行日志；**所有 fire-and-forget 必须显式写 `void fn()`**。被这类 bug 咬过两次才单独加 typescript-eslint 的这一条规则，而不是引入整套 ESLint
- [[E-214]]　Windows 上的换行抖动
    - 触发：开发机产生 CRLF
    - 期望：`biome.json` 显式 `formatter.lineEnding: "lf"` 配 `.gitattributes`，避免整文件 diff
