# M10-T2　三平台桌面壳（Tauri v2）

- 所属模块：[[M10]]　**桌面壳与手机壳**——只做窗口与单实例、系统通知、令牌安全存储三件事的两个原生容器，外加 daemon 未运行时的引导、Windows/macOS/Linux 桌面构建与运行依赖检测。壳按界面声明的可选桥接接口去实现，界面在没有壳时按能力探测降级，因此依赖方向恒为壳→界面
- 前置依赖：[[M10-T1]]、[[M1-T6]]
- 完成后解锁：[[M9-T26]]、[[M10-T4]]、[[M10-T6]]

## 输入 / 产出

- **输入**：M10-T1 的契约；M1-T6 的自启机制与 `DaemonLaunchSpec`
- **产出**：`packages/shell-desktop/`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) Windows、macOS、Linux 只做窗口与单实例、系统通知、令牌安全存储三件事
**壳内不出现 task/run/gate/batch/agent 任何业务词**，任一平台缺壳不得标完整支持（[[E-257]]）
2) daemon 未运行时显示连接失败页 + 「启动 daemon」按钮
壳每次启动根据实际 `current_exe/resource_dir` 解析并校验绝对 `file`、`args[]`、绝对 `cwd`，按钮直接消费该冻结对象且不经 shell，**壳自身不内嵌任何调度或重试策略**（[[E-146]]、[[E-209]]）
3) Windows 缺 WebView2 时由启动检测给安装引导
Linux 由安装前置检查或命令行 launcher 在创建 WebView 前诊断 WebKitGTK/GTK，不能要求尚未启动的 GUI 自己报错
macOS 使用系统 WebKit（[[E-148]]、[[E-258]]）
4) 触发平台原生自启注册：把与按钮相同的 `DaemonLaunchSpec` 交给 M1，逐字段校验注册项 `file/args/cwd`，不一致则重写
失败降级为手动启动并给本平台命令（[[E-209]]、[[E-210]]）
5) 用户手动关掉自启项时只检测并询问，**不静默重注册**，询问带「不再提醒」（[[E-208]]）
6) 通知点击以 `#/run/〈runId〉` 交给 WebView，**不做自定义 IPC 传业务数据**

## 必须处理的边界

- [[E-146]]　桌面壳启动时 daemon 未运行
    - 触发：壳先于服务启动
    - 期望：显示连接失败页 + 「启动 daemon」按钮（调用外部已安装的启动命令）；壳自身不内嵌任何调度或重试策略
- [[E-148]]　缺少 WebView2 运行时
    - 触发：Windows 上未安装 WebView2
    - 期望：启动时检测并给出安装引导，不得白屏
- [[E-208]]　用户关掉了系统自启项
    - 触发：外部禁用了计划任务、LaunchAgent 或 systemd 用户服务
    - 期望：壳下次启动**只检测并询问「是否重新注册」，不静默重注册**；询问带「不再提醒」选项
- [[E-209]]　升级后自启项指向旧路径
    - 触发：安装位置、macOS `.app` 位置或 Node 脚本参数变化，原生自启项仍引用旧启动方式
    - 期望：壳每次启动根据实际安装位置解析完整 `DaemonLaunchSpec`；`register` 幂等接收该冻结对象，逐字段校验原生注册项与当前绝对 `file`、`args[]`、绝对 `cwd`，不一致则重写；桌面按钮和自启共用同一对象且恒不经 shell，安装包不得预写固定绝对路径；重写失败降级为「需手动启动」并给出该平台可复制命令
- [[E-210]]　注册被系统拒绝
    - 触发：Task Scheduler、`launchctl` 或 `systemctl --user` 因权限或策略拒绝
    - 期望：注册失败**必须非致命**：daemon 仍由壳当场拉起、功能完整，仅重启后需手动开壳；设置页提供「重试注册自启」按钮并显示原生错误
- [[E-257]]　平台支持只完成一半
    - 触发：某平台能启动 daemon，但桌面壳无法构建或启动
    - 期望：该平台不得标记为完整支持；三平台发布检查失败，并列出缺失的产品层
- [[E-258]]　Linux 缺少桌面运行依赖
    - 触发：WebKitGTK、GTK 或 Tauri v2 要求的系统库缺失，GUI 甚至无法创建窗口
    - 期望：安装包前置检查或命令行 launcher 在启动 WebView 前列出缺失包与当前发行版可执行的安装指引；不得依赖 GUI 自己报错，该环境不计入已验证平台

## 实施沉淀

<!-- notes:begin -->
1. 壳层词汇隔离：严格禁止 `task/run/gate/batch/agent` 出现在壳代码中，深层链接仅作为不透明字符串由壳桥接到 WebView location.hash，防止壳与调度器业务实体产生双向耦合。
2. Linux 依赖前置诊断：Linux 下 WebKitGTK/GTK 缺失会导致 WebKit 进程在初始化阶段段错误（SEGV），GUI 窗口根本无法创建；因此诊断必须在桌面壳或命令行 launcher 创建任何 Webview 之前于终端输出发行版包管理器命令并退出，绝不可假设 GUI 能就地报错。
3. 自启检测与「不再提醒」：当自启项被外部禁用时，壳不能根据 `status.registered === false` 自动执行 `register`，否则会直接覆盖用户的系统偏好；通过轻量偏好存储记录 `wasPreviouslyConfigured` 与 `neverAskAgain`，区分首装未注册与手动禁用两种截然不同的场景。
4. 进程拉起不经 shell：`launchDaemon` 必须维持 `shell: false` 且传递独立 argv 数组，直接将参数喂给 OS 系统调用，避免 Windows cmd 字符转义和 POSIX shell 注入风险；且壳内绝不附带轮询或重试循环，以保持壳作为透明原生宿主的边界。
5. 单实例与系统通知装配（R1、R2）：通过 `tauri-plugin-single-instance` 在 `start_desktop` 注册单实例钩子，第二个实例拉起时通过 `Manager` 唤醒并聚焦现有主窗口；通知引入 `tauri-plugin-notification`，权限未授予或发送失败时静默降级，禁止 alert 弹窗；通知点击仅将 deepLink 以 location.hash 赋给 WebView，顺带清理 eval 字符串桥接。
6. 令牌安全存储与权限收紧（R3、R5）：Rust 侧接入跨平台凭据库 `keyring`（Windows Credential Manager / macOS Keychain / Linux Secret Service），前端默认 backend 切为 `NativeSecureStorageBackend`，不再使用进程内内存存储；同时关闭 `withGlobalTauri`，配置严格 CSP，`launch_service` 不再接收前端路径参数，直接消费启动期根据实际安装根目录固化的 `DaemonLaunchSpec`，杜绝任意进程拉起漏洞。
7. 自启机制归属 M1 与持久化偏好（R6、R7）：删除壳内自造的 adapter bridge 与对比函数，改收 M1 的 `AutostartAdapter`，复用 M1 `boot/autostart.ts` 的幂等校验与逐字段重写能力；默认偏好存储采用 `FileAutostartPreferenceStore` 落盘至 `.config/agsched-desktop/autostart-preference.json`，确保用户在系统设置禁用自启后不会在下次开机时被静默重注册。
8. 端口与样式规范（R8、R9）：移除所有硬编码 `127.0.0.1:7817`，未探测到确切地址时 `hostHint` 返回 null 交由 base-url 发现链降级；`connection-ui.ts` 属于独立原生降级错误页，内部样式改用 CSS variable tokens；`launch-spec.ts` 平台由调用方注入，去掉 process.platform 直读，跨包统一通过 workspace 引用。
