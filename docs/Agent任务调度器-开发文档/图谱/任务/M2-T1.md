# M2-T1　REST 骨架、插件链顺序与错误信封

- 所属模块：[[M2]]　**接入与设备信任**——定义两端如何连上 daemon 并不丢事件地保持同步：一次性配对码与可单独吊销的设备令牌、鉴权与操作归属、REST 骨架与 API 版本、SSE 服务端的事件信封／重放窗口／保活，以及自写的 SSE 客户端。凡「谁能连上、连上之后按什么协议收发」的都归它
- 前置依赖：[[M1-T2]]、[[M1-T10]]

## 输入 / 产出

- **输入**：M1-T10 的 `createContainer(config)`、`createHttpServer()` 与最小健康检查实例；10 节端点表
- **产出**：`src/http/plugins/`（00→90 八个）、`errors/AppError.ts`、`httpStatus.ts`、沿用 `http/routes/health.ts` 补齐 10 节健康诊断字段

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 插件按数字前缀注册且顺序为 request-id → logging → security-headers → auth → ratelimit → routes → static → error-handler
2) `90-error-handler` 是全仓唯一出现 HTTP 状态码数字的文件
未登记 code 与非 AppError 一律 500 + `E_INTERNAL`
3) logger `redact` 覆盖 `authorization`、`*.token`、`*.pairingCode`、`*.deviceToken`，日志中不出现明文令牌
4) 不注册 `@fastify/cors`
代码中出现即判失败
5) 错误信封的 `details` 字段能承载结构化信息（如实测版本串与期望模式），供前端就地渲染而不必解析 message（[[E-195]]）

## 必须处理的边界

- [[E-195]]　探测输出无法识别
    - 触发：版本串不匹配任何已知指纹
    - 期望：该 agent 标「未识别」且不可派发；界面同时显示实测到的版本串与期望模式，并给出手填绝对路径入口

## 实施沉淀

<!-- notes:begin -->
1. **Fastify 插件作用域隔离**：`00-request-id`、`10-logging`、`20-security-headers`、`90-error-handler` 属于跨路由全局中间件，通过标注 `Symbol.for('skip-override')` 穿透 Fastify 默认封装边界，确保根实例与子 scope 统一生效；`30-auth`、`40-ratelimit`、`50-routes` 则注册于 `{ prefix: '/api/v1' }` 封装内部，保证鉴权与限流钩子不会误拦截根作用域下的静态资源服务。
2. **HTTP 状态码唯一收敛**：状态码数字字面量仅存在于 `90-error-handler.ts` 内部，其余业务插件与路由均不得硬编码状态码。业务异常一律抛出携带 `ErrorCode` 的 `AppError`，由错误插件读取 shared `ERROR_CODES[code].defaultHttpStatus` 进行动态映射；未登记的异常编码或普通原生异常统一兜底回落为 `500 E_INTERNAL`，且仅在服务端日志保留原始堆栈，不向客户端泄露内部实现细节。
3. **结构化错误负载（E-195）**：错误信封预留可选 `details` 字典，供版本探测失配等异常携带实测输出（`observed`）、期望正则（`expected`）与执行文件路径（`execPath`），避免前端依赖脆弱的 message 字符串正则提取字段。
4. **路由前缀多态适配**：既有路由（如 `system.ts`、`health.ts`）在不同任务实现中可能分别采用完整路径 `/api/v1/...` 或相对路径 `/...`，`50-routes.ts` 引入 `createRouteTarget` 代理层，在挂载到 `/api/v1` scope 时自动规范化去除多余前缀，防止生成 `/api/v1/api/v1/...` 错误路由。
<!-- notes:end -->
