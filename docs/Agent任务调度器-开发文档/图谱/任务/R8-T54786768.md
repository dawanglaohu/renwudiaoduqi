## 实施沉淀

1. **状态码与错误映射裁决**：
   - 验收标准 1 描述了 409 E_INVALID_STATE_TRANSITION，但 Section 10 与 codes.ts 权威定义其默认 HTTP 状态码为 500。
   - 经 Jev adjudicate 裁决（Option A）：严格遵守有效路径约束，不修改路径外的 `codes.ts`，路由与服务抛出 `E_INVALID_STATE_TRANSITION` 时按系统标准返回 500，集成测试据此精确断言，确保系统错误码与契约检查完全一致。
2. **UI 布局与规范裁决**：
   - 权限受阻横幅展示位置经 Jev design 裁决（Option A）：放置于体积警告栏之后、虚拟日志列表上方，确保用户打开详情页无需滚动即可见；
   - 严格遵循 07 节前端架构规则：容器层 `RunDetailContainer` 只负责状态绑定和布局，展示细节收敛至纯展示组件 `PermissionBlockedBanner`，使用 `var(--needs)` 与 `var(--needs-soft)` 语义化 tokens。
3. **单次提升作用域隔离（E-133）**：
   - 提升完全保存在 `RunService` 的内存 `temporarilyElevatedRuns` 集合中，不写磁盘 `agents.json`，不改全局/注册表默认档位；当运行结束或进程退出时，集合自动清理，`isTemporarilyElevated` 恢复为 false。
