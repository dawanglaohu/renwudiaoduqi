## 实施沉淀

<!-- notes:begin -->
批次树的块间距由容器 `gap: 12px` 统一控制，标题外边距为 0；额外的 8px 外边距会使净距达到 20px，超过 D4 的 18px 上限。浅深主题必须成对维护，不能通过缩小容器 gap 迁就标题，否则同容器其他块会偏离 12px 契约。

换行 flex 行按视觉行边界量净距：竖直方向有重叠的子项属于同一行，以该行最底到下一行最顶的距离为准。导入控件同行的输入框高 48px、按钮高 32px，逐子项测量会把高度差计入间距而报 24px，行边界实测为 8px。仅换行的 row flex 使用此算法；竖向堆叠与 grid 保留原有兄弟净距及显式 gap 检查。

D4 上限保持 `gap × 1.5`，DENSITY 8 为 18px。回归保留 8px 不等高同行正控、40px 换行负控和 24px 竖向堆叠负控。两个测量分支都保留原探针的四分之一视口高度过滤，避免把 `mt-auto` 或 `align-content` 推挤当成块间距；显式 `rowGap` 仍受检查。发生 D4 失败时须先量实际几何，区分布局缺陷与测量误报，不能抬阈值。

本机验收的服务在 WSL root 环境运行，Web 来自本任务提交的生产构建。Windows 机器级实例锁的 ACL 限制见来源收口记录；WSL 的 GLIBC 2.31 需要从源码构建 `better-sqlite3` 绑定，改动只留在依赖目录。真实模型通过 WSL interop 调用已登录的 Windows Codex，临时注册表只覆盖 `execPath`；该适配属于验收环境，未进入产品源码。真实轮次及录像的提交、服务来源和环境例外须保存在审查证据与 PR 正文中，不能以日志长度、中文片段或 fixture 事件代替实际助手输出。

窄屏验收必须区分细指针窗口与粗指针触屏：只把 viewport 调到 390px 仍可能走桌面窄窗，无法证明手机入口。手机引导位于「任务列表」分栏，`showOnboarding` 时装配同一 `emptyConsole`，沿用导入、重绑定、批次选择和指派回调；触屏验收须选择该分栏并保留 `#/?pane=tasks`，核导入/刷新后仍 idle、0 runs。
