## 实施沉淀

<!-- notes:begin -->
两处 D4 失败性质不同，**不要一起当布局缺陷改**。批次树那处是真缺陷：`.deck-batch-tree` 已有 `gap: 12px`（契约块间距），标题又写 `margin-bottom: var(--sp-2)`，净距叠成 20px；修法是让外边距归零、由 gap 单独定间距——**不要**把容器 gap 调小来迁就外边距，那会让同容器其他块之间的间距不再等于契约值。导入行那处是探针的测量口径错：换行的行容器里子项横向排，逐对相邻子项量会把「同一行内 48px 输入框与 32px 按钮的高度差」当成上一块的底到下一块的顶而虚报 24，实际行距是 `rowGap` 的 8。判据是**行的视觉边界**（矩形竖直方向有重叠即同一行），不是子项序号。

探针算法有两条不能丢的约束。其一，只有换行容器（`flex-wrap` 非 nowrap）走行边界；竖向堆叠与 grid 仍按兄弟净距量，否则它们之间的超限间距会漏判——回归里 `stacked` 断言 24 仍失败就是钉这条。其二，D4 阈值保持 `gap × 1.5`（DENSITY 8 即 18），负控用真实 40px 行间距证明行边界口径没把超限一起放过去。**遇到 D4 失败先量页面实际几何，再决定改布局还是改探针；调阈值会把真实超限一起放过去。**

「推挤不算间距」这条口径两个分支都要守：行间距超过四分之一屏高（`align-content: space-between` 一类）时不计入 D4。只给竖向堆叠分支留这个过滤、换行分支漏掉，会把整屏撑开的行距报成违规——回归里 `spreadWrap` / `spreadStacked` 两条断言钉住，去掉换行分支的过滤即红（560 ≠ 0）。

本机起真实服务有一条硬限制：Windows 侧 `C:\ProgramData\agent-scheduler` 的机器级实例锁要求管理员 ACL（`icacls` 把非管理员的当前用户从 ACL 里摘掉，随后写锁文件即 EPERM），非管理员在 Windows 上起不了 daemon；这是环境限制不是产品缺陷（另见 `_run/batches/batch-19-20261013.md`）。真实服务因此放在 WSL 里以 root 起（`/var/lib/agent-scheduler` 可写）；WSL 侧 `better-sqlite3` 的 linux-x64 预编译包要 GLIBC 2.33/2.34 而本机是 2.31，必须从源码重建绑定（只动 `node_modules`，不入库）。真实模型入口：WSL 内没有已登录的 CLI，Windows 侧 codex 0.157.1 已登录，`bin/codex-bridge` 经 WSL interop 调 Windows 的 codex 作为 `execPath`——**这是本机验收环境适配，不是产品接线**，daemon 的默认行为不受影响。GIF 里的真实模型正文（`agent_message_chunk` 的中文内容）来自该真实进程，不是 fixture。
