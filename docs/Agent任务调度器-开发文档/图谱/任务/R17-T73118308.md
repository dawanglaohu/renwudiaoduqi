## 实施沉淀

<!-- notes:begin -->
原生启动预算是累计预算。initialize 慢于 15 秒仍可能在注册表配置的 60 秒内成功；给每个启动 RPC 各发一份 60 秒会把总期限放大。显式 0 表示关闭启动期限，不能用 truthy 默认值覆盖。已有最小注册表调用方可能没有计时器元数据，仅此情况使用既有 native 默认值。

供应商根因证据必须包含合法模型内容控制。相同配置下，bubblewrap 前置诊断也出现在成功运行中；它不能单独解释模型拒绝。错误模型证据使用该运行的真实模型错误与内容事件缺失，stderrTail 仍按最后一条 run.exited 的物理 stderr 展示。

浏览器动作必须等待对应运行的卡片。权威 API 已创建新 gate 时，页面仍可能显示上一轮卡片；重跑后先核卡片回溯链接中的 runId，再检查重派焦点。手机验证还须包含触控条件：仅缩小精细指针桌面视口会进入窄窗档。

手机按钮缺失必须在卡片可见时断言。单栏停留在“运行流”时，任务审批卡整体未呈现，按钮计数为零没有证明力；先经公开导航进入任务列表，核卡片档位和两个可见动作，再核重派按钮的 DOM 缺失。

详情录制必须把供应商结果行放入视口。原生初始化日志可能填满页面，容器文本含有回复并不证明截图能看见它；先经公开会话搜索核命中，再用实际滚轮定位日志，核唯一的 item/completed agentMessage 或 error 行后截屏。

发布录制时在浏览器原生截图阶段遮盖账户配额及包含凭据的日志行，并在 mode 声明范围；文本证据清除凭据 URI 和命名密钥。模型回复、拒绝、审批与公开操作保持可见。不在编码阶段修改截图内容。

失败确认后的最终画面必须等待 API 与 DOM 收敛：卡片消失、公开运行详情状态为 failed、返回甲板后仍无该等待卡。API 已 failed 而卡片尚在的过渡帧不能发布。bootstrap 就绪失败尚未进入浏览器和模型调用，不能写成模型拒绝；独立启动诊断或更早成功录制不能代替最终 HEAD 的整链通过。

Linux 验证使用同一工作树的私有 mount namespace，原生二进制和正常用户配置逐字节相同。Windows 挂载盘会显著拖慢启动及版本探测；RAM 放置只改变存放介质，不替换协议、身份、权限档或生产锁。鉴权副本仅存在私有 tmpfs，不进入提交、截图或上传产物。

bootstrap 的源模块读取也受跨盘文件系统影响。只移动 native 二进制不足以解决该阻断；在原工作树的同一 packages 路径放置逐文件核对的 RAM 内容，并保留原 Git 元数据，可完整验证同一提交。必须保留失败整套结果、736 个跟踪文件和 58 个依赖链接的身份核对，以及无跟踪干预的整套通过；带 strace 的耗时不能直接当作无跟踪基线耗时。

POSIX 配对权限必须实测文件模式。Windows 挂载目录在 Linux 下可能报告 0777，不能据 create 的 0600 参数声称落盘安全。验证数据目录须放在支持 POSIX 权限的文件系统；通过正常数据目录配置接入，不跳过断言，也不修改生产 ACL。

真实供应商 CI 的配置和鉴权必须由仓库提供；普通协议 E2E 通过不能替代这条链。没有实际同 HEAD 成功的 CI 或完整干净 HEAD 录制时，本任务不得声称全部验收通过，也不能将批次改为 clean/fixed。
