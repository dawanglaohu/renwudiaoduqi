# M5-T5　分支进 HEAD 判定与分支尖 SHA 记录

- 所属模块：[[M5]]　**工作区与 Git**——为每个任务准备、隔离与回收独立 worktree，从中读出改动（改动文件数、diff stat、diff 正文）并生成只读落地清单。凡要碰 git 或任务工作目录的都归它
- 前置依赖：[[M5-T2]]
- 完成后解锁：[[M8-T6]]

## 输入 / 产出

- **输入**：M5-T2 的 base 解析；M1-T7 的 spawn（git 一律经它）
- **产出**：`workspace/in-head.ts` 的 `isBranchInHead({repoPath, branchName, worktreePath, tipSha})`；收口 worktree 的分支命名规则

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) `git merge-base --is-ancestor 〈分支〉 HEAD` 退出 0 判进（method=`ancestor`）
退出 1 回退 `git diff --quiet HEAD 〈分支〉`，无差异判进（`no_diff`，[[E-273]]）
`worktreePath` 存在且 `git status --porcelain` 非空一律判未进（`dirty_worktree`，[[E-301]]）
2) 分支本地不存在时用调用方传入的 `tipSha` 做同一套判定，都否返回未进且 method=`branch_gone_unmerged` 并附 `git branch 〈原分支〉 〈sha〉` 命令文本
无 SHA 且 worktree 已清理返回进 HEAD 且 method=`branch_gone`（[[E-289]]）
3) git 报错返回 method=`error` 与 stderr 尾 200 字节，不推断为已合入（[[E-301]]）
4) 全部 git 调用经 proc/spawn、顺序执行不并发
返回 `{inHead, method, tipSha, commandText?, stderrTail?}`，本函数不写库
5) 收口工作区走 M5-T1 建分支 `wrapup/〈批次号〉-〈轮次〉`，分支冲突按 [[E-71]] 加序号，base 恒为当前 HEAD

## 必须处理的边界

- [[E-273]]　squash 合并让祖先判定失败
    - 触发：人用 squash 合并任务分支，`merge-base --is-ancestor` 返回否
    - 期望：回退 `git diff --quiet HEAD 〈分支〉`：无差异视为进 HEAD（method=no_diff）；仍有差异判「未进」，横幅提示改用 `--merge` 或人工裁定，不加第三种猜测
- [[E-289]]　分支本地已不存在时判进 HEAD
    - 触发：landed 运行的分支被 `git branch -d`/`-D` 删除
    - 期望：用 tick 记录的 `branch_tip_sha` 做同一套祖先/无差异判定；都否 → 未进（method=branch_gone_unmerged）并给出 `git branch 〈原分支〉 〈sha〉` 可复制命令；无记录 SHA 且 worktree 已清理 → 视为进 HEAD（method=branch_gone）并暴露 method；worktree 仍在则用其 HEAD SHA 判定
- [[E-301]]　进 HEAD 标记的单调性
    - 触发：分支合入后本地分支被删、worktree 被清理、或后续 git 判定报错
    - 期望：`is_in_head` 一旦为 1 不回 0；tick 在分支存在时记录 `branch_tip_sha`；判定连续 error ≥3 次横幅「无法判定分支是否已合入」，不推断为已合入
- [[E-71]]　分支名冲突
    - 触发：要建的分支名已存在
    - 期望：自动加序号后缀（任务号-2），不复用、不强制覆盖已有分支

## 实施沉淀

<!-- notes:begin -->
- 明确指定 `refs/heads/<branchName>` 引用空间：仓库可能存在同名 tag 或远端引用，直接传递裸分支名在 `rev-parse` 与 `merge-base` 中容易引起 ref 解析歧义；显式加上 `refs/heads/` 限定本地分支命名空间。
- squash 合并的历史断层补救：squash 合并会重写 commit DAG 历史，`merge-base --is-ancestor` 必然返回非零；必须回退比对 HEAD 与分支 tree 的实际差异（`git diff --quiet HEAD <ref>`），无差异即视同合入（E-273），杜绝误报阻断。
- 脏工作区绝对阻断：worktree 存在且 `git status --porcelain` 存在任何未提交内容时，一律判未进（`dirty_worktree`，E-301）。即使对应分支在 commit 维度已合入 HEAD，未提交修改仍会污染后续验证或收口，破坏状态单调性。
- 分支已删除且 worktree 清理时的终态收敛：分支本地已删除、worktree 已回收且无 tipSha 记录时，判定为已安全完成落地的 `branch_gone`；若仍持有 tipSha 且判定未合入，生成确定性的 `git branch <name> <sha>` 可恢复命令文本，防止分支被误删后无法找回（E-289）。
- 收口工作区基线不可篡改：`prepareWrapupWorktree` 硬编码 `baseRef: 'HEAD'`，收口任务必须基于 HEAD 全量状态执行统一验证与收口，禁止调用方自定义基线。
<!-- notes:end -->
