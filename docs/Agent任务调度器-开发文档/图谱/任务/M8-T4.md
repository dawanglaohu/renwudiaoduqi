# M8-T4　三个闸门与预设组合

- 所属模块：[[M8]]　**派发调度**——决定什么时候把哪个任务、用哪个 agent 与哪个模型、以什么权限派出去，并按批次、并行窗口、每 agent 并发与路径冲突限流，在三个闸门处停或放行、失败或重派时重新入队；判定本批分支是否都进了 HEAD、触发收口运行、按收口报告派修复运行与管理收口轮次也归它；泳道（窗口槽位）分配、任务终态后的补位、查 bug 与收口模式两个开关的持久化同样归它——泳道分配是它算出的派生数据。凡涉及顺序、名额、放行、重派的都归它；任务指派写进派发快照、阶段取值链（任务指派 → 阶段覆盖 → agent 默认）与收口指派设置也归它——它是唯一决定「这一阶段用谁跑」的地方，M7 只消费结果
- 前置依赖：[[M8-T3]]、[[M7-T3]]
- 完成后解锁：[[M8-T6]]、[[M9-T10]]

## 输入 / 产出

- **输入**：M8-T3 的推进逻辑；M7-T3 的判定
- **产出**：`Gate` 模型、`domain/gates.ts` 的 `resolveAfterReview()`、`POST /gates/:id/decide`、`PATCH /settings/gates`、`settings` 表迁移与 `repo/settings.ts`、`settings.gates_changed` 事件

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 三个闸门（派发前／审查后／落地前）各自可设「自动」或「等我确认」，落地闸门默认 `manual`、可设 `auto`
`auto` 只表示审查 pass 且审查后闸门也为自动时直接进 `landed`（已验收），代码中不存在任何 git 写操作
`gateOverrides` 允许含 `landing` 且只影响本批尚未到达该闸门的任务（[[E-53]]、[[E-56]]）
2) 预设：半自动 = 派发自动 + 审查后等确认
自动 = 审查 pass 自动进下一个，审查非 pass 一律停
闸门设置存 `settings(key='gates')`，缺行返回内置默认不插行，`value_json` 非法回落默认并 warn 不退出，PATCH 三字段整体写入缺一即 `E_VALIDATION`，写成功发 `settings.gates_changed`（[[E-292]]） 2b) `task.landed` payload 带 `by` 取 auto 或 human 与 `gateId`
3) 闸门等确认而人长时间不来时该任务**释放并发额度、不占窗口**，其他任务继续，仅下游依赖被动等待（[[E-54]]）
4) 执行中途改开关只影响尚未到达该闸门的任务，不需重启批次（[[E-56]]）
5) 两端同时点确认时幂等，第二次提示「已由另一端确认」，不产生两次派发（[[E-57]]）
6) 人工操作优先级高于自动推进，批次可中途暂停／接管，自动派发不得覆盖人的判断（[[E-05]]）

## 必须处理的边界

- [[E-05]]　批次中途人工干预
    - 触发：一批任务跑到一半，用户手动改了某个任务状态
    - 期望：人工操作优先级高于自动推进；批次可在中途暂停/接管，自动派发不得覆盖人的判断
- [[E-292]]　闸门设置存储缺行或损坏
    - 触发：`settings` 表无 key=gates 行，或 `value_json` 非法/含未知值
    - 期望：缺行返回内置默认 `{dispatch:auto, review:manual, landing:manual}` 不插行；非法值回落默认并 warn，不退出、不覆盖坏值直到下一次 PATCH；PATCH 三字段整体写入，缺字段或值不在 auto／manual 返回 `E_VALIDATION`；写成功发 `settings.gates_changed` 让另一端刷新
- [[E-53]]　落地闸门可设自动
    - 触发：三个闸门各自可设「自动」或「等我确认」
    - 期望：落地闸门默认「等我确认」，可切到「自动」：自动只表示审查 pass 后直接进 `landed`（已验收），产品仍不执行任何 git 操作（决策 12）；UI 三个开关同一形态、第三个不再置灰，切到自动时行内常驻一句说明而不弹确认框
- [[E-54]]　闸门等确认而人长时间不来
    - 触发：夜间无人值守，任务停在闸门前
    - 期望：该任务释放并发额度、不占窗口，其他任务继续；仅其下游依赖任务被动等待
- [[E-56]]　执行中途改闸门开关
    - 触发：用户在批次跑到一半时改设置
    - 期望：只影响尚未到达该闸门的任务；已在闸门前等待的任务按新设置立即放行或继续等，不需重启批次
- [[E-57]]　两端同时点确认
    - 触发：手机与桌面同时对同一闸门确认
    - 期望：幂等，第二次提示「已由另一端确认」，不产生两次派发
