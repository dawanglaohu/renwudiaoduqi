# M8-T4　三个闸门与预设组合

- 所属模块：[[M8]]　**派发调度**——决定什么时候把哪个任务、用哪个 agent 与哪个模型、以什么权限派出去，并按批次、并行窗口、每 agent 并发与路径冲突限流，在三个闸门处停或放行、失败或重派时重新入队。凡涉及顺序、名额、放行、重派的都归它
- 前置依赖：[[M8-T3]]、[[M7-T3]]
- 完成后解锁：[[M9-T10]]

## 输入 / 产出

- **输入**：M8-T3 的推进逻辑；M7-T3 的判定
- **产出**：`Gate` 模型、`POST /gates/:id/decide`、`PATCH /settings/gates`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 三个闸门（派发前／审查后／落地前）各自可设「自动」或「等我确认」
**落地闸门本版固定为人工且置灰**，UI 只暴露两个可切换开关（[[E-53]]）
2) 预设：半自动 = 派发自动 + 审查后等确认
自动 = 审查 pass 自动进下一个，审查非 pass 一律停
3) 闸门等确认而人长时间不来时该任务**释放并发额度、不占窗口**，其他任务继续，仅下游依赖被动等待（[[E-54]]）
4) 执行中途改开关只影响尚未到达该闸门的任务，不需重启批次（[[E-56]]）
5) 两端同时点确认时幂等，第二次提示「已由另一端确认」，不产生两次派发（[[E-57]]）
6) 人工操作优先级高于自动推进，批次可中途暂停／接管，自动派发不得覆盖人的判断（[[E-05]]）

## 必须处理的边界

- [[E-05]]　批次中途人工干预
    - 触发：一批任务跑到一半，用户手动改了某个任务状态
    - 期望：人工操作优先级高于自动推进；批次可在中途暂停/接管，自动派发不得覆盖人的判断
- [[E-53]]　落地闸门在本版不可用
    - 触发：因决策 12 不执行提交/PR
    - 期望：落地闸门固定为「等我确认」且置灰；UI 只暴露派发前与审查后两个可切换开关，第三个仅作状态展示
- [[E-54]]　闸门等确认而人长时间不来
    - 触发：夜间无人值守，任务停在闸门前
    - 期望：该任务释放并发额度、不占窗口，其他任务继续；仅其下游依赖任务被动等待
- [[E-56]]　执行中途改闸门开关
    - 触发：用户在批次跑到一半时改设置
    - 期望：只影响尚未到达该闸门的任务；已在闸门前等待的任务按新设置立即放行或继续等，不需重启批次
- [[E-57]]　两端同时点确认
    - 触发：手机与桌面同时对同一闸门确认
    - 期望：幂等，第二次提示「已由另一端确认」，不产生两次派发
