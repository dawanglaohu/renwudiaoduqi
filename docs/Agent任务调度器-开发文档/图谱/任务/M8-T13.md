# M8-T13　开始后的批次自动接力与窗口调度

- 所属模块：[[M8]]　**派发调度**——决定什么时候把哪个任务、用哪个 agent 与哪个模型、以什么权限派出去，并按批次、并行窗口、每 agent 并发与路径冲突限流，在三个闸门处停或放行、失败或重派时重新入队；判定本批分支是否都进了 HEAD、触发收口运行、按收口报告派修复运行与管理收口轮次也归它；泳道（窗口槽位）分配、任务终态后的补位、查 bug 与收口模式两个开关的持久化同样归它——泳道分配是它算出的派生数据。凡涉及顺序、名额、放行、重派的都归它；任务指派写进派发快照、阶段取值链（任务指派 → 阶段覆盖 → agent 默认）与收口指派设置也归它——它是唯一决定「这一阶段用谁跑」的地方，M7 只消费结果

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 导入、刷新、窗口改变与单批启动不会自动开始整份文档
仅文档计划 running 参与顺序自动执行（[[E-360]]）
2) start 后自动激活最早未 done 批次，同批按 laneCount、全局 Agent 名额和有效路径派发及补位，多份文档独立游标但共享额度与路径冲突（[[E-361]]、[[E-362]]）
3) 当前批未 done 时下一批没有实施运行
真实收口 clean/fixed 进入 done 后下一 tick 自动激活下一批
全部 done 写 completed，只发布实际变化（[[E-363]]）
4) 任务草稿优先、文档默认其次、Agent 配置最后，后续批无需人工填写
默认与局部指派共用 EffortValue，合法tier/vendor在冻结快照中保留，阶段覆盖保留原优先级
已注册指定 Agent 临时不可用时保持 running 与 agent_unavailable，保留默认指派不换厂商
恢复观测后下一 tick 自动派发，不需重新开始
同批有效的其他 Agent 草稿任务继续（[[E-365]]）
5) 人工闸门、待进 HEAD、手动收口、needs_attention、失败或契约待复核均保留已有阻断且给出 blockers，同批无依赖兄弟继续
旧单批入口不能越批或绕暂停（[[E-364]]、[[E-366]]）
6) 控制入口校验 expectedVersion
过期继续重试不能撤销较新的暂停，冲突不授予执行权
暂停先提交时，异步预检晚到不能建运行或将 queued 转 starting
暂停前已接受的运行继续并保存结果
继续恢复未派任务及待派审查/返工/查 bug/收口阶段，不重跑原实施
失败/中断不自动重派（[[E-367]]、[[E-368]]）
7) ID/contractHash 变化或源不可读暂停该文档新自动派发
正常刷新确认并继续后比较 membershipFingerprint 与 completionFingerprint，先经 membership_invalidated 重开失效 done 和成员变化的活动状态为 idle 再重规划
wrapping 时新增任务不得卡住，旧代 queued 收口按既有 queued→failed 对账，starting/running 在途时以 source_runs_pending 等待
旧代回调只保存历史且不改变新代批次状态，终态后下一 tick 按顺序补位
已完成批次新增任务必须正常派发并重新收口，移批/删任务/契约变化同样使旧完成证据失效
未受影响有效 done、已验收任务及历史保留
缺旧证明或晚到旧收口不得跳批或恢复 completed
成员变化建立新 generationId，run ID 归属与冻结快照同事务，tasks_json 只保存冻结 task_key 的排序 string[]、契约哈希保留在输入快照与完成指纹，每代2轮有效自动收口/6次物理尝试，历史编号不重用
旧代第6次完成后的新代可首次收口，重复控制/重启不重置，前轮/额度/晚到回调/闸门都按代核对
只 readiness 变化允许就绪兄弟继续（[[E-369]]）
8) 真实容器与生产 tick/spawn 测试覆盖两批接力、窗口补位、默认指派、跨文档额度、双端开始、暂停两种提交顺序、来源变化和重启
pnpm -w check 通过，缺生产入口不判通过（[[E-370]]）

## 必须处理的边界

- [[E-360]]　导入或切换文档意外启动
    - 触发：新导入、刷新、重绑定或页面切换
    - 期望：新导入保持 idle；这些操作不新增执行授权或直接建运行；已有 running 计划在来源不变时继续，来源变化则按 E-369 暂停；仅文档级开始授予执行权
- [[E-361]]　同文档控制并发与响应丢失
    - 触发：双端开始/暂停/继续、重复点击、响应丢失重试或 tick 并发
    - 期望：控制请求携带实际观察的 expectedVersion，状态更新前做版本比较；相同目标状态仅只读返回，过期请求不能撤销更新的暂停；版本冲突返回当前状态，客户端不自动换新版本重试；最多一份活动计划，不重复派任务或占窗口
- [[E-362]]　批次顺序与窗口、Agent 名额、路径冲突
    - 触发：同批任务超过窗口；多文档共用 Agent 或有效路径
    - 期望：只向当前批派实施任务；槽位空闲自动补位，Agent 名额与路径冲突仍全局生效；改变窗口不杀已有运行
- [[E-363]]　收口前越批或收口后缺少接力
    - 触发：当前批任务验收但未进 HEAD、未收口或收口 open；收口 clean/fixed
    - 期望：未 done 不启动下一批；当前批全部满足原收口契约达到 done 后，下一 tick 自动激活最早未完成批次，不要求用户逐批再点派发
- [[E-364]]　人工闸门或失败任务卡住自动推进
    - 触发：派发前、审查后、落地前闸门等待；收口手动或 needs_attention；任务失败
    - 期望：保留现有闸门与失败不自动重派；同批无依赖兄弟继续；下一批等待 done；DTO 与页面给出原因和处理入口
- [[E-365]]　后续批次无逐任务指派或默认 Agent 不可用
    - 触发：只配置一次文档默认指派；后续任务存在局部覆盖；指定 Agent 离线
    - 期望：任务草稿优先，其次文档默认，再读 Agent 配置；默认与草稿共用 effort: EffortValue，合法 vendor 原值经既有取值域校验并冻结，不丢成三档；无局部覆盖的后续批次直接沿用；未知 Agent ID/非法参数拒绝且不建计划；已注册 Agent 临时不可用时保存 running 等待计划与 agent_unavailable，不静默换家，观测恢复后自动补位，其他有效覆盖仍可派发
- [[E-366]]　接管旧的活动批次或手动入口绕过文档计划
    - 触发：开始时已有单批运行、多个活动批次，或自动执行期间手动启动别批
    - 期望：最早未完成的一批已有活动运行则接管不重复；多个旧活动批次明确拒绝并列出；手动批次入口不能越批或绕过文档暂停
- [[E-367]]　暂停与异步派发检查竞态
    - 触发：用户暂停先提交，start/resume/tick 的异步预检后完成；暂停期间收口结束
    - 期望：提交前重读执行状态和 version；暂停后不新增自动运行或将 queued 转 starting；暂停前已接受的 starting/running 继续，结果照常保存；继续恢复待派阶段而不重跑原实施，下一批仍等待继续
- [[E-368]]　daemon 重启与终态任务重复运行
    - 触发：执行计划 running 时重启；任务已 failed、interrupted、orphaned 或 aborted
    - 期望：重启前意图与执行位置持久保留，job 启动前 running 转 paused，显示 daemon_restarted；继续只补未派任务，终态任务需显式重派
- [[E-369]]　执行中文档变更、不可读或契约待复核
    - 触发：任务 ID/contractHash 变化、源失效，或仅 readiness/reasons 更新
    - 期望：契约指纹变化或不可读暂停新自动派发，在途快照不变；已完成批次新增任务、移批、删任务或成员契约变化时，membershipFingerprint 与 completionFingerprint 不一致即作废旧完成证据；显式开始/继续经 membership_invalidated 受控白名单把受影响 done 或真实成员变化的活动状态重置 idle；旧来源 starting/running 在途时以 source_runs_pending 等待，旧代 queued 收口按既有 queued→failed 对账，旧代回调只入历史；确认成员变化才建立新 generationId，每代保留2轮有效自动收口/6次物理尝试上限，同源控制不清额度；新成员重新验收收口，保留已验收任务与历史；仅就绪元数据变化不暂停整份文档，就绪兄弟继续
- [[E-370]]　文档级执行只在测试替身里成立
    - 触发：实现控制接口与批次接力后验收
    - 期望：真实页面导入无运行，点击一次开始后经生产 bootstrap、工作树、收口和 SSE 连续运行；验证窗口、跨批、暂停/继续、重启、双端幂等、已完成批次新增任务不被跳过与实际 Agent 入口，缺证据不得宣称交付

## 实施沉淀

<!-- notes:begin -->
- 执行授权取自持久计划的 running 状态；异步预检后还须在写入事务里重读版本和当前批，否则先提交的暂停仍可能被晚到调度覆盖。
- 同一 tick 的多文档候选基于同一份早期运行快照；实际写入时须再次核对全局 Agent 名额和路径，才能避免两份文档同时占用最后一个名额或相同文件。
- 收口受理时须把成员指纹、代次、运行 ID 与快照放在同一事务；完成证据仅认可本代 clean/fixed 且分支已进 HEAD。旧代回调保留历史，但不得改变新代批次、额度和游标。
- 任务草稿是一组明确指派：草稿存在而模型或思考强度为空时，回退该 Agent 的配置；只有完全没有草稿的任务才使用文档默认，避免跨厂商继承不适用的取值。
- 当前代的 landed 判定须以任务当前契约哈希和实施快照配对；历史 landed 与旧手动状态保留，但不能代替新契约的实施或阻止新尝试。
- 批次行会保留从文档删除的任务；自动与手动收口都按持久计划的成员 ID 取数，否则已删除且未落地的历史行会永久阻断接力。
- queued 阶段的代次可来自自身快照或父运行；收口修复优先取收口父运行，因为其快照可能复制了更早实施代次。同代暂停不改变代次，继续后仍可出队。
- 旧单批 tick 看见无计划时，事务提交也必须确认执行行仍不存在；预检期间新增并暂停的计划会撤销旧 tick 的派发权。
- 文档执行阻断与调度使用同一份当前契约证据；历史 landed 不能遮蔽待派任务的 Agent 不可用状态。旧契约 reworking 运行不再投递，应记录失败并释放其名额与路径。
- 旧代 queued 收口可能属于刷新后已移空的批次；按整份文档对账，事务外同步发布 run.state_changed 与 lane.released，避免页面继续占用已释放槽位。
- 新计划的当前批次可能不同于旧运行的批次；source_runs_pending 必须扫描整份文档的在途运行，否则旧来源仍改工作区时会提前派新任务。
- 旧代收口报告晚到时，已取消或中断的运行保持终态，报告只入历史；在途运行落为终态时清除槽位并发布释放事件。
- 任务移批会换代，即使契约哈希不变也不能继续投递旧代 reworking；旧契约人工闸门的运行和记录留作历史，任务状态解除后按新契约重新实施。没有旧契约实施运行的派发前人工闸门仍须保留。
- 在途运行持有冻结快照中的有效路径；文档刷新后的当前任务路径只适用于新运行，不能替换旧运行的冲突锁。
- 派发契约测试里预置的运行快照必须冻结任务当时的有效路径；空路径替身会掩盖旧运行实际持有的路径锁。
- 旧代 queued 审查或查 bug 失败后，停靠在 reviewing 的实施父运行若仍占并发与路径，也必须同事务清退；source_changed 历史失败不再阻断当前代新实施。
- 新代重建后，旧收口 awaiting_human 的批次级 waiting 闸门必须随旧运行一起失效；历史报告与闸门行保留，但不能再授予新代 done。
- 旧实施 awaiting_human 运行失效时，其任务级 waiting 闸门也要同事务 supersede；只清任务手动状态会留下仍可点击的迟到裁决。
- 已完成计划的任务移批可能不改变文档级 ID/契约哈希指纹；刷新事务仍须比较逐批成员指纹并撤销失效的 completed 授权，保持未变刷新幂等。
- 完成证据按当前成员的契约快照和有效实施运行核对；其他契约版本中较新的失败尝试不能覆盖仍有效的已验收运行。
- 文档计划的收口默认跟随指派也要按当前契约选最近已验收运行；历史较新失败尝试不能让有效成员的自动收口错误转入 needs_attention。
- 收口提示和 open 裁定生成的修复快照须共用当前契约证据；跨批修复仍按当前文档任务集合查找，不能复制另一契约版本的分支、指派与验收材料。
- 任务移批后，旧批次的失败类终态不属于新批次的当前证据；先保留文档变更确认闸门，确认后再派新实施，已验收且契约有效的兄弟任务不重复。
- 收口重试先查幂等键，再校验当前执行状态；暂停或完成后的响应丢失重试仍能取回原运行。
