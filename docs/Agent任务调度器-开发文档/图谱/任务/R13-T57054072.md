1. 实现选择：
   - 采用 Playwright Chromium 驱动真实 Web 构建产物（`packages/web/dist/index.html`），通过独立进程拉起真实 daemon bootstrap.mjs，严格杜绝任何 mock、测试钩子（`window.__setToken`）或 SQLite 直写，完全通过公开 HTTP/SSE API 与 UI 交互完成端到端全链路闭环。
   - 浏览器在正式 Web 页面输入 daemon 可读的 docs-data.js 绝对路径并点击导入；空闲泳道继续显示四步向导，逐任务指派、启动批次派发分别经共享路由表调用公开 API，服务器返回与页面状态交叉验证。
   - 针对 Step 8（离线断网、重连退避与去重补推），通过 `page.evaluate(() => window.stop())` 配合 `page.route` 拦截重连，在零页面重载、零组件卸载、完全保留内存 lastEventId 和 DOM 的前提下注入网络故障。验证离线横幅呈现并匹配连接重连文案、派发能力因断网禁用、重连时间戳具有指数退避特征（连续重连间隔满足至少 1.5s、3s 与增长下限）、断网期间产生消息在断网期 DOM 呈现严格为 0（负向控制），恢复网络后携带 `Last-Event-ID` 重新连上，横幅更新为「最后同步于」，断网消息在 DOM 中严格恰好补推一次（`count === 1`，无重复无遗漏）。
   - 针对 Step 9（人工闸门审批），配置 review: manual 且 landing: auto，真实任务运行完成后进入 awaiting_human 状态停靠在 review 闸门；浏览器运行甲板批次树任务行呈现 data-component="gate-card" 审批卡，由 Playwright 点击 button[data-action="approve"] 完成人工决定；服务端在人工批准 review 闸门时注入 review: auto override 避免循环重复创建 waiting gate，并自动推进至 landing 完成落地，审批卡从 DOM 消失且公开 API 交叉断言闸门为 decided/pass，运行推进至 landed。
   - 针对 Step 11（撤销设备令牌），服务端调用 `DELETE /api/v1/devices/:id` 撤销令牌，服务端断流，旧令牌请求返回 401，浏览器清除凭据并重定向至 `#/pair`，且在重定向后监控验证停止了无限重连（等待期内最多捕获 1 次已在途的重试）。
