# M6-T4　停滞检测与静默计时

- 所属模块：[[M6]]　**运行监管**——管一次运行从启动到结束的全过程：状态机（「已退出」与「已落地」分开）、收流与落盘编排、按游标分段回读与厂商会话文件的只读引用、进度信号、停滞检测、中止与 daemon 重启后的对账、回话投递；任务到达终态后结束并归档该任务全部会话（进程还在走 `killTree` 两阶段），归档后会话引用只读、不得复用，也归它。凡「这一次运行现在怎么样、它说过什么」的都归它
- 前置依赖：[[M6-T3]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：M6-T3 的 `last_event_at`
- **产出**：`stall-detector` job（30s tick）

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 完全无流事件超阈值才升级为醒目告警
**仍在输出时只标弱提示，不改运行状态、不杀进程**（[[E-22]]、[[E-120]]）
2) 阈值按 agent 可配、有出厂默认，不做全局单一阈值
3) 处于「等待人回话」时归类为「等人」而非「疑似停滞」，不重复告警
超阈值后提示「中止以释放并发窗口」（[[E-122]]）
4) tick 不重入，上一次未完成则跳过本次并计数

## 必须处理的边界

- [[E-120]]　长思考被误判停滞
    - 触发：超过阈值但 NDJSON 仍在输出
    - 期望：只标「疑似停滞」的弱提示，不改运行状态；只有完全无流事件超阈值才升级为醒目告警
- [[E-122]]　等人回话期间超时
    - 触发：任务停在「等待人回话」超过阈值
    - 期望：归类为「等人」而非「疑似停滞」，不重复告警；超过阈值后提示「中止以释放并发窗口」
- [[E-22]]　agent 长时间零输出
    - 触发：在等 API 或长思考
    - 期望：用「最后事件距今 N 分钟」做静默检测，标「疑似卡住」并给出查看原始流与终止的入口，不得一直显示「进行中」
