## 必须处理的边界

- [[E-10]]　手机断网期间任务跑完
    - 触发：提醒产生时手机不在线
    - 期望：提醒事件在 daemon 侧按 event id 入队，手机重连后补推并去重，不得丢弃
- [[E-140]]　流里混入非 JSON 行
    - 触发：agent 输出启动 banner、warning、进度条
    - 期望：逐行 try/parse，解析失败的行归入原始日志并继续，绝不中断流或丢弃该行
- [[E-142]]　daemon 长跑内存增长
    - 触发：连续运行数天
    - 期望：内存只保留最近 N 条事件的环形缓冲，历史事件全部落盘按需回读
- [[E-348]]　运行零产出退出
    - 触发：任何 kind 的运行在首条内容事件（`agent_message_chunk`／`agent_thought_chunk`／`tool_call` 任一）之前进程退出（不论退出码，含 0）、启动超时或错误类事件；dsh 无流式时最终输出解析不出任何内容也算
    - 期望：判定只看事件 kind、不匹配 stderr／stdout 文本（与 E-330 同一结构规则）。实施运行（含 `origin=rework`／`wrapup-fix`）：`exited → reviewing → awaiting_human` 两跳（reason `exited_before_output`），**不跑机械检查、不派审查、不计 `rework_count`**，`tasks.lane_no` 置 NULL 并发 `lane.released{reason:'awaiting_human'}`（E-326）；审查运行走 E-62、查 bug 运行走 E-323、收口运行走 E-295。事务后重跑一次该 agent 的登录态探测（dsh 不探）。审批卡（`GateDto.context`）附退出码、退出信号、stderr 末 20 行（来自该 run 最后一条 `run.exited` 事件的 `stderrTail`，已脱敏，旧事件缺字段显示「无记录（旧运行）」）、刚探测的登录态，与固定提示句「agent 未产出任何内容就退出，常见原因：未登录、模型名不可用、参数被拒」，不写「未登录」定论；动作「重跑」（复用 `POST /runs/:id/rerun`）、「换 agent 重派」、「标失败」（`awaiting_human → failed`），手机端只有重跑与标失败；每次都转人不自动重试；同一 agent 多条泳道同时零产出各自转人、不暂停该 agent；启动超时与 spawn 失败仍走既有 `starting → failed`、手动停止不进本判定；内容事件之后才失败走既有路径并正常计数

## 实施沉淀

<!-- notes:begin -->
- 为什么 `run.started` 必须在 `handleEventStateWiring` 中被明确排除：`handleEventStateWiring` 规则为「首条事件到达时将 starting 迁为 running」，但 `run.started` 产生于调度器写库与派发事务刚提交的时刻，此时子进程尚未进入 worktree 准备与 spawn 阶段；若被 `run.started` 提前推进到 running，真正的 `launchRun` 会因检查到非 starting 态而幂等返回，导致子进程无法拉起且 `runs.pid` 永久留空。因此将 `run.started` 与 `run.state_changed` 一同作为状态推进的忽略项，统一由子进程首条内容事件或 `launchRun` 显式迁入 running。
- 为什么适配器输出的事件必须在 `runService.ingestEvent` 补全信封元数据：各 agent 适配器纯函数仅负责厂商协议归一化（产出含 `kind` 与 `payload` 的 `EventEnvelopeInput`），不持有全局单调 id 与序列号；若直接传递给 `logstore.appendEvent`，SQLite `events` 索引表的主键 `id` 会因缺失触发非空约束冲突并中断流。在 service 层统一经由 `envelopeFactory.createEnvelope` 分配全局单调 id 与精确时间戳，既保证适配器无副作用，又确保索引表与 SSE 游标单调一致。
- 为什么 `matching.path` 在 reuse 模式下不能做宿主路径二次解析：跨平台测试与隔离容器中 worktree porcelain 汇报的路径可能与当前宿主路径分隔符不同，二次调用宿主 `path.resolve` 会将相对或异构路径规范化为当前平台盘符路径，破坏工作区路径比对一致性。
- `spawnManaged` 的平台、进程树操作、注册表与时钟由 composition root 一次绑定，dispatch 只传 `LaunchSpec`。这样真实调用与测试替换共用同一个端口，同时保证 proc 层始终收到完整的宿主依赖和 `shell:false` 策略。
- 下游 base 不能由 dispatch 自己把缺省值翻译成 `HEAD`。`launchRun` 把直接上游与快照里的 `RunBaseRef` 交给 M5-T2 的 BaseSelector；只有全部上游已进 HEAD，或用户显式选择某个 upstream branch，才进入 worktree 创建。
- 零产出判定只看归一化事件 kind。实施、rework 与 wrapup-fix 在首条消息／思考／工具调用之前退出时转 `awaiting_human`，不跑机械检查、不增加返工计数；最终 `run.exited` 保留退出码、信号与 stderr 尾，闸门只持久化稳定标记 `exited_before_output`，后续读取侧据此组装诊断上下文。
<!-- notes:end -->
