# M4-T2　参数模板校验与模板变量白名单

- 所属模块：[[M4]]　**Agent 适配**——把形态各异的 agent 抽象成同一个可派发对象：注册表（含每个 agent 通用的版本指纹探测字段与具名的「适配器种类」枚举）、可执行探测、模型清单读取与降级、启动参数与三档权限映射、以各家原生通道为主干把输出归一化成 ACP `session/update` 词汇的事件、可回话与**是否提供流式事件**等能力位，并自实现一个通用 ACP 适配器作为兜底与第 6 家及以后的入口。凡「某一家 agent 跟别家怎么不一样」的都归它；登录态探测（三值、只跑 agent 自己的状态命令、结果缓存）与模型清单的四级来源合并（实时／配置／内置别名／历史）也归它——它们都是「这一家怎么问」的事
- 前置依赖：[[M4-T1]]
- 完成后解锁：[[M9-T14]]

## 输入 / 产出

- **输入**：M4-T1 的注册表
- **产出**：模板解析器与保存时校验

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 只允许 `{model}` `{prompt_file}` `{cwd}` `{session_dir}` 四个模板变量
含未知模板变量或括号未闭合时**保存即拒绝**并高亮出错位置（[[E-89]]）
2) 注册表只发布模板校验通过的快照，运行时渲染入口仍须拒绝未经校验的模板
3) 两个 agent 配成同一可执行路径时允许
会话目录相同则产生 `reason` 精确等于 `session-dir-overlap` 的英文告警但不拒绝保存，中文文案由设置页映射为「会话记录可能互相覆盖」（[[E-95]]）

## 必须处理的边界

- [[E-89]]　参数模板写错
    - 触发：含未知模板变量或括号未闭合
    - 期望：保存时即校验并拒绝，高亮出错位置；运行时永不使用未通过校验的模板
- [[E-95]]　两个 agent 配成同一路径
    - 触发：用户复制配置后没改
    - 期望：允许；会话目录若也相同，daemon 产生 `reason` 精确等于 `session-dir-overlap` 的英文告警但不拒绝保存，设置页按该原因显示「会话记录可能互相覆盖」

## 实施沉淀

<!-- notes:begin -->
- `launch-template.ts` 是零副作用的 domain 叶子模块，不引入基础设施层或 daemon 错误类。校验与渲染都返回判别联合；调用边界只有在拿到完整成功结果后才能使用参数，失败结果由注册表转换为结构化告警。
- 模板变量限定为 `{model}`、`{prompt_file}`、`{cwd}`、`{session_dir}` 四项，采用逐字符状态机精确定位错误起止列偏移，规避全局正则替换无法准确定位未闭合括号及行内高亮的问题。渲染逻辑收敛为纯字符串展开，不耦合特定参数的业务特判。
- 注册表构造必须显式注入 `win32` 或 `posix` 路径语义：POSIX 保持大小写且不转换反斜杠，Windows 统一斜杠并忽略大小写，不根据可执行文件后缀猜测宿主环境。规范会话目录参数使用 `--session-dir`，未提供时以同一可执行路径的默认会话空间比较。
- 注册表加载与热更流程中分别覆盖 defaults、overrides 及最终生效模板的语法合法性，任一层非法均拒绝换代并保留上一版；同路径同会话目录重叠仅触发 `session-dir-overlap` 告警而不阻断加载，告警文案保持英文规范。
<!-- notes:end -->
