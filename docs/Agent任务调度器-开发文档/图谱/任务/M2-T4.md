# M2-T4　事件信封、单调 id 分配器与重放缓冲

- 所属模块：[[M2]]　**接入与设备信任**——定义两端如何连上 daemon 并不丢事件地保持同步：一次性配对码与可单独吊销的设备令牌、鉴权与操作归属、REST 骨架与 API 版本、SSE 服务端的事件信封／重放窗口／保活，以及自写的 SSE 客户端。凡「谁能连上、连上之后按什么协议收发」的都归它
- 前置依赖：[[M1-T2]]、[[M1-T10]]
- 完成后解锁：[[M2-T5]]

## 输入 / 产出

- **输入**：M1-T2 的库；M1-T10 的 composition root；08 节信封形状
- **产出**：`src/events/`：`envelope` / `id-allocator` / `ring-buffer` / `bus`；`repo/event-seq-repo.ts`；在 `boot/container.ts` 构造全进程唯一事件缓冲与总线

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 事件 id 用 SQLite 水位预分配，每满 1000 写一次库
重启后从水位继续，**允许跳号但绝不回退**（[[E-10]]）
2) 环形缓冲全局一个、容量恒 5000（[[E-153]] 的重放窗口）
3) `bus.publish` 出现在事务回调内由架构测试判失败
4) 信封字段与 `packages/shared/src/api/events.ts` 的判别联合一致，新增 kind 时 switch 有穷尽性检查

## 必须处理的边界

- [[E-10]]　手机断网期间任务跑完
    - 触发：提醒产生时手机不在线
    - 期望：提醒事件在 daemon 侧按 event id 入队，手机重连后补推并去重，不得丢弃
- [[E-153]]　断线超过重放窗口
    - 触发：离线时长超过服务端保留的最近 N 条事件
    - 期望：服务端返回「重放窗口已过期」，客户端改为 REST 拉全量当前状态快照后从最新 event id 续接，不允许静默丢事件

## 实施沉淀

<!-- notes:begin -->
- **单调 ID 水位预分配（E-10）**：`event_seq` 的 SQL 与数据库错误转换由 `repo/event-seq-repo.ts` 负责，allocator 只依赖 `EventSeqStore`。首次启动先持久化水位 1000；重启读到水位 `W` 时，先持久化 `W + 1000` 再从 `W + 1` 发号。崩溃时未使用的编号允许跳过，任何已经或可能已经发出的编号都不会复用。composition root 不提供纯内存回退，因此生产启动若无法建立 SQLite 水位就直接失败。
- **固定重放窗口与载荷引用（E-142、E-153）**：进程只构造一个容量为 5000 的 ring，bus 发布和 SSE 重放查询共享该实例。单条 payload 超过 32 KiB 时，调用方必须先获得 `{fileSeq, byteOffset, byteLen}`；预截断信封也须通过相同的正整数与安全整数校验。校验在写入前完成，失败不会淘汰已有事件。`Last-Event-ID < minId - 1` 时返回 `E_REPLAY_WINDOW_EXPIRED`，后续 SSE 层据此拒绝部分重放并要求客户端改走 REST 快照。
- **共享判别联合与信封所有权**：`EVENT_DEFINITIONS` 的键派生 `EventKind`，显式 `EVENT_KINDS` 列表以反向类型检查保证不漏成员，`EventPayloadMap` 必须覆盖每个 kind，最终映射为 `EventEnvelope` 判别联合。新增 kind 若缺 payload、列表或消费者 switch 分支，TypeScript 检查失败。信封工厂不接受 id、ts、scope 或 seq 覆盖；这些字段分别由 SQLite allocator、注入时钟、kind 映射和每 run 内存序列生成。logstore 直接消费该联合，未知字符串不会被归类为里程碑。
- **事务外发布**：事务禁令由架构测试执行，测试沿 `unitOfWork`、`uow`、`database` 与 `db` 的内联、变量及具名回调追踪 `bus.publish`，同时验证普通对象上的 `run`/`publish` 不误报。业务代码必须在 `unitOfWork.run()` 返回后发布事件，不能依赖运行时探针掩盖错误顺序。
- **订阅失败隔离**：`bus.publish()` 先把信封写入 ring 一次，再按订阅时的快照逐个通知。某个订阅者抛错不会阻止其余订阅者，也不会触发递归发布；返回的冻结 `subscriberErrors` 逐项保留原始错误和失败订阅者，调用方可以统一记录或升级处理。
