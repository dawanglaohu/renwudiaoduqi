## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 事件 id 用 SQLite 水位预分配，每满 1000 写一次库
重启后从水位继续，**允许跳号但绝不回退**（[[E-10]]）
2) 环形缓冲全局一个、容量恒 5000（[[E-153]] 的重放窗口）
3) `bus.publish` 出现在事务回调内由架构测试判失败
4) 信封字段与 `packages/shared/src/api/events.ts` 的判别联合一致，新增 kind 时 switch 有穷尽性检查

## 必须处理的边界

- [[E-10]]　手机断网期间任务跑完
    - 触发：提醒产生时手机不在线
    - 期望：提醒事件在 daemon 侧按 event id 入队，手机重连后补推并去重，不得丢弃
- [[E-153]]　断线超过重放窗口
    - 触发：离线时长超过服务端保留的最近 N 条事件
    - 期望：服务端返回「重放窗口已过期」，客户端改为 REST 拉全量当前状态快照后从最新 event id 续接，不允许静默丢事件

## 实施沉淀

<!-- notes:begin -->
- **单调 ID 水位预分配机制（E-10）**：`event_seq` 表仅持久化批次上限水位。启动与崩溃恢复阶段读取现有水位 `W` 后，立即向数据库写入 `W + 1000` 并从 `W + 1` 开始发号。若前序进程在未用满整批即终止，已跨过的编号作为跳号废弃，确保发出的编号严格递增、绝不回退，满足手机端断网重连后根据 ID 幂等去重的契约；稳定运行阶段仅在批次用尽时发生一次 SQLite 写入。
- **环形重放窗口与载荷截断（E-142、E-153）**：环形缓冲区全局单例且容量恒定 5000 条，满额后以先进先出（FIFO）方式覆盖淘汰旧事件。为防止超长输出撑大常驻内存，入缓冲前度量 payload 字节长度，凡超过 32 KiB 者均替换为 `{ truncated: true, byteLen, ref }`，正文保留在 logstore 中按需回读。重放检索时以当前缓冲头部元素 `minId = buffer[head].id` 为基准：若客户端提交的 `Last-Event-ID < minId - 1`，说明客户端落后的跨度已超越保留窗口，存在丢失事件，立即返回 `E_REPLAY_WINDOW_EXPIRED`（409），指示客户端改走 REST 全量快照；仅在请求 ID 大于等于 `minId - 1` 时完整重放未送达事件，杜绝静默丢弃。
- **事务边界隔离与静态架构测试**：better-sqlite3 处于同步单线程模型，事务内发布事件或触发副作用容易导致 WAL 锁长时间占用甚至重入。`EventBus` 运行时支持事务深度感知并在事务内拦截发布；同时由 `packages/daemon/test/arch/bus-transaction.test.ts` 利用 TypeScript Compiler AST 静态扫描所有源码，断言 `bus.publish` 不得出现在 `unitOfWork.run` 与 `database.transaction` 回调体内。
- **判别联合与穷尽性检查**：`packages/shared/src/events.ts` 中将 ACP 原生命名与产品组状态变更事件归一化为以 `kind` 为判别字段的联合类型 `EventEnvelope`，并导出 `assertNever` 辅助函数。未来新增事件 kind 时，未穷尽处理的 switch 语句将在编译期触发 tsc 报错。
<!-- notes:end -->
