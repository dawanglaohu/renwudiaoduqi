# M2-T4　事件信封、单调 id 分配器与重放缓冲

- 所属模块：[[M2]]　**接入与设备信任**——定义两端如何连上 daemon 并不丢事件地保持同步：一次性配对码与可单独吊销的设备令牌、鉴权与操作归属、REST 骨架与 API 版本、SSE 服务端的事件信封／重放窗口／保活，以及自写的 SSE 客户端。凡「谁能连上、连上之后按什么协议收发」的都归它
- 前置依赖：[[M1-T2]]、[[M1-T10]]
- 完成后解锁：[[M2-T5]]

## 输入 / 产出

- **输入**：M1-T2 的库；M1-T10 的 composition root；08 节信封形状
- **产出**：`src/events/`：`envelope` / `id-allocator` / `ring-buffer` / `bus`；`repo/event-seq-repo.ts`；在 `boot/container.ts` 构造全进程唯一事件缓冲与总线

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 事件 id 用 SQLite 水位预分配，每满 1000 写一次库
重启后从水位继续，**允许跳号但绝不回退**（[[E-10]]）
2) 环形缓冲全局一个、容量恒 5000（[[E-153]] 的重放窗口）
3) `bus.publish` 出现在事务回调内由架构测试判失败
4) 信封字段与 `packages/shared/src/api/events.ts` 的判别联合一致，新增 kind 时 switch 有穷尽性检查

## 必须处理的边界

- [[E-10]]　手机断网期间任务跑完
    - 触发：提醒产生时手机不在线
    - 期望：提醒事件在 daemon 侧按 event id 入队，手机重连后补推并去重，不得丢弃
- [[E-153]]　断线超过重放窗口
    - 触发：离线时长超过服务端保留的最近 N 条事件
    - 期望：服务端返回「重放窗口已过期」，客户端改为 REST 拉全量当前状态快照后从最新 event id 续接，不允许静默丢事件

## 实施沉淀

<!-- notes:begin -->
- **单调 ID 水位预分配与仓储收口（R1、E-10）**：根据全仓 SQL 唯一归收 repo 的架构约束，`event_seq` 的所有预编译语句与数据库操作全部收拢在 `repo/event-seq-repo.ts`。`id-allocator.ts` 仅消费注入的 `EventSeqStore` 接口，固定全局 `'events'` 序列与 1000 批大小。启动与重启阶段读取现有水位 `W` 后立即写回 `W + 1000` 并从 `W + 1` 起始发号；未使用的前序编号跳号作废，保证 ID 严格单调递增绝不回退，满足手机断网重连后基于 ID 去重补推的契约。
- **环形重放窗口与载荷截断硬校验（R2、E-142、E-153）**：环形缓冲容量写死为常量 5000 条，删除动态容量与清空能力。当单条 payload 超过 32 KiB 时，调用方必须传入有效的 logstore 磁盘定位引用（`{ fileSeq, byteOffset, byteLen }`）；若未传或为 null，在触碰与污染环形缓冲区之前直接抛出 `E_VALIDATION` 类型化错误。在重放逻辑中以 `minId = buffer[head].id` 为下界，当请求的 `Last-Event-ID < minId - 1` 时明确返回 `E_REPLAY_WINDOW_EXPIRED`（409），指示客户端改走 REST 全量快照续接，不静默丢弃。
- **共享契约单一派生与信封构造约束（R3）**：将共享事件契约迁移至规范路径 `packages/shared/src/api/events.ts`，以单一不可变映射表 `EVENT_DEFINITIONS` 作为唯一真实源，派生出 `EventKind`、`EventScope`、`EventPayloadMap` 与判别联合 `EventEnvelope`。信封工厂 `createEnvelopeFactory` 剥离调用方对 `id`、`ts`、`scope` 的覆写权限，强制由内部 ID 分配器、时钟与映射表提供；`payload` 依据 `kind` 静态约束类型；`seq` 针对每个 `runId` 内部独立自 0 严格递增。logstore 删除私有重复定义直接消费 shared，并通过 negative type test 断言新增 kind 缺分支必导致 tsc 失败。
- **事务边界静态检查与运行时保护（R4）**：强化 `bus-transaction.test.ts` 架构测试，利用 TypeScript Compiler AST 遍历，覆盖内联箭头函数、变量声明回调以及具名函数传递等多种事务回调注入形态；同时严格限定事务承载对象（`unitOfWork`、`database`、`uow` 等），排除其他业务类上的普通 `run` 方法。可选的运行时守卫在捕获事务中发布时抛出 `E_INTERNAL`（避免误用仅供事务嵌套使用的 `E_TX_NESTED`）。
- **总线异常隔离与错误汇收集（R5）**：`bus.publish` 执行时先将信封写入环形缓冲区（全流程仅入缓冲一次），遍历通知所有活跃订阅者。若个别订阅者同步抛出异常，捕获后路由至注入的 `onError` 错误汇（包含错误对象、当前事件与出错订阅者上下文），确保不中断其他订阅者的顺序执行，亦不导致事件重复入队。
