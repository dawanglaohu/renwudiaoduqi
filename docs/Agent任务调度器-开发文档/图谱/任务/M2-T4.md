# M2-T4　事件信封、单调 id 分配器与重放缓冲

- 所属模块：[[M2]]　**接入与设备信任**——定义两端如何连上 daemon 并不丢事件地保持同步：一次性配对码与可单独吊销的设备令牌、鉴权与操作归属、REST 骨架与 API 版本、SSE 服务端的事件信封／重放窗口／保活，以及自写的 SSE 客户端。凡「谁能连上、连上之后按什么协议收发」的都归它
- 前置依赖：[[M1-T2]]
- 完成后解锁：[[M2-T5]]

## 输入 / 产出

- **输入**：M1-T2 的库；08 节信封形状
- **产出**：`src/events/`：`envelope` / `id-allocator` / `ring-buffer` / `bus`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 事件 id 用 SQLite 水位预分配，每满 1000 写一次库
重启后从水位继续，**允许跳号但绝不回退**（[[E-10]]）
2) 环形缓冲全局一个、容量恒 5000（[[E-153]] 的重放窗口）
3) `bus.publish` 出现在事务回调内由架构测试判失败
4) 信封字段与 `packages/shared/src/events.ts` 的判别联合一致，新增 kind 时 switch 有穷尽性检查

## 必须处理的边界

- [[E-10]]　手机断网期间任务跑完
    - 触发：提醒产生时手机不在线
    - 期望：提醒事件在 daemon 侧按 event id 入队，手机重连后补推并去重，不得丢弃
- [[E-153]]　断线超过重放窗口
    - 触发：离线时长超过服务端保留的最近 N 条事件
    - 期望：服务端返回「重放窗口已过期」，客户端改为 REST 拉全量当前状态快照后从最新 event id 续接，不允许静默丢事件
