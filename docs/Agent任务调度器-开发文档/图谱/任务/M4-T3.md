# M4-T3　版本指纹探测与可执行路径解析

- 所属模块：[[M4]]　**Agent 适配**——把形态各异的 agent 抽象成同一个可派发对象：注册表（含每个 agent 通用的版本指纹探测字段与具名的「适配器种类」枚举）、可执行探测、模型清单读取与降级、启动参数与三档权限映射、以各家原生通道为主干把输出归一化成 ACP `session/update` 词汇的事件、可回话与**是否提供流式事件**等能力位，并自实现一个通用 ACP 适配器作为兜底与第 6 家及以后的入口。凡「某一家 agent 跟别家怎么不一样」的都归它
- 前置依赖：[[M4-T1]]、[[M1-T7]]
- 完成后解锁：[[M4-T4]]、[[M4-T8]]、[[M4-T9]]、[[M4-T10]]、[[M4-T11]]

## 输入 / 产出

- **输入**：M4-T1 的注册表；M1-T7 的 spawn
- **产出**：`probeAgent()`、指纹缓存

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 探测做成注册表**每个 agent 都有的通用字段**（探测命令 + 期望模式），不是 grok 专用分支（[[E-36]] 的对偶面）
2) 输出不匹配任何已知指纹时标「未识别」且不可派发，界面同时显示实测版本串与期望模式并给手填入口（[[E-195]]）
3) 平台候选发现命中多个同名可执行时记录首个但**列出全部候选并要求确认**，绝不静默取第一个（[[E-196]]）
GUI/自启最小环境找不到 shell PATH 项时列出已检查位置，不执行 shell 启动文件（[[E-270]]）
4) 指纹按「解析后的真实路径 + mtime + 大小」缓存，批次派发时不逐任务探测（[[E-197]]）
5) 版本串格式微变但仍是官方时用宽松模式 + 区间匹配通过，不因一次例行升级让整个 agent 掉线（[[E-198]]）
6) 用户手填绝对路径时仍经当前平台解析并探测，失败降级为警告横幅而非禁用（[[E-199]]、[[E-264]]）

## 必须处理的边界

- [[E-195]]　探测输出无法识别
    - 触发：版本串不匹配任何已知指纹
    - 期望：该 agent 标「未识别」且不可派发；界面同时显示实测到的版本串与期望模式，并给出手填绝对路径入口
- [[E-196]]　PATH 上有多个同名可执行
    - 触发：`which -a` 命中多个
    - 期望：记录首个命中但**列出全部候选并要求用户确认**，绝不静默取第一个
- [[E-197]]　探测开销
    - 触发：批次派发时的重复探测
    - 期望：指纹按「可执行文件路径 + mtime + 大小」缓存，文件变动才重探；批次派发时不逐任务探测
- [[E-198]]　例行升级导致版本串微变
    - 触发：agent 升级但仍是官方版
    - 期望：指纹用宽松模式 + 版本区间匹配；只有完全无法解析时才判不可用，避免一次例行升级就让整个 agent 掉线
- [[E-199]]　用户手填了绝对路径
    - 触发：显式指定可执行文件
    - 期望：仍执行一次探测，但失败时降级为**警告横幅而非禁用**（与决策 7「用户手改始终优先」同一精神）
- [[E-264]]　配置保存了另一平台的路径格式
    - 触发：当前系统读到 Windows 盘符/UNC，或 Windows 读到 POSIX 绝对路径
    - 期望：保存值原样保留但标为当前平台无效；不擅自转换盘符、反斜杠、根目录或挂载点，要求用户选择本机路径
- [[E-270]]　图形界面或自启进程找不到 shell 中已安装的 agent
    - 触发：agent 只通过 `.zshrc`、`.bashrc` 等 shell 启动文件加入 `PATH`，而 macOS/Linux GUI 或服务没有继承这些变量
    - 期望：先使用用户配置的绝对路径，再检查平台级固定候选目录；仍找不到时列出已检查位置并要求用户选择文件，不读取、不执行用户 shell 启动文件
- [[E-36]]　模型名在派发时已失效
    - 触发：用户在别处删了该模型，或手填了不存在的名字
    - 期望：不做前置白名单校验（清单本就可能不全），直接透传；失败后标「派发失败·模型无效」并原样展示 agent 报错，该任务不占用批次窗口名额
