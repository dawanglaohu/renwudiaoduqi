# M8-T3　批次推进与幂等派发

- 所属模块：[[M8]]　**派发调度**——决定什么时候把哪个任务、用哪个 agent 与哪个模型、以什么权限派出去，并按批次、并行窗口、每 agent 并发与路径冲突限流，在三个闸门处停或放行、失败或重派时重新入队。凡涉及顺序、名额、放行、重派的都归它
- 前置依赖：[[M8-T2]]、[[M5-T2]]、[[M6-T1]]
- 完成后解锁：[[M8-T4]]、[[M8-T5]]

## 输入 / 产出

- **输入**：M8-T2 的可放行集合
- **产出**：`scheduler-tick` job、`http/routes/runs.ts`、`http/routes/batches.ts`、`http/routes/snapshot.ts`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) `scheduler-tick` 全局一把内存互斥量，**禁止并发 tick、禁止重入**，同一任务不会被派两次
2) 幂等键唯一，两端同时点派发时第二次返回既有 run 而非起第二个进程（[[E-126]]）
3) 批内某任务失败或审查未过时不阻塞同批其他无依赖任务
下一批启动条件是本批全部「已落地」（[[E-49]]）
4) daemon 重启或断电恢复后按持久化状态续跑，会话还活着就重挂、已死的标「中断」等人决定，**任何情况下不自动重派**（[[E-51]]）
5) 批次执行途中指纹变化时已派任务用快照跑完，后续派发自动暂停待确认（[[E-50]]）

## 必须处理的边界

- [[E-126]]　两台设备同时派发同一任务
    - 触发：并发点击
    - 期望：daemon 侧按任务加幂等键，第二次返回「已在运行」而不是起第二个进程
- [[E-49]]　批内某任务失败或审查未过
    - 触发：一批中个别任务卡住
    - 期望：不阻塞同批其他无依赖任务；但下一批的启动条件是本批全部「已落地」，未解决的任务会让整批停在那里等人
- [[E-50]]　批次执行途中文档变了
    - 触发：执行期间 `data.tasks` 指纹变化
    - 期望：已派任务继续用快照跑完，后续派发自动暂停并要人确认新文档，绝不热改在途任务
- [[E-51]]　daemon 重启或断电恢复
    - 触发：进程死后重新拉起，部分会话可能还活着
    - 期望：按持久化状态续跑；会话还活着就重挂，已死的标「中断」等人决定；任何情况下不自动重派（防止重复写同一批文件）
