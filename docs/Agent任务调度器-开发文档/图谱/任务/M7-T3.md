# M7-T3　三态判定与失败兜底

- 所属模块：[[M7]]　**审查流水线**——对已结束的运行做「合不合格」的判定：先跑本地机械检查，通过后以只读档派一个 agent 跑文档给出的审查提示词，产出 pass / rework / doc-issue 并回灌 rework 意见；从审查输出提取返工文本、按能力位选回灌／恢复／新开返工运行，以及解析收口运行的八段报告，也归它；第 N+1 轮审查续接同一审查会话、查 bug 阶段的运行与五段报告解析同样归它。凡「判定一次运行的结果」的都归它
- 前置依赖：[[M7-T2]]
- 完成后解锁：[[M7-T4]]、[[M7-T6]]、[[M7-T8]]、[[M8-T4]]

## 输入 / 产出

- **输入**：M7-T2 的审查输出
- **产出**：`ReviewVerdict` 解析器

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 输出不符合 pass/rework/doc-issue 三态时按「审查未完成」处理并保留原文，**不猜测语义**（[[E-63]]）
2) 审查 agent 崩溃或超时时既不算 pass 也不算 fail，标「审查未完成」转人工，**任何情况下不默认放行**（[[E-62]]）
3) 判定 doc-issue 时停止对该任务的自动 rework，汇总意见给用户，不让 agent 反复改代码（[[E-64]]）
4) 解析器同时提取**最后一个** `VERDICT:` 行、`REWORK` 段的 `- R〈n〉` 条目与**最后一个** `rework` 围栏块，返工文本围栏优先、其次条目全文，落 `runs.rework_text` 不截断
VERDICT 为 rework 但两处都没有 R 条目 → `review_verdict='incomplete'` 标「未结构化」、原文全文存 `rework_text` 转人
pass 却带 R 条目 → `inconsistencies` 按 incomplete 处理
doc-issue 忽略围栏
代码中不存在按关键词（「不通过」「有问题」）判 rework 的路径（[[E-278]]）

## 必须处理的边界

- [[E-278]]　返工块解析不出 R 条目
    - 触发：VERDICT 为 rework 但围栏块与 REWORK 段都没有 `R〈n〉` 条目，或 VERDICT 行缺失
    - 期望：标「未结构化」：`review_verdict=incomplete`，原文全文存 `rework_text`，转 `awaiting_human`；审批卡给「投递原文到实施会话」按钮，按能力位灰掉；不猜语义、不裁剪
- [[E-62]]　审查 agent 崩溃或超时
    - 触发：审查这一步自身失败
    - 期望：既不算 pass 也不算 fail，标「审查未完成」转人工；任何情况下不默认放行
- [[E-63]]　审查输出不合三态
    - 触发：输出不是 pass/rework/doc-issue
    - 期望：解析失败按「审查未完成」处理并保留原文，不猜测语义
- [[E-64]]　审查判 doc-issue
    - 触发：问题在文档本身而非代码
    - 期望：停止对该任务的自动 rework（改文档是上游技能的事），汇总意见给用户，不让 agent 反复改代码
