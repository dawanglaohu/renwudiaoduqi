# M9-T5　自写 SSE 客户端与重连

- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯、按窗口数呈现的任务流水线泳道与「会话已归档」历史行、顶栏两个流水线开关，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值、「能否收口」、泳道分配、阶段推进与会话归档都是 daemon 给的字段）；指派面板的分组模型下拉、登录态徽标与刷新按钮、参照条的「来源」段同样只呈现 daemon 下发的字段，不算取值链
- 前置依赖：[[M9-T4]]、[[M2-T5]]
- 完成后解锁：[[M9-T6]]、[[M9-T11]]、[[M9-T19]]

## 输入 / 产出

- **输入**：M2-T5 的 SSE 服务端
- **产出**：`api/sse-client.ts`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 用 fetch + ReadableStream 自己分帧，**能带 `Authorization` 头**，忽略 `:` 心跳注释（[[E-08]] 的客户端侧、[[E-154]]）
2) 全应用只开一条连接，按信封的 taskId/runId 分派，**禁止每流一条 SSE**
3) 指数退避 `[1000,2000,4000,8000,15000]` ±20% 抖动封顶 15s，保留 `Last-Event-ID`，**不做无间隔轮询式重连**（[[E-158]]）
4) 60s 内未收到任何字节判死连接主动 abort 重连
5) 收到重放窗口过期码时清空本地 buffer → 拉 REST 全量快照 → 从最新 id 续接（[[E-153]] 的客户端侧）
6) 收到 401 立即停止退避循环并置 `needsPairing`（[[E-156]] 的客户端侧）

## 必须处理的边界

- [[E-08]]　daemon 被隧道暴露到公网
    - 触发：用户自行接入 Tailscale/frp
    - 期望：鉴权与加密默认开启；代码中不得存在「局域网内免鉴权」分支
- [[E-153]]　断线超过重放窗口
    - 触发：离线时长超过服务端保留的最近 N 条事件
    - 期望：服务端返回「重放窗口已过期」，客户端改为 REST 拉全量当前状态快照后从最新 event id 续接，不允许静默丢事件
- [[E-154]]　反代缓冲导致流不实时
    - 触发：用户自接的隧道或反向代理缓冲了响应
    - 期望：设 `X-Accel-Buffering: no` + `Cache-Control: no-transform`，并按固定间隔发心跳注释行保活
- [[E-156]]　令牌过期而流仍开着
    - 触发：令牌被撤销或过期
    - 期望：服务端主动关闭该流并返回 401，客户端提示重新配对，不进入无限重连
- [[E-158]]　SSE 重连风暴
    - 触发：daemon 重启期间大量重连
    - 期望：客户端指数退避重连并保留 Last-Event-ID，不做无间隔轮询式重连

## 实施沉淀

<!-- notes:begin -->
- **原生 EventSource 的抛弃**：浏览器原生 `EventSource` 不支持注入自定义请求头（`Authorization: Bearer <token>` 与 `X-Agsched-Client`），在守护进程经穿透隧道暴露到公网（[[E-08]]）时无法提供默认强鉴权；采用 `fetch` + `ReadableStream` + `TextDecoder` 自行解码并按 `\n\n` 分帧，既满足协议规范，又保证鉴权覆盖与请求追踪完整。
- **全应用单连接分派架构**：多任务流水线泳道与监看流虽然独立呈现，但前端禁止为每条运行流分别建立 SSE 连接；统一由应用级单例 `sseClient` 维持一条长连接，按照事件信封内的 `runId`、`taskId` 与 `scope` 进行就地分发，避免反向代理与守护进程文件描述符耗尽。
- **静默检测与半开连接处置**：用户端隧道、NAT 或代理在服务端异常断开时常不发 FIN 包，导致客户端读流无限挂起；通过 60 秒无接收任何字节（含保活心跳）即主动调用 `AbortController.abort()` 判死连接并切入退避重连，结合服务端的 15 秒 `:\n\n` 心跳防止反代缓冲及伪假死。
- **重放窗口过期的状态续接保证**：收到 409 或内联 `E_REPLAY_WINDOW_EXPIRED` 时，证明客户端离线时长超出了服务端 5000 条事件的环形缓冲；此时若直接重试旧 `Last-Event-ID` 会产生死循环，若清空游标从头拉取会丢失事件。因此按协议契约触发本地缓冲清空事件，异步拉取 `/api/v1/snapshot` REST 全量快照更新基线状态，并同步更新游标至快照的 `latestEventId` 后无延迟重新连接，杜绝状态丢失与空窗期乱序。
- **吊销与鉴权失败的熔断保护**：握手返回 401 或流内收到 `E_UNAUTHORIZED` / `E_DEVICE_REVOKED` 错误帧时，表示设备令牌已失效或被吊销；立即终止指数退避循环并清除内存与会话存储中的令牌，置位 `needsPairing` 引导跳转配对页，杜绝无意义的无限重试雪崩（[[E-156]]）。
