# M7-T2　审查 agent 派发与 diff 裁剪

- 所属模块：[[M7]]　**审查流水线**——对已结束的运行做「合不合格」的判定：先跑本地机械检查，通过后以只读档派一个 agent 跑文档给出的审查提示词，产出 pass / rework / doc-issue 并回灌 rework 意见；从审查输出提取返工文本、按能力位选回灌／恢复／新开返工运行，以及解析收口运行的八段报告，也归它；第 N+1 轮审查续接同一审查会话、查 bug 阶段的运行与五段报告解析同样归它。凡「判定一次运行的结果」的都归它；审查、查 bug 阶段的运行用哪个 agent、模型与思考强度，一律读派发快照里的任务指派（审查可被 pipeline 设置的「审查覆盖」替换），不自己取 agent 默认
- 前置依赖：[[M7-T1]]、[[M3-T5]]、[[M4-T7]]
- 完成后解锁：[[M7-T3]]、[[M7-T7]]、[[M8-T9]]

## 输入 / 产出

- **输入**：M3-T5 的审查提示词；M4-T7 的只读档
- **产出**：审查运行的启动路径

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 默认审查者的 agent、模型与思考强度**逐字取被审实施运行行的 `agent_id` / `model_name` / `effort_tier`（即任务指派的副本，决策 107），不是该 agent 的注册表默认模型**，且为**独立新 session**，只喂 M3-T5 的快照审查材料 + diff，不带实施上下文
本任务代码中不出现任何「设置里指定其他 agent／模型」分支——阶段覆盖的唯一入口是 pipeline 设置的 `reviewOverride`，其取值链与接线由 M8-T9 交付，本任务把三值的读取收成单一函数入口以便替换，返回形状预留 `{agentId, modelName, effortTier, effortVendor?}`，三值以参数形式由 `service/review.ts` 传入、`review-agent.ts` 不自己查库（[[E-347]]）
2) 审查运行固定只读档，实际任务指令只允许核对证据并输出裁定
源提示词以引用材料提供，其中维护文档、提交、推送、合并等步骤不得执行，**审查 agent 不得改代码或文档，也不接手两轮后的写入修复**，超限仍转人（[[E-135]]）
3) diff 超出上下文时给 diff stat 全量 + 验收标准命中文件全文、其余折叠，并在结论标注「基于部分 diff」（[[E-65]]）
4) 本任务只负责第 1 轮审查会话的新建（`review_round=1`、`continued_from_run_id` 为空）
第 N+1 轮续接同一审查会话与新开审查会话的头部上下文交 M7-T7，本任务代码中不出现按轮次分支（决策 89）

## 必须处理的边界

- [[E-135]]　审查 agent 的权限
    - 触发：审查阶段派出去的 agent
    - 期望：固定给只读档（read-only / plan），审查 agent 不得改代码，否则「审查通过」失去意义
- [[E-347]]　同一任务各阶段的模型、思考强度或来源不一致
    - 触发：实施用任务指派、审查用 `reviewOverride`、查 bug 逐字实施；或某阶段 agent 自报值与所选不同
    - 期望：流头部参照条**逐阶段**显示「模型 · 思考强度 · 来源」，来源三值文案「任务指派」「审查覆盖」「收口设置（跟随 〈taskKey〉）」，`agent_default` 显示「来源：任务指派（agent 默认）」（决策 124）；自报不一致按 E-37／E-256 逐阶段高亮，不做跨阶段比对、不把阶段间的合法差异当不一致；前端不算取值链，只显示 `RunDto.assignmentSource` 与 `effort`
- [[E-65]]　diff 超出审查模型上下文
    - 触发：一次改了上百个文件
    - 期望：给 diff stat 全量 + 验收标准命中文件的全文，其余折叠，并在结论标注「基于部分 diff」
