# M7-T2　审查 agent 派发与 diff 裁剪

- 所属模块：[[M7]]　**审查流水线**——对已结束的运行做「合不合格」的判定：先跑本地机械检查，通过后以只读档派一个 agent 跑文档给出的审查提示词，产出 pass / rework / doc-issue 并回灌 rework 意见；从审查输出提取返工文本、按能力位选回灌／恢复／新开返工运行，以及解析收口运行的八段报告，也归它。凡「判定一次运行的结果」的都归它
- 前置依赖：[[M7-T1]]、[[M3-T5]]、[[M4-T7]]
- 完成后解锁：[[M7-T3]]

## 输入 / 产出

- **输入**：M3-T5 的审查提示词；M4-T7 的只读档
- **产出**：审查运行的启动路径

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 默认审查者为实施该任务的同一 agent 的**独立新 session**，只喂 M3-T5 的快照审查材料 + diff，不带实施上下文
设置里可改为指定其他 agent／模型
2) 审查运行固定只读档，实际任务指令只允许核对证据并输出裁定
源提示词以引用材料提供，其中维护文档、提交、推送、合并等步骤不得执行，**审查 agent 不得改代码或文档，也不接手两轮后的写入修复**，超限仍转人（[[E-135]]）
3) diff 超出上下文时给 diff stat 全量 + 验收标准命中文件全文、其余折叠，并在结论标注「基于部分 diff」（[[E-65]]）

## 必须处理的边界

- [[E-135]]　审查 agent 的权限
    - 触发：审查阶段派出去的 agent
    - 期望：固定给只读档（read-only / plan），审查 agent 不得改代码，否则「审查通过」失去意义
- [[E-65]]　diff 超出审查模型上下文
    - 触发：一次改了上百个文件
    - 期望：给 diff stat 全量 + 验收标准命中文件的全文，其余折叠，并在结论标注「基于部分 diff」
