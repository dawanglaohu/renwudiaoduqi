## 实施沉淀

<!-- notes:begin -->
1. **服务端态共享资源缓存（07 节前端架构 / AC 1）**：
   - 遵照 07 节 267 行规范，以最小开销原生 Map 实现 `read(key, fetcher)`、`invalidate(prefix)` 和 `refetchAll()`，不引入额外三方依赖。
   - 严格禁止暴露 `set/put/patch` 接口，杜绝前端乐观写污染服务端权威；禁止客户端轮询与基于时间戳的 stale 窗口，状态同步完全收拢为由 SSE 事件和连接恢复驱动。
   - 对相同 key 的并发读取复用同一在途 Promise，并将传入的 fetcher 登记/覆盖为该 key 的最新重拉入口。

2. **在途失效与 E-333 语义处理（AC 1, AC 2）**：
   - 当某个 key 在请求在途期间收到失效事件（如 `settings.pipeline_changed` 或泳道事件），标记 `invalidatedWhileInFlight = true`。
   - 在途请求完成时，若已标记失效，严禁将其返回的数据写入 `dataCache`（避免迟到的过期响应覆盖刚失效的缓存状态）；由业务层监听事件后的声明式读取或下次读取时按需触发，避免隐式递归请求造成测试死锁。

3. **事件权威与双编辑器写入保护（AC 2, AC 3, E-157, E-318, E-356）**：
   - 流水线开关及设置页（顶栏与 `#/settings/pipeline`）共用同一个全局单例 `sharedPipelineSource` 与底层 `resource-cache`，所有编辑器共享相同的内存缓存与 `pendingPatch` 写入锁，彻底杜绝了双编辑器并发提交不同四键配置导致相互覆盖的问题。
   - 保留 `sourceVersion` 机制：当收到 `settings.pipeline_changed` 事件时递增版本；GET 响应返回时若版本已落后，则丢弃响应体，确保事件推送的最新四键绝对权威（E-157）。
   - 在最后一个使用方注销后，由 `usePipelineSettings` 主动触发 `unregister` 并注销所有 SSE 监听器与恢复钩子，避免长连接监听残留。

4. **单测环境隔离与 DOM 卸载保障（AC 4）**：
   - 在扩展 `pipeline-toggles.test.tsx` 双容器测试时，确保所有挂载用例在结束时显式执行 `await act(async () => { root.unmount(); })`，彻底释放全局 `eventBus` 订阅与共享缓存引用，防止跨用例状态污染。
