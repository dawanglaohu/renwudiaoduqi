# M7-T6　收口输出解析与有效裁定

- 所属模块：[[M7]]　**审查流水线**——对已结束的运行做「合不合格」的判定：先跑本地机械检查，通过后以只读档派一个 agent 跑文档给出的审查提示词，产出 pass / rework / doc-issue 并回灌 rework 意见；从审查输出提取返工文本、按能力位选回灌／恢复／新开返工运行，以及解析收口运行的八段报告，也归它；第 N+1 轮审查续接同一审查会话、查 bug 阶段的运行与五段报告解析同样归它。凡「判定一次运行的结果」的都归它；审查、查 bug 阶段的运行用哪个 agent、模型与思考强度，一律读派发快照里的任务指派（审查可被 pipeline 设置的「审查覆盖」替换），不自己取 agent 默认
- 前置依赖：[[M7-T3]]
- 完成后解锁：[[M8-T6]]

## 输入 / 产出

- **输入**：M7-T3 的解析器结构；决策 61 的八段格式

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 段头须独立成行，取最后一个 `BATCH_SUMMARY` 之后能按模板顺序找齐八段的那一组
找不齐返回 `ok:false` 与精确缺段清单，不做部分解析、不猜（[[E-274]]）
2) BUGS/NOT_FIXED 条目按 `B〈n〉 [S1／S2／S3] 涉及 〈任务ID〉（跨批）：现象 → 复现 → 根因 → 文件:行` 解析，半角括号、`->` 与全角冒号同样接受
少于四段保留条目但 `isWellFormed:false`
匹配不到 B 号或任务 ID 的条目进 `unassigned` 保留原文（[[E-290]]）
3) 有效裁定由内容算出：TESTS 为 fail、NOT_FIXED 非空、BUGS 有未出现在 FIXED 的、unassigned 非空——任一成立即 `open`
否则有 BUGS 即 `fixed`
否则 `clean`
RECORD 自报值只存 `declaredVerdict`，代码中不存在用自报值当裁定的路径（[[E-286]]）
4) `planWrapupFixes` 把开放项（TESTS 失败 ∪ BUGS∖FIXED ∪ NOT_FIXED）按任务分组、重编号 `R1…` 而原文逐字保留，未知任务归 unassigned
5) 纯函数零依赖、顶层零副作用，17 节列出的单测用例全部通过

## 必须处理的边界

- [[E-274]]　收口输出不合八段
    - 触发：收口运行的最终文本缺任一段、段头顺序找不齐、或条目格式不合
    - 期望：按「收口未完成」处理：保留原文可读、不做部分解析、不猜；收口运行转 `awaiting_human` 并开批次级收口闸门，批次 `needs_attention`，不计入自动轮次
- [[E-286]]　收口自报裁定与实际不符
    - 触发：RECORD 段写 clean 但 BUGS 有未修条目、NOT_FIXED 非空或 TESTS fail
    - 期望：有效裁定由内容算出（open），自报值只存 `declared_verdict`；两者不一致记 warn，UI 同时显示两者；绝不按自报放行
- [[E-290]]　TESTS 失败项无「涉及 〈任务ID〉」
    - 触发：收口报告的测试失败行没写任务号，或任务 ID 不在文档里
    - 期望：进 unassigned，有效裁定为 open；有其他可派条目照派、第 2 轮复跑兜底；全部开放项无主才 `needs_attention`（可派修复条目为零）；不猜归属、不去重

## 实施沉淀

<!-- notes:begin -->
1. 段头切分与前导模板复述：LLM 常在正文前复述提示词中的模板，导致文本内出现多行 BATCH_SUMMARY。通过在全文本按行识别候选段头后寻找满足八段严格递增顺序的候选组并取最后一组，避免了前导模板干扰与跨段错误切分；若最外层包裹代码围栏则先行剥离，防止尾段残留闭合反引号。
2. 找不齐八段与缺段定位：缺失段落时不执行任何部分解析（E-274）。通过计算候选段头序列与八段模板的最长公共子序列（LCS），能确定性产出严格保持模板顺序的精确缺失清单，且完全适配八例单段缺失的参数化判定。
3. 自报裁定与有效裁定物理隔离：deriveWrapupVerdict 的输入仅包含测试状态、未修 Bug、未修条目及未分配项，函数内部不存在任何读取 declaredVerdict 的分支，从签名和调用链层面阻断按自报放行的可能性（E-286）。
4. 无主失败与未知任务归口：TESTS 失败未注任务号、格式损坏缺失 B 号或任务 ID、以及不在 knownTaskKeys 白名单内的开放项，统一进入 unassigned 数组逐字保留原文，只要 unassigned 非空即判定为 open，避免漏修或错误归属（E-290）。
5. TESTS 段状态取自显式声明行而不是全文关键词扫描：通过报告里常见的「0 failed」「失败用例：无」会让整段扫描把 pass 判成 fail，再把干净批次算成 open（E-286）。改为先认「整行只有状态词」的声明行（可带 status: 前缀），找不到才退回关键词扫描且仍保守优先 fail。
