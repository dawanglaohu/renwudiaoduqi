# M1-T5　磁盘占用统计、写满兜底与受限删除原语

- 所属模块：[[M1]]　**运行底座**——让 daemon 在这台机器上稳定跑起来并把字节落到磁盘上：进程单实例与端口、启动自检、开机自启注册、数据目录、结构化存储的连接与迁移、日志正文的追加写与字节偏移索引、以及全部平台差异（进程树终止、路径规范化与长路径、配置目录、子进程编码）的唯一收口。凡与操作系统、磁盘、进程存活打交道而不带任何业务概念的都归它
- 前置依赖：[[M1-T4]]
- 完成后解锁：[[M6-T9]]

## 输入 / 产出

- **输入**：M1-T4 的 logstore
- **产出**：`disk-watch` job、`deleteByPath` / `truncate` / `usage` 三个不带业务语义的原语、`http/routes/system.ts`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 占用超阈值发 `system.disk_warning` 并置「停止新派发」标志（[[E-103]]）
2) 存储盘写满时立即停止新派发并明确报错
恢复后能继续追加且已有记录不损坏（[[E-104]]）
3) M1 只上报写满，**绝不自行删除任何正文**（[[E-205]]）
4) 收到白名单目录之外的删除请求一律拒绝并记违规日志（[[E-206]]）
5) 删除目标正被读取（EBUSY）时返回可重试错误而非抛异常（[[E-204]]）

## 必须处理的边界

- [[E-103]]　磁盘占用达告警阈值
    - 触发：捕获的日志累积过多
    - 期望：顶部横幅列出占用最大的几个任务，提供「按任务 / 按时间归档」的手动入口；默认不自动删除
- [[E-104]]　存储盘写满
    - 触发：追加写失败
    - 期望：立即停止新派发并明确报错；恢复后要能继续追加，已有记录不得损坏
- [[E-204]]　要清的文件正被读
    - 触发：M6 判定某份正文该清，但会话查看器正按偏移分段读它（Windows EBUSY）
    - 期望：M1 的删除原语返回**可重试错误而非抛异常**；M6 本轮跳过该文件、下一轮重试，不向用户报错
- [[E-205]]　磁盘写满时谁来删
    - 触发：M1 检测到写满
    - 期望：M1 **只上报「写满」事件并停写/降级，绝不自行删除任何正文**；由 M6 按策略决定删哪些；策略判定「无可删」则升级为告警并暂停对应运行的写入
- [[E-206]]　清理候选集越界
    - 触发：候选集里混进了任务记录或三段快照
    - 期望：候选集只能由 M6 按「自己捕获的运行输出」目录白名单枚举生成；**M1 收到白名单目录之外的删除请求一律拒绝执行并记违规日志**

## 实施沉淀

<!-- notes:begin -->
- **原语只认路径白名单，不带业务语义**：`deleteByPath` / `truncate` 只校验目标是否严格位于 `runs/` 根目录之内；根目录本身、`..` 穿越、其他卷、`app.db` 等受保护名一律拒绝，并经 `logViolation` 记一行 `[SECURITY_VIOLATION]`。原语不知道任务、快照或保留策略，候选集由 M6 按运行输出目录枚举生成。白名单判定是纯路径运算，不解析符号链接。
- **忙文件是结果不是异常**：Node fs 适配器把所有原生错误在模块边界包成 AppError（ENOENT → `E_LOG_FILE_MISSING`，ENOSPC → `E_DISK_FULL`，其余 `E_INTERNAL` 带 cause）；原语用 `isBusyCause` 从 cause 里识别 EBUSY 与 Windows 上的 EPERM，返回 `{ok:false, retryable:true, code:'EBUSY'}`，M6 按 `retryable` 跳过本轮、下轮重试。`EBUSY` 不是登记过的 `E_` 错误码，因为它只在进程内结果里流转、不进 HTTP 信封；若将来要经接口透出，需先在 10 节登记一个 retryable 的错误码。
- **写满只报不删，标志归 service**：停止新派发标志以 `{cause:'disk_full'|'disk_threshold', message}` 存在 SystemService 内存里，不落库，重启即清。两条进入路径：追加写拒绝 `E_DISK_FULL` 时 LogstoreService 回调 `onDiskFull` → `notifyDiskFull`，同一次故障只发一条 `system.disk_warning`；disk-watch 巡检超阈值或 statfs 报零可用块时置标志，并在每次超限的巡检发一条事件。巡检发现卷已健康则解除标志。`calculateDiskUsage` 只测量、不读标志；M1 任何路径都不删除正文。
- **接线责任**：容器已构造 `services.system`；LogstoreService 与 jobs 的容器装配由后续 boot 任务完成，届时必须把 `onDiskFull: services.system.notifyDiskFull` 传给 `createLogstoreService`，在 listen 成功后启动 `createDiskWatchJob({ service: services.system, logFailure })`，并让 scheduler-tick 在每次派发前检查 `getDispatchHalt()`。
- **阈值来源**：10 GB 占用与 500 MB 剩余是 contract.ts 常量。环境变量全集只有五个，不为此新增；将来若要可调应进 daemon.json 进程配置。
- **未覆盖（FOLLOW_UP）**：ENOSPC 若发生在一行写到一半，文件尾残留半行而 writer 偏移未前进，下一条记录的索引偏移会错位；已有记录不受影响。修法是 run-writer 在 append 失败时把文件截回上次已知长度或按实际长度重新同步偏移。
<!-- notes:end -->
