# M3-T5　审查提示词与验收标准的取用接口

- 所属模块：[[M3]]　**文档接入**——把 `docs-data.js` 变成本产品唯一的任务真相源（任务、依赖、批次、并行窗口、验收标准、边界编号、实施与审查两段提示词），并负责内容指纹、派发时快照与文档重出后的三个标记；收口提示词 `dispatchBatches` 的按任务集合匹配也归它。凡「这条数据来自文档」的都归它
- 前置依赖：[[M3-T3]]
- 完成后解锁：[[M3-T6]]、[[M7-T2]]

## 输入 / 产出

- **输入**：M3-T3 的快照
- **产出**：供 M7 取用的 `getReviewContext(taskId)`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 返回该任务的审查提示词、契约哈希与**派发时快照的那一份**验收标准，而非当前文档的
源提示词是引用审查材料，供 M7 组装只读裁定包，文档维护／提交／合并指令不成为运行时权限
2) 快照缺失时明确报错而不是回落到当前文档
3) 批次执行途中任务 ID/contractHash 指纹变化时，已派任务继续用快照跑完，后续派发自动暂停并要人确认，**绝不热改在途任务**（[[E-50]]）

## 必须处理的边界

- [[E-50]]　批次执行途中文档变了
    - 触发：执行期间任务 ID/contractHash 指纹变化，包括任务行未变而范围、条款或提示词变化
    - 期望：已派任务继续用快照跑完，后续派发自动暂停并要人确认新文档，绝不热改在途任务
