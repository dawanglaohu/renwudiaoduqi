# M3-T5　审查提示词与验收标准的取用接口

- 所属模块：[[M3]]　**文档接入**——把 `docs-data.js` 变成本产品唯一的任务真相源（任务、依赖、批次、并行窗口、验收标准、边界编号、实施与审查两段提示词），并负责内容指纹、派发时快照与文档重出后的三个标记；收口提示词 `dispatchBatches` 的按任务集合匹配也归它。凡「这条数据来自文档」的都归它
- 前置依赖：[[M3-T3]]
- 完成后解锁：[[M3-T6]]、[[M7-T2]]

## 输入 / 产出

- **输入**：M3-T3 的快照
- **产出**：供 M7 取用的 `getReviewContext(taskId)`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 返回该任务的审查提示词、契约哈希与**派发时快照的那一份**验收标准，而非当前文档的
源提示词是引用审查材料，供 M7 组装只读裁定包，文档维护／提交／合并指令不成为运行时权限
2) 快照缺失时明确报错而不是回落到当前文档
3) 批次执行途中任务 ID/contractHash 指纹变化时，已派任务继续用快照跑完，后续派发自动暂停并要人确认，**绝不热改在途任务**（[[E-50]]）

## 必须处理的边界

- [[E-50]]　批次执行途中文档变了
    - 触发：执行期间任务 ID/contractHash 指纹变化，包括任务行未变而范围、条款或提示词变化
    - 期望：已派任务继续用快照跑完，后续派发自动暂停并要人确认新文档，绝不热改在途任务

## 实施沉淀

<!-- notes:begin -->
1. **审查材料与快照单一真相源（AC 1、AC 2、E-50）**：`getReviewContext` 只从 `dispatch_snapshots` 提取验收标准、提示词与契约哈希。即使 `tasks` 表中的记录已被重新导入的文档改写、条款发生位移甚至任务被标记为 `is_removed_from_doc`，审查接口始终忠实反映该次运行派发时的事实基准。快照缺失时直接抛出 `E_NOT_FOUND`，坚决禁止回落至当前 `tasks` 表数据，防止未经快照认定的文档状态污染审查判定。
2. **审查材料只读引用语义（AC 1、E-135）**：在返回对象中显式标明 `isReadOnly: true` 与 `isSnapshot: true`，明确提示词为只读核对参考证据，防止文档中的维护、git commit、push、merge 等操作指令被下游审查流程错误解释为审查 agent 的运行时执行权限。
3. **在途任务隔离与批次暂停机制（AC 3、E-50）**：文档指纹变化（包括任务增删、范围调整或 contractHash 变更）触发时，系统不干涉、不中止正在运行的进程，已派任务继续用既有快照完成执行与审查；同时将当前文档下处于 `running` 状态的批次自动转为 `paused`，阻断后续未派发任务的自动流转，直至人工介入确认新文档后显式恢复。
<!-- notes:end -->
