# M4-T10　pi 原生适配器（RPC 模式）

- 所属模块：[[M4]]　**Agent 适配**——把形态各异的 agent 抽象成同一个可派发对象：注册表（含每个 agent 通用的版本指纹探测字段与具名的「适配器种类」枚举）、可执行探测、模型清单读取与降级、启动参数与三档权限映射、以各家原生通道为主干把输出归一化成 ACP `session/update` 词汇的事件、可回话与**是否提供流式事件**等能力位，并自实现一个通用 ACP 适配器作为兜底与第 6 家及以后的入口。凡「某一家 agent 跟别家怎么不一样」的都归它
- 前置依赖：[[M4-T3]]、[[M1-T8]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：pi 自带的 `./client` 与 `./rpc-entry` 导出
- **产出**：`adapters/pi/` 四件套

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 走 `--mode rpc`，用 pi 自带的官方客户端导出而非第三方 ACP 桥接
2) **禁用 Node `readline`**，用 M1-T7 的行读取器
配一条含 `U+2028` 输出的回归用例（[[E-203]]）
3) 只依赖已验证的最小命令子集（`prompt`／`steer`／`abort`／`get_state`）与 `agent_settled` 事件
大版本升级改了命令集时未知事件忽略并计数，不崩溃（[[E-202]]）
4) `agent_settled` 映射为运行结束信号

## 必须处理的边界

- [[E-202]]　pi 大版本升级改了 RPC 命令集
    - 触发：命令或事件集变化
    - 期望：适配器只依赖已验证的最小子集（`prompt` / `steer` / `abort` / `get_state` + `agent_settled` 事件）；未知事件类型一律忽略并计数，不因新增事件崩溃
- [[E-203]]　pi 的 RPC 行读取
    - 触发：输出中出现 `U+2028` / `U+2029`
    - 期望：**必须自写只按 `\n` 切的读取器，禁用 Node `readline`**——那两个字符在 JSON 字符串里合法但会被 readline 断行；须配一条含 `U+2028` 输出的回归用例

## 实施沉淀

<!-- notes:begin -->
- **选型与传输主干**：放弃第三方 `pi-acp` 桥接，直接使用 pi CLI 的 `--mode rpc` 原生通道与官方 TypeScript 客户端协议。pi 本身不原生提供 ACP stdio，引入第三方桥接会增加额外的进程包装与不透明错误；而原生 RPC 模式天然通过 stdin/stdout 流式传输 JSONL 命令与事件，`agent_settled` 提供了确定性无悬挂的会话完成信号。
- **行读取器陷阱（E-203）**：绝对禁止引入 Node.js 原生 `readline` 模块。Node `readline` 在内部实现中不仅以 `\n` 和 `\r` 断行，还会将 Unicode 的 `U+2028`（Line Separator）和 `U+2029`（Paragraph Separator）视作换行符。而在 JSON 规范中，这两个字符完全允许存在于未转义的字符串字面量中。如果使用 Node `readline`，模型输出包含 `U+2028` 的代码或文本时会强行被切成两段，导致两段均变为非法 JSON 并报 SyntaxError。必须严格复用 M1-T7 的 Buffer 行切分器（只查找 `0x0A` 并去除末尾 `\r`）。
- **命令集收敛与升级容错（E-202）**：pi 后续大版本可能新增扩展命令与事件类型（如 session 分支、extension_ui 等）。适配器严守「最小依赖」原则，只暴露经真实测试验证的 4 个命令（`prompt`、`steer`、`abort`、`get_state`）与 `agent_settled`。流处理中遇到非已知事件类型时，不得臆造未注册的 `EventKind`，也不得抛出未捕获异常导致流中断，而是记录并递增 `unmapped_event_count`，保障调度器对厂商版本演进的前向兼容。
<!-- notes:end -->
