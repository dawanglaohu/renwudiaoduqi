# M1-T2　SQLite 连接工厂、四条 PRAGMA 与迁移执行器

- 所属模块：[[M1]]　**运行底座**——让 daemon 在这台机器上稳定跑起来并把字节落到磁盘上：进程单实例与端口、启动自检、开机自启注册、数据目录、结构化存储的连接与迁移、日志正文的追加写与字节偏移索引、以及全部平台差异（进程树终止、路径规范化与长路径、配置目录、子进程编码）的唯一收口。凡与操作系统、磁盘、进程存活打交道而不带任何业务概念的都归它
- 前置依赖：[[M1-T1]]
- 完成后解锁：[[M1-T4]]、[[M2-T1]]、[[M2-T4]]、[[M3-T1]]、[[M6-T1]]

## 输入 / 产出

- **输入**：M1-T1 的 boot 序列
- **产出**：`src/db/openDatabase.ts`、`migrate.ts`、`unitOfWork.ts`、`migrations/0001_init.sql`

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 打开后四条 PRAGMA（`journal_mode=WAL`、`busy_timeout=5000`、`foreign_keys=ON`、`synchronous=NORMAL`）可被查询验证，且启动失败即退出绝不双写（[[E-150]]）
2) 迁移按文件名升序在独立事务执行并写 `schema_migrations`
3) `unitOfWork.run()` 在 `depth>0` 时抛 `E_TX_NESTED`，不用 savepoint 隐式吞掉
4) 原生模块 ABI 不匹配时捕获加载失败并提示 `pnpm rebuild`，不抛裸栈（[[E-152]]）

## 必须处理的边界

- [[E-150]]　两个 daemon 抢同一个库
    - 触发：单实例锁失效
    - 期望：SQLite 设 `busy_timeout`，启动失败即退出，绝不双写
- [[E-152]]　原生模块 ABI 不匹配
    - 触发：Node 升级后 better-sqlite3 加载失败
    - 期望：启动自检捕获加载失败并提示 `npm rebuild`，给出明确指引而非堆栈崩溃
