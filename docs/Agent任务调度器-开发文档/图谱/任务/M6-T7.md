# M6-T7　自动模式下的提问处置

- 所属模块：[[M6]]　**运行监管**——管一次运行从启动到结束的全过程：状态机（「已退出」与「已落地」分开）、收流与落盘编排、按游标分段回读与厂商会话文件的只读引用、进度信号、停滞检测、中止与 daemon 重启后的对账、回话投递；任务到达终态后结束并归档该任务全部会话（进程还在走 `killTree` 两阶段），归档后会话引用只读、不得复用，也归它。凡「这一次运行现在怎么样、它说过什么」的都归它
- 前置依赖：[[M6-T6]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：M6-T6 的回话通路
- **产出**：`awaiting_reply` 状态接线

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 自动模式下 agent 提问时调度器**一律不代答**，任务转「等待人回话」并计入停滞检测，继续占用该 agent 并发额度（[[E-115]]）
2) agent 需要联网装依赖时默认拦下并转回话通路由人决策，**不提供「自动放行网络」开关**（[[E-134]]）
3) 沙箱拦下 worktree 之外的写入时记「权限受阻」在时间线高亮，**不判失败**
提供「仅本次运行临时提升」的一次性开关，绝不改写默认档位（[[E-133]]）

## 必须处理的边界

- [[E-115]]　自动模式下 agent 提问
    - 触发：全自动运行中 agent 抛出开放问题
    - 期望：调度器一律不代答；任务转「等待人回话」状态，计入停滞检测并继续占用该 agent 的并发额度

    - 期望：记为「权限受阻」事件在时间线高亮，不判失败；提供「仅本次运行临时提升」的一次性开关，绝不改写默认档位
- [[E-134]]　agent 要联网装依赖
    - 触发：执行 `npm i` 之类
    - 期望：默认拦下并转回话通路由人决策，不提供「自动放行网络」开关

## 实施沉淀

<!-- notes:begin -->
- **自动模式提问处置与并发占用（E-115）**：全自动运行下 agent 提问或抛出开放式交互时，调度器严格禁止进行任何假定或机器代答。通过 `isQuestionEnvelope` 识别提问类工具调用与结构化询问字段后，统一将运行状态迁入 `awaiting_reply`。由于 `awaiting_reply` 不属于 `EXCLUDED_FROM_CONCURRENCY_STATES`，该任务持续占据 Agent 并发配额，避免自动派发抢占槽位；同时等待超时由 `stall-detector` 判定为 `waiting_human` 进行弱提示而不误报停滞。
- **依赖安装拦截与零网络放行（E-134）**：Agent 在执行诸如 `npm i`、`pnpm add` 等网络命令时，若当前运行未处于无限制权限，系统必须默认实施阻断并就地注入 `run.permission_blocked` 里程碑事件，将运行挂入 `awaiting_reply` 交由人类裁决。调度器在架构上不暴露任何 `autoAllowNetwork` 配置项或自动放行开关，杜绝依赖供应链投毒与未受控网络外联。
- **沙箱越界写入不判失败与一次性提升隔离（E-133）**：当 Agent 试图写入 worktree 外部被沙箱拦截时，事件被标记为 `run.permission_blocked` 进入 events 表并在前端时间线高亮，状态机严禁将其标记为 `failed` 终态。通过 `elevateRunOnce` 提供单次放行机制仅恢复当前运行至 `running`，运行元数据与 Agent 注册表中的全局/默认权限档位（如 `workspaceWrite`）在此期间受到严格写保护，杜绝权限越权持久化。
- **starting 状态合法迁移时序约束**：派发后的初始运行停留在 `starting` 状态。根据 09 节状态机规范，`starting` 不能直跳 `awaiting_reply`。在 `handleEventStateWiring` 中先通过接收首条可解析事件将状态自然推至 `running`，再在当前事件属于阻断或提问时迁至 `awaiting_reply`，确保事件总线发出的状态变更序列与状态转移白名单完全吻合。
<!-- notes:end -->
