# M6-T7　自动模式下的提问处置

- 所属模块：[[M6]]　**运行监管**——管一次运行从启动到结束的全过程：状态机（「已退出」与「已落地」分开）、收流与落盘编排、按游标分段回读与厂商会话文件的只读引用、进度信号、停滞检测、中止与 daemon 重启后的对账、回话投递；任务到达终态后结束并归档该任务全部会话（进程还在走 `killTree` 两阶段），归档后会话引用只读、不得复用，也归它。凡「这一次运行现在怎么样、它说过什么」的都归它
- 前置依赖：[[M6-T6]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：M6-T6 的回话通路
- **产出**：`awaiting_reply` 状态接线

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 自动模式下 agent 提问时调度器**一律不代答**，任务转「等待人回话」并计入停滞检测，继续占用该 agent 并发额度（[[E-115]]）
2) agent 需要联网装依赖时默认拦下并转回话通路由人决策，**不提供「自动放行网络」开关**（[[E-134]]）
3) 沙箱拦下 worktree 之外的写入时记「权限受阻」在时间线高亮，**不判失败**
提供「仅本次运行临时提升」的一次性开关，绝不改写默认档位（[[E-133]]）

## 必须处理的边界

- [[E-115]]　自动模式下 agent 提问
    - 触发：全自动运行中 agent 抛出开放问题
    - 期望：调度器一律不代答；任务转「等待人回话」状态，计入停滞检测并继续占用该 agent 的并发额度
- [[E-133]]　沙箱拦下越界写入
    - 触发：agent 试图写 worktree 之外
    - 期望：记为「权限受阻」事件在时间线高亮，不判失败；提供「仅本次运行临时提升」的一次性开关，绝不改写默认档位
- [[E-134]]　agent 要联网装依赖
    - 触发：执行 `npm i` 之类
    - 期望：默认拦下并转回话通路由人决策，不提供「自动放行网络」开关

## 实施沉淀

<!-- notes:begin -->
- **08 节厂商隔离与归一化提问/阻断判别（R1、R2）**：调度监管层（`run.ts`）严格遵守架构分层原则，不出现裸 `'tool_call'` kind 字面量、厂商工具名正则或命令文本解析。各类 Agent 抛出开放提问或调用交互工具的判别收口在各自适配器的 `map-events.ts`，统一映射为归一化字段 `requiresReply: true` 与 `isQuestion: true`；联网装依赖（如 `npm i`、`pnpm add`）由适配器就地归一化为 `run.permission_blocked` 并挂载机器可读字段 `blockedCategory: 'network_dependency'`。运行监管服务仅基于归一化事件类型与字段流转状态机，避免厂商协议泄露。
- **自动模式提问处置与并发占用（E-115）**：全自动运行下 agent 提问或抛出开放式交互时，调度器严格禁止进行任何假定或机器代答。收到带有 `requiresReply` 的归一化事件后，统一将运行状态迁入 `awaiting_reply`，迁移原因标准命名为 `RUN_TRANSITION_REASONS.AGENT_QUESTION`。`awaiting_reply` 不属于并发排除集，持续占用并发配额且不释放泳道；同时等待超时由 `stall-detector` 判定为 `waiting_human` 弱告警。
- **仅本次运行临时提升的纯内存生命周期（R3、E-133）**：针对沙箱拦下越界写入或阻断事件，系统记为高亮事件且不判失败。`elevateRunOnce` 提供单次放行机制，在内存维护 `temporarilyElevatedRuns` 集合，仅让当前运行单次迁移回 `running`（事件留痕发 `run.state_changed`）。该操作绝不修改 SQLite `runs` 表与 Agent 注册表的默认权限档位（不落库），并在运行正常退出（`exited`）或关闭流（`closeRunStream`）时立即自动清除（结束失效）。
- **starting 状态首事件推进保证**：派发后的初始运行停留在 `starting` 状态。`handleEventStateWiring` 先通过首条可解析事件将状态自然推进至 `running`，若该首事件本身即为阻断或提问事件，再合规转移至 `awaiting_reply`，严格符合状态转移白名单。
<!-- notes:end -->
