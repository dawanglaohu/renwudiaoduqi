# M5-T4　落地清单与 worktree 处置

- 所属模块：[[M5]]　**工作区与 Git**——为每个任务准备、隔离与回收独立 worktree，从中读出改动（改动文件数、diff stat、diff 正文）并生成只读落地清单。凡要碰 git 或任务工作目录的都归它
- 前置依赖：[[M5-T3]]
- 完成后解锁：[[M9-T16]]

## 输入 / 产出

- **输入**：M5-T3 的 diff
- **产出**：`workspace/landing.ts`、`http/routes/tasks.ts`（含 `landing` 与 `worktree/cleanup` 两个端点）

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 输出 worktree 绝对路径、分支名、diff 摘要、**可一键复制的 `gh stack` 命令文本**与一行可复制的 `python 〈docsPath〉/_run/build_docs.py 〈docsPath〉 --landed 〈任务ID〉`（`docsPath` 取文档记录的目录），**复制而不执行**，产品不调用任何文档维护脚本（[[E-74]]、决策 68）
2) 任务结束后 worktree 默认保留，只在用户显式点「清理」时 `worktree remove`
已清理过的任务重试需重建（[[E-73]]）
3) 清单为只读，产品不执行任何提交／push／PR／合并

## 必须处理的边界

- [[E-73]]　任务结束后 worktree 处置
    - 触发：任务跑完，worktree 仍在磁盘
    - 期望：默认保留（人还要用它落地），只在用户显式点「清理」时 `worktree remove`；已清理过的任务重试需重建
- [[E-74]]　用户要落地
    - 触发：任务已验收，准备合并
    - 期望：提供只读落地清单（worktree 绝对路径、分支名、diff 摘要、可一键复制的 `gh stack` 命令文本），复制而不执行

## 实施沉淀

<!-- notes:begin -->
1. 落地清单的只读性与不代行 Git/文档操作（E-74、决策 68）：
落地清单（`GET /api/v1/tasks/:taskId/landing`）只提取 worktree 绝对路径、分支名、diff 统计和一键复制命令，产品严格不调用任何提交、push、PR 或文档脚本。命令文本中的 `<docsPath>` 动态读取自任务关联文档记录的 `docs_path`，确保跨平台与非标准文档路径的一致性。

2. 工作区默认保留与显式清理（E-73）：
任务在执行或审查完成后，工作区默认驻留磁盘，供人工审查和后续落地复制使用；只有用户显式发起 `POST /api/v1/tasks/:taskId/worktree/cleanup` 时才调用 `removeWorktree`。清理默认 `deleteBranch: false`，仅回收磁盘上的 worktree 目录并执行 `git worktree prune`，不删除分支引用；若用户后续重试该任务，底层工作区分配机制（M5-T1）会探测分支并自动生成序号后缀（如 `task/ID-2`）重新建立隔离 worktree，避免分支冲突与历史覆盖。

3. 工作区缺失与清理后的错误语义：
若任务工作区从未创建或已被用户显式清理，`getTaskLanding` 抛出类型化 `E_NOT_FOUND` 而非 `E_WORKSPACE_UNAVAILABLE`，对齐 HTTP 路由错误码白名单（`E_UNAUTHORIZED`、`E_DEVICE_REVOKED`、`E_NOT_FOUND`、`E_INTERNAL`），明确指示该任务不可直接落地、需重建工作区。
