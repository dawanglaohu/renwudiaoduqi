# M3-T4　文档接管横幅与阅读器入口

- 所属模块：[[M3]]　**文档接入**——把 `docs-data.js` 变成本产品唯一的任务真相源（任务、依赖、批次、并行窗口、验收标准、边界编号、实施与审查两段提示词），并负责内容指纹、派发时快照与文档重出后的三个标记。凡「这条数据来自文档」的都归它
- 前置依赖：[[M3-T2]]
- 完成后解锁：无，它不卡别人

## 输入 / 产出

- **输入**：M3-T2
- **产出**：`system.docs_changed` 事件、接管横幅数据、`http/routes/documents.ts`（含 `open-reader` 与 `settings` 两个端点）

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 首次接管某文档时给一次性横幅「本文档任务状态已由调度器接管，阅读器里的手工三态不再有效」，可关闭并按文档记住（[[E-84]]）
2) 调度器**永不读也永不写**阅读器的 localStorage（[[E-83]]）
3) 「打开原文档阅读器」以系统默认浏览器打开原 `index.html`，不注入脚本、不改磁盘任何文件（[[E-85]]）
4) 文档目录被移动或重命名时提示「文档路径不可用，请重新定位」，任务记录、快照、会话指针全部保留（[[E-86]]）
5) 调度器**不读不写任何浏览器存储**
阅读器里手点三态与手调窗口数都不影响调度器（[[E-249]]）

## 必须处理的边界

- [[E-249]]　阅读器与调度器同时开着
    - 触发：`file://` 阅读器与调度器并行运行
    - 期望：调度器**不读不写任何浏览器存储**；阅读器里手点三态不影响调度器的窗口数与进度
- [[E-83]]　用户仍去点交接台的手工三态
    - 触发：双击打开 file:// 阅读器并点了状态
    - 期望：调度器永不读也永不写那份 localStorage；任务卡上不显示、不同步交接台状态
- [[E-84]]　首次接管某文档
    - 触发：调度器第一次导入这份文档
    - 期望：顶部一次性横幅「本文档任务状态已由调度器接管，阅读器里的手工三态不再有效」，可关闭并按文档记住
- [[E-85]]　打开原文档阅读器
    - 触发：用户点「打开原阅读器」入口
    - 期望：以系统默认浏览器打开原 index.html，原样打开，不注入脚本、不改磁盘上任何文件
- [[E-86]]　文档目录被移动或重命名
    - 触发：入口链接失效
    - 期望：提示「文档路径不可用，请重新定位」；已有任务记录、快照、会话指针全部保留

## 实施沉淀

<!-- notes:begin -->
原文档只读：调度器与 file:// 阅读器完全解耦，不读不写任何浏览器存储，也不向 index.html 注入脚本或改写磁盘文件；「打开原阅读器」把原始 index.html 路径交给系统默认浏览器。

路径失效保护：文档目录被重命名或移动时，openReader 检出 index.html 缺失，抛 E_NOT_FOUND（daemon 侧英文短句，details 带 docsPath/readerPath）并把文档标为 is_source_readable=0；任务记录、快照与会话指针一律保留，不级联清理。「文档路径不可用，请重新定位」由前端按 error.code 渲染。

打开命令解析：hostInputs 由容器注入 createDocsService；open-browser 按平台取候选绝对路径（win32 C:\Windows\explorer.exe、darwin /usr/bin/open、linux /usr/bin/xdg-open）交 platform.resolveExecutable 校验后启动，不读 process.platform。解析失败抛 E_AGENT_EXEC_NOT_FOUND 并带 cause，同时吞掉 detached 子进程的 error 事件，避免它冒泡成 uncaughtException 触发致命退出。

变更感知与持久化：文档内容指纹变动时，写库完成后向全局 EventBus 发布 system.docs_changed；接管横幅由 documents.is_takeover_notified 按文档持久化。documents repo 沿用 devices.ts 的惰性 prepare + 表存在守卫，使容器能在未建 documents 表的测试库上构建。
<!-- notes:end -->
