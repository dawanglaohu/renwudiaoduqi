# M7-T5　返工承接与新会话派发

- 所属模块：[[M7]]　**审查流水线**——对已结束的运行做「合不合格」的判定：先跑本地机械检查，通过后以只读档派一个 agent 跑文档给出的审查提示词，产出 pass / rework / doc-issue 并回灌 rework 意见；从审查输出提取返工文本、按能力位选回灌／恢复／新开返工运行，以及解析收口运行的八段报告，也归它；第 N+1 轮审查续接同一审查会话、查 bug 阶段的运行与五段报告解析同样归它。凡「判定一次运行的结果」的都归它；审查、查 bug 阶段的运行用哪个 agent、模型与思考强度，一律读派发快照里的任务指派（审查可被 pipeline 设置的「审查覆盖」替换），不自己取 agent 默认
- 前置依赖：[[M7-T4]]、[[M8-T5]]、[[M5-T2]]
- 完成后解锁：[[M8-T7]]、[[M8-T9]]

## 输入 / 产出

- **输入**：M7-T4 交来的 `{reviewRunId, targetRunId, reworkText, source}`；M8-T5 的新建运行路径；M5-T2 的 base 选择；派发快照里的 `adapterKind`
- **产出**：`service/rework.ts` 的 `dispatchRework()` 三分支、`domain/rework-prompt.ts` 的 `assembleReworkPrompt()`、`run.rework_dispatched` 事件

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 按被审运行快照 `launch_spec_json.adapterKind` 读代码层能力位（不读注册表当前值，[[E-93]]）：进程活着且 `canReply` → 回灌
已结束且 `canResume` → 恢复后回灌并明示新运行（[[E-112]]）
都不能 → 新开实施运行 `origin='rework'`、同任务 `attempt_no+1`、`spawned_by_run_id`=审查运行、同 worktree 与分支（[[E-279]]）
分支由能力位决定，代码中不存在「先试投递失败再降级」路径
2) 新会话提示词自包含：返工块原文 + 快照实施提示词「收到返工指令时」段（取不到用内置四句）+ 工作区指针 + 「只改列出条目、不 commit/push」（[[E-279]]）
3) worktree 目录已不存在时走 M5-T1 在原分支上 `reuse` 重建
分支不存在转 `awaiting_human` 并在闸门 comment 写 `branch_missing`
不开干净 worktree（[[E-277]]）
4) 三分支都 `rework_count+1` 且继承旧计数，旧计数已达 2 时直接 `reviewing→awaiting_human` 不进任何分支（[[E-55]]）
每分支在事务后发 `run.rework_dispatched{mode, source}`
5) 人工打回（[[E-59]]）与审查产出走同一入口，只以 `source` 区分

## 必须处理的边界

- [[E-112]]　会话已结束后才回话
    - 触发：用户在 agent 回合结束后点发送
    - 期望：支持 resume/fork 的 agent 走「恢复会话后投递」并在 UI 明示这是一次新运行（新运行记录、新退出码）；不支持恢复的禁用发送并提示改用重派
- [[E-277]]　返工需新会话但 worktree 已清理
    - 触发：审查判 rework，原会话不可回灌（需恢复或新开），而 worktree 目录已被清理
    - 期望：走 M5-T1 在原分支上重建 worktree（reuse 模式）再派返工运行；分支不存在则转 `awaiting_human` 并在闸门 comment 写 `branch_missing`；不开干净 worktree、不静默换 base
- [[E-279]]　无续接能力的 agent 需要返工
    - 触发：被审实施运行的 adapterKind 既不能回灌也不能恢复（dsh headless）
    - 期望：新开实施运行（`origin=rework`、同任务 attempt_no+1、同 worktree 与分支），提示词必须自包含：返工块原文 + 派发快照实施提示词里「收到返工指令时」规则段 + 工作区指针 + 只改列出条目；分支由能力位决定，不由投递结果决定
- [[E-55]]　全自动下审查反复判 rework
    - 触发：审查连续不通过
    - 期望：重试上限默认 2 次，超限转「待人确认」，不无限自动改；回灌、恢复后回灌、新开返工运行三种投递方式计入同一个计数
- [[E-59]]　用户点「打回」
    - 触发：审查后人工判定需返工
    - 期望：必须能附一句话意见，该意见复用 rework 通路回灌原会话
- [[E-93]]　配置文件被外部手改
    - 触发：用户直接编辑了注册表文件
    - 期望：daemon 监听变更热加载，只影响之后新起的任务；在途运行沿用启动时的参数快照
