## 必须处理的边界

- [[E-254]]　agent 不支持思考强度
    - 触发：dsh 无对应参数；某些模型或某些 agent 版本也没有
    - 期望：该 agent 的思考强度置 NULL、**派发时不传任何相关参数**，UI 一律显示「—」并在 title 说明原因。**绝不补一个默认档冒充**——补了等于谎称控制生效（与 E-26「数据缺失显示—，不拿 0 冒充」同理）。不因不支持而禁用该 agent（与 E-35 对称）
- [[E-335]]　登录态探测超时、命令不存在或输出无法解析
    - 触发：探测子进程 5 秒（注册表可覆盖）内未退出；`resolvedPath` 为空；stdout 不匹配任何解析规则
    - 期望：置 `unknown` 并给 reason（`timeout`／`exec_missing`／`spawn_failed`／`unparsable`／`exit_nonzero`），`warningCode` 为 `E_AGENT_LOGIN_PROBE_FAILED` 只作提示；**不禁用派发、不改 `canDispatch`**；徽标显示「无法判定」与「N 分钟前探测」；grok 断网走超时判 `unknown` 而不是 `logged_out`；`parser='none'` 的 agent（dsh）不起进程、不写缓存、DTO 的 `login` 为 null 且 UI 不渲染徽标
- [[E-336]]　agent 判定为 `logged_out` 时派发
    - 触发：用户仍把任务指派给它并派发
    - 期望：**照常派发**（决策 108）；徽标与指派行显示「未登录：在终端运行 〈登录命令〉 后点刷新」；派发失败按 E-36 原样展示 agent 报错，零产出退出按 E-348 转人；代码中不存在按登录态拒绝 `POST /runs` 的路径（单测断言 `assertCanDispatch()` 不读登录缓存）
- [[E-338]]　`live` 成功但清单不含配置当前值
    - 触发：`grok models`／`pi --list-models`／codex `model/list` 返回成功，但 `config.toml`／`settings.json` 里的当前模型名不在其中（用户手填了别名或已下线模型）
    - 期望：仍以 `source:'config'` 单独列出该项、标「当前配置 · 清单未列」并作默认选中；不改写、不做别名归并；选它派发原样透传，失败按 E-36
- [[E-339]]　刷新期间与并发刷新
    - 触发：用户点「刷新清单」后 `live` 与登录探测在途；同一 agent 被连点或 `availability_changed` 与手动刷新 5 秒内重叠
    - 期望：在途期间非 refresh 的 `GET /agents/:id/models` **不等待**，用旧 `live`（有缓存）或空 `live`（无缓存）+ config + builtin + history 立即返回并 `isRefreshing:true`；同一 agent 同时只一个 `live` 子进程、一个登录探测（`inflight` Map 去重，后续调用复用同一 promise）；刷新按钮在途时 disabled；`live` 失败不抛错、HTTP 200、`liveFailure` 字段说明原因
- [[E-348]]　运行零产出退出
    - 触发：任何 kind 的运行在首条内容事件（`agent_message_chunk`／`agent_thought_chunk`／`tool_call` 任一）之前进程退出（不论退出码，含 0）、启动超时或错误类事件；dsh 无流式时最终输出解析不出任何内容也算
    - 期望：判定只看事件 kind、不匹配 stderr／stdout 文本（与 E-330 同一结构规则）。实施运行（含 `origin=rework`／`wrapup-fix`）：`exited → reviewing → awaiting_human` 两跳（reason `exited_before_output`），**不跑机械检查、不派审查、不计 `rework_count`**，`tasks.lane_no` 置 NULL 并发 `lane.released{reason:'awaiting_human'}`（E-326）；审查运行走 E-62、查 bug 运行走 E-323、收口运行走 E-295。事务后重跑一次该 agent 的登录态探测（dsh 不探）。审批卡（`GateDto.context`）附退出码、退出信号、stderr 末 20 行（来自该 run 最后一条 `run.exited` 事件的 `stderrTail`，已脱敏，旧事件缺字段显示「无记录（旧运行）」）、刚探测的登录态，与固定提示句「agent 未产出任何内容就退出，常见原因：未登录、模型名不可用、参数被拒」，不写「未登录」定论；动作「重跑」（复用 `POST /runs/:id/rerun`）、「换 agent 重派」、「标失败」（`awaiting_human → failed`），手机端只有重跑与标失败；每次都转人不自动重试；同一 agent 多条泳道同时零产出各自转人、不暂停该 agent；启动超时与 spawn 失败仍走既有 `starting → failed`、手动停止不进本判定；内容事件之后才失败走既有路径并正常计数
- [[E-350]]　清单同名去重、别名与「当前配置」的位次
    - 触发：同一模型名同时出现在多个来源；claude 的 `config` 当前值本身是别名（本机 `opus[1m]`）；注册表 `builtinModels` 为空或条目非法
    - 期望：按 `live → config → builtin → history` 顺序追加，`name` 精确比较（不 trim、不大小写归一、不做别名归并，E-45），同名只保留更靠前者，daemon 去重后前端不再去重；`config` 当前值是别名时只出现一次、归 config 组并默认选中，builtin 组不重复；`builtinModels` 缺失或空数组 → builtin 组不渲染；条目 `name` 含空白或控制字符 → 注册表加载时拒绝**该条 agent**并 warn，其余 agent 照列；非 claude 的 agent 填了 `builtinModels` 同样列出（通用字段，不特判）；将来 claude 有了列模型命令，`live` 同名胜出、builtin 组自动缩小；claude 永远 `isComplete:false` → 下拉底部固定一行「清单可能不全，可手填」，「刷新清单」对它只重读配置与历史；选了别名后运行失败按 E-36 原样展示、不从清单移除
- [[E-351]]　思考强度出现厂商原值
