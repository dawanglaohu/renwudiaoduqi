## 实施沉淀

<!-- notes:begin -->
- **实现选择**：Claude Code 的 stream-json 在 API 调用失败时先输出一条合成 `assistant` 帧，顶层 `error` 取自安装包内置 SDK schema 的枚举（`authentication_failed`、`billing_error`、`rate_limit`、`overloaded`、`invalid_request`、`model_not_found`、`server_error` 等），随后输出 `result` 帧（`terminal_reason: api_error` 与 HTTP 状态）。适配器只认主循环帧（`parent_tool_use_id` 为 null）上的 `model_not_found`，它把模型拒绝与认证失败、上游 5xx 等其他失败分开。子代理帧报的是 agent 为工具调用自选的模型，以工具结果回到主循环，不代表派发的模型无效。`result` 帧的 HTTP 状态、stderr 的 `[claude-code:unrecognized_model]` 与消息正文都不参与判定，正文只原样放进 `vendorMessage`。六家适配器中只有 Claude 的 `reportsModelRejection` 为 true。
- **实测家数**：提供模型专用字段的 1 家，即 Claude Code 2.1.238 与 2.1.283。其余已探测的 agent 都没有能区分模型拒绝的类型字段，能力位保持 false，走 E-348：Codex 0.156.1、0.157.0、0.157.1 的 app-server 只有 `codexErrorInfo: other`，exec 只有文本；Pi 0.87.1 的 RPC 只有字符串 `error` 或 `errorMessage`；Grok 1.0.41 只有 `{type:'error', message}`；OpenCode 1.18.32 给 `UnknownError`、对模型不存在与会话不存在同为 `-32602` 的 JSON-RPC 错误，或与非模型错误同类的 `APIError`；Gemini CLI 0.61.0 未完成模型请求。中转服务自己返回的 `error.code`（如 `model_not_found`）被 agent 压成字符串，不经 agent 协议透出，不算该 agent 的信号。
- **录制方法**：录制用 `buildClaudeLaunchSpec` 生成的生产参数，另加 `--verbose`，并把提示词作为一条 stream-json user 消息写进 stdin（原因见维护约束）；对照组是同一入口的无效令牌（401 · `authentication_failed`）和中转回 503 的无效模型（`server_error`）。凭据只经子进程环境传入；脱敏替换 id、端点与请求号，保留 null 值，夹具已对照 CC Switch 全部供应商的令牌、地址与主机名确认无泄漏。
- **失败教训**：判断厂商协议有没有某个字段之前，先读该版本自带的 schema 或类型声明，再按字段的完整原值记录。只在 `error` 为对象时读取 `type/code` 的探针会漏掉 Claude 帧上的字符串 `error`，结论会误判为 0 家；脱敏时把 null 换成占位串，也会抹掉 `parent_tool_use_id` 这类协议信息。Pi 探针带 `--no-extensions` 会让已列出的正常模型也设置失败，对照组要先确认有效模型能成功。
- **维护约束**：派发管线按行无状态映射，`run.model_rejected` 的 `modelName` 在生产中是空串，模型名以运行的 `model_name` 列和 `vendorMessage` 原文为准。生产的 Claude 启动形状有三处与实测不符，不在本任务有效路径内，需另开任务修复：① 内置参数模板没有 `--verbose`，Claude Code 在 `--print` 配 `--output-format stream-json` 时要求它，本机靠 `~/.claude/settings.json` 的 `verbose: true` 才能启动；② 模板带 `--input-format stream-json`，提示词却只作位置参数传入、stdin 保持打开不写，实测 2.1.283 等待 90 秒没有任何输出，关闭 stdin 则零输出退出；③ 适配器不映射 `type: 'assistant'` 的正常消息帧，未开 `--include-partial-messages` 时正常运行也产出不了内容事件，会被 E-348 当成零产出。三处修好之前，真实 Claude 运行到不了 API 调用，本任务的精确标注只在回放录制的测试中生效。Claude Code 升级后先重录这四份夹具，确认 `error` 枚举与主循环帧形状未变。
