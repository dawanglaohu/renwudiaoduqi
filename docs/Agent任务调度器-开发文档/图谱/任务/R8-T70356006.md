- **实现选择**：无效模型探测覆盖 Codex 0.157.1、Claude Code 2.1.238 与隔离运行的 2.1.283、Grok 1.0.41、Pi 0.87.1、OpenCode 1.18.32。Codex 返回 `codexErrorInfo: other`；Claude Code 2.1.283 的最终 `stream-json` 帧为 `terminal_reason: api_error`、`api_error_status: 503`，没有模型专用 `code/type`；Grok 仅有错误消息文本。Pi RPC 的 `set_model` 响应为 `success:false` 与字符串 `error`，没有类型字段；OpenCode `run --format json` 为 `error.name: UnknownError`，ACP `session/set_model` 对不存在模型与不存在会话均返回通用 `-32602`，仅 `data` 键分别为 `providerId/modelId` 与 `sessionId`。隔离运行的 Gemini CLI 0.61.0 在模型请求前退出，未提供可判断的协议帧。这些结果都不满足本任务的模型专用结构化拒绝信号；满足要求的真实验证家数仍为 0。所有适配器的 `reportsModelRejection` 保持 false，未验证错误继续按 E-348 转人工。Claude 适配器和生产派发入口的合成帧测试覆盖失败、泳道释放与 waiting 审批卡作废，但不充当真实协议正例；任务保持未落地。
