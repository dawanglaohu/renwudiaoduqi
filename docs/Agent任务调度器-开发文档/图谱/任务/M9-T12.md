- 所属模块：[[M9]]　**客户端界面**——两端共用的那一套界面本身：多流监看、会话查看、审批与闸门、设置与配对、落地清单、按批次折叠的批次树与执行行呼吸灯、按窗口数呈现的任务流水线泳道与「会话已归档」历史行、顶栏两个流水线开关，以及同一套代码的窄屏降级。它只通过 M2 的契约与 daemon 通信，**界面里不含任何业务判定**（折叠默认值、「能否收口」、泳道分配、阶段推进与会话归档都是 daemon 给的字段）；指派面板的分组模型下拉、登录态徽标与刷新按钮、参照条的「来源」段同样只呈现 daemon 下发的字段，不算取值链

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 手机竖屏 <400px 降级为单栏切换（任务列表／运行流／详情），**不得横向滚动或并排三栏**（[[E-145]]）
2) 停止与批准固定在拇指区、分置两端或间距 ≥24px、各 ≥44×44px，**不随日志滚动移出视野**（[[E-107]]）
3) 单栏切换到「任务列表」时若某条流转「等你」，必须有可见的未处理计数徽标（[[E-240]]）
4) 手机端中止需二次确认防口袋误触（[[E-124]]）
5) 首屏加载量显著更小（尾部 32KB），不预取全量
切后台回前台不重拉全量（[[E-99]]）
6) 展开的 tool payload 走 bottom sheet 不内联
7) 批次表格在小屏降级为可折叠列表（[[E-13]]）
8) app 曾退到后台时重回前台拉未读列表，**等待中的确认项不过期、不自动放行**（[[E-58]]）
9) **AC5/AC6 的落点与接线责任（本次审查定点补记，不改已有 1–8 条）**：① 展开的 tool payload 不内联的落点是 `packages/web/src/components/stream-row.tsx`（当前在展开区用等宽预格式化块 data-step-payload 内联渲染）＋ `packages/web/src/features/run-deck/` 的 bottom sheet
行组件与甲板之间只准经 `packages/web/src/hooks/use-payload-sheet.ts` 转接（`components` 禁止 import `features`），手机档展开步骤时不得渲染内联 payload，且必须由「甲板 + 真实 StreamRow」的渲染断言证明 sheet 确实被打开
② [[E-99]] 的首屏加载量落点在 `packages/web/src/features/run-detail/use-log-window.ts`：手机档首屏日志请求必须带显著更小的尾部窗口（32KB 量级
daemon 的 `GetRunLogQuery` 只收行数 `limit`，按行数近似并在注释里写明换算），桌面档不变
切后台再回前台不得重发首屏全量
界面上不得出现「已自动开启尾部轻量加载」这类对未实现行为的断言文案

## 实施沉淀

<!-- notes:begin -->
- 窄屏（phone-xs <400px）三栏切换否决了在 store 里维护 mobilePane 内存状态或手写 history.pushState。遵循 07 节约定直接绑定 hash query #/?pane=tasks|stream|detail，由自写路由与 navigateTo() 统一派发。这样既不新增冗余路由分支，又使 Android 物理与手势返回键天然回退到上一 pane，且刷新页面不丢失当前栏位。
- 停止与批准固定在视口底部 min-h-[60px] 的 ThumbBar 内，底部垫入 calc(env(safe-area-inset-bottom) + 11px)。为防单手拇指误触，停止键（左）与批准键（右）通过 justify-between 与 gap-6 强制隔离至少 24px，且在手机模式下拦截直接停止动作，唤起 dialog.tsx 白名单内的二次确认弹窗（E-124）。
- 未处理徽标（E-240）唤起机制：单栏切到「任务列表」或「详情」时，若某条流进入 awaiting_input 或 needsApproval，切栏器仅在非当前激活的「运行流」tab 上点亮暖色徽标；当用户已处于「运行流」时自动抑制该徽标，避免同屏信息噪声。
- Tool Payload 交互边界：手机竖屏宽度下，若直接内联展开大段 JSON 会严重挤爆垂直滚动流。遵循 07 节 components 禁止 import features 的分层约束，以 packages/web/src/hooks/use-payload-sheet.ts 作为转接点，甲板在手机档（phone/phone-xs 或 isTouch）提供 PayloadSheetProvider；StreamRow 展开带 payload 步骤时不再渲染内联 pre 块，而是将入参出参数据送入甲板的 MobileBottomSheet 抽屉，通过 max-h-[80vh] 等宽区域呈现，关闭后主视图滚动位置零偏移（AC 6）。
- 架构禁令机检要求：check-forbidden.ts 规则对 run-deck 目录内所有文件（包含注释与 Tailwind 样式）实施正则机检，严禁出现 overflow-x 字样（即使是 overflow-x-hidden 也会被拦截），必须统一使用 overflow-hidden。
<!-- notes:end -->
