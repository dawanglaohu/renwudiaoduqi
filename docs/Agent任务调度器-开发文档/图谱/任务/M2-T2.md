# M2-T2　设备配对、令牌哈希与吊销

- 所属模块：[[M2]]　**接入与设备信任**——定义两端如何连上 daemon 并不丢事件地保持同步：一次性配对码与可单独吊销的设备令牌、鉴权与操作归属、REST 骨架与 API 版本、SSE 服务端的事件信封／重放窗口／保活，以及自写的 SSE 客户端。凡「谁能连上、连上之后按什么协议收发」的都归它
- 前置依赖：[[M2-T1]]
- 完成后解锁：[[M2-T3]]、[[M9-T15]]

## 输入 / 产出

- **输入**：M2-T1 的插件链
- **产出**：`service/pairing.ts`、`repo/devices.ts`、`/pair/*` 与 `/devices/*` 路由

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 配对码一次性、TTL ≤60 秒、只在内存
用掉或过期即失效（[[E-07]]）
2) 令牌只存 `scrypt` 哈希 + 随机盐，比对用 `timingSafeEqual`，库中无明文
3) 吊销后该设备的活动连接立即断开并返回 401（[[E-127]]）
4) `/pair/*` 每 IP 每分钟 10 次，超限 429 **并立即作废当前配对码**（[[E-07]]）
5) 零已配对设备时把一次性配对码打印到控制台并写入数据目录 `pairing-code.txt`
POSIX 断言 `0600`，Windows 断言当前用户专用 DACL，用后即删
**不新增第四个免鉴权端点**（[[E-226]]）

## 必须处理的边界

- [[E-07]]　配对码泄露或重复使用
    - 触发：配对码被第三方获取
    - 期望：配对码一次性且短时效（≤60 秒），配对后换发长期设备令牌；令牌按设备列出并可单独吊销
- [[E-127]]　设备丢失或令牌泄露
    - 触发：手机丢了
    - 期望：桌面端能列出已配对设备并一键吊销；吊销后该设备的活动连接立即断开
- [[E-226]]　**全新装机的自举困境**
    - 触发：零已配对设备、两个壳都未就绪，而 `POST /pair/code` 需 device 令牌
    - 期望：daemon 必须能把一次性配对码**输出到本机控制台或数据目录文件**；POSIX 文件模式固定 `0600`，Windows DACL 只允许当前用户，用后即删。**不得为此新增第四个免鉴权端点**

## 实施沉淀

<!-- notes:begin -->
1. **令牌安全与防时序攻击**：设备令牌明文仅在 `claim` 响应中出现一次，落库严格采用 16 字节随机盐与 `crypto.scryptSync`（64 字节密钥长度）派生哈希存储。比对必须走 `crypto.timingSafeEqual`，且在比对前显式校验缓冲区长度，杜绝时序攻击泄露哈希前缀。
2. **内存配对码状态机与自举隔离**：配对码存储于服务闭包内存变量中，完全避开持久化层；生命周期在「被成功/失败验证」、「显式作废」、「TTL 过期（≤60s）」任一事件发生时立即置空。零设备自举所生成的 `pairing-code.txt` 遵循最小特权原则（POSIX 0600、Windows 专用 DACL），并在 `claim` 或作废完成后就地物理删除（用后即删），绝不为此增加额外免鉴权端点（E-226）。
3. **活动连接解绑与即时吊销（E-127）**：设备吊销除持久化 `revoked_at` 阻断后续鉴权外，采用内存连接注册表（`activeConnections`）维护当前设备的存活通道。吊销触发时同步派发 `E_DEVICE_REVOKED` 中断所有挂起通道并响应 401，避免长连接或 SSE 会话因未重检令牌而驻留。
4. **Fastify AJV 与子作用域错误传播踩坑**：Fastify 默认开启 `removeAdditional: true`，会导致手写的 `additionalProperties: false` 被静默剥离多余字段而非抛出校验失败；必须在实例级显式配置 `removeAdditional: false`。此外，`server.ts` 中的子作用域 `{ prefix: '/api/v1' }` 会隔断后注册的全局错误处理器，必须在 API 子 scope 内同样挂载错误处理器，确保 `E_PAIRING_CODE_INVALID` 与 `E_VALIDATION` 按 `ERROR_CODES` 正确投影为 401/400 状态码。
<!-- notes:end -->
