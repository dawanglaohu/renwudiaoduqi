# E-348　运行零产出退出

| | |
|---|---|
| 触发条件 | 任何 kind 的运行在首条内容事件（`agent_message_chunk`／`agent_thought_chunk`／`tool_call` 任一）之前进程退出（不论退出码，含 0）、启动超时或错误类事件；dsh 无流式时最终输出解析不出任何内容也算 |
| 期望行为 | 判定只看事件 kind、不匹配 stderr／stdout 文本（与 E-330 同一结构规则）。实施运行（含 `origin=rework`／`wrapup-fix`）：`exited → reviewing → awaiting_human` 两跳（reason `exited_before_output`），**不跑机械检查、不派审查、不计 `rework_count`**，`tasks.lane_no` 置 NULL 并发 `lane.released{reason:'awaiting_human'}`（E-326）；审查运行走 E-62、查 bug 运行走 E-323、收口运行走 E-295。事务后重跑一次该 agent 的登录态探测（dsh 不探）。审批卡（`GateDto.context`）附退出码、退出信号、stderr 末 20 行（来自该 run 最后一条 `run.exited` 事件的 `stderrTail`，已脱敏，旧事件缺字段显示「无记录（旧运行）」）、刚探测的登录态，与固定提示句「agent 未产出任何内容就退出，常见原因：未登录、模型名不可用、参数被拒」，不写「未登录」定论；动作「重跑」（复用 `POST /runs/:id/rerun`）、「换 agent 重派」、「标失败」（`awaiting_human → failed`），手机端只有重跑与标失败；每次都转人不自动重试；同一 agent 多条泳道同时零产出各自转人、不暂停该 agent；启动超时与 spawn 失败仍走既有 `starting → failed`、手动停止不进本判定；内容事件之后才失败走既有路径并正常计数 |
