# E-327　人打回后重新入道

| | |
|---|---|
| 触发条件 | 停靠在 `awaiting_human` 的任务被人打回（附意见） |
| 期望行为 | 当场 decide 闸门、意见落 `rework_text`（source=human）、运行迁 `reworking`，计数照加不受 E-55 拦截；返工进入可放行集合并**排在全部新任务之前**（多个返工按打回时间先后），有空泳道当场入道（泳道号可与原先不同）再按 M7-T5 三分支投递；等泳道期间 `lanes[]` 不含它、批次树该行显示「返工排队 · 等泳道」静态点不呼吸、审批卡已关闭；入道时进程已死或 daemon 重启过则按快照能力位恢复（E-112）或新开 `origin=rework`（E-279），worktree 已清理走 E-277；批次 `paused` 时不入道并显示「批次已暂停 · 返工排队」，恢复后先于新任务入道；返工再次退出后续接同一审查会话第 N+1 轮（未归档） |
| 归属模块 | [[M8]] |

- 投递失败链（第 1 轮审查后补，同分支同文件）：
  1) **启动即退出不算送达**：假进程「spawn 后立刻退出」时公开闸门回 422 `E_MESSAGE_UNDELIVERED`（`details.reason='premature_exit'`），不发 `run.rework_dispatched`；恢复分支与「新开」分支共用 `isReworkDeliveryConfirmed()` 这把尺子（`starting`/`queued`/终态失败都不算送达）。
  2) **spawn 抛错后的状态**：失败返工行落 `failed` + `queued_reason='rework_delivery_failed:spawn_failed'`；目标实施行 `reworking → awaiting_human`（同原因）、`tasks.lane_no` 置 NULL 并发 `lane.released`、留一张 `waiting` 审查闸门卡当可操作入口；**不归档任何会话**（`session_archived_at` 保持 NULL），`rework_count` 仍只记 1。
  3) **一次启动失败 → 恢复投递 → 下一轮审查**：对着那张闸门卡再打回一次即走同一条公开入口，进程真的起来（意见进 argv）→ 退出码 0 → 出现新 `kind='review'` 行（`parent_run_id` = 返工运行）；两次决定共 2 次计数、无重复加。
  4) **tick 侧同一条链**：满槽排队后由 tick 补位投递而 spawn 抛错时，任务同样落到 `awaiting_human` + 类型化原因 + 重试闸门，不被那条失败的返工行挡住；随后同门重试成功并续接审查。
  5) **默认并发=1 的补位**：`maxConcurrency=1`（默认注册表值）下满槽→空槽的 tick 补位仍能把返工投递出去（被返工取代的旧实施行不再占该 agent 名额）。
