# E-349　pi 的登录态按 provider

| | |
|---|---|
| 触发条件 | 探测 pi；`pi auth check` 必须带 `--provider` 或 `--model` |
| 期望行为 | provider 集合与 `defaultProvider` 由 M4-T14 注入 `probeLogin()`：集合 = 本次 `live` 清单（`pi --list-models` 第一列）的 DISTINCT，`live` 失败时只传 `settings.json` 的 `defaultProvider`（`read-models.ts` 的 `currentConfigProvider`），两者都空 → `unknown`（reason `no_provider`）不起进程；上限 10 个 provider，超出的标 `not_probed`；逐个并行各 5 秒；`ready → logged_in`、`not_ready → logged_out`、`invalid` 或解析失败 → `unknown`；agent 级状态取 `defaultProvider` 那一项，缺省取第一个 `logged_in` 的 provider，没有则 `unknown`；`LoginState.providers` 逐 provider 下发，指派面板的 pi 下拉按 provider 子分组、各带徽标；`{provider}` 变量标记只允许出现在 `parser='pi_auth_check'` 的探测参数里，其余 parser 含它注册表校验拒绝 |
| 归属模块 | [[M4]] |
