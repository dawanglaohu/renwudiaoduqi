# E-330　续接撑爆的判定

| | |
|---|---|
| 触发条件 | 第 N+1 轮审查续接投递（回灌或恢复）之后，或返工反喂实施会话之后 |
| 期望行为 | 按归一化事件流结构判定、不看厂商字符串：该轮首条内容事件（`agent_message_chunk`／`agent_thought_chunk`／`tool_call` 任一）之前出现未送达（E-113）、启动超时（E-190）、进程退出或错误类事件 → 判「会话不可续」，只新开一次（审查按 E-304、实施按 E-305），恢复分支产生的失败行标 `failed`（reason `continuation_exhausted`）不计入 `review_round`；内容事件之后才失败按 E-62 转人、不新开；新开的会话再次在内容前失败 → 不再新开，转人并 comment `review_continuation_failed`；投递成功但既无事件也不退出 → 走停滞检测（E-120），不算撑爆；`canReply` 与 `canResume` 皆假的 agent 不进入本判定，按能力位直接新开 |
