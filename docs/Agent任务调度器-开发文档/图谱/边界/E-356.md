# E-356　pipeline 设置四键的写入与校验

| | |
|---|---|
| 触发条件 | `PATCH /settings/pipeline` 缺键、`reviewOverride.agentId` 不在注册表、dsh 配了 `effortTier`、旧库 `pipeline` 行只有两键 |
| 期望行为 | 四键 `{bughunt, wrapupMode, reviewOverride, wrapupAssignment}` 整体写入，缺任一 `E_VALIDATION`（AJV `additionalProperties:false`、`required` 四项）；`reviewOverride`／`wrapupAssignment.agentId` 必须存在于注册表当前快照，否则 `E_VALIDATION`（`details.field` 用点路径），校验只查注册表快照不起探测子进程；`effortTier` 只收三档不收 vendor，该 agent `effortVendorMap` 为 null 时非 null → `E_VALIDATION`（reason `effort_unsupported`）；`modelName` 不做清单校验（等同 manual 来源，E-36）；缺行返回默认 `{bughunt:0, wrapupMode:'auto', reviewOverride:null, wrapupAssignment:{mode:'follow'}}` 不插行，旧行只有两键读侧补默认不改库，任一键形状非法整体回落默认并 warn（E-292 同法）；不需迁移（JSON 列）；写成功发 `settings.pipeline_changed{pipeline}`（完整四键）并 nudge tick；两项设置不进 `gates` 行、不进 `documents`，算出的结果进快照 `assignment_json`、设置本体不进；运行时再核一次 agent 存在与可用，不可用走各阶段既有转人路径 |
