# E-351　思考强度出现厂商原值

| | |
|---|---|
| 触发条件 | 配置文件当前值超出三档（codex `xhigh`、pi `xhigh`）；用户在设置页或指派面板选了厂商原值；配置值拼错；所选模型的 `live` 取值域不含该值 |
| 期望行为 | 值形状 `EffortValue = {tier} ｜ {vendor} ｜ null`，存储 `runs.effort_tier`（三档 CHECK 不改）与新列 `runs.effort_vendor` 恒不同时非空；`{vendor}` **只允许来自 `config` 当前值或 `live` 取值域**：`POST /runs`、`PATCH /agents/:id`、快照写入前校验，不在域内 → `E_VALIDATION`（`details.field:'effort'`、`allowed[]`），手填厂商值同样拒绝；派发时 `{vendor}` 原样传不映射，显示层显示原值；配置值既不在映射表也不在 `live` 域（如 `xhighh`）→ 仍作「当前配置」显示原值并加「无法识别」角标（`currentConfig.effortRecognized:false`），选它照传、失败按 E-36；所选模型的 `effortOptions` 不含该值（gpt-5.2 无 `max`）或三档映射后的厂商值不在其中 → 警告「该模型不支持 〈值〉」，不禁用、不换值；`effortVendorMap` 为 null 的 agent（dsh）传非 null → `E_VALIDATION`（reason `effort_unsupported`）；自报值比较对 `{vendor}` 用原串相等，`normalizeReportedEffort` 的 `xhigh→high` 只用于自报比较不用于存储；pi 模型串自带 `:xhigh` 且同时选了思考强度 → 显式选择优先、剥后缀改传 `--thinking` 并记一条 warn；设置页三行「内置默认／你的覆盖／当前生效」思考强度与模型同规则，当前生效 = 覆盖 ?? 配置 ?? 内置；旧快照缺 effort 字段读作 null 显示「—」 |
