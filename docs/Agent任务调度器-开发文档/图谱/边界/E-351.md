# E-351　思考强度出现厂商原值

| | |
|---|---|
| 触发条件 | 配置文件当前值超出三档（codex `xhigh`、pi `xhigh`）；用户在设置页或指派面板选了厂商原值；配置值拼错；所选模型的 `live` 取值域不含该值 |
| 期望行为 | 值形状 `EffortValue = {tier} ｜ {vendor} ｜ null`，存储 `runs.effort_tier`（三档 CHECK 不改）与新列 `runs.effort_vendor` 恒不同时非空；`{vendor}` 值域为三档映射值、CLI 原生后备集合（Claude 取实际可执行文件帮助中探测的命名档位）、`config` 当前厂商值和缓存 `live` 档位的并集：`POST /runs`、`PATCH /agents/:id`、`PATCH /settings/pipeline`、手动收口与新快照写入前校验，不在域内 → `E_VALIDATION`（`details.field:'effort'`、`allowed[]`），手填厂商值同样拒绝；派发时 `{vendor}` 原样传不映射，显示层显示原值；配置值既不在映射表也不在 `live` 域（如 `xhighh`）→ 仍作「当前配置」显示原值并加「无法识别」角标（`currentConfig.effortRecognized:false`），选它照传、失败按 E-36；模型能力按显式模型 → Agent 生效默认模型 → `currentConfig.model` 检查；`effortOptions: []` 表示明确不支持，UI 显示「—」并提交 null，首派／审查／新收口在默认或继承解析后把运行列与指派快照的强度归零、不传参数；字段缺失表示未知，保留 CLI 后备行为；非空集合不含所选原生值或三档映射值 → 警告「该模型不支持 〈值〉」，不禁用、不换值；`effortVendorMap` 为 null 的 agent（dsh）传非 null → `E_VALIDATION`（reason `effort_unsupported`）；自报值比较对 `{vendor}` 用原串相等，`normalizeReportedEffort` 的 `xhigh→high` 只用于自报比较不用于存储；pi 模型串自带 `:xhigh` 且同时选了思考强度 → 显式选择优先、剥后缀改传 `--thinking` 并记一条 warn；设置页三行「内置默认／你的覆盖／当前生效」思考强度与模型同规则，当前生效 = `hasOverride` 为 true 时采用覆盖（包括显式 null），否则配置 ?? 内置；审查覆盖任一 effort 字段显式 null 且无另一非空字段时清空，固定收口空值按 E-344 继承，手动收口按该轮 body；旧三档配置与 Claude 旧版预算映射继续兼容，厂商原值存储与传输不降档；可执行路径和能力同时冻结，超出冻结 CLI 能力的非空值在启动前拒绝；返工／查 bug／收口修复／原样重跑保留原指派快照；旧快照缺 effort 字段读作 null 显示「—」 |
