# E-204　要清的文件正被读

| | |
|---|---|
| 触发条件 | M6 判定某份正文该清，但会话查看器正按偏移分段读它（Windows EBUSY） |
| 期望行为 | M1 的删除原语返回**可重试错误而非抛异常**；M6 本轮跳过该文件、下一轮重试，不向用户报错 |
| 归属模块 | [[M6]] |

## 被这些任务兜底

- [[M1-T5]]　磁盘占用统计、写满兜底与受限删除原语

## 验证记录

<!-- notes:begin -->
- `packages/daemon/test/unit/disk-primitives.test.ts`「E-204」组：适配器抛原生 EBUSY、或抛把 EPERM 包进 `E_INTERNAL` 的 AppError（Windows 上实际形态）时，`deleteByPath` / `truncate` 都返回 `{ok:false, retryable:true, code:'EBUSY'}` 而不抛。
- 真实 EBUSY 需要另一个进程持有句柄（Node 自己打开的读流带 FILE_SHARE_DELETE，删除不会失败），CI 无法稳定复现，因此用 `LogFileSystem` 替身注入错误；`logstore-fs-errors.test.ts` 另验 `isBusyCause` 对原生与包装两种形态都成立。
<!-- notes:end -->
