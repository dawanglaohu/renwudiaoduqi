# 原始需求（逐字原文，禁止改写、禁止润色）

我需要根据当前使用的技能产出的文档，做一个基于这个任务产出的开发文档的任务调度器，电脑桌面端 + 手机 app 端 ，主要根据文档产出的  任务交接台中的任务发派给不同的  agents  干活，如：codex 桌面版 + claude  桌面端 + pi cli + grok cli  + DeepSeek Harness  ， 此类 agents  产品发派任务：

1. 发派的任务可以看到进度与完成状态提醒，
2. 可以进入任务调度中查看发派agents出去的会话内容，
3. 可以先调研，有没有此类产品，
4. 难度： 需要确认 agents  桌面版，是否可以从外部发派任务给 agents ？

# 追加需求（用户在本次运行途中补充，同样逐字原文，禁止改写）

任务助手可以给不同的 agents 选择指定默认模型（可获取agents配置文件中的模型），模型选择好后，可根据产出的文档中任务交接台中的按批次派活，进行自动/半自动（先实施，审查可自动），开始派发任务。

这条补充带来四件原始需求里没有的事：

- **按 agent 指定默认模型**，且模型清单要能**从 agent 自己的配置文件里读出来**，
  不是让用户手打模型名。
- **按批次派活**——对应交接台里已有的批次/并行窗口结构，不是一个一个点。
- **自动 / 半自动两档**，用户要能选。
- **「先实施，审查可自动」**——实施与审查是两个阶段，审查这一段可以自动跑。
  即：派实施 → 收回 → 自动审查 → 判定。

# 已知硬约束

只记录用户明确说过的：

- **两个端**：电脑桌面端 + 手机 app 端。两端都要，不是二选一。
- **任务来源固定**：unattended-run 技能产出的开发文档，具体是其 HTML 阅读器里的
  「任务交接台」。不是让用户手工录任务。
- **发派目标是既有 agent 产品**，用户点名五个：codex 桌面版、claude 桌面端、
  pi cli、grok cli、DeepSeek Harness。注意这五个里有 **2 个桌面 GUI 应用 +
  2 个 CLI + 1 个 harness**，形态不同。
- **功能点 1**：发派出去的任务要能看到进度与完成状态提醒。
- **功能点 2**：要能进入任务调度里，查看发派给 agents 的**会话内容**。
- **功能点 3**：用户明确要求先做调研——市面上有没有同类产品。
- **功能点 4**：用户自己已经点出核心技术风险——agent 桌面版能不能从外部接收任务。
  这是可行性前提，不是普通需求点。
