# 边界情况登记簿（按裁决顺序连续编号，禁止跳号/改号）

来源：代理用户每次裁决的 EDGE_CASES。13 节直接渲染这张表，19 节的验收标准必须引用编号。

## 第 1 批（决策 1-6：架构骨架）

| 编号 | 场景 | 触发条件 | 期望行为 | 相关决策 |
|---|---|---|---|---|
| E-01 | 桌面 UI 关闭但任务在跑 | 用户关闭或桌面壳崩溃，agent 会话仍在运行 | daemon 继续收流并在完成时发通知；桌面重开后从 daemon 全量拉状态，不重放本地缓存 | 1 |
| E-02 | daemon 重启后会话失联 | daemon 被杀或机器重启，agent 会话还活着 | 按持久化的 task↔session 映射重新 attach；attach 不上的标「失联」而非「失败」，由用户决定是否重派 | 1 |
| E-03 | 端口被占用或多实例 | daemon 端口被占用，或同机多用户登录 | 端口可配置 + 单实例锁，第二个实例拒绝启动并把请求让给已有实例；绝不允许两个调度器同时推进同一批次 | 1 |
| E-04 | 未开桌面直接从手机派活 | daemon 未运行时手机端发起派发 | 明确提示「电脑上的调度服务未启动」，而不是连接超时 | 1 |
| E-05 | 批次中途人工干预 | 一批任务跑到一半，用户手动改了某个任务状态 | 人工操作优先级高于自动推进；批次可在中途暂停/接管，自动派发不得覆盖人的判断 | 1 |
| E-06 | 同网段但连不上 | 手机与 PC 不同网段，或 WiFi 开了 AP 隔离 | 配对失败报到具体环节（「扫到码但连不上 host:port」），并提供手填地址兜底 | 2 |
| E-07 | 配对码泄露或重复使用 | 配对码被第三方获取 | 配对码一次性且短时效（≤60 秒），配对后换发长期设备令牌；令牌按设备列出并可单独吊销 | 2 |
| E-08 | daemon 被隧道暴露到公网 | 用户自行接入 Tailscale/frp | 鉴权与加密默认开启；代码中不得存在「局域网内免鉴权」分支 | 2 |
| E-09 | PC 局域网 IP 变化 | DHCP 续租或切换网络 | 手机保存设备令牌而非 IP；重连走重新发现或提示重扫码，已授权设备不需重新授权 | 2 |
| E-10 | 手机断网期间任务跑完 | 提醒产生时手机不在线 | 提醒事件在 daemon 侧按 event id 入队，手机重连后补推并去重，不得丢弃 | 2 |
| E-11 | 手机离线推送不可达 | app 不在前台且连接已断 | 第一版只保证 app 前台/保持连接时的本地通知 + 重开后的未读列表；真正的离线推送需 APNs/FCM（要服务端），明确不做并在 UI 说明 | 3 |
| E-12 | 壳内 WebView 与 daemon 断连 | 网络中断或 daemon 停止 | 顶部显示「离线，最后同步于 X」并禁用派发按钮，避免用户以为任务已派出；恢复后自动补拉事件 | 3 |
| E-13 | 手机竖屏看批次与并行窗口 | 小屏访问宽表格视图 | 降级为可折叠列表，不得让桌面宽表格横向滚动 | 3 |
| E-14 | 两端版本不一致 | 只更新了桌面壳或只更新了手机壳 | daemon 暴露 API 版本号，壳启动时校验，不兼容时提示升级，而不是抛底层错误 | 3 |
| E-15 | 深色模式与系统字号放大 | 系统主题或字号变更 | 一套 Web UI 跟随系统主题与字号，壳不做覆盖 | 3 |
| E-16 | docs-data.js 编码读错 | 在中文 Windows 上按系统默认编码读取 | 强制按 UTF-8 读取（生成时 ensure_ascii=False）；格式为 `window.DOCS = 〈JSON 字面量〉;` 去头去尾 JSON.parse，不需 JS 引擎 | 4 |
| E-17 | 用时间戳误判文档变更 | payload 无 schemaVersion，只有每次重建都变的 generated | 适配器按 data.tasks 内容算指纹判断文档是否真变，不得拿 generated 当变更依据 | 4 |
| E-18 | 任务从文档中消失 | 文档重新生成后某任务 id 已不存在，但本地有运行记录 | 标「文档中已移除」并保留历史与会话链接，不静默删除 | 4 |
| E-19 | 验收标准被事后改动 | 同一 id 的 input/output/accept 文本被改过 | 派发时把这三段快照进任务记录；列表标「文档已更新，与派发时不一致」 | 4 |
| E-20 | 依赖脏数据 | deps 指向不存在的 id，或依赖成环 | 导入时校验，禁止进入自动批次派发；仍允许手动单点派发，不得因一条脏边卡死整个交接台 | 4 |
| E-21 | 多份文档同时接入 | 用户接入多个项目的文档 | 按 pres.handoff 的 repo/branchPrefix 加文档指纹分工作区，任务 id 不跨项目冲突 | 4 |
| E-22 | agent 长时间零输出 | 在等 API 或长思考 | 用「最后事件距今 N 分钟」做静默检测，标「疑似卡住」并给出查看原始流与终止的入口，不得一直显示「进行中」 | 5 |
| E-23 | 退出码为 0 但活没干完 | agent 自行放弃或上下文超限后正常退出 | 退出码不等于验收通过；状态机必须把「已退出」与「已落地」分开，后者只能由自动审查或人确认 | 5 |
| E-24 | 单任务日志膨胀 | 会话输出达到几十 MB | 落盘归档并轮转，UI 只加载尾部与分页，内存不留全量 | 5 |
| E-25 | 会话内容含密钥 | agent 打印了环境变量或 token | 跨设备推到手机前做基本脱敏，或至少在首次开启远程查看时明确告知 | 5 |
| E-26 | token 用量字段缺失 | 各家字段名/单位不一致或压根没有 | 缺失时显示「—」，不得拿 0 冒充 | 5 |
| E-27 | 同一任务重试或续跑 | 任务被重派 | 进度只展示最近一次运行，历史运行可展开；两次运行的事件不混成一条流 | 5 |
| E-28 | DeepSeek Harness 的破坏性变更 | 已查清它有 `--profile headless` / `--profile acp` / 官方 Python SDK，但官方声明会有破坏性变更且 `SESSION_FORMAT_VERSION = 0` | 通过「通用 ACP 适配器」的预置注册表项接入，**版本钉死**；启用前必须先跑探测 + 冒烟任务，通过才允许进批次派发；握手失败即标该 agent 不可用并移出选择器，绝不影响其余四家与整批推进 | 6, 35 |
| E-29 | agent 没装或版本过老 | 不在 PATH，或版本没有 --output-format | 启动时探测并在 UI 置灰该 agent 且写明缺什么，不得等到派发那一刻才失败 | 6 |
| E-30 | 模型名无权限或已改名 | 从配置文件读到的模型实际不可用 | 派发前做一次轻量校验并明确指向「模型配置问题」；绝不做跨家模型等价映射，每个 agent 只用它自己配置里读到的名字 | 6 |
| E-31 | 同一 agent 并发多任务 | 一个 agent 被同时派多个任务 | 每任务独立 session 与独立工作区（grok 用自带 --worktree，其余用 git worktree 兜底），并设每 agent 并发上限 | 6 |
| E-32 | 桌面端会话不共享 | claude 桌面端若不与 CLI 共享会话（codex 已确认共享，claude 未确认） | 调度器自己的会话查看界面即唯一入口，必须做完整，不得指望用户「去 GUI 里看」 | 6 |

## 第 2 批（决策 7-12：派发管线）

| 编号 | 场景 | 触发条件 | 期望行为 | 相关决策 |
|---|---|---|---|---|
| E-33 | 设了覆盖模型的任务重试 | 任务上设过模型覆盖，随后重派 | 沿用该任务上次实际使用的模型（记在任务快照里），不回落 agent 默认；只有用户显式清除覆盖才回落 | 7 |
| E-34 | 任务切换执行 agent | 用户把某任务从 codex 改派给 grok | 清空该任务的模型覆盖并回落新 agent 的默认；模型下拉只列当前 agent 的清单，不允许跨家残留 | 7 |
| E-35 | 从未设过默认模型 | 首次使用，agent 默认模型为空 | 不阻塞派发，派发时不传 `--model`，UI 标注「跟随 agent 配置」，而不是弹窗强制先去设置 | 7 |
| E-36 | 模型名在派发时已失效 | 用户在别处删了该模型，或手填了不存在的名字 | 不做前置白名单校验（清单本就可能不全），直接透传；失败后标「派发失败·模型无效」并原样展示 agent 报错，该任务不占用批次窗口名额 | 7, 8 |
| E-37 | 环境变量与命令行参数冲突 | claude 的 `env.ANTHROPIC_MODEL` 等覆盖与 `--model` 同时存在 | 派发时在子进程环境里清掉这类变量，并从 NDJSON 首帧读回 agent 自报的实际模型，UI 显示「实际使用：X」，与所选不一致时高亮 | 7 |
| E-38 | 列模型命令超时或失败 | `grok models` / `pi --list-models` / codex app-server `model/list` 超过注册表 `modelsLive.timeoutMs`（出厂默认 5 秒，codex 出厂 10 秒，按家可覆盖）或退出码非 0 | 清单降级为「配置文件当前值 + 内置别名 + 该 agent 历史用过的模型 + 手填」，`isComplete:false`、`liveFailure` 说明原因，UI 标注「清单可能不全」，绝不阻塞派发（决策 120） | 8 |
| E-39 | 列模型输出格式变化 | 厂商改了输出格式，解析不了 | 同 E-38 降级，且把原始 stdout 保留在可展开日志里，不静默吞掉 | 8 |
| E-40 | agent 未安装或不在 PATH | 探测不到可执行文件 | 该 agent 标「未检测到」，不列清单且不可被选为派发目标；已指向它的任务在派发前就报错，而不是跑到一半失败 | 8 |
| E-41 | 模型清单最终为空 | 配置无值、命令不可用、用户未手填 | 允许留空表示「跟随 agent 自身配置」，派发时不传 `--model`，而不是禁止使用该 agent | 8 |
| E-42 | 模型名含 shell 元字符 | 模型名带空格、引号或 `;` `&` 之类 | 参数以数组形式传给子进程，任何情况下不拼接 shell 字符串 | 8 |
| E-43 | 配置文件缺失或损坏 | TOML/JSON 语法错误，或文件不存在 | 视为「无配置值」，不崩溃；UI 提示解析失败并给出文件绝对路径 | 8 |
| E-44 | 用户在别处切换了模型 | 外部修改了 agent 配置文件后回到设置页 | 每次打开设置页按文件 mtime 重读，不长期缓存 | 8 |
| E-45 | 别名与完整模型 ID 并存 | claude 的 `opus`/`sonnet` 别名与完整 ID 同时出现在清单 | 两者都原样透传，不做别名映射、不做去重合并 | 8 |
| E-46 | 同批任务抢同一批文件 | 同批内两个任务的 `taskPaths` 有交集 | 后者排队，等前者到达「已落地」（不是「已退出」）才起；worktree 隔离不作为放行理由 | 9 |
| E-47 | 单 agent 并发满但窗口有空位 | 某 agent 达到并发上限，整体窗口未满 | 空位让给其他 agent 的任务，不空转等待 | 9 |
| E-48 | 窗口数为 1 或依赖纯串行 | 依赖链无法并行 | 退化为逐个派，不报错、不提示「无法并行」 | 9 |
| E-49 | 批内某任务失败或审查未过 | 一批中个别任务卡住 | 不阻塞同批其他无依赖任务；但下一批的启动条件是本批全部「已落地」，未解决的任务会让整批停在那里等人 | 9 |
| E-50 | 批次执行途中文档变了 | 执行期间 `data.tasks` 指纹变化 | 已派任务继续用快照跑完，后续派发自动暂停并要人确认新文档，绝不热改在途任务 | 9, 13 |
| E-51 | daemon 重启或断电恢复 | 进程死后重新拉起，部分会话可能还活着 | 按持久化状态续跑；会话还活着就重挂，已死的标「中断」等人决定；任何情况下不自动重派（防止重复写同一批文件） | 9 |
| E-52 | 并发瓶颈来源不明 | 实际并发数低于用户预期 | 实际并发取 min(窗口数, 每 agent 上限, 用户设定)，UI 显示这三者中哪一个成了瓶颈；用户可向下调，向上超过窗口数需显式解锁并提示后果 | 9 |
| E-53 | 落地闸门在本版不可用 | 因决策 12 不执行提交/PR | 落地闸门固定为「等我确认」且置灰；UI 只暴露派发前与审查后两个可切换开关，第三个仅作状态展示 | 10, 12 |
| E-54 | 闸门等确认而人长时间不来 | 夜间无人值守，任务停在闸门前 | 该任务释放并发额度、不占窗口，其他任务继续；仅其下游依赖任务被动等待 | 10 |
| E-55 | 全自动下审查反复判 rework | 审查连续不通过 | 重试上限默认 2 次，超限转「待人确认」，不无限自动改 | 10 |
| E-56 | 执行中途改闸门开关 | 用户在批次跑到一半时改设置 | 只影响尚未到达该闸门的任务；已在闸门前等待的任务按新设置立即放行或继续等，不需重启批次 | 10 |
| E-57 | 两端同时点确认 | 手机与桌面同时对同一闸门确认 | 幂等，第二次提示「已由另一端确认」，不产生两次派发 | 10 |
| E-58 | 手机曾退到后台 | 无离线推送（决策 3），确认项在后台期间产生 | 重回前台拉未读列表；等待中的确认项不过期、不自动放行 | 10, 3 |
| E-59 | 用户点「打回」 | 审查后人工判定需返工 | 必须能附一句话意见，该意见复用 rework 通路回灌原会话 | 10, 11 |
| E-60 | 机械检查覆盖有限 | 项目未在文档里声明 build/test 命令 | 机械检查分两层：零配置层（diff 非空、退出码、会话无致命错误、验收标准关键词命中）恒执行；项目命令层留空则跳过并在 UI 明示「机械检查覆盖有限」 | 11 |
| E-61 | 退出码 0 但没有改动 | agent 正常退出但 diff 为空 | 机械层直接判失败（呼应 E-23），不派审查 agent，标「无改动」转人 | 11, 5 |
| E-62 | 审查 agent 崩溃或超时 | 审查这一步自身失败 | 既不算 pass 也不算 fail，标「审查未完成」转人工；任何情况下不默认放行 | 11 |
| E-63 | 审查输出不合三态 | 输出不是 pass/rework/doc-issue | 解析失败按「审查未完成」处理并保留原文，不猜测语义 | 11 |
| E-64 | 审查判 doc-issue | 问题在文档本身而非代码 | 停止对该任务的自动 rework（改文档是上游技能的事），汇总意见给用户，不让 agent 反复改代码 | 11 |
| E-65 | diff 超出审查模型上下文 | 一次改了上百个文件 | 给 diff stat 全量 + 验收标准命中文件的全文，其余折叠，并在结论标注「基于部分 diff」 | 11 |
| E-66 | build/test 命令挂死 | 测试进程不退出 | 默认 10 分钟超时后杀掉，标「机械检查超时」转人，不重试 | 11 |
| E-67 | 机械检查跑错目录 | 检查命令的执行位置 | 恒为该任务的 worktree，绝不在用户主工作区跑，避免污染 | 11, 12 |
| E-68 | rework 后改动反而回退 | 回灌意见后 diff 缩小或撤回 | 仍走同一套检查，重试计数 +1，达上限转人 | 11 |
| E-69 | 目标目录不是 git 仓库 | 无法建 worktree | 不静默降级到共享目录并行，改为强制串行（一次只跑一个任务）并明确告知原因 | 12 |
| E-70 | 下游 base 缺上游产出 | 上游任务改动尚未被用户落地进当前 HEAD 就要派下游 | 拒绝派发并说明「下游 base 缺上游产出」，同时提供「以上游任务分支为 base 建 worktree」的显式选项；绝不默默从旧 HEAD 起 | 12 |
| E-71 | 分支名冲突 | 要建的分支名已存在 | 自动加序号后缀（任务号-2），不复用、不强制覆盖已有分支 | 12 |
| E-72 | 主工作区有未提交改动 | 用户自己手上有活没提交 | 建 worktree 不受影响也不去 stash 用户的东西；diff 基线取 worktree 自身 HEAD，不与主工作区混算 | 12 |
| E-73 | 任务结束后 worktree 处置 | 任务跑完，worktree 仍在磁盘 | 默认保留（人还要用它落地），只在用户显式点「清理」时 `worktree remove`；已清理过的任务重试需重建 | 12 |
| E-74 | 用户要落地 | 任务已验收，准备合并 | 提供只读落地清单（worktree 绝对路径、分支名、diff 摘要、可一键复制的 `gh stack` 命令文本），复制而不执行 | 12 |
| E-75 | agent 自己动了远端 | agent 在 worktree 里自行 `git commit` 或 `git push` | 不拦截其行为（拦不住），但 push 到远端的事件要在任务详情里高亮标注，让人知道发生了什么 | 12 |
| E-76 | worktree 创建失败 | 磁盘不足或权限问题 | 该任务标「派发失败·工作区不可用」，释放窗口名额给下一个任务，不让整批卡死 | 12 |

## 第 3 批（决策 13-17：数据生命周期与界面）
