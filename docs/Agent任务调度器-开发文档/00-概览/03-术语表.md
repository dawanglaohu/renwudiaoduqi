# 术语表

一个概念一个名字。这张表是**命名的唯一依据**——代码、界面文案、
其余 23 节里出现同一个概念时，必须用这里的名字，不许另起一个。

第三列是代码中的标识符。命名风格见 `06-系统架构与模块划分.md` 的共用约定小节。

| 术语 | 含义 | 代码中对应 |
|---|---|---|
| 任务交接台 | `unattended-run` 技能产出的 HTML 阅读器里的一个页面，任务的**来源**。它自己那套手工三态已被本产品接管 | `handoffConsole`（仅出现在文档接入模块的注释与文案里） |
| 文档源 | 阅读器生成的 `docs-data.js`，形如 `window.DOCS = 〈JSON〉;`，是本产品唯一的任务真相源 | `DocsSource` / `docsDataPath` |
| 内容指纹 | 按任务 ID 排序，对 `[id, dispatch[id].contractHash]` 列表算出的哈希；涵盖任务增删、范围、条款与提示词变化，不能用 `generated` 或 mtime 判变更 | `contentFingerprint` |
| 派发快照 | 派发那一刻把任务的 input / output / accept 三段逐字存进运行记录的副本，验收以它为准 | `DispatchSnapshot` |
| 任务 | 从文档读入的一条待办，带 ID、模块、依赖、验收标准、边界编号、涉及路径 | `Task` / `taskId` |
| 批次 | 交接台按依赖分好的一组任务，本产品按批推进 | `Batch` / `batchNo` |
| 并行窗口 | 交接台算出的「同时可开几个会话」的数量，本产品据此限流 | `laneCount` |
| 路径冲突 | 两个任务的 `taskPaths` 有交集。**依赖只保证逻辑不冲突，worktree 挡不住两个任务改同一个文件** | `pathClash` |
| agent | 被派活的那个外部 AI coding 程序（codex / claude / pi / grok，将来还有别的） | `Agent` / `agentId` |
| 字母组 | agent 身份的视觉与文本形式，两个字符的短码（`CX` / `CL` / `PI` / `GK`），**用户可编辑、需唯一**。agent 身份**永不使用色相** | `monogram` |
| agent 注册表 | agent 的接入配置。**分两层**：数据层可配（路径、参数模板、并发上限、默认模型），代码层不可配（参数转义、解析器） | `AgentRegistry` / `agentRegistryEntry` |
| 适配器种类 | 注册表里的具名枚举，决定这个 agent 走哪条通道：`native` 或 `generic-acp`。**切换是改一行数据，不是改代码** | `adapterKind` |
| 能力位 | 某个 agent 支不支持某项操作（可否回话、可否恢复会话、可否列举历史、**是否提供流式过程事件**）。UI **按能力位灰掉按钮**，而不是点了才报错。`hasStreamingEvents` 为假的 agent（目前只有 dsh）不显示逐步展开，也**不伪造中间事件**（E-253） | `AgentCapabilities` |
| 版本指纹探测 | 派发前跑一次探测命令核对这个可执行文件到底是哪个产品。**每个 agent 都有此字段**，不是给 grok 打的补丁 | `versionFingerprint` / `probeAgent()` |
| 权限档 | 本产品对 agent 权限的**三档抽象**：只读 / 工作区可写 / 无限制。映射到各家原始参数的表在代码层，用户不直填厂商参数 | `PermissionTier`（`readOnly` / `workspaceWrite` / `unrestricted`） |
| 运行 | 一个任务的一次执行。同一个任务可以有多次运行（重派、换 agent） | `Run` / `runId` |
| 运行流 | 一次运行的事件时间轴，界面上的主角 | `runStream` |
| 运行轨 | 运行流左侧那根贯穿全高的 2px 竖线，**用形状先于颜色表达状态**。本产品的签名元素 | `spine` |
| 已退出 | agent 进程结束了。**退出码为 0 不等于活干完了** | `exited` |
| 已落地 | 这次运行的产出被判定合格，即**已验收**。**只能由自动审查或人确认进入，绝不由退出码推定**；不表示分支已合进 HEAD，那是另一个派生标记 | `landed` |
| 停滞检测 | 按「最后一条事件距今多久」判断是不是卡住。**仍在输出只标弱提示，完全无事件才升级告警** | `stallDetector` |
| 失联 | daemon 重启后重新 attach 不上、但进程可能还活着的运行状态。**不等于失败** | `orphaned` |
| 闸门 | 流程里三个可各自设「自动」或「等我确认」的关卡：**派发前 / 审查后 / 落地前**。落地闸门可设自动，默认「等我确认」；自动只表示审查 pass 后直接标已验收，产品仍不执行任何 git 操作 | `Gate` / `gateMode` |
| 半自动 | 预设组合：派发自动 + 审查后等确认 | `presetSemiAuto` |
| 自动 | 预设组合：派发自动 + 审查 pass 自动进下一个。**审查非 pass 一律停** | `presetAuto` |
| 机械检查 | 审查的第一级，本地命令，**不烧 agent**。分零配置层（diff 非空、退出码、验收关键词命中）与项目命令层（build / test） | `mechanicalCheck` |
| 审查 agent | 审查的第二级，机械检查通过后才派。**固定只读档**，跑的是交接台生成的审查提示词 | `reviewRun` |
| 审查判定 | 三态：`pass` / `rework` / `doc-issue`。**解析不出三态一律按「审查未完成」转人工，绝不默认放行** | `ReviewVerdict` |
| 回灌 | 把 rework 意见送回原会话让它改。原会话已结束但能恢复就恢复后回灌；不能续接就改派返工运行。三种方式都计入同一个重试计数，自动上限 2 次 | `reworkInjection` |
| 回话 | 人从两端向正在跑的会话发一句话或点批准。受能力位约束 | `replyToRun()` |
| 工作区 | 为每个任务开的独立 git worktree。**产品只建与读，不提交不推送** | `Worktree` / `worktreePath` |
| 落地清单 | 任务验收后给出的只读信息：worktree 路径、分支名、diff 摘要、**可一键复制的 `gh stack` 命令文本**与一行可复制的 `build_docs.py --landed 〈ID〉` 命令。复制而不执行 | `LandingChecklist` |
| 进 HEAD | 一次已验收运行的分支是否已被人合进当前 HEAD。由 daemon 用 `git merge-base --is-ancestor` 判定，失败时回退「分支相对 HEAD 无差异」；是任务行上的**派生标记**，不是运行状态，也不由产品去合 | `isInHead` / `inHeadMethod` |
| 收口 | 一批任务全部已验收且分支都进了 HEAD 之后，对整批做的一次运行：跑测试 → 逐任务复核 → 查接缝 → 修复 → 八段回报。提示词取自文档导出的 `dispatchBatches[层号].wrapup`，产品外层包装覆盖其中的提交／推送／PR／合并步骤 | `wrapup` / `kind='wrapup'` |
| 收口报告 | 收口运行最终文本里的固定八段 `BATCH_SUMMARY / TESTS / BUGS / FIXED / NOT_FIXED / SUSPECT / RECORD / NEXT`。解析不出八段按「收口未完成」转人，**不猜** | `WrapupReport` / `parseWrapupReport()` |
| 收口裁定 | 由报告内容算出的 `clean` / `fixed` / `open`，**不是 agent 自报**：有未修的 BUGS、NOT_FIXED 或 TESTS 失败即 `open` | `WrapupVerdict` / `deriveWrapupVerdict()` |
| 修复运行 | 收口发现的开放项按「涉及 〈任务ID〉」分组后，给每个任务派的一次实施运行：`origin='wrapup-fix'`，在收口工作区上继续，走正常审查 | `origin: 'wrapup-fix'` |
| 返工运行 | 审查判 rework 但原会话不能回灌也不能恢复时，为同一任务新开的一次实施运行：`origin='rework'`，在原 worktree 与分支上继续，提示词自包含 | `origin: 'rework'` |
| 返工文本 | 从审查输出里提取的返工指令：`rework` 围栏块优先，其次 `REWORK` 段条目。解析不出结构时保留原文并标「未结构化」，人可一键投进实施会话 | `reworkText` / `rework_text` |
| 批次树 | 左栏与任务列表页里按批次折叠的任务清单。折叠默认值与「能否收口」由 daemon 给字段，前端不算；`batch.advanced` 到达时自动展开该批，只增不减 | `BatchTree` / `defaultExpanded` |
| 呼吸灯 | 批次树里正在执行任务行上的 8px 圆点 + 1.6s 呼吸环，与运行轨当前步共用 `--pulse` 与同一 keyframe，算同一种动画。只对机器在干活的状态呼吸 | `PulseDot` / `--pulse` |
| 配对码 | 一次性、≤60 秒有效的短码，用来把一台设备加进来 | `pairingCode` |
| 设备令牌 | 配对后换发的长期凭据，**每设备一枚、可单独吊销** | `deviceToken` / `actorDeviceId` |
| 事件信封 | SSE 推给客户端的统一外壳，带单调递增 id、topic、taskId | `EventEnvelope` / `eventId` |
| 重放窗口 | 服务端保留的最近约 5000 条事件，供断线客户端按 `Last-Event-ID` 补齐 | `replayBuffer` |
| 偏移索引 | 日志正文文件里每个片段的字节位置，支撑分段回读 | `offsetIndex` |
| 厂商会话文件 | agent 自己写在自己目录下的会话记录。**只读引用，不拷贝、不删改** | `vendorSessionRef` |
| ACP | Agent Client Protocol。方向是**外部驱动 → agent**（与 MCP 相反）。本产品用它作**内部事件词汇**，并作为第 5/6 个 agent 的接入槽 | `acp` / `SessionUpdate` |
| 边界编号 | `E-01` 起的连续编号，贯穿边界表、任务验收标准与覆盖矩阵 | `edgeId` |
| 语域 | 界面的设计语言类别。本产品是 **工作台 + 代理层** | （仅文档概念） |
