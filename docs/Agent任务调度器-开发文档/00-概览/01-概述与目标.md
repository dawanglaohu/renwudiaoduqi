# 概述与目标

## 这个东西是什么

一个**跑在本机的 AI coding agent 任务调度器**。

它读一份由 `unattended-run` 技能产出的开发文档，从中取出已经拆好、带依赖关系的任务清单，
把任务**按批次派发**给装在这台电脑上的多个不同厂商的 AI coding agent 去写代码，
然后盯着它们干活、自动跑审查、把需要人拍板的地方摆到人面前。

它由三部分组成：一个**常驻服务（daemon）**、一个**桌面端**、一个**手机端**。
daemon 是真正干活的那个；两个端只是它的两副面孔，共用同一套界面代码。

## 解决的是什么问题

这份开发文档的阅读器里本来就有一个「任务交接台」。它的现状是：

- 人点一下「复制实现提示词」，把提示词粘到 codex 之类的 agent 里
- agent 干完，人再点「复制审查提示词」，拿回来给审查者
- 通过了，人手工走 `gh stack` 落地
- 任务状态靠**人手工点击**在「待派 / 进行中 / 已落地」三态之间切换，存在浏览器 localStorage 里

也就是说，**交接台知道该干什么，但对 agent 实际在干什么一无所知**。
中间「复制 → 粘贴 → 等 → 回来看一眼 → 再复制」的全过程都是人肉的，
人必须守在电脑前，而且一次只顾得上一两个。

这个调度器接管的正是这一段：把人肉的复制粘贴变成自动派发，
把手工点击的三态变成**从 agent 真实输出观测到的状态**，
并且让人在离开电脑之后仍然能看见进度、能回话、能叫停。

## 谁用它

**一个人**——写这份开发文档的那个开发者本人。单人单机，不是团队产品，没有账号体系。

他的典型一天：

1. 选一份开发文档，选这一批要干的任务
2. 给每个 agent 选好默认模型
3. 点派发，然后**长时间盯着几个运行流**
4. agent 中途问「要不要装这个依赖」，他回一句
5. 某个 agent 跑偏了，他把它中止，换一个 agent 重派
6. 审查自动跑完，他看结论、点放行
7. 夜里派一批活，第二天早上看结果；白天出门时用手机看进度

### 补充需求 2026-09-12：把一个任务的全部阶段连成一条流水线，会话跟任务走

用户 2026-09-12 的补充需求把上面那条线换了一个观看角度：不再按「一次运行一条流」看，
而是按「一个任务一条流水线」看，并把三件事定死——泳道数就是窗口数、会话跟任务走、
查 bug 与收口各有一个开关。下表逐句对应到任务；编号 87–94 是用户本人直接裁定的，其余由代理用户裁决。

| 原话分段 | 对应能力 | 任务 | 决策 |
|---|---|---|---|
| 「把按任务派出的任务窗口连成一条线更直观的查看到任务，实施 --- 审查 --- 审查结果反喂 ---- 实施窗口 --- 实施模型修复审查结果后在通知审查窗口继续审查」 | **任务流水线泳道**：一条泳道同一时刻只放一个任务，该任务从实施到落地的全部阶段（实施、审查、反喂、返工实施、再审、查 bug）都在这条泳道里连成一条阶段链，返工画成审查节点回到实施节点的回环并标第 N 轮，点任一阶段节点打开该阶段的运行详情。**审查结果反喂进同一个实施会话**；实施方修完再次退出后，产品通知**同一个审查会话**续审第 N+1 轮、只核上一轮的 R 条目；agent 不支持续接或会话已撑爆时新开审查会话并带上一轮 REWORK 条目原文。泳道分配由 daemon 算出随快照与事件下发，前端不算 | **M7-T7、M8-T8、M9-T21（新）**；M7-T2、M9-T9（改） | 87、89、90 |

## 什么算做完

第一版满足下面全部八条，才算交付：

1. 选一份真实的开发文档，任务、依赖、批次、验收标准、边界编号全部正确读入。
2. 给 codex / claude / pi / grok / DeepSeek Harness 五个 agent 各派出一个真实任务，五个都能跑起来并正常结束。
3. 任务状态能从 agent 的真实输出观测得出，且「已退出」与「已落地」不会被混为一谈。
4. 能在任务详情里翻完一个几十万字的会话，桌面端与手机端都打得开、不卡死。
5. 一整批任务能在半自动模式下跑完：自动派发 → 自动机械检查 → 自动 agent 审查 → 停在人面前等放行。
   开启自动落地闸门后，同一批还能继续走完：审查 pass 自动标已验收 → 人把分支合进 HEAD → 自动派收口运行 →
   收口发现的问题自动派成修复运行 → 收口 clean/fixed 后批次标 done、下一批解锁。
   并行窗口设为 4 时运行甲板呈现 4 条任务流水线泳道；其中一条走完 实施 → 审查 rework → 反喂同一实施会话 →
   再审续接同一审查会话 → 查 bug（开关开启时）→ 已验收 → 会话归档 → 泳道补位下一个任务且会话引用全新。
6. 手机与电脑完成配对后，能在手机上看到进度、收到完成通知、回一句话、中止一个任务。
7. 派发过的任务都能给出落地清单，人照着它用 `gh stack` 就能落地。
8. Windows、macOS、Linux 的 daemon、平台路径/进程/自启适配器与 Tauri 桌面壳全部通过发布门禁；
   三个平台各有人工启动记录，缺任一层都不算该平台受支持。

## 明确的边界

- **不替用户提交、push、建 PR 或合并**——见 `02-非目标.md`。
- **不自建任何服务器**，会话内容与源码不出本机。
- **不改动开发文档目录里的任何文件**，包括不回写交接台的状态。
