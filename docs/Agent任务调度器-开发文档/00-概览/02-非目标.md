# 非目标

这一节是后续所有范围争论的裁决依据。分两类：**用户明确没要的**，
以及**权衡过之后决定不做的**——后者带「考虑过，因为 X 放弃」，三个月后有人问「为什么没有导出」时，这就是答案。

## 一、不替用户动 git 的写操作

**不做**：自动 `git commit`、`git push`、建 PR、合并 PR、删分支。

**考虑过，因为这个放弃**：技能原本的落地流程确实是 `gh stack` 一任务一层，
把它自动化看起来很自然。但**用户的原话与补充需求里，「git」「分支」「PR」一个字都没出现**。
自动 push 或合并一旦搞错，破坏的是用户真实仓库的历史，且不可逆。
按可逆优先，只做读与隔离：建 worktree、读 diff。
落地时给一份**可一键复制的 `gh stack` 命令文本**，复制而不执行（决策 12，E-74）。

配套的硬约束：运行环境**不注入任何 git 凭据、不启用 credential helper**，
使得即便 agent 自己想推远端，也会在凭据层失败（E-138）。

## 二、不自建中继服务器，不做离线推送

**不做**：自己的云端服务、账号体系、APNs / FCM 离线推送。

**考虑过，因为这个放弃**：产品顾问提的候选 C-02 就是「中枢服务与推送链路」，估 8-14 人天。
要传输的是**源码和 agent 对话内容**，自建中继等于把这份数据的责任揽到产品身上；
而原话通篇没提账号、云端或外网（决策 2）。

直接后果，必须在界面上说清楚而不是假装没有：
**手机端只保证 app 在前台或保持连接时的本地通知 + 重开后的未读列表**。
app 被系统杀掉期间发生的事，只能等下次打开时补拉（E-11、E-147）。
想在外网用，用户自己接 Tailscale / frp 之类的隧道——产品不代劳，但**鉴权默认开启**，
代码里不允许存在「局域网内免鉴权」的分支（E-08）。

## 三、不回写任务交接台

**不做**：把调度器里的任务状态同步回阅读器的那套手工三态。

**考虑过，因为这个放弃**：候选 C-05 原本包含双向同步。但阅读器是 `file://` 打开的离线单文件，
外部程序写不进它的 localStorage；硬要绕，等于把稳定性押在一个**会被脚本反复重新生成的
DOM 结构**上。而原话第 2 点是「可以**进入任务调度中**查看」——用户自己把观看位置定在了调度器。

所以调度器是任务状态的**唯一权威**，首次接管一份文档时用一条横幅说明
「阅读器里那套手工三态不再有效」（决策 14，E-84）。

## 四、不做多人协作

**不做**：账号、角色、权限矩阵、任务认领、协作冲突处理。

**理由**：原话通篇第一人称「我需要」，agent 全装在「电脑桌面端」这一台机器上，
没有任何多人痕迹；且与「不自建服务器」直接矛盾（决策 20）。

只做**设备配对**：一次性配对码换长期令牌，每台设备一枚、可单独吊销。
但运行记录里保留 `actorDeviceId`（谁派的、谁中止的、谁回的话），
将来真要加人，历史数据不必迁移（E-128）。

## 五、不承诺未经验证的平台版本、发行版与架构

**不做**：把“能编译”扩写成所有系统版本、Linux 发行版和 CPU 架构都已获得同等级支持；
也不把未签名、未公证的 macOS 构建验证件当成正式分发包。

Windows、macOS、Linux 的 daemon、路径与子进程、Tauri 桌面壳均进入第一版范围
（决策 53）。支持声明只跟随 Node.js 22、Tauri v2 的官方平台下限、三平台 CI
与实际发布资产：Windows 10/11；macOS 11 及以上；Linux 以 CI 已验证发行版和依赖基线为准，
其他发行版属于尽力兼容（决策 54，E-257～E-260）。平台相关逻辑仍只允许存在于
单一 `platform` 模块，三套适配器缺一套都不能宣称完成（E-132）。

这次范围变化**只扩展电脑桌面宿主**。手机端第一版仍做 Android；
“支持 macOS”不等于新增 iOS 手机端，iOS 仍不在本版范围内。

## 六、不为 dsh 伪造流式过程，也不接它的 ACP 通道

**dsh 已提进第一版**（2026-09-01 翻案，见决策 35）——原来的非目标「第一版不接
DeepSeek Harness」作废。它现在是第五家一等 agent，走 `--profile headless` 接入。
但接进来的同时划两条线：

**不做之一：不给 dsh 造流式事件。** 它只有 headless 通道，跑完才吐最后一条
assistant 文本，中途**没有任何可归一化的过程事件**。能力位 `hasStreamingEvents`
置假，运行轨对它只显示「已派发 → 运行中 → 完成/失败」三段，逐步耗时退化成整段耗时。
**宁可显示得少，也不假装有过程**——伪造的中间步骤会让人以为能看见它在干什么，
而那正是本产品最不该骗人的地方（E-253）。

**不做之二：不接 `--profile acp`。** 2026-09-01 实测确认这条通道**不存在**：
`@deepseek-ai/dsh-acp` 在 `0.1.0-rc.6` / `0.1.1-rc.2` / `0.1.2-alpha.3` 各版本
**均无 `dsh.bundle` 字段**（它是库，不是可启动的 profile 层，对照 `dsh-headless`
有 `bundle.patch`）；`latest` 标签指向的 `0.0.1-rc.1` 依赖 npm 上不存在的
`@deepseek-ai/dsh-type-meta`（404），根本装不上。实际启动 `--profile acp` 的结果是
零输出直接退出。**文档里任何 `dsh --profile acp` 的写法都已作废。**

通用 ACP 适配器仍然产出，但它的服务对象改成**第 6 家及以后**，不再是 dsh（M4-T12）。

## 七、不做文档的版本管理

**不做**：文档 diff 可视化、三方合并、多版本历史留存、任务自动作废、自动重派。

**考虑过，因为这个放弃**：文档确实会被反复重新生成，验收标准会变。
但派发时已经把 input / output / accept 三段**快照**进任务记录（决策 4），
真正缺的只是「拿快照和当前文档比一次并打标」，增量 0.5-1 人天。
做成完整的版本子系统是用大炮打蚊子（决策 13）。

保留的最小实现：三个布尔标记（任务已消失 / 验收标准已变 / 提示词已变）+ 角标 + 一条横幅。
**在途运行一律不打断。**

## 九、补充需求 2026-09-10 里权衡后不做的

这一段对应 01 节「把派发 → 审查 → 返工 → 收口 → 标记接成一条线」。
补充需求裁决时产品顾问提的五条候选（收口 agent 取值、批次等人出口、收口结果的界面落位、
跨批修复的状态语义、人工撤回）**全部采纳**（决策 74～78），所以这里没有被否的候选；
下面是各岔路口上被否掉的那一边。

- **不建 PR 评论通道来传返工指令**。原话把「返工提示词或分支 PR 评论」并列，但产品既然自己派了审查运行，
  审查输出本来就在产品手里，再经 GitHub 绕一圈只会多一个要轮询的外部真相源。
  返工文本直接从审查输出解析（决策 59）；PR 评论只在人工流程留档。
- **不新增 `accepted` 运行状态**。「已验收」与「已合入」的区别用 `landed` 的语义写明 + 任务行的
  「进 HEAD」派生标记表达（决策 64）。加状态会动已落地的 M6-T1 状态机白名单，还要给 11 节形状表加形状。
- **不读取、不显示文档侧的 `batchRecords`**（人工收口流程写进仓库的记录）。调度器是收口记录的唯一权威
  （决策 14 的精神，决策 73）；两处各管各的，将来要显示只是 M3 多读一个只读键。
- **收口运行不做「只报告不修」**（决策 69）。用户裁定的收口五步里就有「修复」，且权限档已定为 `workspaceWrite`。
- **修复运行不跳过审查**（决策 70）。不为 `origin=wrapup-fix` 加任何审查例外分支，第 2 轮收口是整体复验不是替代。
- **批次树不默认展开「下一批」**（决策 71）。原话是「正在派发的」；要加只是 daemon 多给一个字段。
- **收口轮次上限不做成设置项**（决策 72）。`WRAPUP_AUTO_MAX_ROUNDS = 2` 是代码常量，与 E-55 同一个数。
- **不加 `POST /batches/:id/close` 人工标 done 的路由**（决策 81）。`done` 只由收口裁定写；人工出口统一为批次级收口闸门。
- **不加文档级「收口用哪个 agent」设置面**（决策 80）。从本批最晚已验收的实施运行推导，手动触发时可覆盖。
- **不用哨兵任务行或去掉 CHECK 来回避迁移重建**（决策 84）。整表重建按 SQLite 官方步骤做，例外只有一个首行标记。
- **窄屏 narrow 档不为批次树另开「批次」抽屉按钮**（决策 86）。沿用 1100–1180 档已有的左栏抽屉。

## 十、补充需求 2026-09-12 里权衡后不做的

这一段对应 01 节「把一个任务的全部阶段连成一条流水线，会话跟任务走」。下面是各岔路口上被否掉的那一边。

- **不把泳道绑定到 agent、进程或某一次运行上**。泳道 = 窗口槽位，一条泳道同一时刻只放一个任务，任务的全部阶段共用这个槽位（决策 87）。
  「一条泳道一个 agent」会让窗口数与 agent 数纠缠；「一次运行一条泳道」会让一个任务在甲板上散成三四条流——两种画法都否。
- **不复用会话跑新任务**（决策 88）。同一泳道换下一个任务时，上一任务的实施／审查／查 bug 会话一律结束归档，
  哪怕 agent 支持续接、哪怕上一任务只跑了五分钟。原话把理由写死了：「防止上下文污染与上下文撑爆」。省下的一次冷启动不值一次串台。
- **不用 PR 评论传审查轮次**（决策 89）。第 N+1 轮由产品直接投递到同一审查会话；决策 59 已否掉 PR 评论通道，这里不重开。
- **不新增运行状态、不新增批次状态**。查 bug 阶段用 `kind='bughunt'` 的独立运行承载，落在既有 13 个状态上；
  收口手动模式用既有 `canWrapup` 与 `POST /batches/:id/wrapup`，不加第八个批次状态（决策 91、92）。
- **不为泳道数另开设置项**（决策 87）。泳道数就是决策 48 的并行窗口数，一个数两处用。
- **两个开关不存前端本地**（决策 93）。与闸门设置同一手法，全走 daemon 的 `settings` 表，换设备开关值一致。
- **查 bug 阶段默认关**（决策 91）。它多一次完整 agent 运行，单人自用按需打开。
- **不给查 bug 加手动触发端点**（决策 103）。查 bug 是开关决定走不走的阶段，不是可按任务点的动作；交接台那颗「查 bug」按钮就是既有的定点查法。
- **查 bug 运行不 commit**（决策 101）。与收口、返工新运行同一禁令表：改动留在工作区，产品出落地清单；再审由产品直接喂 diff，提交这一步在产品里没有用途。
- **等人期间不归档会话、但让出泳道**（决策 99）。归档只在任务终态；等人时占着泳道会让整夜停在 4 个任务上，与 E-54 相悖。

## 十一、补充需求 2026-09-12（二）里权衡后不做的

这一段对应 01 节「一次指派贯穿整条流水线，登录态与清单来源说清楚」。下面是各岔路口上被否掉的那一边。

- **不读、不缓存、不解析任何 agent 的凭据文件**（决策 108，重申 14 节）。`~/.codex/auth.json`、`~/.claude/.credentials.json`、`~/.pi/agent/auth.json` 一个字节都不碰；
  pi 的 `auth print-api-key` / `print-bearer-token` 这类输出凭据的子命令在注册表校验层直接拒绝。登录态只能来自 agent 自己的状态命令。
- **登录态不当派发闸门**（决策 108）。`logged_out` 与 `unknown` 都能派，派发失败按 E-36 原样展示 agent 报错。本机实测 claude `loggedIn:false` 却正常工作——把它当闸门就会拦住能用的 agent。
- **不定时轮询登录态**（决策 115）。只在启动、手动刷新、可用性事件与「运行零产出退出」四个点探测；每 10 分钟起四个子进程去碰网络，换来的只是「早几分钟知道过期」。
- **不为 claude 猜一条列模型命令**（决策 109）。它没有，`live` 来源就是缺失；用内置别名表补位并标注「实际可用由登录账号决定」。
- **别名表不放代码层**（决策 113）。`builtinModels` 是注册表数据层的通用字段，Anthropic 加别名改数据不改代码；不做按 agentId 的 claude 特判。
- **history 来源不按文档分**（决策 114）。按 agent 全局从 `runs` 派生一条 SQL，不建 `agent_model_history` 表——双写会漂移，查询频率是「打开面板」级。
- **收口不固定用某一家 agent**（决策 116，重申决策 80）。默认跟随本批最后落地任务的指派，用户要固定才在 pipeline 设置里改。
- **阶段覆盖不开第二个入口**（决策 107）。只有 pipeline 设置里的「审查覆盖」一处；M7-T2 原「设置里可改为指定其他 agent／模型」收进同一处。返工、查 bug、收口修复三个阶段**逐字**读任务指派快照，没有回落。
- **不按 stderr 文本猜「未登录」**（决策 118）。零产出退出的判定只看事件结构（首条内容事件前退出），与 E-330 撑爆判定同一条规则；按家维护 stderr 特征表会随厂商改版漂移（E-39 同类）。
- **不手填厂商原值的思考强度**（决策 117）。三档抽象不扩；`xhigh` 这类超出三档的值只能来自配置文件当前值或 live 取值域，手填即 `E_VALIDATION`。
- **指派快照不随配置文件回写**（决策 107，E-343）。用户事后改了 `config.toml` 的模型，在途任务与已派快照一律不动。

## 八、不做的其他

- **不解析每个 agent 的私有 tool 调用语义**来推算细粒度进度。只取四家都能给的通用信号，
  「改了多少文件」用 git diff 得出（决策 5）。跨家做深度语义解析，适配成本按 agent 个数乘。
- **不做跨厂商的模型等价映射**（把「强模型」映射到各家的旗舰）。
  每个 agent 只用它自己配置里读到的模型名，原样透传（E-30、E-45）。
- **不拷贝厂商的会话文件**。只读引用 + 记路径与偏移；删了它们会破坏 `claude --resume`
  之类的原生续接能力（E-96）。
- **不提供「自动放行网络访问」的开关**。agent 要联网装依赖时一律拦下转人决策（E-134）。
- **不做插画式空态**。空态直接是「选文档 → 选批次 → 选模型 → 派发」的四步引导（E-108）。
