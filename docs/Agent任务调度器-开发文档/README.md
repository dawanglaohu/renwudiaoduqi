# Agent 任务调度器 · 开发文档

一个跑在本机的 **AI coding agent 任务调度器**：读一份 `unattended-run` 技能产出的开发文档，
把里面拆好的任务**按批次派发**给装在这台电脑上的多个不同厂商的 agent
（codex / claude / pi / grok / DeepSeek Harness）去写代码，
然后盯着它们干活、自动跑审查、把该人拍板的地方摆到人面前。
Windows、macOS、Linux 桌面端与 Android 手机端**共用同一套界面**。

## 怎么读

**双击 `index.html`。** 不需要起服务器、不需要联网——
数据走 `script` 标签的 `src` 加载，所有图都是手写 SVG，拷到内网机器上照样打得开。

阅读器左侧有两个入口在 24 节之上：

- **概览** —— 模块地图、任务依赖图、边界覆盖矩阵、演进与决策时间线、并行窗口甘特图
- **⚡ 任务交接台**（或直接按 `H`）—— 派活的地方，见下方「怎么开工」

左上角的搜索框覆盖任务、边界、端点与术语。

**另一种读法**：用 Obsidian「以库的形式打开文件夹」打开本目录，
`_MOC.md` 是入口，`图谱/` 下每个模块、任务、边界都是一张互相链接的原子笔记。

            16 可观测性 · 17 测试策略
04-执行/    18 部署与运维 · 19 模块任务拆分 · 20 里程碑与交付顺序 · 21 风险与未决事项
05-附录/    22 决策记录 · 23 变更记录 · 24 参考资料

index.html      阅读器（脚本生成，不要手改）
docs-data.js    阅读器的数据（脚本生成，不要手改）
_MOC.md         知识库总索引（脚本生成，不要手改）
图谱/           模块 / 任务 / 边界的原子笔记（脚本生成；只有「实施沉淀」等保护块可写）

**`_run/` 是内部台账，不是交付物**——它不进阅读器，也不进 Obsidian 图谱。

## 怎么开工

1. 打开阅读器，左侧点 **「⚡ 任务交接台」**（或按 `H`）
2. 页面顶部先告诉你**这个项目值得开几个窗口、每个窗口按什么顺序做哪些任务**，
   每条泳道下有「复制这个窗口的任务序列」
3. 下面是按批次的任务列表。**先点开工提示词**发给写代码的模型，然后从那里逐个派发——
   页面会实时算出**此刻能并行开几个会话**，每派出一个，剩下的重新算
4. 模型交回来后，复制**同一行的审查提示词**拿去审；`pass` 才落地
5. 落地走 `gh stack`，**一个任务一层**

第一批能立刻并行开工的任务：**M1-T1 一个**（它是唯一无依赖的任务，
其余九个模块全部依赖 M1）。这不是排布得不好——是 M1 的 spawn 基座本来就是所有适配器的地基。
从第二批起并行度才起来。

## 这份文档的几个特别之处

- **271 条边界情况**，每一条都是「什么条件下 → 期望什么行为」；
  268 条由任务直接覆盖，E-250～E-252 是已登记的文档维护约束
- **57 条决策全部由代理用户裁决**，其中 **15 条驳回了最初提问**——
  那 15 行是最该复核的
- **本机实测与平台 runner 分工明确**：五个 agent 的程序化入口以现有实测为基线，

## 改了文档之后

**文档是唯一事实源。** 改完必须按顺序重跑三个脚本，否则派出去的提示词还是旧的：

```bash
python _run/review.py . --json > _run/review.json && python _run/build_docs.py . && python _run/build_vault.py .
```
