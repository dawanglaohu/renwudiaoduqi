# 前端架构

本节只管 **M9 客户端界面**与它到 **M10 壳**的边界。
两端共用同一套 Web UI，由 daemon 静态托管**同一份产物**。

唯一的检验标准：**这句话能不能直接写进代码。**

## 目录结构

```
packages/web/
├─ index.html            唯一 HTML 入口，只有 #root 与 module script
│                        禁止内联样式、禁止任何 CDN link、禁止第二个 html
├─ vite.config.ts        base:'./'、两个 define 注入版本、manualChunks 只三块
├─ tailwind.config.ts    只声明 content 扫描与「4px 栅格/圆角 → var(--sp-*)/var(--r*)」映射
│                        禁止在此写任何 hex 或字体栈
├─ scripts/              check-contrast.ts（解析 tokens.css 算 WCAG 配对，决策 30 的机检下限）
│                        check-forbidden.ts（禁令 grep）。由 pnpm -w check 调用
├─ public/fonts/         自托管 woff2，只放实际用到的字重（E-176）
│                        禁止放中文字体、禁止图标字体
└─ src/
   ├─ main.tsx           唯一 createRoot：探测壳 → 取令牌 → 解析 baseUrl → 挂 app-root
   │                     此文件零业务代码
   ├─ styles/            tokens.css（全仓库唯一允许出现颜色字面量的文件）、base.css、fonts.css
   ├─ app/               应用骨架：app-root / routes（唯一路由表）/ route-guard
   │                     error-boundary / theme-provider / connect-failed / app-version
   ├─ pages/             7 个页面装配件，一页一文件。只拼栏位，不取数
   ├─ features/          容器层，按产品概念分目录：run-deck / task-list / run-detail
   │                     landing / settings-agents / settings-devices / pairing
   │                     唯一允许调 src/api 与订阅 store 的层
   ├─ components/        展示层纯 props 组件：spine / status-badge / gate-card / stream-row
   │                     stream-column / virtual-rows / log-lines / thumb-bar
   │                     offline-banner / batch-summary-bar / empty-onboarding
   ├─ ui/                shadcn CLI 生成物原样放 ui/shadcn/，其上二次封装放 ui/*.tsx
   │                     此目录禁止出现任何业务词
   ├─ hooks/             纯 UI 行为：use-density-tier / use-follow-tail / use-hotkey / use-copy
   │                     禁止 import src/api、src/store、src/features
   ├─ store/             zustand 四个 slice：connection / ui-prefs / selection / notice
   │                     禁止放事件流与日志正文
   ├─ api/               唯一 fetch 出口：http-client / sse-client / event-bus / base-url
   │                     resource-cache / cache-keys / cache-invalidation + 按域的调用函数

   │                     界面中文字符串只从这里来
   ├─ lib/               纯函数，无 React、不 import 以上任何目录。每个文件配同名 .test.ts

```

**禁令**：全树禁止 `index.ts`（含 `ui/shadcn/`）；禁止新增第二个 `src` 顶层目录
（要加先回文档改本节）；禁止 `src/utils/`、`src/helpers/`、`src/common/`、`src/types/`
这四个名字（分别归 lib / lib / 不存在 / `@agsched/shared`）；
禁止在 web 包内出现 daemon 或壳的源码。

## 组件分层

四层，调用方向**单向** `pages → features → components/ui`，任何反向 import 一律打回。

| 层 | 能做什么 | 禁止 |
|---|---|---|
| **pages/** | 只做装配：读路由参数、决定栏位骨架、把 feature 容器摆进去 | **禁止 import `src/api` 与 `src/store`**；禁止在此写业务状态判定 |
| **features/** | 唯一允许 import `src/api`、订阅 store、订阅 event-bus 的一层。每域固定两类文件：`use-〈域〉.ts`（取数与订阅，返回拼好的 props）与 `〈域〉-container.tsx` | 只允许写 grid/flex/gap 类名，**禁止在容器里写颜色、字号、圆角** |
| **components/** | 纯函数组件，props in / callback out | **禁止 import `src/api`、`src/store`、`src/features`、`src/shell`**；禁止内部 `useEffect` 取数；`useState` 只许用于纯本地 UI |
| **ui/** | shadcn 生成物与二次封装 | **禁止出现 task / run / agent / gate / batch / spine 任何业务词**——出现即说明该组件属于 components 层 |

### 「界面不含业务判定」逐条落地

前端**不得计算**：能否派发、能否回话、闸门是否放行、审查是否通过、批次四个数字、
实际并发瓶颈是谁、模型清单是否可用。
一律读 daemon 快照/事件里的字段（`capabilities.canReply`、`gates[]`、`state`、
`summary.*`、`bottleneck`）；**字段缺失就显示「—」（E-26），不得用前端逻辑补齐**。

**只开两个例外：**

1. **呈现派生**——断点档位、密度档、是否贴底、虚拟窗口区间、分组排序
2. **停止的乐观呈现**——按停止键后**一帧内**写 `local-intent`
   （`{runId, kind:'stopping', atStep}`，存在 event-bus 旁的 mutable Map，**不写进 `run.state`**）；
   渲染层把 intent 与服务端状态取并集显示「你在第 N/M 步停止」；
   服务端事件到达即清 intent，接口失败则清 intent + 顶栏横幅回滚。
   这样 11 节 avoid#11（不许等回包才变样）与 E-157（状态以回流事件为准）同时成立。

**每条运行流一个 ErrorBoundary**——一条流渲染崩了不许带走另外四条（E-106）。

## 组件库

shadcn CLI 的生成物**原样落 `src/ui/shadcn/` 且不手改**（升级时可整目录重生成）。
二次封装放 `src/ui/〈name〉.tsx`，只做三件事：绑 token（`bg-[var(--needs)]` 形式）、
锁死高度/圆角（`--h-btn` / `--r-sm`）、收敛变体枚举。

button 变体只有四个：`primary | stop | danger | ghost`——
`--glow` 只允许出现在 primary，且**全页只许出现一个 primary**。

**业务组件禁止直接 import `@radix-ui/*`**。唯一允许 import radix 的目录是 `src/ui/`；
确需未封装的原语时，先在 `src/ui/` 加封装文件再用。
允许的传递依赖只有 shadcn 自带的四个：`class-variance-authority`、`clsx`、
`tailwind-merge`、`lucide-react`。**禁止再引第五个 UI / 图标 / 动画库**
（含 framer-motion、headlessui、react-icons）。

lucide **只许用于非语义图标**（chevron、copy、x、external-link）。
**9 个运行状态与 6 个步骤类型的字形一律来自 `lib/spine-shape.ts` 的形状枚举表**，
禁止用 lucide 或 emoji 表达状态（E-110 / E-172）。

**四个产品特有组件全部在展示层**：

- `spine.tsx`——props `segments: SpineSegment[]`；**必须渲染到容器全高含未来虚线段**；
  内部不允许知道 `runId`
- `status-badge.tsx`——props `state` / `text`；字形 + 文字 + 颜色三层，**颜色永远是第三层**
- `gate-card.tsx`——props 四段内容 + 三个 callback；
  **禁止 import dialog、禁止 `createPortal`**，只能被 stream 的时间轴渲染（E-109）
- `stream-row.tsx`——30px 折叠 / 44px 触摸，网格 `20px minmax(0,1fr) auto 16px`

`src/ui/dialog.tsx` 的用途**白名单只有四项**：停止二次确认、拒绝二次确认、
吊销设备、手机原样重跑确认（E-124）。**审批不许用 dialog。**

虚拟滚动只允许经 `components/virtual-rows.tsx` 一个包装使用 TanStack Virtual，
**禁止第二处直接 import `@tanstack/react-virtual`**。

**样式规则**：颜色/字号/间距/圆角一律 `var(--token)`；
**只有 `styles/tokens.css` 的 `:root` 与 `[data-theme=...]` 两个块允许颜色字面量**
（E-170 由 `check-forbidden.ts` 机检）；深浅两套 token **必须同 PR 内成对新增**（E-173）；
主题走 `html` 元素上的 `data-theme` 属性，默认 `system`，
**禁止锁根字号、禁止 `text-size-adjust:none`、禁止 zoom**（E-15）；
全页只允许 spine 当前步一处连续动画，其余 transition ≤ `var(--dur)`。

## 路由

路由表唯一文件 `src/app/routes.tsx`，导出 `ROUTE_PATHS` 与 `ROUTES` 两个 `as const` 常量。
**自写 hash 路由**（决策 44），约 80 行：`hashchange` 监听 + 路径表 + 单段 `:param` 匹配 + `navigateTo()`。

**必须 hash 模式**，七条平铺路径：
`#/`（运行甲板）、`#/tasks`、`#/run/:runId`、`#/landing/:taskId`、
`#/settings/agents`、`#/settings/devices`、`#/pair`。

hash 而非 history 是**硬取值**：同一份产物要被 daemon 的 `/`、Tauri 的 `tauri://localhost`、
Capacitor 的 `https://localhost` 三处加载，history 模式要三份 fallback 配置；
且壳的通知深链只需把 `#/run/〈id〉` 交给 WebView。

鉴权守卫**只在 `src/app/route-guard.tsx` 一处**，只判一件事：内存里有没有设备令牌，
没有就强制渲染 `#/pair`。`#/pair` 是唯一免守卫路由。
**禁止在页面或容器里再判一次登录态；禁止做角色/权限**（单人自用，没有角色）。

懒加载切点只有两处：`settings/*` 与 `landing` 用 `React.lazy` + 一个共享 Suspense 兜底。
**运行甲板、任务列表、运行详情必须留在主 chunk**（首屏就是它们）。

手机窄屏三栏切换**不新增路由**，走 hash query `#/?pane=tasks|stream|detail`——
这样 Android 返回键天然回上一 pane，无需壳新增能力。
**禁止用 `mobilePane` 之类 store 字段做 pane 切换；禁止 pushState 手写历史。**

**禁令**：禁止路由参数以外的 URL 状态（筛选、展开、密度都不进 URL）；
禁止嵌套路由与 loader/action 模式；
禁止在组件内写 `location.hash = ...`（一律用 `navigateTo()`）。

## 状态管理

分三处，各有硬边界。

### 一、高频事件流不进 zustand，也不进 React state

`src/api/event-bus.ts` 持一个**非响应式** 以 `runId` 为键的 `RunStreamBuffer` 表。
Buffer 是定长环形数组 `STREAM_BUFFER_MAX = 600`（桌面 5 流上限 3000 条，
超出丢头部，历史一律回 daemon 拉，E-142 / E-143）。

- SSE 回调只做「push 进环 + 标脏」，**不 `setState`**
- flush 由 `requestAnimationFrame` 合并且最小间隔 `FLUSH_INTERVAL_MS = 80`
  （落在 E-144 的 50–100ms 区间）
- 一次 flush 每条脏流只 bump 一个整数 `version`
- 组件用 `useSyncExternalStore(subscribe(runId), () => buffer.version)` 订阅，
  **`getSnapshot` 只返回 version 数字，禁止返回数组或对象**——
  否则每帧引用变化 = 全量重渲染
- 渲染时再从 buffer 读切片

每流一个订阅集合 → **只有该流重渲染，与事件条数无关**。

### 二、zustand 只放四类低频状态

| slice | 内容 |
|---|---|
| `connection-store` | `status`（取值 `online` \| `reconnecting` \| `offline`）、`lastSyncedAt`、`lastEventId`、`needsPairing`——E-12 的顶栏与派发禁用**只读它** |
| `ui-prefs-store` | `theme`（`system` \| `dark` \| `light`）、`densityTier`、`expandedRunId`、`lastDocId` |
| `selection-store` | 当前文档/批次/勾选任务/派发草稿（agent + model + 权限档） |
| `notice-store` | 横幅列表、未读计数——**计数值来自服务端快照，前端只存不算** |

### 三、服务端态缓存

不引第三个库，用 `src/api/resource-cache.ts` 一个极小实现
（`read(key, fetcher)` / `invalidate(prefix)` / `refetchAll()`），key 由 `cache-keys.ts` 集中生成。

**失效只由事件驱动**：`cache-invalidation.ts` 一张常量表把事件 kind 映射到要失效的 key 前缀
（如 `run.started` → `['runs','batches']`）；断线重连后调一次 `refetchAll()`（E-12 恢复补拉）。
**禁止轮询、禁止时间型 stale 窗口**——局域网单人，事件是权威。

日志正文独立：`features/run-detail/log-window.ts` 只保留
`LOG_SEGMENT_MAX_IN_MEMORY = 6` 段（每段 ≤2000 行），滚出窗口即丢弃并可重拉（E-98 / E-143）。

**持久化白名单是一张显式键表，表外的任何 `localStorage.setItem` 由 `check-forbidden.ts` 判失败：**

| 键 | 存储 | 内容 | 何时写 |
|---|---|---|---|
| `agsched.ui.v1` | localStorage | `theme` / `densityTier` / `lastDocId` | 用户改设置时（手写 30 行读写，**不用 persist 中间件**） |
| `agsched.host` | localStorage | 用户手填的 daemon 地址（E-06 的兜底） | 手填时 |
| `agsched.token` | **sessionStorage** | 设备令牌，**仅在无壳的浏览器模式下**（决策 45） | 配对成功时；有壳时以壳的安全存储为唯一真相源并清掉会话副本（E-227） |

**令牌绝不进 localStorage**；
**事件、运行、日志、快照一律不持久化**（E-01 重开从 daemon 全量拉）。

**明确禁止**：把 SSE 事件数组塞进 zustand；把全量日志放进 store 或 DOM；
用 Context 传高频数据；在 store 里存派生值（`isBusy` / `pendingCount` 一律 selector 或服务端字段）；
selector 里返回新对象/数组字面量（一律返回原子值，多字段用 `useShallow`）；
一份数据在两处缓存；在组件里写 `useEffect(() => { fetch(...) })`。

## API 客户端层

**唯一 fetch 出口** `src/api/http-client.ts`，导出 `createHttpClient({getBaseUrl, getToken})`。
**除 `http-client.ts` 与 `sse-client.ts` 外，全仓库禁止出现 `fetch(`**（`check-forbidden.ts` 机检）。

**baseUrl 运行时发现**，`src/api/base-url.ts` 三级顺序：
壳注入的 `hostHint()` → 用户手填（存 localStorage `agsched.host`，E-06 的兜底）→
`location.origin`（浏览器直连天然正确）。
**禁止构建期常量、禁止任何 `import.meta.env` 里出现 host/port。**

**拦截器只做四件事，不做第五件**：注入 `Authorization: Bearer 〈deviceToken〉`
（令牌从 shell 异步取一次后缓存在模块内变量，**不进 store**）、
注入 `X-Agsched-Client: web/〈VITE_APP_VERSION〉`（E-14）、
写请求注入 `X-Idempotency-Key`（`crypto.randomUUID()`，重试复用同一个，E-126 / E-177）、
把响应规格化成 `ApiError`。
**禁止在拦截器里做重定向、弹窗、刷新令牌、上报。**

超时用 AbortController，常量表 `TIMEOUT_MS = {get: 8000, post: 15000, probe: 30000}`。

**重试策略**：只重试 GET，且只在网络错误与 502/503/504，最多 2 次，退避 300/900ms。
**POST 一律不自动重试**（停止与重跑带幂等键，但只由用户点「重试」触发）。

错误冒出方式：http-client 抛 `ApiError {code, message, requestId, status?, details?}`；
**容器层只 catch 一次并交给 `useErrorSink()`，展示层不 catch**；
**前端一律按 `error.code` 分支**，状态码只用于「要不要重试 / 要不要重新配对」。

类型只从 `@agsched/shared` 来：DTO 从 `shared/src/api/*`，method 与 path 从
`shared/src/api/routes.ts` 常量表取（`ROUTES.runsList`）。
**禁止前端定义任何与后端对应的 DTO、禁止 URL 字符串字面量、禁止 `as any` 绕过、
禁止 zod 之类运行时校验层。**

### SSE 客户端（唯一实现 `src/api/sse-client.ts`）

`createSseClient({getUrl, getToken, onEnvelope, onStatus})`，
用 `fetch(url, {headers: {Authorization, 'Last-Event-ID': cursor}, signal})`
+ `res.body.getReader()` + TextDecoder，自己按 `\n\n` 分帧、解析 `id:` / `event:` / `data:`、
**忽略 `:` 心跳注释**（E-154）。

- **全应用只开一条连接**，多流复用，按信封的 `taskId` / `runId` 分派到 event-bus。
  **禁止每流一条 SSE。**
- `Last-Event-ID` 存模块内变量，每次 flush 同步写 `connection-store.lastEventId`；
  **壳可用时另写 shell 存储**（E-147：被系统杀后重开补拉）
- 重连指数退避 `SSE_BACKOFF_MS = [1000,2000,4000,8000,15000]` 且加 ±20% 抖动，
  封顶 15s（E-158）；`document.visibilityState === 'hidden'` 时暂停重连、回前台立即试一次
- **60s 内未收到任何字节（含心跳）判死连接**，主动 abort 重连
- 收到 401 立即**停止退避循环**并置 `needsPairing`（E-156）
- 收到「重放窗口过期」码则清空本地 buffer → REST 拉快照 → 用快照里的最新 eventId 续接（E-153）

**写请求（派发/停止/回话/审批/重跑）一律不拿响应体改状态**，
只用它判「请求是否被接受」，状态等回流事件（E-157）。

## 工具层

`src/lib/` 只放纯函数——不 import React、不 import `src` 下任何其他目录
（只允许 `import type` from `@agsched/shared`）、无模块级副作用、同输入同输出。

已定清单：`format-duration` / `format-bytes` /
`format-token-count`（**无数据返回 `'—'`，禁止返回 0**，E-26）/ `format-time-ago` /
**`spine-shape`（9 状态 + 6 步骤类型 → 形状枚举的唯一映射表，E-159 / E-172 的落点）** /
`ansi-collapse`（剥 ANSI + 折叠重复刷新行，E-101）/
`truncate-line`（按宽度截断 + 返回可展开标记，E-102）/ `group-by-batch` /
`monogram`（两字符短码的展示规则，**不做推导**，E-183）/
`class-names`（clsx + tailwind-merge 的唯一出口）。

**什么不算工具**：带 React 的（→ `src/hooks/`）、读 store 的（→ features）、
发请求的（→ api）、只有一个组件用的私有函数（就近写在该组件文件底部，
**不许为它单开一个 lib 文件**）、任何业务判定（→ daemon）、任何「通用 helper 大杂烩」。

**硬规则**：`src/lib/` 是**唯一强制单测**的目录，每个文件必须有同名 `.test.ts`
（其余目录不强制，单人项目不做覆盖率门槛）；
禁止 `lib/utils.ts` / `lib/misc.ts` / `lib/common.ts` 这类名字；
禁止 lib 里出现 `document` / `window`（除 `class-names` 外都应可在 node 环境跑测试）。

## 错误呈现

对着共用约定的错误体系，分三种形态，各有唯一落点。

| 形态 | 判定 | 呈现 |
|---|---|---|
| **字段错** | `E_VALIDATION` 且 `details.field` 存在 | 只渲染在对应输入框下方 12px 提示 + `aria-invalid` + `aria-describedby`，文案写清原因与改法。**不弹 toast、不整页替换、不清空已填内容** |
| **业务错** | 其余 code | **就地 inline notice**，位置固定为「触发它的那块面板」——派发面板内、该流头部下、该任务卡内；`--down-soft` 底 + 具名动作。同一 code 重复到达只更新计数不叠加。**禁止 toast 堆叠、禁止 alert、禁止升级成整页** |
| **整页失败** | **只有两种** | ① 未配对（`E_UNAUTHORIZED` / 401）→ 路由到 `#/pair`；② 首屏快照拉不到 → `connect-failed.tsx` 单屏，显示当前 baseUrl、原始 requestId、三个动作（重试 / 改地址 / 壳内额外「启动调度服务」），文案按 E-04 写「电脑上的调度服务未启动」而不是「连接超时」 |

**运行流已经在屏上时，任何错误都不得整页替换**——否则等于遮住证据并谎称全停（与 E-109 同精神）。

**401 只在两处处理**（http-client 与 sse-client），动作固定：
清内存令牌 → `connection-store.setNeedsPairing()` → 跳 `#/pair` → SSE 停止退避循环。
**禁止自动重试、禁止静默刷新令牌**（没有 refresh 机制），禁止在业务代码里再判 401。

ErrorBoundary 三层：app 根（兜白屏，显示 requestId 与「重载」）、每页一个、**每条运行流一个**。

文案唯一来源 `src/i18n/error-messages.ts`（`code → 中文`，缺键回落显示原始 code + requestId）。
**禁止组件内出现中文错误字符串**；daemon 的英文 `message` 只允许出现在
可展开的「技术详情」块里并附一键复制 requestId；**禁止把英文 message 当用户文案直接显示**。

**其他禁令**：禁止 `catch` 后只 `console.error` 就吞掉；禁止按 HTTP 状态码写业务分支；
禁止把 code 写成裸字符串（一律 `ERROR_CODES.E_XXX` 的键引用）；禁止「重试」按钮无限自动点自己。

## 环境变量

客户端可见前缀 `VITE_`，**全集只有两个**：
`VITE_APP_VERSION`（进 `X-Agsched-Client` 与设置页版本校验，E-14）、
`VITE_BUILD_ID`（短 hash，只给「关于」与故障复述用）。
两者由 `vite.config.ts` 的 `define` 从 `package.json` 与 git 短 hash 注入。

**仓库里不得出现 `.env` / `.env.example` / `.env.local`**（`check-forbidden.ts` 机检）。
`import.meta.env` **只允许出现在 `src/app/app-version.ts` 一个文件**，其余从它 import。

daemon 地址是**运行时发现**的，令牌是运行时从壳安全存储取的：
**禁止出现 `VITE_API_BASE_URL` / `VITE_PORT` / `VITE_TOKEN` 之类任何变量**；
**禁止 `AGSCHED_` 前缀出现在 web 包任何文件**（那是 daemon 独占）。
禁止把端口、局域网 IP、配对码、任意 token、daemon 数据目录绝对路径写进源码或构建配置——
诊断信息一律由 API 返回后显示，不由前端拼。

## 构建产物

`vite.config.ts` 取值：

- **`base: './'`（必须相对）**——同一份产物要被 daemon 的 `/`、Tauri 的 `tauri://localhost`、
  Capacitor 的 `https://localhost` 三处加载，绝对 `/assets/…` 在壳里必然 404
- `build.outDir: 'dist'`、`build.target: 'es2020'`（Android WebView 保守档，
  **禁止 `@vitejs/plugin-legacy`**）
- `build.sourcemap: 'hidden'`、`minify: 'esbuild'`、`assetsInlineLimit: 4096`

产物固定在 `packages/web/dist/`：daemon 用 `@fastify/static` 指向它，
Tauri 的 `frontendDist` 指向它，Capacitor 的 `webDir` 同步一份拷贝——
**三处消费同一次构建，禁止为壳单独打第二份产物、禁止两个壳产物不同**。

代码分割手工三块 `manualChunks`：`vendor-react`、
`vendor-ui`（radix、cva、clsx、tailwind-merge、lucide、@tanstack/react-virtual）、
其余业务进主 chunk。**禁止按组件粒度 lazy、禁止动态 import 拼字符串路径。**

字体：只自托管拉丁字重（Public Sans 400/500/600、Commit Mono 400/500/600），
`@font-face` 集中在 `styles/fonts.css`，`font-display: swap`；
**中文一律走系统栈兜底，禁止打包任何中文字体**；
回退时列宽用 `ch` 计算，禁止依赖具体字体度量的写死像素宽（E-174）。

**禁令**：任何 CDN / 外链（E-175）、任何 CSS-in-JS 运行时、`vite-plugin-pwa`（PWA 已被否决）、
任何 analytics / Sentry / 自动上报、把 `dist` 提交进仓库。

**验收侧**：`pnpm -w check` 必须串起 web 包的 `tsc --noEmit`、`biome ci`、`vitest run`、
`scripts/check-contrast.ts`、`scripts/check-forbidden.ts`。
后者至少覆盖**八条 grep 禁令**：靛紫 hex（`#6366f1` / `#5E6AD2` / `#635BFF` / `#7C3AED`）、
tokens.css 之外的颜色字面量、api 之外的 `fetch(`、任意 `index.ts`、
`ui/` 之外的 `@radix-ui`、`shell/` 之外的 `__TAURI` / `Capacitor`、
甲板容器上的 `overflow-x`、`.env` 文件存在。

## 壳边界（本项目特有）

边界只有一句：**Web UI 通过唯一桥接文件访问壳，壳不知道任何业务概念。**

契约类型放 `packages/shared/src/shell/bridge-contract.ts`（纯类型，无依赖，
两个壳包与 web 都 import 它）；web 侧唯一实现 `src/shell/shell-bridge.ts`。
**除 `src/shell/` 两个文件外，全仓库禁止出现 `window.__TAURI_INTERNALS__`、
`@tauri-apps/*`、`window.Capacitor`、`@capacitor/*`。**

**能力只有三件，禁止加第四件**（要加先回文档改 M10 范围）：

```ts
tokenStore.get / set / clear
notify({ title, body, deepLink })
hostHint()
```

另带两个只读位：`platform: 'browser' | 'tauri' | 'capacitor'` 与
`capabilities: { hasSecureStorage, hasNativeNotification }`。

**能力探测**写法固定：`detect-shell.ts` 同步读两个全局——
`window.__TAURI_INTERNALS__` 存在 → `tauri`；
`window.Capacitor?.isNativePlatform?.() === true` → `capacitor`；否则 `browser`。
结果在模块加载时冻结成 `const SHELL`，运行期不再变。
**禁止用 userAgent 判定、禁止 try/catch 试探 API、禁止在渲染中重复探测。**

**降级（E-200：无壳时桌面浏览器直连必须可用）**：

- `tokenStore` 无壳时落 **`sessionStorage`**（键 `agsched.token`）并在顶栏常驻一条 12px 提示
  「浏览器模式 · 关闭标签后需重新配对」（决策 45）——
  **禁止无壳时把令牌写 localStorage 或 IndexedDB**
- `notify` 无壳时：已授权则用 Notification API，未授权则退化为 notice-store 未读徽标 +
  `document.title` 前缀 `(N)`；**权限最多请求一次，禁止 alert，禁止在浏览器里假装有原生通知**
- `hostHint()` 无壳时返回 `location.origin`

UI 侧对能力位的用法**只有一种**：按 `capabilities` **灰掉或隐藏对应入口并写明原因**
（与 E-117 的 agent 能力位同一手法），**禁止点了才报错**。
这条同样管住 `hasStreamingEvents`：该位为假时（第一版只有 dsh）运行轨只渲染
「已派发 → 运行中 → 完成/失败」三段、逐步耗时退化为整段耗时，
**不得为了让界面好看而合成中间步骤**（E-253）。

允许 import `src/shell/` 的目录只有三处：`src/app/`、`src/api/`（取令牌与 hostHint）、
`src/features/settings-devices/`；**pages 与 components 一律禁止**。

**壳侧禁令**：壳内禁止出现 task / run / gate / batch / agent 任何业务词；
禁止解析事件、禁止调 daemon 业务 API、禁止内嵌重试或调度策略
（E-146：连不上时壳只给「启动 daemon」按钮，逻辑仍在 Web UI 里）；
通知点击一律以 `#/run/〈runId〉` 形式交给 WebView，**不做自定义 IPC 传业务数据**。
