# UI

## 语域判定（register）

**`product` → 工作台（workbench）+ 代理层（AI agent 控制台）。**

判定依据：用户反复做的是**同一件事**——派活 → 盯着 agent 干 → 审查 → 放行，
而不是围着一批业务对象转，所以是**工作台不是后台**；
而屏幕上最重要的东西是**多个 agent 会话的实时运行流**，人在旁边看并决定放不放行，
所以在工作台之上再叠一层**代理层**。

这条判定是下面每一个 UI 取值的前提（决策 17）。它带来一个必须写死的推论：

> **主角是运行流，不是图表。** 批次汇总只能是四个数字 + 一条比例条，
> **不能升格成饼图或环形图**——那会把主角挤下去。

代理层意味着失败模式既不是「看不懂」也不是「填不完」，而是**不可信**。
四个问题必须在没人问的时候就一直答着：
*它现在在干什么 / 它凭什么这么干 / 这花了我多少 / 我怎么让它停*。
本节所有取值都能回溯到这四问之一；回溯不到的就是装饰，而在这个语域里装饰读作**心虚**。

> ✅ **本方向已于 2026-09-01 经用户目视确认**（R-03 已关闭）。
> 确认依据是一屏真页（运行甲板，覆盖运行中／等你／部分完成／失败／已停止全套运行轨形态），
> 用户看后表示「ui 风格可以确认了」。真页同时实测验证了下面这张 token 表：
> **深浅两套各 18 组对比度全部 ≥4.5:1，`:root` 外颜色字面量 0 处，连续动画确认只有心跳点一处。**
>
> 按决策 28，方向仍**只以 token 层表达**，日后要改代价依旧 ≤ 改一个 token 文件（E-159）——
> **这条不因已确认而放松**。另注意确认的是方向不是像素：真页用的是回退字体栈，
> 自托管的 Commit Mono 与 Public Sans 到位后字形质感会有差异（M9-T1 的实现范围）。

## 三个刻度（dials）

| dial | 值 | 理由 |
|---|---|---|
| **SOUL** | **6** | 这是他自己的台子，中性到没有性格就没有第二次打开的理由；但用户对观感一个字没说，性格只能从**语义系统**里长出来，不能从造型里编。定 6 不定 7，是因为 7 要求造型也带态度，而那部分没有依据 |
| **SPECTACLE** | **2** | 全页只允许**一种连续动画**：呼吸环（1.6s，只动 opacity 与 scale），出现在运行轨当前步与批次树执行行两处，共用同一个 keyframe 与 `--pulse`。它回答「是卡死了还是在跑」，是唯一挣得来的动效。其余全是反馈动效（≤180ms） |
| **DENSITY** | **8** | 预设是 6–7，这里**主动上调一档**，原因写死在需求里：桌面端要 5 条以上运行流并置。5 栏 × 每栏可读 = 密度不是审美选择而是硬约束 |

## 视觉方向

### 先于选色的两条分配规则

这块屏幕的颜色槽位极度紧张：**9 个运行状态 + 4 个并发 agent + 语义 up/down**。
所以先定分配规则，再选 hex：

1. **色相全部留给「运行状态」。agent 身份一律用字母组（monogram）+ 中性 ink 片，永不给厂商配色**（决策 33）。
   否则屏幕上是 4 个厂商色 + 9 个状态色 = 13 种颜色，谁都区分不出来。
2. **暖色 = 要你；冷绿 = 机器自理；红 = 坏了；没有颜色 = 不用管。**
   机器正常推进占 90% 的像素，它**不配一个色相**。
   这条规则一句话可验：*屏幕上出现任何暖色，就等于有东西在等人*。

由此派生的一条判定：`partial`（部分完成 / 审查有保留）**并入暖色而不是自开一档**——
在本产品里「有保留」本质就是「要人看一眼」。它靠**形状**（半填方块 ◧）
和文案（`部分完成 · 跳过 81 条`）与「等你」区分，**绝不渲染成绿色**。

底色选**偏冷的石墨**而不是暖石：暖底会把琥珀吃掉，而「要你」必须是全屏最响的东西。
冷绿（「不用管」）反而与底同族，天然后退——**平静的颜色在墙里，警报的颜色不在**。

### 字体

三个角色，两个字族。论点：**机器的声音用一种字（等宽），应用自己的壳用另一种（无衬线）**。
display 角色由等宽承担——屏幕上所有大号数字都是机器产出的（步数、耗时、token、批次计数），
让它们天然 tabular 对齐，5 栏并置时数字列不会跳。

| 角色 | 字族 | 梯级 |
|---|---|---|
| **display** | `Commit Mono` 600，`letter-spacing:-.02em`，`tabular-nums` | **26px**（批次汇总四个大数）· **20px**（每流头部 run id / 已耗时） |
| **body / UI** | `Public Sans` | 16 / **14（默认）** / 13（密集）/ 12（meta、chip）/ 11（微标签，克制）。字重 400 / 500 / 600，**标题不用 700 以上** |
| **utility（等宽）** | `Commit Mono` 400·500·600 | **12.5px**（日志行，`line-height:1.5`）· 12px（tool payload、diff）· 11.5px（手机端日志） |

**两者都自托管**（决策 31）：Windows WebView2、macOS/Linux WebKit 与 Android WebView
的等宽字形并不一致，走系统栈会让同一份日志在不同宿主上列宽与数字对齐漂移。
只打包实际用到的字重（E-176）。

一条硬规则：**日志 / 运行流 / 文件路径 / 命令 / diff 一律等宽，UI 标签一律不用等宽**
（「等宽 = 技术感」是懒惰）。

### 布局概念

**控制塔**——左边是编队（批次·队列·派发），中间是 N 条竖直的**任务流水线泳道**并排铺开（N = 并行窗口设置，1–6，决策 87），
证据和审批就地长在各自那条泳道里。一条泳道同一时刻只放一个任务，从实施到落地的全部阶段都在这条泳道里走完；
收口运行也占一条普通泳道（M9-T20 既有设计，不重画）。

**显式拒绝的壳**：常见的「rail | stream | aside」三栏。它假设同时只有一条 live run，
右侧 aside 是全局的；本产品同时有 5 条以上，一个全局 aside 必然要么只服务其中一条
（其余四条的证据无处可去），要么变成会打断别人的模态。
**所以右栏被拆散、下沉进每条泳道内部**——这也正好兑现 E-109「审批卡就地插在该流的时间轴里」。

栅格与圆角基准：

```
4px 栅格：4 / 8 / 12 / 16 / 20 / 24 / 32
--r: 14px（卡片/泳道）  --r-sm: 9px（按钮/输入/徽标）  --r-lg: 20px（抽屉/表单外壳）
```

圆角比常见后台低一档：320px 宽的栏并 5 条时，20px 圆角会吃掉角上的内容并读作消费级；
**14 / 9 / 20 读作仪表。锁死这一套，不混用。**

### 签名元素：「运行轨」（the spine）——一个任务的流水线

每条泳道左侧那根**贯穿全高的 2px 竖线**。它不是装饰性分隔线，**它就是状态条本身**。
补充需求 2026-09-12 起，轨贯穿的不再是「一次运行」而是**一个任务的整条流水线**（决策 90）：
阶段（实施、审查、返工实施、再审、查 bug、落地）是轨上的**大节点**，阶段内的步骤仍是串在轨上的**小节点**；
返工画成**审查节点回到实施节点的回环**（画在 20px 轨列内，不占文字列），审查节点行以文字标「第 N 轮」；
点任一阶段节点打开该阶段对应运行的详情（E-313）。轨的六种形态与 12 个状态形状**不变**，
只是「当前步」可能落在任一阶段的任一步上，轨的形态从上到下讲完这个任务的一生：

| 轨段 | 形态 | 含义 |
|---|---|---|
| 已完成段 | 实线，`--spine-done` | 走过了（已过阶段折成一行，带该阶段总耗时） |
| 当前步 | 实心圆点 8px + 1.6s 呼吸环，`--auto` | 正在跑（**呼吸环是全页唯一的连续动画种类**，只出现在这里与批次树执行行） |
| 未执行段 | **虚线**（2px dashed，同色） | 还没走到（含还没进入的阶段，耗时列留空） |
| 等你 | 当前点变**空心方块** 9px + **当前点以下整段轨转 `--needs`** | 这条流水线卡在你身上（审批卡就地插在该节点下） |
| 失败 | 轨在此**平头截断**（4px 横向端帽），`--down` | 断了，下面不会再走 |
| 已停止 | 轨变**半调虚线**，端点一段 10px 横杠 | 是你停的，不是它崩的 |
| 返工回环 | 从审查节点沿轨列画回实施节点的细线，`--spine-done`；审查节点行文字「第 N 轮」 | 审查判 rework 后回到了实施；`rework_count=0` 不画回环、不写轮次 |

**为什么是它**：桌面端同时 4–6 条泳道，用户不可能逐条读文字。
**轨是唯一一个不用读就能扫完所有泳道的元素**——形状先于颜色传达状态，
因此天然满足 E-110「状态区分不能只靠色相」（投屏、色觉差异、灰度打印都成立）。
它在手机端只剩一条，仍然工作。

**约束**：轨必须**贯穿整栏全高**（含未来阶段与未来步骤的虚线部分）。
一旦只画到当前步，它就退化成普通时间线装饰，签名就没了。**紧凑档也不折、不换表示**（决策 95）——
每个阶段一行 30px，已过阶段折成一行带总耗时，当前阶段行下只保留它的最后一行步骤；
不做「一行图标」、不做「只显示当前阶段」，260px 放不下就按 E-166 加宽列宽（E-315）。

### 主题解析（写 DOM 之前必须做的一步）

store 里的 `theme` 存三个值 `system` \| `dark` \| `light`，
但 **`theme-provider` 解析后只往 `html` 元素的 `data-theme` 属性写 `dark` 或 `light` 两者之一**。
`system` 的解析依据是 `matchMedia('(prefers-color-scheme: dark)')`，并**订阅它的变化**跟随系统切换。

> ⚠️ 若把 `system` 原样写进 DOM，下面两个 `[data-theme]` 块都不匹配、只剩 `:root` 生效，
> 结果是**永远深色**——与 E-15「跟随系统主题」直接冲突，而且在浅色系统下毫无征兆。

`color-scheme` 同样随解析结果切换（`dark` 或 `light`），不恒为 `dark light`，
否则原生滚动条与表单控件会与页面主题脱节。

### 组件规范

**按钮**

| 变体 | 用途 | 高度 / 圆角 | 静态样式 |
|---|---|---|---|
| `.btn-primary` | 派发 · 批准并继续 | 32（手机 44）/ 9 | `background:var(--needs); color:var(--on-needs); font:600 13px/1 var(--font-ui)` |
| `.btn-stop` | **停止** | 同上 | `background:transparent; color:var(--ink-1); border:1.5px solid var(--border-strong)`，前置 `■`。**不是红的**——红留给拒绝/删除 |
| `.btn-danger` | 拒绝 · 丢弃 | 同上 | `color:var(--down-ink); border:1px solid var(--down)`；只有二次确认那一步才填充 |
| `.btn-ghost` | 改一下 · 次要 | 同上 | `color:var(--ink-2); border:1px solid var(--border)` |

**primary 的唯一性按容器算，不按整屏算**——整屏只允许一个 primary 这条规则在本产品下自相矛盾：
E-109 要求每条流各自内联一张审批卡，5 条流并置时同屏必然出现 2–5 个「批准并继续」。
准确规则是：**每个可见容器内至多一个 primary**（左栏派发面板 1 个、每条泳道 1 个），
而 **`--glow` 只允许出现在左栏那个派发按钮上**，审批卡里的 primary 用实底无 glow。

状态：`hover` 底提亮 4% + 边框升 `--border-strong`，`transition:var(--dur-fast)`，**不放大不弹跳**；
`focus-visible` → `box-shadow:0 0 0 3px var(--needs-soft)` + `border-color:var(--needs)`，
**永不 `outline:none` 而不给替代**；`active` → `filter:brightness(.92)`，手机端另加 `scale(.97)`；
`disabled` → `opacity:.45; cursor:not-allowed`。
**唯一例外：`.btn-stop` 在两次运行之间保持原位、边框不减淡、只淡化文字**——
它必须一直看起来「在那儿」，否则用户会以为界面坏了（E-106 要求常驻）。

**输入框 / 选择器**：高度 32（手机 44）/ 圆角 9 / `background:var(--panel-2)` /
`border:1px solid var(--border)` / 内边距 `0 10px` / 13px。
派发用的提示词框 `min-height:72px; max-height:200px`，**用 `--font-mono`**（这段文字要喂给写代码的 agent）。
`error` → `border-color:var(--down)` + 下方 12px 提示，**说清原因和改法**
（「模型 `o4-mini` 不在 codex 配置里，选一个或手填」），配 `aria-invalid` + `aria-describedby`。
**永不拿 placeholder 当 label。**

**卡片**：`background:var(--bg); border:1px solid var(--border); border-radius:14px;
padding:14px（密集）/ 18px（宽松）; box-shadow:var(--shadow)`。
深色下面板向前一级就变亮（`#0F1213` → `#171B1C` → `#1F2425`），
**明度才是深度，禁止 `1px solid #333` 这种硬灰边**。

**流头部参照条（回答「它凭什么这么干」）**

每条流的头部之下常驻一条 `padding:5px var(--sp-3)`、`background:var(--panel-2)` 的窄条，
等宽 11px `--ink-3`，三段以 `·` 分隔：**模型 · 思考强度 · 权限档**。
它安静但不可折叠——四问里的「凭什么」如果要点开才看得到，等于没答。

- **思考强度**取三档（低／中／高，决策 52）。**不支持的 agent 显示「—」**，
  title 说明原因，**绝不补一个默认档冒充**（E-254）。
- **自报值与所选不一致**时两者都显示并转 `--needs`（`sonnet-5 → 实际 sonnet-5-mini`），
  模型与思考强度同规则（E-37、E-256）。
- **权限档为最高档时**该段转 `--down` 并带前置标记，**持续显示而非一次性提示**（E-136）。

**agent 身份 chip 带会话序号**：同一个 agent 可以同时开多个会话跑不同任务（E-31），
所以 monogram 右下角挂一个 `13px` 的中性小角标标出这是它的第几个会话。
**序号是中性的、不占色相**——它是身份的一部分，不是状态。

**运行流条目（本产品特有）**
```
[轨点] [步骤标签 · 具体到工具+对象]        [耗时] [∨]
       ↳ 结果第一行，截断
```

折叠高度 30px（手机 44px），网格 `20px minmax(0,1fr) auto 16px`，轨在 `--spine-x:11px` 处贯穿。
标签 13px `--font-ui`，**必须写「读取 `orders.csv`（2,481 行）」，不许写「工具调用」**。
耗时 12px 等宽 tabular `--ink-3`，**每一步都必须有**——它是「慢」和「卡死」的唯一分界。
图标按**形状**分类型（思考 ◇ / 工具 ⬡ / 写文件 ▤ / 网络 ⌁ / 等你 ◆ / 输出 ▮）。
展开区 `background:var(--panel-2); padding:10px; font:12px/1.5 var(--font-mono); max-height:240px`，
**入参/出参逐字原样，不许美化成散文**。
**成功步默认折叠，失败步默认展开**，失败步提供「从这一步重试」。
键盘焦点用**内嵌** 2px 环，不能用会撑开布局的 outline（否则滚动列表整体抖）。

**状态徽标**：`height:20px; border-radius:6px; padding:0 7px; font:600 11px/1 var(--font-ui)`。
**矩形不是药丸**。**永远是「字形 + 文字」，颜色是第三层信息。**

> ⚠️ **下表的 Unicode 字符是「语义来源与 `aria-label` 文案来源」，不是渲染实现。**
> 实际渲染一律用 `lib/spine-shape.ts` 里的**内联 SVG path**（决策 46）——
> Android WebView 的中文回退字体不保证有 `⬡` / `▤` / `⌁` 的字形，
> 缺字形会显示成豆腐块，而那正是「不能只靠颜色」时的唯一替代信息（E-233）。
> 另需为「失联」「审查未完成」「未识别／降级」各补一个**专属形状**，绝不复用 `✕`（E-230）。

| 状态 | 字形 | 文案 | 颜色 |
|---|---|---|---|
| queued | `▢` | 排队 3 | `--ink-3` @70% |
| thinking | `◇` | 思考中 | `--ink-2` + 轨上心跳 |
| tool | `⬡` | 调用工具 | `--ink-2` + 轨上心跳 |
| streaming | `▮` | 输出中 | `--ink-2` + 光标 |
| **awaiting-input** | `◆` | **等你** | `--needs` |
| succeeded | `✓` | 完成 | `--auto` |
| **partial** | `◧` | **部分完成** | `--warn`（=`--needs`）**绝不绿** |
| failed | `✕` | 失败 | `--down` |
| **stopped** | `▬` | 你在第 4/9 步停止 | `--stopped` + **虚线边框** |

**批次树（左栏第一区块，任务列表页同一组件）**

按批次折叠，一批一个 `treeitem`；标题行网格 `16px minmax(0,1fr) auto auto`（开合槽 · 「第 N 批」+ 计数 · 收口徽标 · 收口按钮槽），
任务行网格 `20px minmax(0,1fr) auto 7ch`（呼吸点槽 · `taskKey` 等宽 12px + 标题 13px 截断 · 状态徽标 · 进 HEAD 标记）。
行高 `--row-h` 30px，触摸档 `--row-h-touch` 44px，开合槽在触摸档撑到 44×44。

- **标题计数**固定文案 `已落地 {landedCount}/{taskCount} · 在跑 {runningCount} · 等你 {waitingCount}`，12px 等宽 tabular `--ink-3`；
  `waitingCount > 0` 时**只有**「等你 z」一段转 `--needs-ink`。四个数字全部来自 daemon，前端不做减法（E-272 的「等你落地 N 个」用 `notInHeadCount`）。
- **收口徽标**用既有形状不新增：`wrapping`「收口中 · 第 n/2 轮」中性文案不占形状；`done` + clean「已收口 · 干净」与 `done` + fixed「已收口 · 已修」

  `awaiting_landing` 用 `◆` 暖色「等你落地 N 个」。轮次 ≥2 时进 title 与 aria-label。任一时刻只显示一个收口徽标。
- **默认展开**只读 `BatchDto.defaultExpanded`（daemon 算：`state ∈ running / wrapping / awaiting_landing / needs_attention`，决策 71）；
  `batch.advanced` 到达时并入展开集，只增不减（E-284）。
- **呼吸点**：任务行第一列放 `pulse-dot`，`live`（starting / running / reviewing / reworking）圆点 + 呼吸环，
  `waiting`（awaiting_reply / awaiting_human / orphaned）只有静态暖点，终态与 queued 无点；标题行**不放**呼吸点（E-282）。
- **进 HEAD 标记**：最后一列固定 `7ch`，等宽 11px `--ink-3`，三态「进 HEAD」／「未进 HEAD」／「—」同色不用色相，`false` 的 title 显示判定方法（E-298）。
- **跨批修复**：任务行标题后 20px 高矩形 chip「跨批修复」（11px `--ink-3`），批次标题追加「· 含跨批修复」。
- **收口行**：批次标题下第一行「批次收口 · 第 N 轮」，网格与任务行相同，第一列按收口运行状态呼吸，点击进该运行详情。
- **收口按钮**：`.btn-ghost` 高 `--h-btn-sm` 在标题行第四槽，只在 `canWrapup` 且非手机档时渲染；手机端不出（决策 32）。
- **键盘**：标题行 `tabindex=0`，Enter/Space 开合，ArrowDown 进首行、ArrowUp 回标题，ArrowLeft 折叠本批、ArrowRight 展开；
  焦点用内嵌 2px 环。aria：根 `role="tree"`，批次 `treeitem aria-expanded aria-level=1`，行 `treeitem aria-level=2`。

**顶栏闸门开关**：三个开关同一形态（两段「等我确认 | 自动」，高 `--h-btn-sm`），第三个「落地前」不再置灰；
切到自动时**不弹 dialog**，开关行下常驻一行 12px `--ink-3`「审查 pass 后直接标记已验收，仍不执行任何 git 操作」（E-299）。
值从 `GET /settings/gates` 来、写走 `PATCH /settings/gates` 全量三值，状态以 `settings.gates_changed` 回流为准，**禁止乐观翻转**。

**顶栏流水线开关**（三个闸门右侧，同一形态、同一高度，中间一条 1px `--border` 竖线隔开，决策 93）：
「查 bug」两段「关 | 开」（默认关）、「收口」两段「自动 | 手动」（默认自动）。
值从 `GET /settings/pipeline` 来、写走 `PATCH /settings/pipeline` **全量两值**，状态以 `settings.pipeline_changed` 回流为准，**禁止乐观翻转**；
切「查 bug」到开时开关下常驻一行 12px `--ink-3`「审查 pass 后先派一次查 bug 运行再进落地闸门；只影响尚未到达该阶段的任务」（E-306）；
切「收口」到手动时常驻「批次落齐后只亮『可收口』按钮，不自动派收口」（E-312）。

**任务流水线泳道**（运行甲板主体，一条泳道 = 一个窗口槽位，决策 87）

泳道数恒等于并行窗口设置 `laneCount`，**由 daemon 的 `lanes[]` 决定**——前端按 `laneNo` 升序排列，不算槽位、不算下一个任务、不推断阶段（E-317）。
每条泳道从上到下四段：

- **头部**（`--stream-head-h` 40px）：左起 `laneNo` 等宽 11px `--ink-3`「泳道 k」· agent monogram + 会话序号 chip · `taskKey` 等宽 12px + 标题 13px 截断 · 右端状态徽标 + 常驻停止键（`.btn-stop`，E-106）。
  头部之下是既有的流头部参照条（模型 · 思考强度 · 权限档）。
  收口运行占的泳道头部按 M9-T20 写「批次收口 · 第 N 轮 · 第 M 批」。
- **阶段链**：即上文的运行轨，每阶段一行 30px（触摸 44px），网格沿用运行流条目 `20px minmax(0,1fr) auto 16px`：
  轨列 · 阶段标签 13px `--font-ui`（「实施」「审查 · 第 N 轮」「返工实施 · 第 N 轮」「查 bug」「落地」）· 阶段耗时等宽 12px `--ink-3`（已过阶段写总耗时，当前阶段写进行中计时，未来阶段留空）· 开合槽。
  阶段行 `tabindex=0`，Enter 打开该阶段最近一次运行的详情，焦点用内嵌 2px 环。
  已过阶段默认折成一行；当前阶段展开其步骤（运行流条目，30px）；紧凑档下当前阶段只保留最后一行步骤（E-315）；完整档展开全部步骤。
  「查 bug」阶段只在该任务实际进入该阶段时才出现，不画灰色「已跳过」节点（E-306）。
  返工回环：审查判 rework 时当前脉冲点回到实施节点，审查节点保持实线并带「第 N 轮」文字，审查以下轨段仍虚线（E-315）；
  查 bug 后再审画成查 bug 节点回到审查节点的回环，轮次沿用同一 `rework_count`（E-307）。
  某阶段转人（`awaiting_human`）时该阶段节点用「等你」空心方块、以下整段轨转 `--needs`，审批卡就地插在该节点下（E-109）。
- **历史行**（当前任务与它之间一条 1px `--border-strong` 分隔线 + 上下各 `--sp-2`）：**只有一行**（决策 98，E-325），
  折叠内容固定 `taskKey · 标题截断 · 终态徽标（字形+文字）· 第 N 轮（N≥2 才显示）· 总耗时 · 「会话已归档」chip`（20px 高矩形，11px `--ink-3`）；
  展开后显示该流水线的阶段链（同一组件，只读、无脉冲、无回话框、无停止键、无重跑，E-314）。
  泳道第一个任务不渲染历史行与分隔线；紧凑档展开历史行走 E-165 同一展开态。
- **底部**（`--stream-foot-h` 36px）：既有收据行。

**空闲泳道**：头部「泳道 k · 空闲」，阶段链位置一行 13px `--ink-2`「空闲 · 队列下一个是 〈ID〉（等 〈前置〉 落地）」（文案来自 daemon 的 `nextTaskId` 与 `nextBlockedBy`），
无未派任务时「空闲 · 本批已全部派出」；不画假的阶段链；停止键置灰但保持原位；历史行照常显示上一任务（E-319）。
窗口数调小时被移除的空泳道连同其历史行一起消失，仍在跑的泳道不消失并标「超出窗口数」（E-309）；调大时新泳道立即出现（E-310）。
**停靠中的任务不在甲板上**：任务停在人工闸门（`awaiting_human`）时泳道已让出、会话未归档，它的入口只有批次树「等你」行、全局未处理徽标与任务／运行详情里的审批卡；
人打回后它排在全部新任务之前重新入道，等泳道期间批次树该行显示「返工排队 · 等泳道」静态点（E-326、E-327）。

**与收口泳道并存**：`kind='wrapup'` 的运行按 M9-T20 占一条普通泳道，头部、停止控件、参照条、运行轨与实施流一致；
它不是任务流水线，不画阶段链、不参与补位，`lanes[]` 里以 `stage='wrapup'` 标出；它跑完后该泳道的历史行显示「批次收口 · 第 N 轮 · 第 M 批」+ 收口裁定徽标（E-325）。

**收口报告面板**（运行详情页在 `run.kind === 'wrapup'` 时装配在会话流之上）：每轮一张卡，头部「第 N 轮 · 裁定徽标」，
`promptSource='builtin'` 时追加 chip「文档未提供收口提示词」；TESTS 状态词 + 条目；findings 每条一行等宽 12px
`{id} [{severity}] 涉及 {taskKey}（跨批）：{现象}` 整行可点跳该任务，`isWellFormed=false` 行尾 chip「格式不全」；
unassigned 标题「未归属 N 条」；landing 块列 worktree / 分支 / diffStat / `isDirty` 时「工作区有未提交修改」+ 可复制命令；
`reportText` 收进可展开「八段原文」块（等宽 12px，`max-height: var(--payload-max-h)`）。**不在前端解析原文**（E-297）。

**审批卡（就地插在该流时间轴里）**：宽度 = 该栏全宽，
`border-radius:14px; border:1px solid var(--needs); background:var(--needs-soft); padding:14px`。
**不用左侧 3px 彩条**（被点名的廉价手法），整卡染色 + 全边框。
四段固定顺序：① **要做什么**（14px/600）② **影响什么**（那个吓人的数字用 26px 等宽 `--needs`；
不可逆则 `--down`）③ **凭什么**（12px，**必须带一个可点的链接回产出该结论的那一步**——
这段最常被砍，而它决定答案）④ **三个固定动作** `[批准并继续]`(primary) `[改一下]`(ghost) `[拒绝]`(danger outline) **+ 一个条件动作**：
审查判「未结构化」（`reviewVerdict='incomplete'` 且 `reworkText` 非空）时在「拒绝」之后多一个 `[投递原文到实施会话]`(ghost)，
按目标实施运行的 `capabilities.canReply` 灰掉并带 title 说明（E-278、E-117），第③段内先放一块默认折叠 3 行的返工原文；
**「改一下」不是可选项**。底部一行超时策略：`无人应答不会自动批准，任务保持等待`。
**卡片阻塞的是这一条流，不是整个页面**（E-109）。

**成本**：每轮页脚一行**收据**，等宽 tabular 且安静：`9 步 · 42.6s · 18.2k token`。
厂商拿不到花费时降级为「耗时 / 轮次 / 可得时的 token」，
并**显式标注「该 agent 未提供花费数据」，不要留空也不要编**（E-26）。

### 明确拒绝的做法（avoid）

逐条可检查：

1. **靛紫 / violet 主色**。grep 全仓库：`#6366f1` `#5E6AD2` `#635BFF` `#7C3AED` 一个都不许出现。
2. **紫色 / 蓝色辉光**、悬浮发光球体、✨ 星星图标、「AI」二字上的渐变文字。
3. **绿字黑底磷光终端**（`#00FF41` 一族）与 **Graphite&Lime 开发者套装**——这是「拒绝紫色」之后的二阶默认，同样拒。
4. **Linear 克隆**：`#08090A` 底 + 6% hairline + 靛紫。
5. **聊天气泡当运行流**。右对齐用户输入可以，**只有气泡就是失败**——那意味着队列和历史都不在屏幕上。
6. **一个转圈 spinner 代替九个状态**。任何 indeterminate loader 站着代表整轮运行 = 硬失败。
7. **全局模态审批**。它同时遮住证据、并且谎称整个工作台停了。
8. **`partial` 渲染成绿色或归进「成功」计数**。2400/2481 不是成功。
9. **状态只靠色相**。两问必须都是「能」：删掉字形还能区分吗？放灰度还能区分吗？
10. **停止键藏在 `⋯` 菜单里 / 只在 hover 显示 / 跑起来才挂载**；**停止和删除同形同位**。
11. **停止按下后等服务端回包才变样**。必须一帧内本地置 `stopped` 并写明死在第几步，失败再横幅回滚。
12. **每个 agent 一个厂商品牌色**。用 monogram（决策 33）。
13. **图表当主角**。批次汇总一旦升级成环形图，运行流就被挤成小卡片。
14. **假精确数字**：`准确率 98.7%` `提效 60%`。在一个以可审计为前提的页面上，编了就崩。
15. **拟人化步骤标签**：`让我想想…` `正在努力中`。步骤标签是日志行。
16. **步骤标签写成类目**：`工具调用 ×7` `处理中`。必须是「工具 + 对象」。
17. **日志区用比例字体**；反过来，**UI 标签用等宽**装技术感。
18. **卡片左侧 3px 彩条**、**玻璃拟态**、**渐变流光边框**、**卡片 hover 弹跳放大**。
19. **`#fff` / `#000` / 硬 `1px solid #333` 边 / 纯灰 `#f5f5f5-#e5e5e5-#737373` 阶**。
20. **Inter 当默认字体**（以及 IBM Plex Mono / Space Mono 当默认等宽）。
21. **空态放插画**。必须是四步引导。
22. **手机端把桌面三栏压成一条竖条**；**拇指区没有停止/批准**；**日志一滚按钮就跑没了**。
23. **超时自动批准**。可以超时自动取消（写明即可），**绝不自动批准**。
24. **`:root` 之外出现颜色字面量**。需要新值就升进 token 再引用——这是色锁的执行机制。
25. **多于一种连续动画**。呼吸环是全页唯一的连续动画种类，只出现在运行轨当前步与批次树执行行；
    两处共用 `@keyframes agsched-pulse` 与 `--pulse`，出现第二个 `@keyframes` 名即违规。批次标题行、徽标、按钮一律不许动。

## 响应式断点与目标设备

| 断点 | 行为 |
|---|---|
| ≥ 1440px | 完整档 3 栏满宽；流数 ≥ 4 时默认紧凑档（E-163、E-164） |
| 1180–1440px | 左栏可折成 64px 图标条 |
| 1100–1180px | 左栏变抽屉 |
| < 1100px（桌面窗口被拖窄） | **退化为单列列表**；不套用手机端规则，也不允许在 900px 硬塞三栏（E-168）。左栏（含批次树）沿用上一档的同一抽屉，不另开「批次」按钮；单列首行保留批次汇总条，显示最近一次 `batch.advanced` 的批，点击打开抽屉并滚到该批（决策 86） |
| 手机竖屏 ≥ 400px | 顶部常驻运行条 44px + 单流占满 + 底部拇指栏 60px；运行条写「泳道 k/N · 〈taskKey〉 · 状态」，两端各一个 ≥44×44 的 ◀ ▶ 切泳道，N=1 时禁用不隐藏；泳道不并排、不跟随窗口数（决策 97，E-324） |
| **手机竖屏 < 400px** | 单栏切换（任务列表 / 运行流 / 详情），**不得横向滚动或并排三栏**（E-145）；运行流 pane 同样一次一条泳道 |

**紧凑档**用 auto-fill **换行网格**（每格 min 260px）**而非横向滚动**——
八条流在 1440px 下折成两行全部可见（E-164）。
展开某条时该条占满宽度，**其余保持 260px 留在同屏、绝不折叠消失**——
E-106 要求每条流常驻停止控件，看不见的流等于停不掉（E-165）。
紧凑档的阶段链**不折、不换表示**：每阶段一行，已过阶段折一行带总耗时，当前阶段只保留最后一行步骤（决策 95，E-315）。

**手机端拇指区**：底部拇指栏固定三键，`padding-bottom: calc(env(safe-area-inset-bottom) + 11px)`，
`[■ 停止]`（左端）… `[批准]`（右端），**两者分置两端或间距 ≥ 24px**，各 ≥ 44×44px，
**不随日志滚动移出视野**（E-107）。展开的 tool payload 走 bottom sheet 不内联。
**触摸时默认关闭自动滚动**，距底 ≤40px 才恢复，否则显示 `↓ 3 条新步骤` 药丸（E-100）。

目标设备：桌面 Windows 10/11（WebView2）、macOS 11+ 与 Linux（WebKitGTK）；
手机 Android（Capacitor）。
**壳不画假状态栏**——状态栏由原生壳提供。
