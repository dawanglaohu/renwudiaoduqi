# 接口约定

所有接口挂在 `/api/v1` 子 scope 下。**鉴权与限流注册在该 scope 内部**，
不挂根实例——Fastify 的封装边界一旦挂错，会连带拦住静态资源或漏掉后注册的路由（见 08 节）。

`packages/shared/src/api/routes.ts` 里有一张常量表是本节的**机器化载体**；
daemon 侧 `test/arch/routes.test.ts` 断言「实际注册的 method+path 集合 === 该表」，
**多一条少一条都失败**。

## 配对的自举：第一枚令牌从哪来

**这是一个必须显式解决的鸡生蛋问题。** `POST /pair/code`（生成配对码）需要 device 令牌，
而全新装机时**一枚已配对设备都没有**——尤其在两个壳都还没就绪的开发窗口里（R-01 / R-02），
浏览器直连是唯一入口。

解法**不是**再开一个免鉴权端点：

> daemon 启动时若检测到**零已配对设备**，把一枚一次性配对码
> **打印到本机控制台并写入数据目录下的 `pairing-code.txt`**（`0600` 权限，用后即删）。
> 能读到这个文件的人，本来就已经能读 `%APPDATA%` 下的库与全部日志——
> 也就是说他早已拥有 daemon 的全部权限，**这条通道没有放大任何攻击面**。

**免鉴权白名单仍然只有三条**，E-08「代码中不存在局域网免鉴权分支」一字不动（E-226）。

## 分页、排序、筛选

- 一律**游标分页**，不用 offset：入参 `cursor`（不透明串）+ `limit`（默认 50，上限 200）
- 返回 `nextCursor`，为 `null` 表示到底
- 日志回读用 `fromSeq` + `direction`（`backward` 默认，向上翻历史）+ `limit`（默认 200 行），
  返回 `prevCursor` / `nextCursor` 两端游标——因为运行流既要向上翻历史也要向下跟随
- 排序字段**只能来自封闭枚举 `SORTABLE_COLUMNS`**，禁止把用户串直接当列名（见 08 节）
- 筛选参数一律精确匹配，**不做模糊搜索**（决策 43：本版不建全文索引）

## 幂等与重试

| 端点 | 幂等机制 | 客户端该不该重试 |
|---|---|---|
| `POST /runs`、`POST /runs/:id/rerun` | **必须带 `idempotencyKey`**，落 `runs.idempotency_key` UNIQUE。重复提交置 `409 E_RUN_ALREADY_EXISTS`，**既有 run 放在 `details.run` 里**（失败信封没有别的位置放它） | 不重试，按返回的既有 run 处理 |
| `POST /gates/:id/decide` | 天然幂等，第二次返回「已由另一端确认」（E-57） | 可重试 |
| `POST /runs/:id/abort` | 天然幂等，已终态直接返回 accepted | 可重试 |
| `POST /runs/:id/messages` | 返回 `messageId`；投递失败落「未送达」**并保留原文可复制**，绝不静默丢弃（E-113） | 不自动重试，由人决定 |
| `POST /pair/claim` | **一次性**，配对码用掉即失效（E-07） | 不重试 |
| 所有 GET | 幂等 | 可重试 |

**写操作的最终状态一律以回流事件为准**，UI 不拿 POST 响应体直接改状态（E-157）。

## 限流与超时

- **只有 `/pair/*` 限流**：每 IP 每分钟 10 次，自写内存滑动计数器（不引限流库）。
  超限返回 `429` **并立即作废当前配对码**（E-07）。其余端点不限流——单人自用，限了只会碍事。
- HTTP 请求无服务端硬超时；**长耗时操作一律异步化**：
  `POST /runs` 立即返回 `queued` 的 run，实际进展走 SSE。
- 客户端超时建议：普通 GET 10s，`POST /agents/:id/probe` 15s（探测本身有 5s 上限），
  SSE 不设超时、靠心跳判活。

## 版本

版本在**路径里**（`/api/v1`）。`GET /version` 返回 `apiVersion`，
**壳启动时校验**，不兼容时提示升级而不是抛底层错误（E-14）。

破坏性变更的处理：本项目单人自用、daemon 与两个壳同批分发，
**不做多版本并存**——直接升 `/api/v2` 并要求两端一起更新。
`GET /version` 就是让「只更新了一端」这件事被立刻发现的机制。

## 字段级契约

| 字段 | 类型 | 必填 | 值域 | 长度/范围 |
|---|---|---|---|---|

| `dispatch` / `review`（闸门） | enum | 是 | `auto` / `manual` | — |

## 请求/响应示例

**成功**——派发一个任务：

```json
POST /api/v1/runs
{
  "taskId": "tsk_M4T2",
  "agentId": "codex",
  "model": "gpt-5.6-sol",
  "permissionTier": "workspaceWrite",
  "idempotencyKey": "M4-T2-attempt-1"
}

200 OK
{
  "run": {
    "id": "run_01J8XA",
    "taskId": "tsk_M4T2",
    "attemptNo": 1,
    "state": "queued",
    "agentId": "codex",
    "modelName": "gpt-5.6-sol",
    "permissionTier": "workspaceWrite",
    "idempotencyKey": "M4-T2-attempt-1",
    "startedAt": null
  }
}
```

**失败**——模型名被 agent 拒绝（派发已发出、agent 报错回来）：

```json
422 Unprocessable Entity
{
  "error": {
    "code": "E_MODEL_INVALID",
    "message": "Agent 'codex' rejected model name; passed through verbatim.",
    "requestId": "req_2b91ce04",
    "details": {
      "agentId": "codex",
      "model": "o4-mini",
      "agentStderrTail": "unknown model: o4-mini"
    }
  }
}
```

> **路径冲突不是失败。** 同批里抢同一批文件时 run **已经建好并落库**，
> 只是停在 `queued`，所以返回 **200 + `{run}`**，`run.queuedReason` 说明被谁挡住——
> 返回错误信封会让客户端拿不到 `runId` 从而无法跟踪这次派发（E-46）。

## 非 REST 通道：SSE

**只有一条 SSE 连接**承载全部事件，事件体带 `scope` 与 `taskId` 由前端分发。

- 端点 `GET /api/v1/events`，`Accept: text/event-stream`
- **必须自写客户端**（fetch + ReadableStream）——
  浏览器原生 `EventSource` 不能带 `Authorization` 头，
  而鉴权默认开启且**不许有局域网免鉴权分支**（E-08、决策 27）
- 响应头固定：`Content-Type: text/event-stream`、`Cache-Control: no-cache, no-transform`、
  `Connection: keep-alive`、**`X-Accel-Buffering: no`**（防用户自接的反代缓冲，E-154）
- 每 **15 秒**写一行 `:\n\n` 心跳保活
- 每条事件带**单调递增的 `id`**；断线重连带 `Last-Event-ID`，服务端从
  **5000 条环形缓冲**里补齐（E-10、E-153）

单条事件的线格式：

```
id: 184213
event: message
data: {"id":184213,"ts":"2026-08-31T14:07:53.902Z","runId":"run_01J8XA","taskId":"tsk_M4T2","scope":"run","kind":"tool_call","seq":417,"actorDeviceId":null,"payload":{"title":"读取 packages/daemon/src/adapters/codex/map-events.ts","status":"in_progress"}}

```

**重放窗口过期**——`Last-Event-ID` 小于缓冲最小 id 时，
服务端立即以 `409 E_REPLAY_WINDOW_EXPIRED` 关闭该流，
客户端改走 `GET /api/v1/snapshot` 拉全量状态后从最新 id 续接。
**不允许静默丢事件**（E-153）。

**令牌过期或被撤销**——服务端主动关闭该流并返回 `401`，
客户端提示重新配对，**不进入无限重连**（E-156）。
重连一律**指数退避 + 保留 `Last-Event-ID`**，不做无间隔轮询式重连（E-158）。

两端同时在线时，**每条连接各自维护自己的游标与去重**，
服务端不做「只有一个客户端」的假设（E-155）。

## 错误码表

与 08 节的错误类型体系同源：枚举定义在 `packages/shared/src/errors/codes.ts`，
**本表是源，`codes.ts` 是投影**：`scripts/check-error-codes.mjs` 断言
`codes.ts` 的键集合与本表逐行一致，不一致即 `pnpm -w check` 失败。
方向不能反——文档是唯一事实源，代码跟着文档走。
