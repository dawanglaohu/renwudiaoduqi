# UX

## 关键流程

六条主流程，每条都走到失败分支为止——**只画顺利路径的时序图价值减半**。
图里的参与方一律用模块 ID，步骤上标边界编号；在阅读器里两者都可点开。

### 流程一：按批次派发一个任务

```mermaid
sequenceDiagram
  autonumber
  actor U as 用户
  participant M9 as M9 界面
  participant M2 as M2 接入
  participant M8 as M8 派发调度
  participant M3 as M3 文档接入
  participant M4 as M4 Agent 适配
  participant M5 as M5 工作区
  participant M6 as M6 运行监管

  U->>M9: 选文档 → 选批次 → 给每个 agent 选模型 → 点派发
  M9->>M2: POST /batches/:id/start（带幂等键与设备令牌）
  M2->>M8: 转交
  M8->>M3: 取任务、依赖、taskPaths、实施提示词
  M3-->>M8: 任务集 + 并行窗口数
  M8->>M8: 算可放行集合 = min(窗口, 每 agent 上限, 用户设定) E-52
  alt 同批两任务抢同一批文件
    M8-->>M9: E_PATH_CLASH_QUEUED，后者排队 E-46
  end
  M8->>M4: 该 agent 可用吗？模型有效吗？
  M4->>M4: 版本指纹探测（按路径+mtime+大小缓存）E-197
  alt 指纹不匹配任何已知模式
    M4-->>M8: E_AGENT_VERSION_UNRECOGNIZED E-195
    M8-->>M9: 该 agent 置灰，给手填绝对路径入口
  end
  M4-->>M8: 可用 + 能力位 + 权限档
  M8->>M5: 建 worktree（base = 当前 HEAD 或上游任务分支）
  alt 上游产出尚未落地进 HEAD
    M5-->>M8: E_UPSTREAM_BASE_MISSING，拒绝派发 E-70
  else 磁盘不足或权限问题
    M5-->>M8: E_WORKSPACE_UNAVAILABLE，释放窗口名额 E-76
  end
  M5-->>M8: worktree 路径 + 分支名
  M8->>M8: 派发前闸门：自动 or 等我确认 E-53
  opt 闸门 = 等我确认
    M8->>M2: task.gate_waiting
    M2->>M9: SSE 推送，手机拇指区亮起「批准派发」E-182
    U->>M9: 批准
  end
  M8->>M6: 启动参数 + 幂等键（三段快照已落库 E-19）
  M6->>M4: spawn（shell:false + 参数数组 E-42）
  M4->>M6: 归一化事件流（ACP session/update 词汇）
  M6->>M2: run.started，按 event id 入队
  M2->>M9: SSE
  M9-->>U: 运行轨出现，当前步心跳
```

### 流程二：agent 中途提问，人从手机回话

这条流程是「自动派活」能不能真的自动的关键——
中档权限必然会在装依赖处停下（E-134），没有回话通路则整条链停摆。

```mermaid
sequenceDiagram
  autonumber
  participant M4 as M4 Agent 适配
  participant M6 as M6 运行监管
  participant M2 as M2 接入
  participant M9 as M9 界面
  actor U as 用户（手机）

  M4->>M6: 事件：agent 请求执行 npm i / 抛出开放问题
  M6->>M6: 状态 running → awaiting_reply E-115
  Note over M6: 自动模式下也一律不代答；<br/>该任务继续占用该 agent 并发额度
  M6->>M2: task.gate_waiting / run.permission_blocked E-133
  M2->>M9: SSE（审批卡就地插在该流时间轴里 E-109）
  alt 手机在后台被系统杀掉
    M9->>M2: 重开后带 Last-Event-ID 补拉未读 E-147
    M2-->>M9: 重放窗口内的事件
  end
  U->>M9: 在拇指区点「批准」或输入一句话
  M9->>M2: POST /runs/:id/messages（幂等）
  M2->>M6: 投递
  alt 进程已死或管道已断
    M6-->>M2: E_MESSAGE_UNDELIVERED，原文保留可复制 E-113
  else 该 agent 无注入能力位
    M6-->>M2: E_CAPABILITY_UNSUPPORTED（按能力位 UI 本就该灰掉）E-117
  else 会话已结束但支持 resume
    M6->>M4: 恢复会话后投递，明示这是一次新运行 E-112
  end
  M6->>M4: 写 stdin（检查 write 返回值，false 则等 drain）
  M4-->>M6: 继续输出
  M6->>M6: awaiting_reply → running
  M6->>M2: run.message_delivered
  M2->>M9: SSE，审批卡收起
```

### 流程三：审查流水线（两级）

```mermaid
sequenceDiagram
  autonumber
  participant M6 as M6 运行监管
  participant M7 as M7 审查流水线
  participant M5 as M5 工作区
  participant M3 as M3 文档接入
  participant M4 as M4 Agent 适配
  participant M8 as M8 派发调度

  M6->>M7: 运行结束（退出码 + 会话指针）
  Note over M7: 退出码为 0 不等于验收通过 E-23
  M7->>M5: 取 diff（执行目录恒为该任务 worktree E-67）
  alt diff 为空
    M7-->>M8: 机械层直接判失败，标「无改动」转人 E-61
  end
  M7->>M7: 零配置层：diff 非空 / 退出码 / 验收关键词命中
  opt 文档声明了 build / test 命令
    M7->>M5: 在 worktree 内跑（10 分钟硬超时，杀后不重试 E-66）
    alt 命令挂死
      M7-->>M8: 标「机械检查超时」转人
    end
  end
  Note over M7: 未声明命令则跳过，<br/>并在 UI 明示「机械检查覆盖有限」E-60
  M7->>M3: 取该任务的审查提示词与派发时的验收标准快照
  M3-->>M7: 两段文本
  M7->>M4: 派审查 agent（**固定只读档** E-135）
  alt diff 超出审查模型上下文
    M7->>M7: 给 diff stat 全量 + 命中文件全文，其余折叠，<br/>结论标注「基于部分 diff」E-65
  end
  M4-->>M7: 审查输出
  alt 解析不出 pass/rework/doc-issue 三态
    M7-->>M8: 「审查未完成」转人工，保留原文，绝不默认放行 E-63
  else 审查 agent 崩溃或超时
    M7-->>M8: 同上，既不算 pass 也不算 fail E-62
  else doc-issue
    M7-->>M8: 停止自动 rework，汇总意见给用户 E-64
  else rework 且未达上限
    M7->>M7: 提取返工文本：rework 围栏块优先，其次 REWORK 段条目 E-278
    alt 原会话活着且可回话
      M7->>M6: 回灌意见到原会话（重试计数 +1）E-59
    else 已结束但支持 resume
      M7->>M6: 恢复会话后回灌，明示这是一次新运行 E-112
    else 不能续接（dsh headless）
      M7->>M8: 新开返工运行：同任务 attempt_no+1、同 worktree 与分支、自包含提示词 E-279
      alt worktree 已被清理
        M8->>M5: 在原分支上重建 worktree E-277
      end
    end
  else rework 但返工块解析不出 R 条目
    M7-->>M8: 标「未结构化」转人，原文可一键投递 E-278
  else rework 且已达上限（默认 2 次）
    M7-->>M8: 转「待人确认」，不无限自动改 E-55
  else pass 且落地闸门为自动
    M7-->>M8: 直接进 landed（已验收），产品不执行任何 git 操作 E-53
  else pass 且落地闸门为人工
    M7-->>M8: 停在人面前等放行 E-53
  end
```

### 流程五：批次收口与修复派发

这条流程是补充需求 2026-09-10 的主体：一批任务全部已验收之后，产品自己把「测一遍 → 派修复 → 再测一遍 → 标 done」跑完，
人只在两处出现——合并分支进 HEAD，以及批次转 `needs_attention` 时的裁定；收口模式切到手动（决策 92）时多一处：批次落齐后点「可收口」。

```mermaid
sequenceDiagram
  autonumber
  actor U as 用户
  participant M8 as M8 派发调度
  participant M5 as M5 工作区
  participant M3 as M3 文档接入
  participant M4 as M4 Agent 适配
  participant M7 as M7 审查流水线
  participant M9 as M9 界面

  Note over M8: scheduler-tick 第 1 步：刷新 landed 运行的进 HEAD 标记
  M8->>M5: isBranchInHead(分支, worktree)
  alt 祖先判定否，squash 合并
    M5-->>M8: 回退无差异判定 E-273
  else 分支已被删
    M5-->>M8: 用记录的 branch_tip_sha 判定 E-289
  else 工作区有未提交改动
    M5-->>M8: 未进 HEAD（dirty_worktree）E-301
  end
  Note over M8: 第 2 步：本批全部 landed？全部进 HEAD？
  alt 有分支未进 HEAD
    M8->>M9: batch.advanced → awaiting_landing，标题「等你落地 N 个」E-272
    U->>U: 按落地清单 gh pr merge --merge
  end
  alt 收口模式 = 手动 E-312
    M8->>M9: 批次标题只亮「可收口」，tick 不自动派收口
    U->>M9: 点「收口」
    M9->>M8: POST /batches/:id/wrapup（幂等键）E-288
  else 收口模式 = 自动
    Note over M8: tick 第 2 步按 E-283 自动派收口
  end
  M8->>M3: getWrapupContext(批次)：按任务集合匹配 dispatchBatches
  alt 匹配不到
    M3-->>M8: 内置通用收口提示词，标「文档未提供」E-296
  end
  M8->>M8: 推导收口 agent：本批最晚 landed 实施运行的 agent/model/effort E-287
  alt 该 agent 不可用
    M8-->>M9: 批次 needs_attention（agent_unavailable），不静默换家
  end
  M8->>M5: 建收口 worktree wrapup/<批次>-<轮次>，base=HEAD
  M8->>M4: 派收口运行（workspaceWrite，占 1 名额）E-283
  M8->>M9: batch.wrapup_started，批次树自动展开该批 E-284
  M4-->>M7: 收口运行退出，最终文本
  M7->>M7: 八段解析 + 有效裁定（不看自报）E-286
  alt 不合八段
    M7-->>M8: 「收口未完成」转人，开批次级收口闸门 E-274
  else 收口运行失败或被中止
    M7-->>M8: 不回滚工作区，批次 needs_attention E-295
  else 裁定 clean 或 fixed
    M7-->>M8: 批次 done，下一批解锁 E-49
  else 裁定 open
    M7-->>M8: 开放项按「涉及 <任务ID>」分组；无主项进 unassigned E-290
    M8->>M4: 每个任务派一次修复运行（origin=wrapup-fix，在收口工作区上）E-275
    alt 修复运行与在途任务抢路径
      M8->>M8: 排队；同收口的修复运行串行 E-280
    end
    M4-->>M7: 修复运行退出 → 正常审查（流程三）
    M7-->>M8: pass → landed；人合并收口分支进 HEAD
    M8->>M8: 第 2 轮收口（同上）
    alt 第 2 轮仍 open
      M8-->>M9: 批次 needs_attention，不派第 3 轮 E-276
      U->>M9: 批次级收口闸门：pass 附评语 → done；或手动再收口（硬顶 6 轮）E-288
    end
  end
```

### 流程六：一个任务的流水线（泳道视角）

这条流程是补充需求 2026-09-12 的主体，也是运行甲板上一条泳道从空到满再到空的完整一生：
实施 → 审查 → 反喂同一实施会话 → 返工实施 → 通知同一审查会话续审 → 查 bug（开关）→ 落地闸门 → 会话归档 → 泳道补位新任务、全套新会话。
泳道分配、阶段推进与会话归档全部由 daemon 算出并下发，M9 只呈现（决策 87–91）。

```mermaid
sequenceDiagram
  autonumber
  actor U as 用户
  participant M9 as M9 界面
  participant M2 as M2 接入
  participant M8 as M8 派发调度
  participant M6 as M6 运行监管
  participant M4 as M4 Agent 适配
  participant M7 as M7 审查流水线
  participant M3 as M3 文档接入

  Note over M8: scheduler-tick 补位步：泳道 k 空闲，按可放行集合取下一个任务 E-311
  M8->>M8: 断言新会话引用不等于任何其他任务运行的引用 E-303
  alt 复用了已归档会话的引用
    M8-->>M9: 拒绝派发 E_SESSION_ARCHIVED，泳道保持空闲 E-303
  end
  M8->>M6: 为该任务新建实施运行（全新会话，三段快照落库）
  M8->>M2: lane.assigned{laneNo, taskId, runId}
  M2->>M9: 泳道 k 头部换成该任务，阶段链第一个节点亮起
  M6->>M4: spawn 实施会话
  M4-->>M6: 实施会话退出
  M6->>M7: 运行结束 → 机械检查 → 为该任务新建审查会话（第 1 轮）
  M4-->>M7: 审查输出 rework，提取返工文本 E-278
  alt 实施会话活着且可回话
    M7->>M6: 反喂返工文本进同一实施会话 E-59
  else 已结束但支持 resume
    M7->>M6: 恢复同一实施会话后反喂，明示新运行 E-112
  else 不能续接或上下文撑爆
    M7->>M8: 新开返工运行，提示词自包含 E-279 E-305
  end
  M4-->>M6: 实施会话修完再次退出
  Note over M7: 第 2 轮审查：续用同一审查会话，只核上一轮 R 条目（决策 89）
  alt 审查会话可回话或可恢复
    M7->>M6: 投递「第 2 轮，只核上一轮的 R 条目」到同一审查会话
  else 不能续接或已撑爆
    M7->>M4: 新开审查会话，头部带轮次与上一轮 REWORK 原文 E-304
  end
  M4-->>M7: 审查输出 pass
  alt 查 bug 开关开启 E-306
    M7->>M3: 取该任务派发快照里的 dispatch[id].bug
    alt 文档未提供
      M3-->>M7: 内置通用查 bug 提示词，标「文档未提供」E-316
    end
    M7->>M4: 派查 bug 运行（kind=bughunt，workspaceWrite，同一工作树）
    M4-->>M7: 五段报告
    alt 不合五段
      M7-->>M8: 「查 bug 未完成」转人，保留原文 E-320
    else FIXED 非空
      M7->>M6: 通知同一审查会话再审一轮，只核修改，rework_count+1 E-307
    else NOT_FIXED 含 S1/S2
      M7-->>M8: 任务转 awaiting_human，审批卡列出未修项 E-308
    else 干净或只剩 S3
      M7-->>M8: 走落地闸门 E-321
    end
  end
  M8->>M8: 落地闸门：自动直接 landed，人工等放行 E-53
  opt 落地闸门为人工
    M8->>M2: lane.released{reason: awaiting_human}，泳道让出、会话不归档 E-326
    M2->>M9: 该任务离开泳道，批次树「等你」行 + 审批卡在任务详情
    U->>M9: 放行或打回
    alt 打回
      M8->>M8: 返工排在全部新任务之前重新入道，再按能力位投递 E-327
    end
  end
  M8->>M6: 任务终态：结束并归档该任务全部会话 E-302
  alt killTree 两阶段后仍有进程存活
    M6-->>M8: task.sessions_archived 带 residualPids，横幅给「杀掉」入口 E-322
  end
  M8->>M2: lane.released{laneNo, taskId} + task.sessions_archived
  M2->>M9: 该任务折成「会话已归档」历史行，泳道 k 空出 E-314
  alt 可放行集合非空
    M8->>M8: 立即补位：下一个任务、全套新会话（回到第 1 步）
  else 无可放行任务
    M8->>M2: 泳道 k 空闲 · 队列下一个是 〈ID〉（等 〈前置〉 落地）E-319
  end
  Note over M8: 窗口数调小只停止补位、不杀在跑流水线 E-309；调大立即补位 E-310
```

## 交互反馈

| 场景 | 反馈形态 |
|---|---|
| **加载中** | 首屏用骨架屏；**运行流绝不用 spinner 代表整轮运行**——九个状态各有字形（11 节 avoid#6） |
| **成功** | 不弹 toast。状态由运行轨与徽标承载，**颜色是第三层信息** |
| **失败** | 三种形态各有唯一落点（见 07 节）：字段错在输入框下、业务错就地 inline、整页失败只有两种 |
| **空态** | **不是插画**，是「选文档 → 选批次 → 选模型 → 派发」四步引导，当前步高亮、已完成步显示所选值可点回改（E-108） |
| **首次使用** | 同上；另有一次性横幅说明「阅读器里那套手工三态已被本调度器接管」（E-84） |
| **停止** | **一帧内本地置 stopped 并写明死在第几步**，不等回包；服务端事件到达即清 intent，失败则横幅回滚（11 节 avoid#11 + E-157） |
| **离线** | 顶栏持久条「已断开，最后更新 hh:mm」，停止按钮置灰并说明原因，恢复后自动补齐（E-12、E-112） |
| **等待人回话** | 审批卡就地插在该流时间轴，全局只用一个未处理计数徽标；**绝不弹全局模态打断其他还在跑的流**（E-109） |
| **批次等人** | 批次标题的收口徽标转暖色（「等你落地 N 个」「收口等你」），批次树自动展开该批且不再自动折叠；批次级收口闸门与任务级闸门同一张审批卡形态（E-272、E-288） |
| **切落地闸门到自动** | 不弹确认框，开关下常驻一句「审查 pass 后直接标记已验收，仍不执行任何 git 操作」；状态等 `settings.gates_changed` 回流（E-299） |
| **正在执行** | 批次树里该任务行的 8px 圆点呼吸；等人的行静态暖点；终态无点。与运行轨当前步是同一种动画（E-282） |
| **任务落地、泳道补位** | 该泳道的阶段链整段转实线并折成一行「会话已归档」历史行，分隔线下方立即换成下一个任务的头部与第一个阶段节点；无可派任务时显示「空闲 · 队列下一个是 〈ID〉」（E-319、E-325） |
| **任务停在闸门等人** | 该任务离开泳道（泳道立即补位）、会话不归档；批次树「等你」行暖色静态点 + 全局未处理徽标，审批卡在任务／运行详情里就地插入；打回后排在新任务之前重新入道，等泳道期间批次树显示「返工排队 · 等泳道」（E-326、E-327） |
| **返工与续审** | 审查节点回到实施节点的回环出现、审查节点行写「第 N 轮」，脉冲点回到实施节点；实施再次退出后脉冲点回到审查节点，轮次 +1（E-315） |
| **查 bug 阶段** | 开关开着时 pass 后阶段链多出「查 bug」节点；报告不合五段或有未修 S1/S2 时该节点变「等你」并插审批卡；关着时该节点根本不出现（E-306、E-308、E-320） |
| **切流水线开关** | 不弹确认框，开关下常驻一行说明；状态等 `settings.pipeline_changed` 回流（E-306、E-312） |
| **疑似停滞** | 显示「已 N 分钟无新输出」的静默计时，而不是让用户自己猜（E-22）；仍在输出时只标弱提示（E-120） |

## 文案原则

- **步骤标签必须是「工具 + 对象」**：写「读取 `orders.csv`（2,481 行）」，
  不许写「工具调用」「处理中」（11 节 avoid#15、#16）
- **不拟人化**：没有「让我想想…」「正在努力中」。步骤标签是日志行
- **不假精确**：没有「准确率 98.7%」「提效 60%」。这是一个以可审计为前提的页面，编了就崩
- **错误文案说清原因与改法**：「模型 `o4-mini` 不在 codex 配置里，选一个或手填」，
  而不是「模型无效」
- **审批文案如实**：手机上批准派发前闸门，文案必须写「批准派发」，
  **不得含糊成「同意」**——否则用户不知道自己刚刚启动了一次运行（E-182）
- **中文用户文案只在前端** `src/i18n/`；daemon 的英文 message 只出现在可展开的「技术详情」里
- **数据缺失显示「—」，不拿 0 冒充**（E-26）

## 无障碍基线

- **状态区分不能只靠色相**——每个状态必须同时有形状与文字。
  两问必须都是「能」：删掉字形还能区分吗？放灰度还能区分吗？（E-110、E-172）
- 形状由 `lib/spine-shape.ts` 的**内联 SVG path** 承载而非 Unicode 字符（决策 46）——
  Android WebView 的中文回退字体不保证有 `⬡` / `▤` / `⌁` 的字形，
  缺字形会显示成豆腐块，而那正是不能只靠颜色时的唯一替代信息
- **键盘可达**：所有交互控件可 Tab 到达；`focus-visible` 用
  `box-shadow: 0 0 0 3px var(--needs-soft)`，**永不 `outline:none` 而不给替代**
- 运行流条目的键盘焦点用**内嵌环**，不能用会撑开布局的 outline（否则滚动列表整体抖）
- **对比度**：深浅两套 token 各自独立核算并由 `check-contrast.ts` 机检（决策 30）；
  正文与次要文字均 ≥4.5:1，已在 11 节逐项标注实测值
- **焦点顺序**跟随视觉顺序：左栏 → 顶栏闸门开关 → 顶栏流水线开关 → 流甲板（按泳道从左到右）→ 泳道内阶段链（自上而下）→ 阶段内时间轴
- 阶段行 `tabindex=0`，Enter 打开该阶段的运行详情；历史行 Enter/Space 开合；焦点用内嵌 2px 环（E-313、E-314）
- 审批卡出现时**焦点移到卡内首个动作**，关闭后焦点回到触发它的那条流
- `prefers-reduced-motion` 下呼吸环（运行轨当前步与批次树执行行）冻结在中间不透明度、流式文本改为整块追加；
  **耗时计数器仍在走**，所以「是不是卡死了」依然有答案
- 批次树是 `role="tree"`，批次标题 Enter/Space 开合、方向键在行间移动，折叠的批不渲染子行；
  收口徽标的 aria-label 含裁定词（「已收口，已修」），屏幕阅读器不能只听到「完成」
- 跟随系统主题与字号，**禁止锁根字号、禁止 `text-size-adjust:none`、禁止 zoom**（E-15）
- 手机端触摸目标 ≥44×44px，停止与批准分置两端或间距 ≥24px（E-107、E-124）

## 感知性能目标

这些是**目标**，不是承诺——15 节说明了哪些数没有实测依据。

| 指标 | 目标 | 依据 |
|---|---|---|
| 首屏可交互 | < 1.5s（局域网，冷缓存） | 产物本地托管、无 CDN、主 chunk 只含三个首屏页 |
| 事件到达 → 屏幕更新 | < 120ms | flush 按帧合并，最小间隔 80ms（E-144） |
| 切换到某条流的历史片段 | < 300ms | 按字节偏移分段读，单段 ≤2000 行（E-98） |
| 十万行日志的滚动 | 不掉帧 | 虚拟列表只挂载可视窗口，**任何时候不把全量放进 DOM 或 store**（E-143） |
| 手机首屏加载会话 | 尾部 32 KB | 不预取全量，切后台回前台不重拉（E-99） |
| 停止按钮的视觉反馈 | 一帧内 | 本地乐观置态，不等回包（E-157） |
