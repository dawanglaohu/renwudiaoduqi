# 安全与权限

**先把这个产品的危险性说清楚：它是一个监听网络端口、能以用户身份启动任意子进程
并让那些进程改磁盘文件的常驻服务。** 一旦有人能对它发请求，
他就能在这台机器上跑代码。本节的全部设计都围着这一句。

## 认证方式

**设备令牌，没有账号体系**（决策 20：单人单机）。

| 环节 | 机制 |
|---|---|
| 配对 | 桌面端生成**一次性配对码**，TTL ≤60 秒，只活在内存（E-07） |
| 换发 | `POST /pair/claim` 用配对码换一枚**长期设备令牌**，配对码立即作废 |
| 存储 | daemon 侧**只存 `scrypt` 哈希 + 随机盐，绝不存明文**；比对用 `timingSafeEqual` |
| 客户端存储 | 壳的安全存储（Tauri / Capacitor Preferences）；**禁止 localStorage**。无壳时降级为 `sessionStorage` 并常驻提示（决策 45） |
| 携带 | `Authorization: Bearer 〈deviceToken〉`。**SSE 也走这个头**——这正是不能用原生 `EventSource` 的原因 |
| 吊销 | 桌面端列出已配对设备，**每台可单独吊销**；吊销后活动连接立即断开并返回 401（E-127、E-156） |
| 限流 | **只有 `/pair/*` 限流**：每 IP 每分钟 10 次，超限 429 **并立即作废当前配对码**（E-07） |

**免鉴权白名单只有三条，写死在一个常量数组里**：
`GET /health`、`POST /pair/claim`、`GET /version`。

**代码中禁止出现任何基于 `remoteAddress` / 网段 / `isPrivateIp` 的绕过分支（E-08）。**
这条是硬约束，因为用户可能自己接 Tailscale / frp 把 daemon 暴露到公网（决策 2）——
「局域网内免鉴权」在那一刻等于裸奔。`AGSCHED_DEV` **明令不得影响鉴权、不得放宽任何校验**。

## 权限矩阵

只有一种主体（已配对设备），所以矩阵很短——但**「谁」仍然要记下来**：

| 操作 | 未配对 | 已配对设备 | 备注 |
|---|---|---|---|
| `GET /health` `/version` | ✅ | ✅ | 不含任何用户数据 |
| 静态资源（Web UI 产物） | ✅ | ✅ | 匿名可取，**这是唯一的非鉴权面**；产物里不含用户数据 |
| `POST /pair/claim` | ✅ | ✅ | 需有效配对码 |
| 其余全部 API | ❌ 401 | ✅ | |
| 生成配对码 | ❌ | ✅ | 已配对设备才能拉新设备进来 |
| 吊销设备 | ❌ | ✅ | 可吊销包括自己在内的任意设备 |

每条写操作都记 `actorDeviceId`（谁派的、谁中止的、谁回的话）；
系统发起（jobs）记 `null`（E-128）。**将来真要加人，历史数据不必迁移。**

## 敏感数据的传输与存储

| 数据 | 传输 | 存储 |
|---|---|---|
| 设备令牌 | 仅在 `Authorization` 头 | daemon 侧只存哈希；客户端存壳安全存储 |
| 配对码 | 响应体一次 | **只在内存**，用掉或过期即消失 |
| agent 的登录凭据 | **本产品从不接触** | 由各 agent 自己维护（`~/.codex/auth.json` 等）。**调度器绝不读取、不搬运、不代管**。登录态探测（决策 108）只跑 agent 自己的状态命令（`codex login status`、`claude auth status`、`grok models`、`pi auth check --provider`），**不读、不缓存任何凭据字段**：`LoginState` 只含枚举与时间；注册表校验拒绝 `print-api-key` / `print-bearer-token` / `--credentials` 这类输出凭据的参数；arch 测试扫全仓禁止出现 `auth.json` / `credentials` 路径串（E-353） |
| 探测命令的 stdout / stderr | 不传输 | 落日志、事件 payload 或 `rawStdout` 之前先过 `redactSecrets()`（`sk-…`、`xai-…`、`ghp_…`、`Bearer …`、JWT 三段形状一律替换为 `[REDACTED]`）；解析器读原文，日志只见脱敏后（E-354） |
| 会话正文 | 走 SSE / REST，**只在局域网或用户自接的隧道内** | 本机文件，不出机器 |
| 源码与 diff | 同上 | 同上 |

**日志与事件里禁止出现令牌、配对码、`Authorization` 头**——
logger 的 `redact` 列表与事件构造处**各挡一道**。

**会话正文可能含密钥**（agent 打印了环境变量或 token）。
跨设备推到手机前做基本脱敏，或至少在首次开启远程查看时明确告知（E-25）。

**没有第三方服务、没有遥测、没有崩溃上报**——
`analytics` / Sentry / 任何自动上报在前端是明令禁止的（07 节）。

## 本项目真正暴露的攻击面

不是通用清单，是这个产品具体开的口子：

### 一、`0.0.0.0:7817` 上的一个能起进程的服务

**最大的一处。** `POST /runs` 的效果是在这台机器上 spawn 一个能改文件的进程。
防线只有一层：设备令牌。所以——

- 令牌泄露 = 机器沦陷。因此令牌**只存哈希**、**可单独吊销**、**吊销即断流**
- 配对码是拿令牌的唯一入口，所以它 **≤60 秒、一次性、限流、超限即作废**
- **绑定地址默认 `0.0.0.0` 是有意的**（手机要连），正因如此鉴权**不能有任何旁路**

### 二、子进程注入

`LaunchSpec` 的 `file` 与 `args` 部分来自用户可编辑的注册表（路径、参数模板）、
部分来自文档（提示词）、部分来自 API（模型名）。

- **调用方恒提供原始参数数组，`proc` 恒 `shell: false`；业务层禁止拼命令串和预转义**（E-42）
- `.cmd` / `.bat` 仅由 Windows 适配器按 08 节接收完整参数并生成 ComSpec 命令，
  该分支设置 `windowsVerbatimArguments: true`；直接启动原生程序仍为 `false`。
  `quoteForCmd()` 与包装接口必须通过真实 `.cmd` / `.bat` 的最终 argv 验证，
  覆盖空格 / 引号 / 分号 / `&` / `^` / `%` / `!`，不得执行额外命令或展开环境变量。
  NUL、CR、LF 参数在启动前返回带参数下标的 `E_VALIDATION`（E-130）。
- macOS/Linux 目标经 `realpath`、普通文件与 `X_OK` 校验后直接 spawn；
  **不得自动 `chmod`、不得交给 `/bin/sh`、不得执行用户 shell 启动文件**（E-262、E-263、E-270）
- 参数模板**只允许白名单模板变量**（`{model}` `{prompt_file}` `{cwd}` `{session_dir}`），
  含未知模板变量保存时即拒绝（E-89）
- 模型名**原样透传不做白名单校验**（清单本就可能不全，E-36），
  所以业务层必须原样传参数数组；ComSpec 例外只由 08 节的 Windows 适配器处理，
  **不得把模型名解释成命令语法**

### 三、agent 自己就是任意代码执行

派出去的 agent 会写文件、跑命令。这不是漏洞，是产品功能。边界靠三条：

1. **权限档默认中档**（`workspace-write` / `acceptEdits`），破坏面限制在该任务的 worktree（决策 22）
2. **运行环境不注入 git 凭据、不启用 credential helper**——
   `GIT_TERMINAL_PROMPT=0`、`GIT_ASKPASS=`、`GCM_INTERACTIVE=never`、
   `GIT_CONFIG_NOSYSTEM=1`、`GIT_CONFIG_GLOBAL=〈空文件〉`。
   **即便 agent 想 `git push`，也会在凭据层失败**（E-138）
3. **落地闸门默认人工，可设自动**（E-53）——自动只表示审查 pass 后直接标已验收，
   产品仍不执行任何 git 操作；分支进不进 HEAD 由人合并决定，产品只判定不动手
4. **四类运行的权限档写死**：实施运行与收口运行 `workspaceWrite`（收口要修 bug，E-283）、
   修复运行与返工运行 `workspaceWrite`（它们就是实施运行）、**查 bug 运行 `workspaceWrite`**（它在该任务同一工作树里直接修，
   不给 `unrestricted`，破坏面仍限在该任务的 worktree）、审查运行 `readOnly`（E-135；续接第 N+1 轮仍是只读，投递的续审消息不改变档位）。
   **收口运行不给 `unrestricted`**，破坏面仍限在它自己的 wrapup 工作区；
   收口与查 bug 提示词的外层包装说明明令禁止 `git commit/push/checkout/branch/merge`、`gh` 任何子命令、
   运行文档维护脚本与改 `docs/` 下文件——这是提示词层的约束，git 凭据层（E-138）仍是真正的闸
5. **归档后的会话只读**：任务到达终态后该任务全部运行的会话被归档，`vendor_session_ref` 从此只作只读引用——
   产品不删、不改、不再向它注入任何消息（E-96 的延伸）；同一泳道换下一个任务时一律新开会话，
   任何新建运行的 `vendor_session_ref` 不得等于其他任务任一运行的引用，违反即拒绝派发并返回 `E_SESSION_ARCHIVED`。
   这条既是「防止上下文污染」的产品要求，也是权限边界：一个任务的 agent 会话拿不到另一个任务的提示词与工作区

**联网装依赖默认拦下并转人决策，且不提供「自动放行网络」的开关**（E-134）。
某个 agent 被手动调到最高档时，**该 agent 卡片与每次派发确认页持续显示醒目标记**
（非一次性 toast），且档位**不随切换到「自动模式」而隐式变化**（E-136）。

### 四、SQL 与路径

- SQL 只在 `repo/`，参数一律绑定；唯一动态片段是排序方向，
  且必须来自封闭枚举 `SORTABLE_COLUMNS`，**禁止把用户串当列名**（08 节）
- `docsPath` 必须是绝对路径且以 `docs-data.js` 结尾（10 节字段契约）
- 清理的候选集**只能由 M6 按白名单目录枚举**；
  **M1 收到白名单之外的删除请求一律拒绝并记违规日志**（E-206）——
  这是防「路径穿越导致误删」的那道闸

### 五、静态资源是唯一的匿名面

Web UI 产物匿名可取。**因此产物里不得含任何用户数据**——
禁止把端口、局域网 IP、配对码、任意 token、数据目录绝对路径写进源码或构建配置（07 节）。
诊断信息一律由 API 返回后显示，不由前端拼。

### 六、明确不在范围内的

- **CSRF**：无 Cookie 认证，令牌只在 `Authorization` 头，天然免疫。**不注册 CORS 插件**（同源）
- **XSS**：会话正文以文本渲染，**禁止 `dangerouslySetInnerHTML`**；
  ANSI 处理走 `ansi-collapse` 剥转义而不是转 HTML
- **多租户隔离**：不存在，单人单机

## 审计留痕

不做独立的审计子系统——**事件流本身就是审计记录**：

- 每条事件带 `actorDeviceId` 与 ISO8601 时间戳
- 写操作（派发、中止、回话、闸门决定、配对、吊销）全部落 `events.ndjson` 全量原文，**永不截断**
- **`agent 自行 push 到远端` 要在任务详情里高亮标注**——拦不住，但必须让人知道发生了什么（E-75）
- 权限受阻记 `run.permission_blocked` 并在时间线高亮，**不判失败**（E-133）
- 自动清理**只清自己捕获的日志正文**；任务记录、三段快照、派发元信息（谁派的、何时、结果、模型）
  **一律保留，历史仍可回溯**（E-105）

**保留期**：默认不自动删除，达阈值只告警（决策 16）。
这既是产品取向，也是审计要求——单人自用场景下，丢历史的代价大于占磁盘。
