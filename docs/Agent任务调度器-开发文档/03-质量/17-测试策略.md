# 测试策略

**本地强制点是验收命令，发布强制点是三平台 CI。** 每个任务的验收标准都必须写死
`pnpm -w check`；任何宣称支持 Windows、macOS、Linux 的版本，还必须在对应 runner 上通过
workspace check、平台集成测试与桌面壳构建。任一平台失败，整个发布检查失败（决策 57，E-265）。

## 那条命令

```bash
pnpm -w check
```

它是三段串联，任一失败即任务不予验收：

```
biome ci .          # 只检查不改写（决策 41）
tsc -b --noEmit     # 全仓类型检查
vitest run          # 单元 + 集成 + 架构断言 + 两个前端检查脚本
```

`vitest run` 里包含 `packages/web/scripts/check-contrast.ts`（决策 30 的机检下限）
与 `check-forbidden.ts`（八条 grep 禁令，07 节）。

**禁止在任务里用 `--no-verify` 式的绕过，或临时关掉某条规则。**

## 分层

| 层 | 做什么 | 位置 | 是否强制 |
|---|---|---|---|
| **架构断言** | 分层禁令、路由表一致性、shared 零依赖、目录名黑名单 | `packages/daemon/test/arch/` | **是**——违规即失败，不靠人 review |
| **单元** | `domain/`（状态机迁移、闸门判定、窗口计算、指纹、冲突判定）与 `adapters/*/map-events.ts` | 各包 `test/unit/` | daemon 的 `domain/` 与 web 的 `lib/` **强制** |
| **集成** | 真起 Fastify + 临时 SQLite + **假子进程**，跑完整的派发→收流→审查链路 | `packages/daemon/test/integration/` | 是 |
| **平台集成** | 路径解析、可执行位、进程组终止与原生自启适配器；每个平台 runner 只执行本机适配器 | `packages/daemon/test/platform/` | 是，Windows/macOS/Ubuntu 矩阵 |
| **前端检查脚本** | 对比度配对、八条禁令 grep | `packages/web/scripts/` | 是 |
| **端到端冒烟** | 真起 daemon + 真构建产物 + 真浏览器：样式生效、配对、派发主流程 | 仓库根 `e2e/`（`vitest.e2e.config.ts`） | 是——单独 CI job，见下方「端到端冒烟」 |
| **手工验收** | 真派一个任务给真 agent；真机看形状；三平台桌面启动；两端配对 | — | 见下方「必须人工过的七件事」 |

**不做覆盖率门槛**——单人项目，覆盖率数字只会诱导写无意义的测试。
强制的是**哪些目录必须有测试**：daemon 的 `domain/`、web 的 `lib/`
（每个文件配同名 `.test.ts`），以及全部架构断言。

## 端到端冒烟

单测与集成测试证明不了「用户打开页面能不能用」——接线审计（2026-09-19）发现 85 个已落地任务全部单测绿，
而产物 CSS 里 `@tailwind` 原样残留、七条路由只挂一条、`sseClient.connect()` 零调用。
所以加一层**端到端冒烟**（M1-T11），它是唯一一个从用户入口进去的测试：

- **真起服务**：`pnpm --filter @agent-scheduler/web build` 出产物后，在临时 `AGSCHED_DATA_DIR`、随机 `AGSCHED_PORT`
  下用 `node packages/daemon/bootstrap.mjs` 起真实 daemon，从 `pairing-code.txt` 读一次性配对码走 `POST /pair/claim`（E-226）
- **真浏览器**：Playwright 只作浏览器驱动库（`playwright` 包的 chromium）在 Vitest 里跑，**不引入 `@playwright/test` 第二套 runner**（05 节）；
  打开 `http://127.0.0.1:〈port〉/#/pair` 完成配对后到 `#/`
- **样式断言**：`getComputedStyle(document.body).fontFamily` 含 `Public Sans`，`#root` 首个子元素的 `background-color`
  不是透明，`document.styleSheets` 里存在含 `.flex` 规则的样式表——没有这三条，运行甲板就是一堆无样式 div（E-159、E-175）
- **一次真实请求 + 一次真实事件**：导入 `e2e/fixtures/docs-data.js`（两个任务的小文档），用 `e2e/fixtures/agents.json`
  里指向假 agent 脚本（按剧本吐 codex NDJSON）的注册表派发第一个任务，断言运行轨出现该运行、
  至少一条 `agent_message_chunk` 文本经 SSE 到达 DOM（E-108、E-10）
- **每层一条**：每个接线注册点（06 节）至少被一条冒烟步骤走到——路由、容器、页面装配、构建管线、事件
- **不 mock**：不替换 `spawnManaged`、不往生产代码注入测试钩子（`window.__setToken` 之类出现即 arch 测试失败）；
  冒烟用的假 agent 是注册表里的一条普通条目，走与真 agent 相同的 spawn 路径（E-135）

- **CI**：`pnpm -w e2e`（`vitest run -c vitest.e2e.config.ts`）作为独立 job 至少在 Ubuntu runner 跑，失败阻断发布（E-265）；
  `pnpm -w check` 的 include 不含 `e2e/`，本地开发不被它拖慢
- **壳内冒烟**归 M10-T6：以 `AGSCHED_SMOKE=1` 启动壳可执行文件，壳加载首页后轮询 `data-style-loaded` 与

## 验收方式

- **每个任务的验收标准必须可客观判定**，且引用它涉及的边界编号（19 节）
- 验收命令固定为 `pnpm -w check`；涉及 GUI 的任务另需 `record-browser-gif` 产出的动图
- **审查阶段的机械检查会跑项目自己声明的 build/test 命令**——
  也就是说本节定的这条命令，同时是产品**运行时**要执行的那条（08 节 M7）。
  这不是巧合：调度器审查它自己的任务时，走的就是这套
- 文档若没有声明测试命令，机械检查会**明示「覆盖有限」并跳过**（E-60），
  而不是假装检查过
