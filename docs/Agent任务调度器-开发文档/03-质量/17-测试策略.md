# 测试策略

**唯一的强制点是验收命令。** 本项目单人自用，**没有 CI、没有 pre-push 钩子**，
所以「跑测试」不是靠纪律，而是靠 19 节每个任务的验收标准里写死了那条命令——
任务不跑它就不算完成（06 节）。

## 那条命令

```bash
pnpm -w check
```

它是三段串联，任一失败即任务不予验收：

```
biome ci .          # 只检查不改写（决策 41）
tsc -b --noEmit     # 全仓类型检查
vitest run          # 单元 + 集成 + 架构断言 + 两个前端检查脚本
```

`vitest run` 里包含 `packages/web/scripts/check-contrast.ts`（决策 30 的机检下限）
与 `check-forbidden.ts`（八条 grep 禁令，07 节）。

**禁止在任务里用 `--no-verify` 式的绕过，或临时关掉某条规则。**

## 分层

| 层 | 做什么 | 位置 | 是否强制 |
|---|---|---|---|
| **架构断言** | 分层禁令、路由表一致性、shared 零依赖、目录名黑名单 | `packages/daemon/test/arch/` | **是**——违规即失败，不靠人 review |
| **单元** | `domain/`（状态机迁移、闸门判定、窗口计算、指纹、冲突判定）与 `adapters/*/map-events.ts` | 各包 `test/unit/` | daemon 的 `domain/` 与 web 的 `lib/` **强制** |
| **集成** | 真起 Fastify + 临时 SQLite + **假子进程**，跑完整的派发→收流→审查链路 | `packages/daemon/test/integration/` | 是 |
| **前端检查脚本** | 对比度配对、八条禁令 grep | `packages/web/scripts/` | 是 |
| **手工验收** | 真派一个任务给真 agent；真机看形状；两端配对 | — | 见下方「必须人工过的六件事」 |

**不做覆盖率门槛**——单人项目，覆盖率数字只会诱导写无意义的测试。
强制的是**哪些目录必须有测试**：daemon 的 `domain/`、web 的 `lib/`
（每个文件配同名 `.test.ts`），以及全部架构断言。

## 优先覆盖：13 节的边界编号

**边界编号是测试用例的第一来源。** 240 条里，下面这些必须有自动化用例——
它们是「写错了不会报错、只会在某天静默出事」的那一类：

| 编号 | 为什么必须自动化 |
|---|---|
| **E-203** | pi 的 RPC 行读取。必须配**一条含 `U+2028` 输出的回归用例**——用 `readline` 会静默丢帧，人工测不出来 |
| **E-131** | CRLF 与 UTF-8。用带中文 + `\r\n` 的假 agent 输出跑一遍 |
| **E-141** | 单行 > 1 MiB 的截断与继续找下一个 `\n` |
| **E-140** | 流里混入非 JSON 行（banner / 进度条）→ 归入 raw.log 并继续，不中断 |
| **E-23 / E-61** | 退出码 0 但 diff 为空 → 必须判失败而不是落地。**这是决策 5 的核心断言** |
| **E-126** | 幂等键：并发两次派发同一任务，断言只起一个进程 |
| **E-46** | 路径冲突排队：两个任务 `taskPaths` 有交集，断言后者等到前者「已落地」才起 |
| **E-123** | daemon 重启对账：伪造一条 `running` + 不存在的 pid，断言标「异常终止」而非成功 |
| **E-153** | 重放窗口过期：`Last-Event-ID` 小于缓冲最小 id → 409 而不是静默丢事件 |
| **E-150** | 第二个实例启动 → 拒绝并退出，断言绝不双写 |
| **E-215 / E-216** | 请求体类型与 JSON Schema 的双向漂移，编译期 + 契约测试各挡一道 |
| **E-236** | 逐档位断言停止控件存在——**把 E-106 从人工检查变成机检** |
| **E-234** | 形状表与状态枚举一一对应，不允许「先上线后补形状」 |
| **E-42** | 参数含 shell 元字符时仍以数组传递；`quoteForCmd()` 必须有覆盖空格/引号/`;`/`&`/`^` 的用例 |
| **E-138** | 断言子进程环境里 git 凭据相关变量全部被禁用 |

**假子进程是集成测试的关键装置**：容器里 `proc.spawnManaged` 可替换
（08 节 DI 要求「凡与外部世界交互的都必须有可替换实现」），
测试用一个能按脚本吐 NDJSON、控制退出码与时序的假实现。
**禁止在测试里 mock 模块路径**——替换容器里的实现，不是 hack import。

同理，`clock` 与 `ids` 必须从 DI 注入，否则 `domain/` 无法确定性测试（08 节 utils）。

## 必须人工过的六件事

自动化测不了，但**没过就不算交付**（对应 01 节的七条完工标准）：

1. **四个 agent 各派一个真任务**，四个都能跑起来并正常结束——
   假子进程测不出参数拼错、模型名无效、登录态过期
2. **真机看形状**：Android 真机 + Windows 125%/150% 缩放各看一次，
   12 个形状不许糊成一团（E-232）
3. **两端配对全流程**：生成配对码 → 手机扫 → 收到完成通知 → 回一句话 → 中止一个任务
4. **翻完一个几十万字的会话**，桌面端与手机端都打得开、不卡死
5. **半自动跑完一整批**：自动派发 → 自动机械检查 → 自动 agent 审查 → 停在人面前等放行
6. ~~**第一个前端任务出一屏真页给用户看**~~ **已于 2026-09-01 完成并获确认**——
   R-03 关闭，视觉方向不再是未决项（决策 28、E-160）。
   后续前端任务照 11 节已确认的 token 表实现即可，**不再重开方向讨论**

## 验收方式

- **每个任务的验收标准必须可客观判定**，且引用它涉及的边界编号（19 节）
- 验收命令固定为 `pnpm -w check`；涉及 GUI 的任务另需 `record-browser-gif` 产出的动图
- **审查阶段的机械检查会跑项目自己声明的 build/test 命令**——
  也就是说本节定的这条命令，同时是产品**运行时**要执行的那条（08 节 M7）。
  这不是巧合：调度器审查它自己的任务时，走的就是这套
- 文档若没有声明测试命令，机械检查会**明示「覆盖有限」并跳过**（E-60），
  而不是假装检查过
